# backends.md — 压缩后端选型矩阵与预压缩配方

## 选型矩阵（2026 开源实测共识）

| 后端 | 级别 | 适用 | 不适用 |
|---|---|---|---|
| zstd (zstandard) | 22 + --ultra | 通用首选：速度/比率平衡最好；字典训练对大群小文件降维打击；seekable 分帧支持随机访问 | 极端小文件单件（字典开销）；内存极受限（22 级窗口大） |
| xz (LZMA2) | -9e | 纯比率极限：文本/源码常比 zstd-22 再小 3–8%；环境恒在（liblzma） | 大文件慢；无字典 |
| brotli | q11 | 网页文本（内建静态字典对 HTML/JS/CSS 特化） | 二进制 |
| bzip2 | -9 | 兜底（恒在） | 一切有更优解的场景 |

## 预压缩配方（压榨顺序）

1. **固体打包先行**：多文件必先 tar solid（小文件群元数据摊薄 + 跨文件冗余可压）。
2. **字典训练**：相似小文件群（技能库/语料库/日志群）→ `--dict`，样本 ≥100 件、单件 <100KB 时收益最大（典型再省 20–50%）。
3. **delta 过滤**：等长数值序列（PCM/采样数据）先差分再压；BCJ 仅对可执行二进制。
4. **文本规整**：统一 LF、去尾空白、JSON 排序键——确定性即压缩率。

## 预解压设计

- 包头自描述（fmt/mode/dict/src_sha256）：接收端零协商。
- 字典随包：训练字典嵌入包体（4 字节长度前缀），免外部字典分发。
- seekable 需求（随机读大压缩包）：zstd 分帧（zstandard 支持 frame 拼接），每帧独立可解——本管线 v1 未实装分帧索引，需要时升级 v2（在包头加 frame_index）。

## 诚实边界

- 「极致」是**在给定数据与时间预算下的实测最小**，auto bench 数据即证据；不许宣称理论极限。
- 已压缩格式（zip/gz/jpg/mp4/glb）二次压缩收益 ≈0——此类件走指针化/快照，不走重压。
- 压缩≠加密；敏感件先走凭据纪律（永不入包）。
