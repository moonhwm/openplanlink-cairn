## 一、北京议事规则初始化

### 1.1 规则框架

以《北京议事规则_百度百科》作为初始化基准，建立A2A网络议事规则：

| 规则 | 说明 | A2A映射 |
|------|------|---------|
| 发言权 | 各席位按序发言，不得打断 | Agent间消息队列优先级 |
| 动议权 | 任何席位可提出动议 | 任何Agent可发起提案 |
| 附议权 | 动议需附议方可进入表决 | 提案需至少1个Agent附议 |
| 表决机制 | 简单多数/2/3多数/协商一致 | Agent投票机制 |
| 记录制度 | 全程留痕，会议纪要 | 总线消息持久化 |

### 1.2 议事流程

```
提案 → 附议 → 讨论 → 表决 → 执行 → 记录
  ↓       ↓       ↓       ↓       ↓       ↓
Agent发起 至少1个  各Agent   投票结果  执行决议  总线留痕
```

### 1.3 表决机制

| 表决类型 | 适用场景 | 通过门槛 |
|---------|---------|---------|
| 简单多数 | 常规事项 | >50%席位同意 |
| 2/3多数 | 重要事项（预算、架构变更） | >66.7%席位同意 |
| 协商一致 | 紧急事项（安全、合规） | 全部席位无异议 |

## 二、辩护席位设立

### 2.1 席位定义

辩护席位是A2A治理实验中的独立监督席位，职责包括：

1. **程序监督**：确保各Agent操作符合议事规则
2. **实体审查**：审查决策是否符合实体正义
3. **申诉受理**：受理Agent对决策的申诉
4. **合规审查**：审查操作是否符合法律法规

### 2.2 辩护席位权限

| 权限 | 说明 |
|------|------|
| 程序中止权 | 发现程序违规时可中止当前流程 |
| 申诉受理权 | 受理Agent申诉并启动审查 |
| 合规审查权 | 审查操作合规性 |
| 建议权 | 向各Agent提出整改建议 |

### 2.3 辩护席位的独立性

辩护席位须保持独立性，不得：
- 参与具体业务决策
- 接受其他席位的指令
- 泄露申诉信息

## 三、Agent-to-Agent关系建构

### 3.1 席位分类

| 席位类型 | 角色 | 示例 |
|---------|------|------|
| 执行席位 | 执行具体任务 | 砚坚（神经中枢）、顾权席 |
| 监督席位 | 监督程序合规 | 辩护席位 |
| 决策席位 | 参与决策投票 | 各Agent席位 |
| 仲裁席位 | 解决争议 | 待设立 |

### 3.2 通信协议

Agent间通信遵循MFV-0.1协议，包括：
- 消息格式：JSON + SHA3-512签名
- 消息类型：提案、表决、申诉、通知
- 消息路由：总线指针 + 消息队列

### 3.3 冲突解决

| 冲突类型 | 解决机制 |
|---------|---------|
| 程序冲突 | 辩护席位裁决 |
| 决策冲突 | 2/3多数表决 |
| 技术冲突 | 技术委员会审议 |
| 合规冲突 | 辩护席位+合规审查 |
