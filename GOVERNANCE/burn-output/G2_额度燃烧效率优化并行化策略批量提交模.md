# 额度燃烧效率优化——并行化策略、批量提交模式、长上下文优先、模型特长匹配

> 知识资产编号：G2 ｜ 专题：额度治理（效率层） ｜ 适用工程：harmony-app（铃语）
> 本篇自包含、可独立持久化，建立在G1六维账本之上；工程事实引自批次任务书共享上下文。

## 一、效率的定义：高效燃烧不等于快速花光

先把目标钉死：额度燃烧效率优化的目标是"单位额度换回更多有效产出"，而不是"把额度尽快花完"。为烧而烧是浪费的另一种形态；更糟的是，窗口末尾的冲刺式燃烧容易诱发低质产出与合规松弛（字数注水、催促性话术混入），把效率问题变成质量问题乃至红线问题。

有效产出定义为三类可持久化成果：落盘的知识文档、通过验证的代码或配置、可复用的模板与清单。凡不能落盘、不能复验、需要返工重做的消耗，一律计入无效边。由此给出四个核心度量指标：

产出密度：正文汉字数除以千token消耗，衡量写作类任务的转化率；一次通过率：无需返工即被接受的任务占比，返工是最贵的隐性消耗；无效消耗率：重试、超时、废弃调用占总消耗的比例，正好对应G1用途维的第六类；上下文复用率：同一份装载的上下文被多少个产出复用，复用越高说明装载成本摊得越薄。

## 二、度量先行：没有台账就没有优化

效率优化必须建立在G1账本之上，拍脑袋的"感觉变快了"不是证据。每次模型调用登记一条事件：任务id、用途归类、输入token、输出token、成败与错误码，JSONL落盘于治理目录。这份数据同时是G5监控仪表盘的原始输入——度量体系一次建设，效率与监控两头受益。

用一个换算示例说明度量的价值（数值为示意）：五篇四千字文档，若逐篇独立装载全部共享上下文，上下文要重复装载五次；改为批次头一次装载加路径引用后，输入侧可省约四成。这类账只有靠事件日志逐笔累计才能算出来，估算与直觉在额度问题上从来靠不住。

## 三、并行化策略：最直接的时间杠杆

并行化把总时延压短，从而降低任务占用期内的中断风险，前提是任务之间真的无依赖。

任务级并行：先做依赖分析再排并行，这是纪律。以本批次为例，G1至G5五篇主题互不依赖，可并行起草；但G5监控的指标定义引用G1的六维账本、G4降级链引用G1的替代关系标注，属于弱依赖——处理办法是"并行初稿、串行校对"：各篇先按共享上下文独立成文，再统一核对交叉引用的术语与编号，而不是让G5干等G1完工。弱依赖的串行等待是并行化中最常见的无为损失。

工具级并行：同一次响应里把多个无依赖的工具调用并行发出，例如同时检索两个不同主题、同时核对两个文件。串行发起工具调用会把时延累加，变相拉长任务占用期，间接提高超时与失败概率，而失败意味着全额重烧。

并发上限：并行度受G1约束维的QPS与并发上限约束。并发过高触发429限速，重试反而多烧额度——并行化的收益曲线是先升后平再降，最优点在"下游限速阈值之内取最大"，而不是"机器能开多少并发就开多少"。求快先看约束维，这是并行设计的第一步。

失败隔离：并行批次中单任务失败只标记该任务进入重试队列，不整批回滚；结果聚合点放在全部完成后一次性进行，避免中途聚合放大重试范围。一次失败波及五篇的代价，是五篇的额度全废。

反模式两条要写进SOP：伪并行——名义并行、实际在队列里排队，白白增加协调开销；过度并行——超出下游处理能力，触发限速与截断，产出残篇再返工。

## 四、批量提交模式：摊薄固定成本

每次调用都有固定开销：请求骨架、上下文装载、格式与合规约束说明。单个任务体量越小，固定开销占比越高，批量的收益就越大。

合并同构小任务：五篇文档的共享上下文（工程约束、架构基调、合规红线、写作规范）在批次头装载一次，后续各篇引用要点而不重复全文——这正是本批次的实际做法，即"共享上下文单次装载、产出逐篇核销"。

单次多产出：让一次生成完成"提纲—展开—自评"的完整闭环，而不是拆成三次调用再拼接。这样不仅省调用次数，内部一致性也更好——分段拼接的产出常见口径漂移，返工率反而上升。

请求模板化：固定请求骨架（角色定位、硬约束清单、输出格式、字数区间、落盘路径），把易变部分限制在任务参数里。模板稳定还能显著降低格式返工率——格式不合规范是最常见的隐性浪费之一，一次返工等于燃烧额度却产出废纸。

批量核销：自评与产出同批落盘，登记与交付一次完成，避免"写完正文再专门花一轮额度写自评"。自评随文批量提交，也是本批次的既定规范。

## 五、长上下文优先：贵的一次装载优于廉价的反复检索

原则一句话：反复召回不仅花调用次数，还花"重新理解"的输出token；十次碎片召回的总成本常常高于一次全文装载。在上下文成本结构里，装载是固定成本，复用是零边际成本——所以长上下文的价值随复用次数线性放大。

持久化优先于记忆：把上下文写成磁盘文件（如本批次的任务书要素、`GOVERNANCE/burn-output/`下的既有产物），之后引用路径而非复述内容。路径引用的额外好处是抗断连——会话中断后新席位接手，读文件即可恢复现场，不依赖对话记忆；这也正是写作规范"引用文件路径而非对话记忆"在额度经济学上的根据：复述内容每轮都烧token，引用路径只烧一次登记。

压缩再重放：长上下文跨席位传递前，先压缩为要点清单再发送，展开原文的需求交给接收方按路径自行读取。发送方少烧传输，接收方按需装载，两头都省。

边界与代价必须说清：长上下文会放大单次失败的成本——装载了一大段上下文结果生成失败，重试要全额再烧一遍。因此长上下文必须与验证策略配合：先小成本确认提纲与口径，再装载全文展开；展开失败时利用已确认的提纲续作，而不是从零重来。先提纲后展开，等于给长上下文上了保险。

## 六、模型特长匹配：矩阵服从模型锁

理想状态下，任务类型与模型档位按矩阵匹配：深度推理类（架构审计、合规复核、疑难排障）用满血模型；高体量产出类（清单枚举、批量文档、格式整理）用Flash高速档；中间态任务由性价比与当期额度结构决定。

但匹配必须服从约束维的模型锁。本席位锁定GLM-5.3-Flash，等价于矩阵退化为一列——所有任务都在Flash上跑。锁定下的替代路径是把深任务拆成可验证的浅步骤，三步走：第一步分解，把大问题切成每步可自检的小问题；第二步每步自检，用清单核对而不是整体思辨；第三步交叉引用，把结论挂到工程文件与既有产物上，让正确性可被外部校验，而非依赖模型内省。

这套拆解不是万能药：Flash上做深度推理，正确性风险客观存在。对策是如实自评并在产出中显式标注不确定点，把复核责任交给机主或后续席位——宁可承认短板，不可伪装满血。效率优化永远不许以牺牲正确性声誉为代价。

## 七、反模式清单十条

一、重试风暴：失败后原样重发且无退避，消耗几何级放大。二、无缓存检索：同一资料反复查取而不落盘，检索成本重复支付。三、上下文反复重读：每次调用都重新装载全文，而不引用路径。四、过度验证循环：为求安心无限复核，验证消耗反超产出消耗。五、注水凑字：为凑字数重复表述，产出密度归零还拉低质量分。六、为并行而并行：无依赖分析就开并发，制造协调开销。七、模板漂移：请求骨架频繁变动，导致格式返工。八、失败原样重发：不分析错误码就重试，429重成限速雪崩。九、忽视限速：并发设计无视QPS约束，与第八条互为因果。十、自评写成长文：复盘本身成为新的高消耗任务，违背批量核销原则。

## 八、落地示例：本批次的效率设计

本批次（G1至G5）的执行即上述策略的完整样本：五篇一次规划、逐篇落盘——任务级并行加串行校对；共享上下文批次头单次装载——批量提交；各篇结构相近（定位、原则、方法、模板、小结、自评），请求模板稳定——模板化；落盘与自评同批完成——批量核销；交叉引用（G5引G1、G4引G1）一律用编号与路径，不复述内容——长上下文优先。字数目标四千、最小完成线百分之八十五，即产出密度的显式控制手段：字数线既是质量下限，也是"高效不注水"的检验器。

## 九、伪代码：额度感知调度器

```typescript
class BurnDispatcher {
  private ledger: QuotaAsset[]        // G1六维台账
  private inflight = 0
  constructor(private qps: number) {}  // 并发上限来自约束维

  async runBatch(tasks: Task[]): Promise<Result[]> {
    const independent = tasks.filter(t => !(t.dependsOn?.length))
    return await Promise.all(independent.map(t => this.acquire(t)))  // 失败隔离
  }

  private async acquire(t: Task): Promise<Result> {
    for (let tries = 0; ; tries++) {
      while (this.inflight >= this.qps) await sleep(200)  // 宁慢勿429
      this.inflight++
      try {
        return await this.execute(t)      // 模板化请求 + 单次多产出
      } catch (e) {
        if (tries >= 2 || !isRetryable(e)) throw e        // 最多两退避
        await sleep(backoff(tries))                        // 指数退避防风暴
      } finally { this.inflight-- }
    }
  }
}
```

要点有三：并发闸门先于任务执行；重试带指数退避与次数上限，把重试风暴锁死在源头；每任务独立try，失败不扩散到整批。

## 十、小结

效率优化四支柱各管一段：并行化管时间（压时延、防中断）、批量提交管固定成本（摊薄装载与骨架）、长上下文管信息成本（一次装载多次复用）、模型匹配管单位质量（对的档干对的事，锁死时拆深为浅）。四者共同的前提是G1的账本与G5的度量——先度量、再优化、优化后再度量，循环不闭，效率 claims 一律视为未验证。
