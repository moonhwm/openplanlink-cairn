# 12. Phi Accrual故障检测器：原理、参数与实现

> 摘要：本文讲解Phi Accrual故障检测器如何把到达间隔建模为概率分布并输出连续可疑度，推导其核心公式，给出实现代码骨架，分析参数敏感性以及与固定阈值检测器的对比。

## 一、从二元判定到连续可疑度

固定阈值检测器输出非黑即白的结论：超时即死，未超即活。这种二元的输出丢失了大量信息——超时一毫秒与超时十秒得到同样的结论，而两者的可信度天差地别。超时十秒几乎可以断定失效，超时一毫秒则很可能只是抖动。Phi Accrual检测器的思想源于海桑卡亚等人的研究并由Akka广为人知：把心跳到达间隔建模为概率分布，输出"当前已经等待的时长在正常分布下有多不正常"的连续值，称为phi。phi越高越可疑，且随等待时间平滑增长，调用方可以按不同严厉程度取不同阈值——同一个检测器同时服务于"快速告警"与"谨慎切换"两种用途，无需重复检测。

## 二、核心公式推导

设心跳到达间隔服从均值mu、标准差sigma的正态分布（保守变体使用最小值、均值与标准差三者取最大方差）。当前时刻距最近一次心跳已经过t时间，则phi定义为负以十为底的log乘以P概率：phi = -log10(P(X > t))，其中P(X > t)是正常情况下间隔超过t的概率。直观解读：若正常分布下等待超过当前时长的概率是百分之十，phi约0.1的可信度级别；概率是千分之一，phi约3。phi每增加一，可疑程度提升一个数量级。检测器维护滑动窗口内最近的到达间隔序列，持续估计mu与sigma，从而自动适应网络与负载的长期变化——白天间隔均值升高，分布参数随之漂移，同样的等待时长在夜间的phi值反而更高，误报被自然吸收。

```python
# Phi Accrual 检测器骨架
import math, statistics, time, deque

class PhiAccrual:
    def __init__(self, window=1000, min_std=0.01):
        self.hist = deque(maxlen=window)   # 到达间隔历史
        self.last = None
        self.min_std = min_std
    def heartbeat(self, now):
        if self.last is not None:
            self.hist.append(now - self.last)
        self.last = now
    def phi(self, now):
        if self.last is None or len(self.hist) < 2:
            return 0.0
        mu = statistics.fmean(self.hist)
        sigma = max(statistics.pstdev(self.hist), self.min_std)
        t = now - self.last
        # 正态生存函数的对数近似(标准差远小于均值时用简化式)
        if t <= mu:
            return 0.0
        z = (t - mu) / sigma
        p = 0.5 * math.erfc(z / math.sqrt(2))     # P(X > t)
        return -math.log10(max(p, 1e-12))
# 用法: phi >= 1.0 告警; phi >= 8.0 切换; 阈值按用途分层
```

## 三、参数体系与敏感性

窗口大小决定分布估计的记忆长度：窗口越大参数越稳定但对行为突变适应慢，窗口越小越灵敏但分布估计噪声大，常用值在数百到一千个样本。最小标准差防止分布退化——当心跳极其准时sigma趋零，任何微小延迟都会爆出巨大phi，设置下限是必需的保险。阈值语义：phi为1对应正常情况下约十分之一的概率事件，每天心跳上万次的系统中会频繁触发，只适合做低级别的观察信号；phi为8对应亿分之一的概率，适合触发切换；中间档位用于告警。三档阈值对应三种动作，是phi体系相对固定阈值的核心优势——一个检测器实例服务多种置信度需求。

敏感性方面要注意三点。其一，正态假设在长尾网络上并不成立，间隔分布常呈重尾，保守变体（用min间隔、均值、标准差中的最大者作为等效标准差）可以缓解但无法根除，重尾明显的环境应改用对数正态或核密度估计。其二，窗口内的样本必须来自同一行为模式，进程重启或负载模式切换会污染分布，epoch跳变时应清空历史重新积累。其三，phi在t接近mu处增长平缓、远离后陡增，阈值的选择要参考真实分布的分位数而不是拍脑袋等比缩放。

## 四、与固定阈值检测器的对比与选型

固定阈值的优势是行为可预测、实现简单、参数含义直白，劣势是误报与延迟刚性绑定，且不能自适应漂移。phi的优势是连续输出、多阈值复用、自适应分布漂移，劣势是行为不那么直白——调参者必须理解概率语义，排障时还要解释分布估计本身。选型建议：规模小、节点行为稳定的体系用固定阈值即可；规模大、环境异构、需要同一检测服务于多种动作时，phi的收益显著；最稳妥的实践是混合——固定阈值做第一道快速通道（如硬超时兜底），phi做精细判定层，两者结论都汇入状态机。

## 五、工程化注意事项

- 分布参数估计值（mu、sigma）与当前phi一起作为指标导出，供排障与调参；
- 窗口初始化阶段样本不足时输出phi为零，冷启动期用保守的固定阈值过渡；
- epoch变化清空窗口，防止重启前后不同分布互相污染；
- 重尾环境评估对数正态或保守变体，以实测ROC曲线验证误报率；
- 阈值变更走灰度，先对少量对象生效并观察误报计数；
- 与固定硬超时并联兜底，phi估计自身卡死时体系仍能给出基础判定。

## 六、验收方法

phi检测器的验收采用注入实验：对健康节点采集两周间隔数据得出基线误报率；注入进程杀死、网络丢包梯度、延迟注入三类故障，测量从失效到各档phi阈值首次越过的时间分布。合格标准通常定为：健康态误报（phi越过8）为零或每周不超过一次，硬失效的切换级检出时间P99小于设计上限，且软失效（延迟恶化）能被中档阈值及时捕捉。验收数据随每次参数或窗口策略变更重测归档。
