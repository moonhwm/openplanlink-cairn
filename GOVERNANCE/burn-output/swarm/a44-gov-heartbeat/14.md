# 14. 拓扑感知的存活检测：机架、可用区与地域维度

> 摘要：本文阐述为什么存活检测必须感知部署拓扑：观察者的故障域分布、被判定对象的相关失效、心跳路径的拓扑多样性，以及跨地域检测的特殊处理，给出拓扑元数据管理与相关性告警的实践。

## 一、拓扑无关检测的隐患

若心跳体系完全无视部署拓扑，把所有节点当作独立个体，会遭遇两类系统性问题。第一类是相关性失效被误读为独立事件：一个机架的交换机故障会让该机架上百个节点同时失联，拓扑盲的检测器会同时产生上百条独立告警，值班人员被淹没，而真正该告警的"交换机故障"反而隐藏其中。第二类是观察者失效：如果检测器实例恰好与被监控对象共享同一故障域，该域故障时检测器与对象一起沉默，形成检测盲区且无人知晓。拓扑感知的本质是把"网络位置"作为心跳体系的一等公民，让判定、告警与观察者布局都能利用位置信息做出正确决策。

## 二、观察者的故障域布局

观察者（检测器实例）的布局原则是：对任意单故障域的失效，至少多数观察者仍能独立观察该域内对象。落地时按层级校验：设故障域层级从低到高为主机、机架、可用区、地域，对每个被监控对象，计算覆盖其观察者在各层级的分布；若某层级上单一域故障即导致观察者损失过半，则布局不合规。常用配置是三可用区各部署一个观察者，跨区观察延迟差异通过分位数校准吸收而非统一阈值硬比较。观察者自身的心跳也要上报其拓扑位置，让布局审计自动化：一个定时任务持续计算"任一域失效后的剩余观察矩阵"，发现违规即告警。这防止了集群扩容或迁移过程中观察者悄悄聚到同一域而不自知。

## 三、相关性失效的聚合判定

拓扑感知判定的核心能力是失效相关性归因。当多个对象在短时间内先后失联，检测器不应逐个独立判定，而应先做拓扑聚类：若失联对象集中在同一机架，则挂起个体判定，先发起对机架级与交换机级的基础设施探测；若机架级探测确认故障，个体失联被归并为一条机架级事件，附失联对象清单。归并判定的收益有三：告警数量从N降为一；处置指引指向正确层级（换交换机而非重启百台机器）；个体误判被群体证据纠正。实现上需要一张拓扑映射表：节点到机架、机架到可用区、可用区到地域的从属关系，来源可以是基础设施的CMDB或编排系统的标签，必须保持自动同步，手工维护的拓扑表很快会与现实脱节。

```text
# 相关性归并判定伪码
on_batch_suspect(nodes, window=10s):
    groups = group_by(nodes, key=机架)          # 按拓扑聚类
    for rack, members in groups if len(members) >= 阈值:
        result = probe_rack_infra(rack)          # 询问交换机/带外管理
        if result == FAULT:
            emit 机架级事件(附成员清单); 挂起成员个体判定
        else:
            继续成员级正常判定流程(可能是巧合聚集)
    阈值建议: 机架内失联比例超过一半, 或绝对数超过5
```

## 四、跨地域检测的特殊处理

跨地域链路的长尾与抖动远超同地域，直接套用同地域阈值会造成常态误报。标准做法是地域维度双轨化：同地域观察者负责精细判定（快速、低阈值），跨地域观察者只参与仲裁级判定（慢速、高阈值），两地观察者的结论通过汇聚层按地域权重融合。另一个跨地域特有问题是光速与排队延迟带来的心跳间隔下界：洲际往返几十到一百多毫秒，心跳间隔不宜低于数百毫秒，否则链路自身排队就会造成分布发散。跨地域判定还应感知地域间链路的健康度——链路丢包率升高时，该链路上观察者的票权自动降级，防止链路故障被误读为对端地域全体失联。

## 五、拓扑元数据管理

拓扑感知体系的质量上限由元数据质量决定。管理要求包括：节点元数据（机架、可用区、地域、宿主机）在节点注册时强制携带并随调度事件自动更新；拓扑表变更事件（机架扩容、可用区迁移）推送给检测器热生效；每周执行一次拓扑快照与CMDB比对，漂移即告警；观察者读取拓扑带版本号，判定日志记录当时所用版本，保证历史判定可解释。曾发生过的教训是：机房搬迁后部分节点的机架标签未更新，机架交换机故障时归并判定失灵，退化为个体告警风暴——拓扑数据失真时，感知体系不仅无益反而有害。

## 六、落地检查清单

- 每个被监控对象标注机架、可用区、地域三层拓扑标签，自动同步；
- 观察者布局通过"任一单域失效仍有多数观察者"的自动审计；
- 短时批量失联先做拓扑聚类归并，基础设施探测确认后再下结论；
- 跨地域观察者只参与仲裁级判定，票权随链路健康度动态调整；
- 心跳间隔下界考虑跨地域往返，不用同地域参数硬套；
- 拓扑表版本化，判定日志记录拓扑版本，快照比对每周执行；
- 机架级、可用区级故障注入演练每年至少一次，验证归并判定生效。
