# 09. 推拉结合：混合探活模式的结构与适用场景

> 摘要：本文分析推模式与拉模式各自证据特性的局限，给出混合探活的三种结构——互验型、分工型与升级型，讨论证据融合与冲突仲裁规则，并附混合判定状态机与选型清单。

## 一、单一模式的证据盲区

推模式的证据是"节点还能发声"，它无法发现进程假活——专门的喂狗线程可以长期掩盖业务线程的死锁；它也无法证明服务真的可被外部使用，因为心跳通道与业务通道可能命运不同。拉模式的证据是"节点还能应答"，它无法感知节点即将到来的失效，例如内存即将耗尽前的挣扎期；它也受探测方自身网络位置的局限，单探测点的失联结论可能只是局部网络问题。两种证据在故障覆盖上几乎互补：推模式对崩溃类故障灵敏，拉模式对假活类故障灵敏。因此对关键对象，成熟的体系从不依赖单一方向，而是推拉并用，让两条独立路径互为佐证。

## 二、混合结构的三种形态

第一种是互验型：推心跳与拉探测同时常驻运行，任何一方的失联结论都必须经另一方确认后才升级为可触发切换的硬结论。例如心跳停了但探测仍通，判为疑似假活，触发深入诊断而非直接切换；探测失败但心跳正常，判为服务路径异常，同样进入诊断通道。这种结构把误切换率压到极低，代价是判定延迟略增，适合切换代价高昂的存储与数据库层。

第二种是分工型：按对象属性静态分配模式。可改造的自有服务用推模式获取丰富的进程内证据，不可改造的外部依赖用拉模式做黑盒探测，两者结果汇入同一判定层，用统一的状态机与告警语义管理。这种结构工程上最常见，重点在判定层的统一，避免两套体系各自告警、语义打架。

第三种是升级型：常态只跑低成本的一种（通常是推心跳），当推心跳出现异常嫌疑时，判定层临时发起拉探测作为复核；反之，拉探测发现响应变慢时，也可以请求节点侧补充心跳内的队列深度等细节。探测是按需调用的诊断手段而非常驻负载。这种结构开销最小，但要求判定层具备动态发起探测的通路，实现复杂度集中在判定侧。

## 三、证据融合与冲突仲裁

```text
# 混合判定状态机（简化）
状态: HEALTHY --(推停或拉败任一)--> SUSPECT
SUSPECT:
    if 推停 且 拉败:        -> DEAD        (双证据一致，可切换)
    if 推停 且 拉通:        -> PSEUDO_ALIVE (假活嫌疑，诊断+人工/自动处置)
    if 推在 且 拉败:        -> PATH_FAULT  (服务路径故障，摘流量不切主)
    if 复核窗口内双双恢复:   -> HEALTHY     (记录一次flap)
DEAD: 启动切换流程; 恢复需双证据回归且观察期通过
```

融合规则的设计原则有三。第一，影响越大的动作需要越强的证据：重启Pod可以单证据加时间确认，主从切换必须双证据加仲裁。第二，两个证据源独立失效的概率远小于单一来源，因此双证据一致的结论可信度按乘积近似而非简单相加，冲突时宁可信"坏得没那么彻底"的结论。第三，冲突本身就是信息：推停拉通指向假活，推在拉败指向路径问题，这两类结论对应完全不同的处置手段，绝不能合并成一个笼统的"节点异常"。仲裁还需要考虑证据新鲜度——拉探测刚成功而心跳停了五秒，与心跳停了五分钟而探测是三分钟前的旧结果，结论权重完全不同，融合时必须打时间折扣。

## 四、实施要点与成本控制

混合模式的主要成本是体系复杂度翻倍：两套采集、两套超时参数、一套融合逻辑。控制复杂度的手段包括：把推与拉的原始结论归一为统一的三态加置信度表示，融合层不感知证据来源细节；两套参数共用同一份误报预算，分别核算再合并；为融合状态机的每个迁移路径编号并在日志中记录触发证据对，使任何一次判定都可回放。升级型结构还应限制动态探测的并发与频率，防止复核风暴。此外要防环路：判定层调用拉探针，探针又依赖被判定节点的服务，若被判定节点恰是探针的依赖，必须显式打断循环，例如探针的依赖故障时直接返回本地质询结果而非挂起。

## 五、适用场景与选型清单

- 切换代价高的核心存储：采用互验型，双证据才允许切换；
- 自有服务与外部依赖并存的中台：采用分工型，统一判定层收口；
- 万级以上规模、探测成本敏感：采用升级型，常态只跑心跳；
- 融合状态机的每个状态有明确处置预案，无"无人认领"状态；
- 冲突结论（假活、路径故障）有独立的告警级别与值班路由；
- 证据新鲜度参与融合加权，旧证据自动降权；
- 定期用注入实验回验四条迁移路径的判定延迟与准确率。

## 六、演进建议

混合模式不必一步到位。推荐的演进路径是：先以推模式建立基线检测能力；再为最关键的前百分之五对象叠加拉探测形成互验；运行稳定后把融合状态机通用化，逐步扩大双覆盖对象比例；最后按成本预算决定其余对象停留在分工型还是升级型。每一步都以误报率、漏报率与切换准确率三项指标验收，确保复杂度的每次增加都换来可度量的检测质量提升，而不是为了架构图好看而叠加机制。
