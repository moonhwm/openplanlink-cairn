# 22. 告警风暴抑制：去重、聚合、静默与收敛机制

> 摘要：本文系统讲解告警风暴的四道抑制闸门——去重、聚合、静默与收敛——的原理与实现，分析风暴的成因模式，给出风暴模式的进入退出条件与事后续航清单。

## 一、风暴的成因与危害

告警风暴指单位时间告警量骤增，超出人与系统的处理能力。心跳体系的风暴成因有典型模式：一是扇出风暴，一个上游故障（交换机宕机、汇聚器故障）引发其下所有对象的告警同时爆发，数量与拓扑规模成正比；二是抖动风暴，网络临界状态下对象反复失联恢复，每个flap产生成对事件，数量与时钟抖动时长成正比；三是级联风暴，失联触发切换，切换引发新的不健康，新告警叠加原告警；四是检测体系自身故障造成的全局误报，例如某观察者时钟跳变使其判定全体对象失联。风暴的直接危害是通知通道过载（短信通道被占满、群消息刷屏），深层危害是注意力湮灭——真正的根因告警埋在几百条衍生告警里，值班人员在混乱中做出错误判断。风暴抑制的设计目标：无论风暴多大，抵达人的告警流保持在与处理能力匹配的速率内，且根因始终置顶。

## 二、第一道闸门：去重

去重处理同一事件的重复通知。判定"同一"需要事件指纹：由对象标识、事件类型、根源标识、分级四要素构成哈希。指纹相同的事件在活动期内合并——计数增加、时间戳更新，但不产生新通知。去重的关键参数是活动期与重通知间隔：活动期内完全静默重复，超过重通知间隔仍未恢复则再发一次提醒（携带累计次数），防止"发过一次就再也不发"导致长时间故障被遗忘。去重的陷阱是指纹设计过粗或过细：过细（含时间戳）则重复不被识别，去重失效；过粗（只含对象）则不同类型事件互相吞并，丢失信息。指纹字段集合必须版本化，指纹算法变更是不兼容变更。

## 三、第二道闸门：聚合

聚合处理不同但相关的事件。相关性来源有三：拓扑相关（同机架、同宿主机、同汇聚器域）、时间相关（短窗口内先后发生）、因果相关（A事件的处置动作触发B事件）。实现上，聚合器订阅全量事件流，按相关性键做流式分组：短窗口（如三十秒）内共享拓扑键的事件归并为一个根因候选组，组内选代表告警（通常选覆盖对象最多的层级），其余作为成员挂靠。代表告警的通知携带成员计数与清单指针，恢复时整组联动评估——代表恢复且成员全部恢复才关组，成员残留则根因判断修正为部分恢复。聚合与第14篇的拓扑归并判定相衔接：判定层归并产生根因事件，告警层聚合兜住漏网成员，两道防线互为备份。

## 四、第三道闸门：静默与第四道闸门：收敛

静默是主动的抑制指令：按对象、按标签、按时段、按维护单号声明静默窗口，窗口内匹配事件不通知只记录。静默的治理要点：每条静默必须有创建人、理由与到期时间，无期限静默一律禁止；最高级别事件的穿透条件内置（对象静默中但发生多数派失联类事件仍通知）；静默清单每日审计，过期未清理的自动回收并通报。收敛是最后总闸：当抵达通知层的告警速率超过阈值（如每分钟二十条）时进入风暴模式——新告警只保留当前最高级别的一条升级通知，其余全部进入队列；队列内事件按聚合键二次合并，风暴模式期间每五分钟播报一次增量摘要（新增事件数、涉及对象数、当前最高级别）。风暴模式退出条件：速率连续两个采样周期低于阈值的半数，退出时发送完整风暴报告（总事件数、根因组列表、静默统计）。风暴模式的启用与退出本身作为P2级元告警通知，值班者必须知道系统正在替他挡子弹。

```text
# 风暴模式状态机
NORMAL --速率>20/min--> STORM
STORM: 只升级最高级别新事件; 其余入队按聚合键合并
       每5min播报: "风暴中: 新增37事件, 涉及2聚合组, 最高P1: rack-07失联"
STORM --速率<10/min持续10min--> EXIT -> 播报风暴报告 -> NORMAL
进入/退出 STORM: 各发一条P2元告警
```

## 五、风暴后复盘清单

每次风暴模式触发都是一次体系考试，标准复盘清单：风暴诱因归类（扇出、抖动、级联、误报）；根因告警是否在风暴中保持置顶可见；聚合是否正确归并（人工抽查成员归属）；通知通道是否过载（通道自身的丢弃与延迟数据）；风暴模式期间是否有需要人工介入但被延迟的事件。复盘产出的行动项分三路：判定层改进（拓扑归并是否该更早介入）、告警层改进（指纹与聚合键修正）、体系层改进（误报风暴要回溯第16篇的二类错误治理）。不复盘的风暴必然重演，且通常以更大规模。

## 六、落地检查清单

- 事件指纹四要素版本化，活动期与重通知间隔可配置；
- 聚合支持拓扑键、时间窗、维护单号三种相关性来源；
- 静默必须有期限与理由，最高级别穿透条件内置，每日审计；
- 收敛总闸有明确的进入阈值、退出条件与播报节奏，进出均发元告警；
- 通知通道容量经过压测，过载时的丢弃策略是"丢通知不丢事件"；
- 风暴模式每季度演练一次（合成风暴注入），链路全验证；
- 每次风暴触发必复盘，行动项闭环跟踪。

## 七、小结

四道闸门各司其职：去重压同一事件的重复，聚合压相关事件的冗余，静默承接计划内的可预期噪声，收敛兜住不可预期的极端风暴。它们共同的底线是只抑制通知、永不丢弃事件数据——所有被抑制的告警都必须完整记录、可查可审计，抑制的是打扰，不是真相。
