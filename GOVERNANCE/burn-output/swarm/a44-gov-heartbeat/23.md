# 23. 指数退避与告警重试设计

> 摘要：本文讲解指数退避在心跳体系两处的应用——检测端对疑似异常对象的复核重试、通知端对告警送达的重试——的参数设计、退避上界与抖动、重试风暴的预防，并给出实现骨架与配置清单。

## 一、重试无处不在，但多数设计粗糙

心跳体系中有两处天然需要重试。第一处在检测端：发现疑似异常后需要复核确认，单次复核失败不能立刻定罪，需要按退避节奏继续复核直到证据充分或对象恢复。第二处在通知端：告警发出后渠道可能失败（电话未接、消息网关超时、值班系统不可用），必须重试或切换渠道，否则告警静默丢失。粗糙的重试设计有两个通病：固定间隔重试在对象或网关处于过载时等于持续加压，重试流量本身成为故障放大器；无上界的指数增长让重试周期很快超过故障持续时间，重试变成形式主义。本文的立场：重试策略与初始检测同等重要，必须显式设计、显式测试。

## 二、指数退避的数学与参数

指数退避指重试间隔按几何级数增长：第n次重试的间隔为基数乘以二的n次方，并附加上限。参数有四个。基数：第一次重试的等待时长，检测复核场景应小于判定窗口的十分之一（保证窗口内能完成多轮复核），通知场景取渠道典型延迟的两到三倍。倍率：通常为二，紧急场景可用一点五放缓增长。上界：间隔封顶值，检测复核的上界必须小于总判定时限的一半——若上界大于时限，最后一轮复核可能永远等不到；通知重试的上界取决于告警时效性，P1级别的上界不宜超过一分钟，超出后应换渠道而非继续等。抖动：每档间隔乘以百分之二十到五十的随机因子，防止多个观察者或多个告警的退避相位同步——同步的退避会形成周期性重试脉冲，恰好复现第19篇的共振问题。

```python
# 带抖动与上界的退避序列生成
import random
def backoff(n, base=0.5, factor=2.0, cap=30.0, jitter=0.3):
    d = min(base * (factor ** n), cap)
    return d * (1 + random.uniform(-jitter, jitter))
# 检测复核: base=0.5s cap=15s  => 前几档 0.5/1/2/4/8/15/15...
# 通知重试: base=2s  cap=60s  => 2/4/8/16/32/60, 60s后切换渠道
# 总时限预算: 检测复核Σ档位 ≤ 判定时限的60%, 留40%给处置
```

## 三、检测复核的重试设计

检测端复核的目标是"在判定时限内积累到足够证据"。设计要点：复核次数与判定阈值挂钩——k连丢判定对应至少k减一次复核机会，复核通过则计数清零，复核失败则计数累进；复核内容应加深——第一次复核用与初判相同的探针，后续复核逐级换更深的探针（第8篇的金字塔），让证据强度随重试递增；复核失败与复核超时区分计数，网关超时不算对象有罪，只算证据缺失。复核重试还有防饿死问题：复核请求占用检测器资源，大量对象同时进入复核会挤压资源，复核并发必须封顶并排队，排队延迟计入判定时限预算。曾出现的反面案例：某体系复核无并发限制，网络抖动一下让三千对象同时进入复核，复核流量打满检测器，结果三千对象全部因"复核超时"被判失联——复核风暴直接制造了史上最大误报。

## 四、通知重试与渠道切换

通知重试的目标是"告警必须送达或显式失败"。设计要点：渠道内重试与渠道间切换分离——每个渠道内部重试三到五次（带退避与抖动），渠道整体失败后按渠道优先级切换（电话失败转短信、短信失败转备用群、最终落死信端点）；送达语义区分"已发送""已送达""已确认"——电话接通是送达、按键确认是确认，P1要求至少达到已确认级别，未确认即升级（与第21篇的确认超时衔接）；死信兜底——所有渠道穷尽后，告警落入死信队列并触发体系级元告警（检测体系用自己的最后手段呼叫），死信队列每小时重放尝试并播报积压。通知重试的幂等性必须保证：同一条告警重复送达同一渠道不产生重复打扰，靠告警指纹实现（第22篇的事件指纹在此复用）。

## 五、重试风暴的预防

重试风暴的预防三板斧。其一，全局重试预算：体系层面统计每秒重试总量，超过预算时新重试请求降级（直接拉长间隔或推迟），宁可单对象判定变慢也不让重试总量压垮共享组件。其二，熔断联动：当被复核对象所在域的基础设施探测已确认故障（拓扑归并生效），个体复核暂停——对已知故障域内的对象逐个复核毫无信息增量，纯属流量浪费，归并事件统一给出结论。其三，退避状态持久化：检测器或通知器重启后，各对象的重试档位不归零——归零意味着每次重启都从最短间隔重新轰击一遍，重启风暴叠加重试风暴。持久化粒度可以粗化（按对象聚合组存档），但绝不能没有。

## 六、测试与验收清单

- 退避序列（含抖动边界）有单元测试锁定，参数变更走评审；
- 检测复核总时限预算经过验算：Σ档位小于判定时限的六成；
- 复核并发封顶，三千对象同时疑似时判定延迟仍可预测；
- 通知渠道链路逐级失效注入测试：单渠道失败、全渠道失败、死信触发，全部通过；
- 送达语义分级明确，P1的确认要求与升级计时联动；
- 重试档位持久化，检测器重启后不产生重置风暴；
- 全局重试预算与拓扑熔断联动有专门注入用例验证。

## 七、小结

指数退避的本质是用"随失败递增的耐心"换取系统的稳定：对象越不可达，打它的频率越低，但永不彻底放弃——直到上界与预算把控制权交还给人工或更高层机制。基数字、倍率、上界、抖动、预算五个参数齐备，加上持久化与熔断联动，重试才能从隐患变成心跳体系的可靠组件。
