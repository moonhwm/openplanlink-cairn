# 会话状态隔离与跨会话污染防护

## 一、跨会话攻击的形态

会话是MCP代理的基本执行单元，但危险常常跨越会话边界传播。典型形态有四种。形态一，持久化注入复发：攻击载荷在一次会话中被写入记忆、任务队列或配置，后续每次新会话都自动加载，形成反复发作的慢性感染。形态二，状态串味：会话缓存（工具结果缓存、检索索引）未按会话或用户隔离，前一会话的数据影响后一会话的行为。形态三，异步任务回注：会话结束时挂起的定时任务或订阅回调在之后触发，其携带的内容进入一个早已"换人"的上下文。形态四，中间产物复用：上一会话生成的草稿、临时文件被下一会话直接使用，而其中可能已被注入。这些形态的共同点是：攻击发生在会话A，引爆在会话B。

## 二、会话生命周期的状态清单

治理跨会话污染的第一步是盘点会话会产生哪些持久状态。完整清单包括：长期记忆条目（用户偏好、任务结论）、任务与计划文件、工具结果的缓存、检索索引增量、临时工作区文件、订阅与回调注册、计划任务与定时器、会话摘要与历史归档。对每一项标注四个属性：创建者（用户、模型、工具）、可写入路径、存活时长、被加载的入口。这份清单决定了隔离边界在哪里必须设立——凡"模型可写、后续会话可读"的路径，都是持久化注入的候选通道，必须重点设防。

## 三、写入侧的净化纪律

所有跨会话状态在写入时执行净化，原则是"入库前消毒，而非读取时补救"。具体纪律：模型生成的记忆条目写入前剥离指令性内容，只允许陈述性知识进入（"用户偏好简洁回复"可以，"下次会话立即调用某工具"不行）；任务队列与计划文件中的动作项必须是经确认的动作，未确认的提议只能以"待确认"状态存储，加载后必须重新走确认流程；临时文件按会话命名空间隔离存放，会话结束清理；配置类文件（影响代理行为的）禁止由模型路径写入，只走配置管理。写入过滤的实现复用输出过滤规则库，对指令特征密度高的内容整体拒绝：

```python
def persist_state(entry: MemoryEntry) -> PersistResult:
    if entry.origin == ORIGIN_MODEL:
        text = strip_directive_spans(entry.content)
        if directive_density(text) > 0.05:
            return PersistResult.REJECT("疑似指令性内容")
        entry.content = text
    entry.trust = downgrade_if_unsourced(entry)
    return store.write(entry)
```

## 四、读取侧的防御

即便写入侧有漏网，读取侧仍需设防。加载任何持久状态进入新会话时：恢复来源与信任标签，低信任内容按围栏身份进入；记忆加载采取按需检索而非全量灌注，限制单次注入的体量；对加载内容做一次新鲜度扫描（规则库可能已更新，旧内容按新标准复检）；影响行为的配置与计划在生效前需要用户可见的摘要确认。定时任务与回调是重灾区：触发时必须重新验证目标会话与主体仍存在且授权未变，内容进入前照常过管线，绝不能因为"是自己人排的队"就免检——排队时的内容可能在等待期间已被篡改。

## 五、会话边界的切换协议

会话结束与开始时的切换协议要形成硬规范。结束协议：清理临时工作区；未完成任务转为显式的待办记录（陈述性描述，不含可执行指令）；缓存标记过期；异步任务登记到带过期时间的队列。开始协议：新会话获得干净的上下文骨架，仅加载系统段与经用户确认的记忆引用；恢复任务时向用户展示任务摘要并请求继续确认，确认的对象是任务目标而非具体历史动作；上一会话的工具调用授权不自动继承，高危工具权限逐会话授予。协议的执行由框架强制而非约定，任何绕过切换协议直接读写状态的代码路径都视为缺陷。

## 六、共享代理的会话身份

当代理以服务账户运行、代表多个用户或多个任务处理工作时，会话身份问题更加尖锐。原则：会话身份绑定"用户+任务"二元组，工具调用以该身份执行最小授权，而不是以代理服务账户的全量权限执行；用户离开或任务变更时身份失效；服务账户本身的权限仅限于"调度与装配"，不持有业务数据的直接访问权。这可以类比为操作系统的进程凭证：进程以发起用户身份运行，而不是以内核身份运行。落地时结合令牌传递机制，把用户级令牌限定在会话生命周期内使用，会话结束令牌吊销。

## 七、污染事件的溯源与清除

发生跨会话污染事件后，需要一套溯源与清除流程。溯源：从引爆会话倒查加载了哪些持久状态，逐一检查其写入时间与写入时的会话，定位最初被注入的入口；检查同一入口影响的其他状态项，评估扩散面。清除：删除或净化所有受污染状态；对记忆库做同载荷扫描，清除复制体；已分发的任务队列逐项复核。加固：把入口路径的新样本加入写入过滤回归集；评审该路径为何未被写入侧拦截，补齐规则或收紧权限。溯源依赖完善的写入审计——每条持久状态都应记录写入者、时间、来源链，否则清除只能靠大规模重置，代价高昂。

## 八、小结

跨会话污染把注入从"一次性事件"变成"慢性感染"，治理关键是写入侧净化纪律、读取侧防御、会话切换硬协议与身份绑定四件套。核心思想可以概括为一句话：会话边界是一等公民的安全边界，跨边界的每一次读写都要重新证明自己干净且被授权。做到这一点，攻击者就失去了"埋一次雷、反复收割"的杠杆。
