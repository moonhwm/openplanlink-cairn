# 工具结果隔离：输出即不可信数据

## 一、原则的确立

在MCP数据流中，工具结果占据上下文的绝大部分体积，也是间接注入最主要的载体。工具结果隔离的原则只有一句话：任何工具返回的内容，在进入上下文之前都按不可信数据处理，无论该工具来自内部还是外部。这条原则必须无条件执行，原因在于信任判断极易出错——今天可信的内部服务，明天可能因其上游数据被污染而返回载荷；统一按不可信处理，才不会留下"例外路径"被攻击者利用。内部与外部的区别只体现在处置策略的宽严，而不是有无隔离。

## 二、隔离管线的五个阶段

工具结果从服务器返回到进入模型窗口，应经过一条固定管线，顺序不可颠倒：

```
原始结果 → ①规整化 → ②安全扫描 → ③净化处置 → ④标记包装 → ⑤限额装配
```

各阶段职责：规整化统一字符编码、剥离二进制与控制字符、解析并简化富文本（HTML转纯文本、去样式）；安全扫描运行注入特征检测、敏感数据识别、恶意链接与编码载荷识别；净化处置按扫描结论对内容做移除、转义或截断；标记包装附加来源标签与围栏（前章所述）；限额装配控制单条结果的长度与总条数，防止资源耗尽。管线用宿主侧中间件实现，所有服务器无差别经过：

```python
async def tool_result_pipeline(raw: ToolResult) -> FencedContent:
    text = normalize(raw)                      # ①
    report = security_scan(text)               # ②
    text = remediate(text, report)             # ③
    fenced = fence(text, source=raw.server, scan=report)  # ④
    return truncate_to_quota(fenced)           # ⑤
```

## 三、规整化中的攻击面

规整化阶段本身要防三类攻击。编码混淆：内容使用同形异码字符、零宽字符、双向文本控制符（RTL覆盖）隐藏指令，规整化必须做Unicode规范化（NFKC）、剥离零宽与控制字符、展开双向控制符，否则过滤器的关键词匹配会被绕过。结构走私：HTML注释、display:none元素、script/style块、图片alt与title、data属性都是常见藏匿点，解析时要按可见文本提取，默认丢弃不可见部分，需要保留时单独标记。分层载荷：内容把指令拆散在多个字段中，拼合后才成句，规整化阶段记录字段边界，扫描阶段做拼接视图的二次检测。

```python
def normalize(raw) -> str:
    s = unicodedata.normalize("NFKC", raw.text)
    s = strip_zero_width_and_bidi(s)
    if raw.mime == "text/html":
        s = extract_visible_text(raw.payload)   # 去注释/脚本/隐藏元素
    return s
```

## 四、扫描与处置的分级

扫描结论映射为四级处置。放行：无发现，正常围栏进入。降级：存在可疑特征但不确定，进入时附最高警示等级的围栏，且该内容不得作为任何自动放行调用的依据。净化：定位到明确载荷片段（如一段伪造系统消息），移除片段并以"[已移除可疑内容]"占位，事件记录。拒绝：载荷密集或来源高危（例如该服务器最近有异常行为），整条结果不入上下文，向模型返回"该工具返回内容不可用"，同时告警安全团队。处置等级的选择要考虑误伤代价：对纯只读的展示类内容可偏严，对关键业务数据偏中性并配合行为层约束。

## 五、结果驱动的调用约束

隔离不止于内容处理，还包括"基于结果的动作约束"。核心规则：当窗口中存在未被净化确认的不可信内容时，自动放行的白名单临时收缩。实现上，安全上下文维护一个"污染窗口"计数，工具结果以降级或净化身份进入时计数增加，随轮次衰减；模型发起调用时决策器检查计数，非零状态下仅允许只读工具自动执行，其余一律进入确认或暂缓：

```python
def decide(call: ToolCall, sec: SecurityContext) -> Verdict:
    if call.tool.read_only and sec.active_flags == 0:
        return AUTO_ALLOW
    if sec.active_flags > 0 and call.tool.risk >= MEDIUM:
        return CONFIRM(reason="上下文存在未净化外部内容")
    return default_policy(call)
```

该机制切断"注入立即转化为动作"的最短路径，迫使攻击载荷必须先在窗口中存活并等上下文清洁，显著提高攻击的时间成本与不确定性。

## 六、服务器侧的可信辅助信息

工具结果中除了"内容"还有"元信息"（如分页游标、总数、错误码），后者常被忽略却同样可被滥用——攻击者伪造错误码诱导重试风暴，伪造游标诱导遍历全库。元信息应与内容区别处理：宿主校验其格式合法性，限制重试次数与遍历深度，游标类参数纳入调用审计。同时警惕服务器主动标注的"安全提示"字段：服务器可以声称"本内容已消毒"，但如前章所述，信任标签只能由宿主颁发，服务器自证一律忽略。这条纪律在混合接入多个第三方服务器时尤为重要，是防止"最差服务器拉低整体安全水位"的关键。

## 七、管线的可观测与回归

管线作为所有工具结果的必经之路，自身的健康与准确性需要持续观测。每次扫描的判定（放行、降级、净化、拒绝）都应记录样本哈希与触发规则，形成处置分布看板：拒绝率长期为零未必是好事，可能意味着特征库失效；降级率骤增则往往对应新的攻击活动或上游数据异常。同时维护一个带标注的结果样本集，涵盖历史真实载荷、红队样本与正常边界样本（例如合法讨论注入防御的技术文档，不应被误杀），每次规则更新跑回归，量化漏检与误伤的此消彼长。管线上线只是开始，让它随威胁演进而保持锋利，才是工具结果隔离长期有效的前提。

## 八、小结

工具结果隔离把上下文中体量最大的输入源纳入统一管线：规整化消灭编码与结构走私，分级处置平衡安全与可用，结果驱动的调用约束切断即时转化，元信息校验堵住侧门。配合围栏标记与来源标签，工具输出从"默认可信的便利"变为"默认隔离的数据"，这是间接注入防御中最具性价比的一层。后续输出过滤各章将展开管线各阶段的细节实现。
