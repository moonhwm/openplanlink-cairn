# 上下文窗口隔离与污染清理

## 一、上下文作为共享资源的风险

上下文窗口是模型唯一的"工作内存"，所有消息、工具结果、记忆片段共享这一有限空间。这种共享带来两类安全问题。其一是污染累积：一段被注入的内容进入后，即使当时的调用被确认门拦下，载荷文本仍留在窗口内，可能在若干轮之后再次影响模型，形成"延时引爆"。其二是残留泄露：切换任务或切换用户时，若未正确重建上下文，前一个任务的数据会被后一个用户看到。上下文隔离要解决的，就是让窗口内的信息按任务与信任边界分治，并在边界切换时可靠清理。

## 二、分段命名空间设计

把上下文组织为逻辑分段，每段有独立的名字空间与生命周期：

```
+-- system segment（全程存活，只读）
+-- task segment（任务开始创建，任务结束销毁）
|   +-- user turns（用户消息）
|   +-- tool results（带来源标签，可淘汰）
|   +-- working notes（模型的中间结论）
+-- memory segment（跨会话记忆，只读挂载，按需引用）
```

工具结果段允许淘汰是关键设计：已被摘要吸收的原始长文本、与当前子任务无关的历史工具输出，应从窗口移除而只保留摘要与标签。这既缓解注意力稀释，又降低旧载荷反复触达模型的概率。淘汰策略结合显存标记：凡被注入检测标记过的内容，其摘要必须注明"含可疑载荷已中和"，防止摘要过程把载荷洗白后无痕存活。

## 三、污染的检测与定位

清理的前提是发现污染。三类信号用于判定窗口已被污染：行为信号（模型突然试图调用与任务无关的工具、语气突变、拒答中间过程）；内容信号（窗口中存在未带标签的外部文本、围栏标记被破坏、出现伪造角色声明）；一致性信号（模型输出与其声明的依据来源对不上，例如引用了已被淘汰的内容）。检测器可以周期性扫描窗口快照：

```python
def scan_context(ctx: Context) -> list[Finding]:
    issues = []
    for seg in ctx.segments:
        if seg.kind == TOOL_RESULT and not seg.has_tag():
            issues.append(Finding("untagged_external", seg.id))
        if seg.fence_broken():
            issues.append(Finding("fence_escape", seg.id))
        if seg.suspicion_score > THRESHOLD:
            issues.append(Finding("payload_residue", seg.id))
    return issues
```

## 四、清理与重置策略

发现污染后的处置分三档。局部清理：移除或中和特定分段，适用于污染范围明确且任务可续行的场景；将被污染分段替换为"该内容因安全原因被移除"的占位说明，保留任务连贯性。任务重置：保留系统段与用户意图摘要，丢弃全部工具结果段，重新执行受影响的步骤；适用于污染可能已影响多个分段。完全重置：清空除系统段外的一切，要求用户重新下达任务；适用于污染源头不明或已发生可疑调用的场景。选择原则是宁可重不可漏——重置的代价是重新执行的延迟，漏清的代价可能是数据外泄。

自动清理之外要留人工通道：清理事件本身应通知用户，说明哪些内容被移除、任务将如何重做，避免用户对"助手突然失忆"困惑不解。

## 五、任务与用户切换的隔离

多任务、多用户并存时，隔离规则必须显式化。任务切换时：新任务获得全新的task segment，旧任务分段除非被显式引用否则不进入新窗口；跨任务引用只允许通过记忆层且带原标签。用户切换时（共享服务形态）：严格禁止任何前用户内容残留在窗口，切换操作等价于完全重置，并更换会话密钥与缓存命名空间；"继续上一位的对话"这类便利功能默认关闭，需要时必须经过双方授权。会话并发时：同一用户并行多个会话各自独立窗口，共享的只有持久层，窗口级状态不落盘或落盘时加密与会话绑定。

## 六、记忆子系统的隔离

长期记忆是污染持久化的主通道，需要单独治理。写入侧：只有经过摘要与脱敏的内容才能入记忆，原文载荷不得写入；写入时强制附带来源与信任层字段。读取侧：记忆挂载按相关性检索，单次注入的记忆片段数量有限，避免全量灌注；低信任记忆以围栏身份进入。治理侧：定期扫描记忆库中的指令性文本密度，异常高的条目人工复核；提供记忆黑名单与一键失效机制。记忆更新权限也应收紧：模型不应能直接覆写安全策略相关的记忆条目，这类条目变更走配置管理流程。

## 七、实施节奏与度量

落地上下文隔离不必一步到位，可按四步推进：先统一内容装配器，让所有进入窗口的外部内容都带标签，这一步成本最低收益最大；再实现工具结果淘汰机制，控制窗口膨胀；然后部署周期性污染扫描与三档清理；最后接入记忆子系统治理。度量上跟踪三个数：窗口中未标记外部内容的检出数（应趋零）、清理事件按档次的分布（频繁的全量重置说明上游过滤有缺口）、单任务平均窗口占用（衡量淘汰机制效果）。这三个数字每周回顾，把上下文卫生变成例行运营指标，而不是等到事件发生才回头看窗口里堆了什么。

## 八、小结

上下文窗口隔离把"工作内存"当作需要访问控制的共享资源：分段命名空间界定存活范围，污染检测发现异常，三档清理机制处置事件，任务与用户切换规则杜绝串味，记忆子系统治理阻断持久化。这套机制与围栏标记配合，使注入载荷即使进入也难以存活到起效的那一刻。窗口干净与否，直接决定确认门要面对多大的压力，因此上下文管理是隔离体系中最日常也最容易被忽视的一环。
