# access_token生命周期管理与多实例缓存刷新策略

> 摘要：本文围绕access_token从签发、缓存、共享、刷新到失效的全生命周期，给出单机与多实例集群下的缓存设计、提前刷新算法、惊群防护与灰度轮换方案，并附参考实现代码。

## 一、生命周期模型与状态机

access_token是典型的小时级短命凭证，其生命周期可建模为五态：签发、缓存有效、临近过期、刷新中、失效。业务侧维护的不是令牌本体而是"过期时间戳"，每次取用前先判断剩余寿命。工程上不应当在令牌恰好过期时才刷新，因为那一刻恰好可能有大批消息待发，同步刷新会串行阻塞发送链路；标准做法是设置安全提前量，例如剩余寿命低于总时长的三分之一（或固定五到十分钟）即触发异步刷新，刷新期间旧令牌继续服务，新令牌到达后原子替换。这一"提前量+双令牌过渡"模型可以完全消除刷新抖动对消息时延的影响，是令牌管理器设计的核心。

## 二、刷新算法与单飞惊群防护

集群场景下最大的坑是惊群：缓存集中在Redis时，N个实例同时发现令牌过期，同时去授权端点刷新，既浪费请求又可能在并发窗口内出现"新令牌被更新令牌覆盖回旧令牌"的错乱。解法是分布式锁加单调校验：抢到锁者刷新，未抢到者短暂等待后重读缓存；写入缓存时校验新令牌的过期时间必须晚于当前缓存值，防止旧响应覆盖新值。参考实现：

```java
// TokenManager.java（节选）
public String getValidToken() {
    CachedToken c = redis.get(KEY);
    if (c != null && !c.nearExpiry()) return c.getToken();      // 快路径
    if (redis.tryLock(LOCK_KEY, 5, SECONDS)) {                  // 单飞
        try {
            CachedToken again = redis.get(KEY);                 // 双重检查
            if (again != null && !again.nearExpiry()) return again.getToken();
            CachedToken fresh = oauthClient.fetch();            // 调用授权端点
            redis.put(KEY, fresh, fresh.ttlMinusBuffer());      // 带缓冲的TTL
            return fresh.getToken();
        } finally { redis.unlock(LOCK_KEY); }
    }
    sleep(200);                                                 // 未获锁者让路
    return getValidToken();                                     // 重读
}
```

## 三、缓存层次与一致性设计

缓存选型上有两种主流形态。其一是集中式（Redis类），优点是全集群共享、刷新次数最少，缺点是引入网络往返与缓存服务自身可用性依赖，适合大规模实例；其二是进程内本地缓存，配合集中式版本号做轻量同步，读取零网络开销，适合发消息的网关进程。折中方案为两级缓存：本地缓存短TTL兜底、Redis长TTL为准，刷新永远先走分布式锁。一致性上要处理两个边界：消息端点返回鉴权失败错误码时，无论本地判断是否过期都应强制失效缓存并刷新一次重试，这是对时钟漂移与服务端提前吊销的兜底；令牌刷新成功后要广播本地缓存失效，避免个别实例继续用旧令牌发送。此外务必将"令牌剩余寿命""刷新成功率""刷新耗时"打点暴露，这三项是令牌模块仅有的但足够的核心指标。

## 四、轮换、演练与运维清单

令牌生命周期管理最终要落到运维动作上。上线前与日常运维清单：

- 密钥轮换预案：AGC侧更换App Secret后，KMS同步更新，部署双读宽限期，观察取令牌错误率归零后下线旧密钥；
- 时钟同步：所有实例开启NTP，避免本机时钟快慢导致提前量计算失真；
- 故障演练：定期注入"授权端点不可达"故障，验证刷新退避、熔断与消息降级队列是否符合预期；
- 容量评估：按消息峰值推算取令牌QPS（正常情况下仅与刷新频率相关，约每数十分钟一次），确认远低于授权端点限流阈值；
- 监控告警：令牌刷新连续失败、剩余寿命持续低于阈值、单飞锁持有超时三类事件设独立告警，分别对应授权服务故障、刷新逻辑缺陷与实例僵死三种病因。

综上，令牌生命周期管理的目标可以概括为一句话：让消息发送链路在任何时刻都"感觉不到令牌的存在"——取之即得、换之无感、坏之有备。达成这一目标依赖提前刷新、单飞防护、两级缓存与强制失效兜底的组合拳，它们共同构成推送网关的令牌基础设施。
