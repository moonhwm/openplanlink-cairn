# 裁判席的成本与延迟优化

## 一、裁判的双重账单

裁判席在质量体系中是重复调用最多的角色之一:每个争议件一次、合议乘以席数、抽检复核再乘一层。它的账单分两页:成本页(调用费随件数线性走)与延迟页(裁决处于关键路径上时,裁决耗时直接加到用户等待上)。优化必须两页分开记账,只压一页常把另一页推爆——缓存压成本可能引入陈旧裁决,并行压延迟可能抬高调用量。

## 二、成本侧的四板斧

1. **分级分流**:规则能判的不过裁判,轻量模型能判的不上重模型。分流漏斗的第一层永远是免费的规则层,实践证明五成以上的"争议"其实是阈值问题;
2. **裁决缓存**:争议件按(问题标准化哈希, 选项内容哈希, 标尺版本)缓存,同类争议零成本复用。标尺版本进键是纪律——标尺变了旧裁决必须失效;
3. **合议降档**:独任高置信即终局,合议只收低置信与高风险件;五席减三席的门槛按翻转风险动态调;
4. **批量合裁**:同类小争议合并成一次裁决调用,一次裁一列,边际成本远低于逐件调用。

## 三、延迟侧的三板斧

- **并行裁决**:合议各席并发亮票,墙钟等于最慢席;给每席设截止时间,慢席缺席按"缺席审判"规则处理(记录在案,不阻塞);
- **关键路径外移**:非阻塞裁决(如事后抽检、离线巡检)移出用户等待路径,只有放行判定留在关键路径;
- **预裁决**:可预期的争议点(如已知冲突类型)在产物生成阶段就并行预裁,争议正式提交时裁决已就绪。

```python
async def panel_with_deadline(dispute, judges, budget_s=8.0):
    tasks = [asyncio.wait_for(j.judge(dispute), budget_s)
             for j in judges]
    done, pending = await asyncio.wait(tasks)
    verdicts = [t.result() for t in done if not t.exception()]
    if len(verdicts) >= QUORUM:
        return tally(verdicts)          # 缺席审判:达法定人数即裁
    return escalate(dispute, reason="quorum_timeout")
```

## 四、缓存的三条纪律

裁决缓存省钱效果最好,也最容易出错。纪律:键覆盖全部影响裁决的输入(含选项排序的规范化);版本失效不只对标尺,对裁判模型版本同样生效;缓存命中产出时带"缓存裁决"标记,争议方有权要求现场重裁一次。最后一条是公平性要求——当事人对过期判例的复审权,不能用效率理由没收。

## 五、成本-延迟联合预算

给裁判环节设联合预算才能真正约束优化方向:单争议的期望成本上限与 P95 延迟上限同时写进配置,运行时二选一超限即触发降档(减席位、换轻量模型)而非报错。预算的分配参考价值密度:关键路径上的放行裁决给延迟预算多一点,离线巡检给成本预算紧一点。每类争议的预算档位连同实际消耗月度公示,预算的权威来自消耗可见。

## 六、优化不得伤害的两条底线

所有优化动作过两道底线检查:其一,校准一致性——优化前后对金标集的裁决一致率不得显著下降(降档换模型尤其要跑金标回归);其二,可审计性——缓存命中、缺席审判、批量合裁都必须留完整审计痕迹,优化省下的钱不能从审计成本里偷偷扣回来。守住这两条,成本与延迟的优化才是工程,否则只是把风险记账记到了别处。

## 七、成本优化的实施顺序

裁判席的成本优化按既定顺序推进,跳步是常见错误:第一步永远是分流治理——统计裁决原因分布,把规则可判的部分迁走,通常能消化三到四成量;第二步是缓存建设——键设计、版本失效、复审权保障三件套齐备后开启;第三步才是合议降档与批量合裁;模型降档放最后,且必须以金标回归通过为前提。

每步实施前估算、实施后核验:预期的节省额、对一致率的影响幅度,两周后用实测对账。核验不通过的优化回退——优化动作的可回退性与功能变更同等要求,防止"省了钱伤了校准"的优化以既成事实固化。

延迟优化的实施要点不同:先做关键路径盘点,明确哪些裁决真正在用户等待路径上(通常不足三成),只对这部分做并行化与预裁决;其余裁决全部移出关键路径改异步。盘点常带来意外收获——大量"看起来在路径上"的裁决,实际产出只进日志不进用户视野,它们本就不该同步。

成本与延迟的联合看板月度发布:各类争议的单位成本、P95 延迟、校准一致率三线并排。三线的联动关系是看板的灵魂——任何一线的改善以另一线的恶化为代价时,看板上会呈现剪刀差,提示权衡已到需要重新决策的时点。看不到剪刀差的优化决策,都是凭感觉的赌博。

## 八、裁判经济的年度决算

年末对裁判席做经济决算,回答"这一年争议处理花得值不值"。决算结构:支出侧——各档裁判的调用成本、合议增量成本、人工专家成本、校准与运维人力;产出侧——裁决拦截的质量事故估算(按历史事故成本折算)、规则沉淀带来的自动处理增量(本年新沉淀规则替代的裁决量)、纠纷解决的时效改善。

产出侧的估算是决算的难点,坚持保守原则:质量事故的拦截价值只按有据可查的案例折算,不脑补;规则沉淀的替代量按实际减少的裁决量计。保守估算下若收支仍然为正,裁判席的价值就是铁的;若为负,先看支出结构里的浪费(未分流的可规则化争议、过度合议的高风险件占比),砍浪费后再评估存废。

决算的另一个产出是来年的预算建议:按业务量增长与规则沉淀速率的剪刀差,预测裁决量的演化,给出各档裁判的容量与校准投入建议。预测附带置信区间,年底对照,持续修正预测模型——裁判经济也要有自己的复利。

最后,决算报告向全员公开关键数字:单争议的完全成本、拦截率、自动处理率。公开不是自证清白的姿态,是让"争议处理有价"成为共识——只有共识了价,才会认真对待每一条争议的产出,裁判席的每个环节才配得上它花的钱。
