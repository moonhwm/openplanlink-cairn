# MapReduce 式并行检索

## 一、把经典并行范式迁移到检索

MapReduce 的核心思想是"数据不动计算动、先局部后全局":把大任务切成片,每片独立映射出中间结果,再归约成最终答案。检索型多智能体任务天然契合这个骨架——查询分解是分片,多路检索与阅读是映射,证据汇总与答案合成是归约。迁移的关键不是术语替换,而是识别出哪些环节可以无状态并行,哪些必须集中收口。

## 二、检索场景的 Map 与 Reduce

- **Map 阶段**:每个执行者拿到一个子查询与独立的检索预算,产出结构化证据卡(来源、摘录、相关度、时效),执行者之间不通信;
- **Reduce 阶段**:聚合器对所有证据卡做去重、冲突标记、按论点聚类,形成统一的证据底座,再据此合成答案。

两阶段的职责边界必须锋利:Map 期禁止做全局判断(不知道也不利用其他路的存在),Reduce 期禁止再发起检索(收口后不开新口)。违反第一条会引入隐性依赖破坏并行,违反第二条会让归约退化为递归扇出、成本失控。

## 三、证据卡的参考结构

```python
@dataclass
class EvidenceCard:
    claim: str          # 该证据支持的具体命题
    quote: str          # 原文摘录,保留可核对性
    source: str         # 来源标识与定位符
    subquery: str       # 由哪个子查询产生,可回溯
    freshness: str      # 证据时效
    reliability: float  # 来源可靠性
    conflicts_with: list[str] = field(default_factory=list)
```

字段设计里两个容易省略但价值最高的:subquery 让每条证据可回溯到分解器的输出,聚合失败时能定位是哪个子查询跑偏;conflicts_with 在归约期由聚合器填充,把"证据矛盾"从隐式感觉变成显式图结构,后续裁判席可直接消费。

## 四、归约期的三步工序

归约不是一步合并,推荐固定三步:

1. **归一**:同义命题、异形表述归并到同一标准命题,消除表述噪声;
2. **聚类**:按论点把证据分组,每组形成"论点 + 支持证据 + 反对证据"的三元组;
3. **定级**:每组按证据数量、可靠性、时效给出结论强度,强度不足的论点标记为"存疑"进入答案的限定语。

三步工序的价值是可中断、可缓存:第一步产物可缓存复用,第三步的"存疑"输出是下游裁判席的天然输入。

## 五、并行度与分片策略

分片质量决定 Map 效率。检索场景的分片策略按优先级尝试:

- **按维度正交切**:时间维度、地域维度、语言维度各成一片,天然无重叠;
- **按数据源切**:不同检索库各派一片,互补而非互替;
- **按假设切**:同一问题按候选假设分片,各查各的证伪路径。

禁止按"均分关键词"切:关键词均分会产生大量交叉命中,Map 期浪费,Reduce 期去重负担重。分片后应跑一次快速重叠估计,预估重叠率超过三成的分片方案推倒重来。

## 六、失效与治理

- **空洞分片**:某子查询无结果,归约时表现为论点缺证据,正确动作是标记空洞而非让合成器自行脑补;
- **慢尾分片**:检索源响应慢,Map 期墙钟被拖长,用截止时间加部分结果回收,证据卡不足额也能进入归约;
- **归约溢出**:证据卡过多超出合成上下文,先按可靠性截断再按论点配额,保证每个论点至少留一条最优证据;
- **递归诱惑**:合成时发现新线索想再检索,统一收口到"补充检索队列"作为下一轮任务,本轮坚决不再开 Map。

## 七、小结

MapReduce 式并行检索的收益来自两点:并行缩短墙钟、证据结构化提升可核对性。它的纪律成本同样明确——Map 无状态、Reduce 不开口、矛盾显式化。守住这三条纪律,该模式可以稳定支撑大规模证据合成类任务。

## 八、检索分片的工程细节

分片质量决定 Map 阶段效率,落地时三个细节常被低估。其一,子查询的重写:用户原始查询直接切片往往粒度不均,先经一步查询重写(补全指代、拆分复合问句)再分片,子查询的独立性与均衡性都会显著改善。重写本身也要受控——只做结构化拆分,不改变语义,重写前后的一致性抽检纳入测试。

其二,证据卡的容量控制:单路检索可能返回大量卡片,Map 出口处按"每论点保留最优 K 张"预压缩,防证据洪峰冲垮 Reduce。预压缩的淘汰规则透明化(按可靠性、时效、相关度的加权分),被淘汰的卡片进冷档,Reduce 发现证据不足时可显式回捞。

其三,空结果的处理:子查询无命中时产出"空洞卡"而非静默消失,空洞卡声明查过哪里、用了什么关键词、为什么可能没结果。空洞卡是 Reduce 判断"再派一轮还是标记不可得"的依据,没有它,缺证据与没查过在黑板上是同一个样子。

Reduce 侧还要维护一个冲突图:证据间的矛盾关系显式建边,输出时把"多源一致"与"单源孤证"在结论中区分标注。这个区分是下游信任分级的基础——用户对两类结论的采信度理应不同,系统有义务把差异呈现出来,而不是合并成同一口径的自信。

## 八、检索质量的地基建设

MapReduce 式检索的上限不在编排而在检索质量本身,地基建设三件事:来源目录——所有可检索源的登记(覆盖主题、更新频率、可靠性评级、成本),分片决策与来源选择都基于目录;查询规范——子查询的构造规范(术语标准化、范围限定、排除词),规范让多路子查询的语言风格一致,归一成本下降;结果评级——每个来源的历史命中质量统计,定期复核评级,评级的衰减影响其在聚合中的权重。

来源多样性的度量要落到数字:按来源域名或索引维度计算子结果的多样性指数,指数持续走低说明检索路径收敛到了同质源,扇出的覆盖承诺名存实亡。多样性指数低于阈值的任务批次触发告警,处理动作是分片策略复查与来源目录扩充。

慢源的隔离带:统计各来源的延迟分布,长尾源单独设置更宽的超时与更低的并发配额,并考虑将其移出首轮流(降级为补流派)。慢源混在首轮流里,每批任务的墙钟都被它定义,而它的贡献往往不成比例。

最后,检索的地基要有专人责任制:来源目录与评级、查询规范、多样性监控各有明确责任人,按月出体检报告。检索质量的退化是渐进且无声的,没有责任人的地基会安静地沙化,直到某天所有模式的指标一起变差,才发现根子在最早的那一层。
