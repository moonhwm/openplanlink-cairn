# 扇出聚合的成本控制

## 一、成本结构:钱花在哪里

扇出聚合的成本由四块构成,治理必须分块进行,笼统说"降成本"无处下手:

- **调用成本**:模型与外部服务的调用费用,与执行次数和每次上下文长度成正比;
- **上下文成本**:每个执行者都要装载的任务背景,重复装载是最大的隐性浪费;
- **聚合成本**:合并 N 份结果的计算,常被忽略却随宽度超线性增长;
- **失败成本**:超时作废、验收不过返工、重试放大,失败率乘以单价即是纯损耗。

## 二、宽度的边际分析

扇出宽度是成本的第一杠杆。经济宽度满足"边际收益等于边际成本":第 K 路执行者带来的质量增量,若小于其调用成本,宽度就该停在 K-1。实操上用回放集测宽度-质量曲线:同一批任务分别在宽度 1/2/4/8 下跑,看质量指标何时走平。绝大多数互补型任务在宽度 3-4 后进入平缓区,盲目的宽度堆叠只是购买心理安慰。

## 三、分层的省钱手段清单

按侵入性从低到高排列:

1. **结果缓存**:子任务结果按(子查询,源,参数)哈希缓存,命中免调;
2. **上下文瘦身**:给执行者的背景按需裁剪,与子任务无关的背景一律不带;
3. **分级模型**:粗筛用轻量模型,仅晋级任务用重模型,级联即省钱;
4. **早停**:投票场景一旦多数已定,余路立即取消,不再等待;
5. **去重派发**:分解器输出的子任务先做相似度去重,高度雷同的合并成一路;
6. **预算熔断**:单请求、单用户、全局三级预算,超限即拒新任务排队。

```python
async def early_stop_vote(subtasks, workers, need=3):
    wins = collections.Counter()
    for batch in chunks(subtasks, size=4):        # 分批派发
        results = await parallel_run(batch, workers)
        for r in results:
            wins[normalize(r.answer)] += 1
        top, cnt = wins.most_common(1)[0]
        if cnt >= need:                            # 多数已定
            cancel_pending()                       # 取消在途
            return top
    return None
```

分批加早停的组合,把"最坏情况付全款"变成"多数情况付部分款",是投票类扇出最有效的单一优化。

## 四、缓存的三条纪律

缓存是扇出省钱第一手段,也是第一污染源。纪律:

- 键必须包含全部影响输出的输入,漏一项就是错缓存;
- 时效敏感源带 TTL,知识截止敏感的任务键里含知识版本;
- 缓存命中也走验收,验收不过的缓存条目主动失效。

## 五、聚合成本的抑制

聚合随宽度超线性是因为两两比较的比对次数按平方增长。抑制手段:归约前先按论点聚类,把两两比较限制在簇内;聚类用便宜的嵌入模型,精确比较留给簇内少量候选;聚合输入按可靠性预截断,宽度先减后合。

## 六、单位经济学监控

成本治理的最后一块是持续的单位经济学监控:每千次请求的各分项成本、宽度分布直方图、缓存命中率、失败损耗占比、聚合计算耗时占比。把"单请求期望成本"做成随时间演进的看板,任何新版本上线前后对比这一条曲线,成本回归无处遁形。没有这条曲线的团队,成本问题永远靠事后账单震惊来发现。

## 七、成本账单的组织化展示

成本控制的终点是账单,账单要设计成组织各角色都能读懂的形态。三层账单结构:请求层——单次请求的分项消耗(哪路执行者、哪个环、哪次裁决各花多少),用于排障与个例归因;任务层——按任务类型的单位经济学(每千次成本、宽度分布、缓存命中率),用于选型与参数决策;系统层——月度总账与环比,用于容量规划与预算申请。

账单上的数字要有"单位感":把 token 换算成货币,把调用次数换算成配额占用百分比。原始 token 数对非工程角色没有直觉,"单请求平均三角钱、占月度预算千分之一"才能引发正确讨论。换算系数(模型单价)单独配置并注明更新日期,防止单价变动后账单整体失真。

异常成本要能在账单上直接定位:单请求成本超过该任务类型 P99 的,自动标记并关联其追踪编号;月度环比涨幅超过阈值的分项,账单附上涨幅归因(是流量、宽度、失败率还是单价)。让"钱变多了"永远伴随着"为什么变多了",成本治理就从月度惊讶变成日常监控。

一个反直觉的提醒:账单不要太精确。分摊算法追求小数点后两位的精确,会消耗团队大量对账精力且引发无谓争议。粗粒度但稳定一致的账单,优于精细但口径常变的账单——成本治理需要的是趋势可信,不是审计级精确。

## 八、成本治理的组织机制

成本治理要有组织机制承载,否则沦为工程界的自觉运动。三层机制:月度成本会(账单回顾、异常归因、下月关注点,运维与各模式负责人参加)、季度成本规划(结合业务量预测做容量与预算规划,立项优化专项)、年度架构决算(复杂度与成本的匹配度总评,识别结构性浪费)。

成本会的一项固定议程是"浪费猎手":每期由一位成员认领一个浪费嫌疑点(缓存未命中的原因、宽度冗余的维度、失败损耗的重灾区),下期汇报猎杀结果。轮值制让每个工程师都定期用成本视角看一遍系统,成本意识从口号变成肌肉记忆。

优化专项的立项标准:预期节省超过实施成本三倍,且不触碰质量底线(金标回归通过)。两项标准卡掉两类坏项目——得不偿失的折腾与省钱伤质的自杀。立项后的验收同样严格,预期与实际的偏差超三成的项目要复盘估算方法,防止规划能力原地踏步。

最后是预算的弹性机制:业务高峰期的临时预算申请走快速通道(一小时审批),配套事后强制复盘。刚性预算在流量洪峰前要么误事要么被绕过,弹性加复盘才是既保业务又保纪律的设计。成本治理的终极目标不是省钱,是让每一分钱都花在明处。
