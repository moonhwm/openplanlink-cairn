# 确定性与非确定性编排的对比

## 一、两类编排的本质差异

确定性编排指相同输入必然产生相同控制流:走哪些节点、按什么顺序、在哪里合并,全部可预先断言。传统工作流引擎执行的 DAG 是典型代表。非确定性编排指控制流由模型在运行时决定:下一步路由给谁、要不要再循环一轮,取决于模型对当前状态的判断。

差异的工程后果集中在三处:可测试性(确定流可做断言测试,非确定流只能做统计测试)、可审计性(确定流的决策路径是静态的,非确定流必须记录每次决策依据)、故障复现(确定流可重放,非确定流重放也不保证同路径)。

## 二、确定性编排的适用面

以下特征指向确定性编排:

- 流程已被领域知识固化,变化频率低;
- 合规要求全链路可复现,审计员要能从结果反推路径;
- 失败重试要求幂等重放,路径漂移会导致副作用重复;
- 团队需要用常规 CI 手段保障流程质量。

确定性编排的设计要点是把"变化"限制在节点内部:节点内的提示词、工具可以随时换,节点间的连线保持稳定。这样既保留可断言的骨架,又容纳局部的模型不确定性。

## 三、非确定性编排的适用面

以下特征允许甚至要求非确定性:

- 任务结构因输入而异,预定义流程无法覆盖长尾;
- 需要模型根据中间结果决定"继续深挖还是收束";
- 探索类任务,路径本身就是信息。

非确定性编排的安全护栏必须是硬的,软提示不起作用:

```text
动作白名单:   模型只能从预注册的动作集中选择
预算熔断:     总步数、总调用次数、总 token 三项任一超限即停
状态不变量:   每步后校验关键不变量,破坏即回滚
路径记录:     每次决策连带输入快照落盘,事后可归因
退出兜底:     连续 N 步无进展则强制走确定性降级路径
```

## 四、分层混合:主流实践

真实系统极少纯用一类,主流做法是三层嵌套:

1. 外层确定性骨架:阶段划分、审批点、超时用 DAG 固定;
2. 中层受限路由:阶段内部由模型在白名单动作间选择;
3. 内层纯模型推理:单个节点内的生成与理解。

这个分层的判据是"不确定性的影响半径":影响控制流的放在中层并加护栏,不影响控制流的放进内层自由发挥。把高影响半径的不确定性放进内层,是把系统命运交给运气;把零影响半径的确定性抬到外层,是无谓地牺牲灵活性。

## 五、测试策略对比

两类编排的测试手段完全不同,用错手段会得到虚假的安全感:

- 确定性编排用快照测试:给定输入,断言执行路径与输出完全一致;重构时快照差异即回归信号。
- 非确定性编排用性质测试:不断言具体路径,断言不变性质——所有路径都满足预算上限、终态总是合法状态、白名单从未被突破。再辅以蒙特卡洛式批量运行统计失败率。

混用的常见错误是给非确定流写精确断言,结果测试随机飘红,团队随即删掉断言,护栏形同虚设。

## 六、迁移路线

从确定走向非确定应渐进:先在某个低风险阶段引入模型路由,运行一段时间统计其决策分布与失误率,再决定是否扩大权限。反向迁移同样常见——非确定路径中频繁被固定选择的分支,沉淀为确定性连线,这是系统随使用数据自我硬化 的自然过程。两个方向的迁移都以"决策日志"为依据,没有日志就没有迁移资格。

## 七、决策日志:混合系统的记忆

分层混合系统中,每一次"这条边为什么是确定的/这条路由为什么交给模型"的决策,都应记入决策日志。日志字段:决策对象(某条边/某个节点)、决策时的数据依据、被否决的替代方案、复审触发条件。决策日志的价值在半年后显现——当某人提议把某条确定性边改成模型路由时,能先查日志:当初为什么定死,条件变了吗。

不确定性的影响半径要定期复算。业务演化会让原本低影响的判断变得关键(某个曾经无害的模型选择,在新增敏感功能后突然影响合规)。每季度把中层白名单动作按"出错后果"重排一次,后果升级的动作下移到确定性层或加硬护栏。

决策日志还有跨团队对齐价值。平台团队提供的路由能力,业务团队在各自节点里如何用,通过日志汇总成使用画像。画像显示某些动作被高频选择,是沉淀为确定连线的信号;某些动作从未被选,是白名单冗余的信号。用进废退,让混合结构随使用数据自然优化。

最后,把决策日志的覆盖率当架构健康指标:系统中每个"分叉点"都应有对应日志条目,覆盖率低于八成说明相当一部分结构是无人认领的即兴之作。即兴结构不是不能存在,但不能无人知晓——知晓即风险,未知才是风险。
