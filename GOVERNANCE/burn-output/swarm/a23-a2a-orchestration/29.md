# 裁判可解释性输出

## 一、裁决必须自带理由

一份只有结论的裁决,下游只能选择盲信或盲疑:盲信则裁判的错误被放大传播,盲疑则裁决失去终局效力。可解释的裁决书把裁判的推理路径外化,使结论可以被检查、被质疑、被推翻、被沉淀为判例。对自动裁判而言,可解释性不是加分项,是裁决具备法律意义上"效力"的最低配置。

## 二、裁决书的最小结构

```text
裁决书 v1
争议编号:  D-2026-00117
争议问题:  <一句话的待决问题>
裁决结论:  <选定项/判定,精确引用候选项标识>
推理过程:  1. 逐维度评分与依据(引用证据编号与标准条款)
          2. 关键取舍点:为何采纳 A 证据而非 B(可质证性说明)
          3. 排除项理由:每个未选项的一句话否决依据
置信度:    high/medium/low + 一句话依据
边界说明:  本裁决适用的前提条件,超出即失效
升级建议:  low 置信或标准边界情形时附注
```

其中"排除项理由"最常被省略也最有价值——它暴露裁判真正的取舍逻辑,是翻案与校准分析的主要素材。

## 三、依据的可回溯性

推理过程中的每个论断都必须挂到可回溯的锚点:证据编号指向共同认可证据集,条款编号指向评分标尺版本,判例编号指向既往同类裁决。无锚点的自由推理段落(哪怕写得再流畅)在审计中按无效论据处理。这条纪律的工程形态是裁决书的结构化输出:

```python
@dataclass
class ReasoningStep:
    claim: str            # 本步论断
    evidence_refs: list[str]  # 引用的证据编号,可为空
    rule_refs: list[str]      # 引用的条款/判例编号
    step_type: str        # scoring | tradeoff | exclusion | boundary

def audit(verdict) -> list[Finding]:
    issues = []
    for step in verdict.reasoning:
        if not step.evidence_refs and not step.rule_refs:
            issues.append(Finding(step, "无锚点论断"))
    return issues
```

审计函数应挂在裁决流水线上,自动拦截锚点缺失的裁决书。

## 四、解释的忠实性问题

要区分"忠实解释"与"合理化叙事":前者是裁判真实计算路径的外化,后者是结论确定后补写的漂亮理由。两者在文本上难以分辨,检验靠干预实验:对同一争议件做受控扰动(替换某条证据、调换选项顺序),观察推理过程是否随之合理变化。扰动不敏感的解释大概率是叙事模板。运营上把"解释-扰动敏感度"纳入裁判校准指标,防止可解释性沦为格式表演。

## 五、面向不同读者的分层解释

裁决书的读者不止一类,解释应分层产出:

- **机器层**:完整结构化推理,供审计、归因、判例匹配;
- **请求方层**:三句话版——结论、最关键依据、下一步怎么办,重在可执行;
- **治理层**:聚合视图——本裁决触及的条款、与既往判例的一致性,供标准演进分析。

三层从同一结构化数据渲染,而非让裁判分别生成三份(分别生成必然出现层间不一致)。

## 六、判例沉淀

可解释裁决的长期红利是判例库:边界情形的裁决连同推理归档,新争议先做判例匹配,命中则直接引用既判,不再重复裁决。判例库要维护一致性:新裁决与既有判例冲突时,必须显式区分"推翻"(附推翻理由,旧判例标记失效)与"规避"(说明本案与判例的情境差异)。无管理的判例引用会让体系积累自相矛盾的先例,比没有判例更糟。

## 七、裁决书的文档工程

裁决书是长期资产,文档工程要配套:统一模板(结构化字段加自由推理区)、编号体系(按争议类别编年)、全文检索(裁决理由可被后续争议引用检索)、判例链接(引用既往裁决时自动建链)。工程到位后,裁决书的积累会形成组织独有的"判例法体系"——比任何通用标准都更贴合本系统的真实边界。

推理区的写作规范要专门培训:论断与锚点交替出现,每个论断后紧跟依据引用;避免无锚点的过渡性修辞("显然""不难看出"这类词触发审计告警);取舍点必须显式写出比较过程,不允许只给结论。规范执行初期裁决书会变长,坚持一段时间后长度回落而信息密度上升——啰嗦被结构取代。

裁决书的消费场景要预先设计:请求方看到的三句话版从结构化字段渲染;审计方展开完整版本与证据链;治理方的聚合视图按条款维度统计引用频次。三视图同源渲染,任何手工改写都计为违规——同源保证三视图永不错位,错位的解释会让信任体系从裂缝开始崩塌。

判例库的检索匹配是隐形基础设施:新争议提交时自动检索相似判例附在争议件后,供裁判参考。匹配质量按"裁判实际引用率"评估,引用率低的匹配算法迭代优化。判例只有被方便地找到才会被引用,检索能力决定了判例体系是活的还是陈列品。

## 八、裁决书的可计算化

裁决书的结构化字段(结论、依据引用、置信度)天然适合可计算处理,进阶用法三则:一致性检查自动化——新裁决的条款引用与既往判例的引用做图比对,同条款下的矛盾结论自动标红送人工复核;判例推荐——争议件提交时,按条款与事实特征的相似度检索最相关的既往裁决书,附给裁判参考;趋势统计——按条款维度聚合裁决结果分布,分布突变提示标准或环境的变化。

可计算化的前提是字段纪律:条款编号引用必须真实存在(引用失效编号的裁决书被审计拦截)、置信度的取值语义统一(高中低的判定标准写进裁判提示,禁止各自想象)、推理步骤的锚点引用完整。字段纪律靠审计脚本日常守护,违规裁决书的比例是裁判质量的先导指标。

裁决书的版本化与引用稳定:裁决书的修订(如置信度笔误更正)出新版本,旧版保留;后续产物引用裁决时锁定版本号。引用漂移(产物指向的裁决被悄然改写)会摧毁整个证据链的可信度,版本锁定是最廉价的保险。

最后,裁决书的可计算化要服务于"体系学习":按季度把全部裁决书喂给治理分析(哪些条款被高频引用、哪些条款从未被引用、哪类争议的置信度持续偏低),分析结论直接驱动标尺修订与规则补全。裁决书不只是个案的终点,更应是体系认知的累积起点。
