# 黑板版本与快照

## 一、给黑板装上时间轴

黑板是持续变化的共享状态,没有版本机制时,一切跨时间的问答都无法进行:"这个结论是基于哪一刻的黑板得出的?"、"回滚到冲突发生前重跑一遍会怎样?"、"这周黑板的行为与上周相比退化了吗?"版本与快照机制给黑板装上时间轴,使它从一个"当前值"变成一部"可翻阅的历史"。

## 二、代与版本的两级时间

推荐两级时间结构:

- **条目版本(entry version)**:条目每次被取代或修订,版本号递增。并发写入的前提校验依赖它(见冲突消解一章);
- **黑板代(generation)**:调度器每完成一轮选择与执行,黑板进入新一代。代是黑板状态的逻辑时钟,所有快照、重放、统计都以代为单位。

代的划分让"稳定读取"有了明确语义:某代内不再有新写入时,该代即为一致快照点。知识源的触发判定、持久化、对外导出,都应绑定完整代,避免读到半更新状态。

## 三、快照的实现

```python
class GenerationStore:
    def snapshot(self, gen: int) -> BoardState:
        # 方案A: 每代全量冻结(简单,存储换速度)
        # 方案B: 条目级增量 + 代指针(省空间,重建需计算)
        return self._replay_until(gen)

    def diff(self, g1: int, g2: int) -> BoardDelta:
        added, superseded, conflicts = [], [], []
        for e in self._entries_between(g1, g2):
            (added if e.ts_gen <= g2 and e.ts_gen > g1
             else superseded).append(e)
        return BoardDelta(added, superseded, conflicts)
```

代间 diff 是快照机制的高频消费者:知识源想"看看我上次执行后发生了什么",拿 diff 比拿两个全量快照对比便宜得多。

## 四、快照的四个用途

1. **触发一致性**:触发谓词绑定代快照,保证判定可复现——同一代同一知识源,判定结果恒定;
2. **崩溃恢复**:持久化按代落盘,恢复时回到最后完整代,未完成代的知识源执行作废重放;
3. **分支实验**:从第 K 代复制出分支黑板,尝试不同的调度策略或知识源组合,主线不受影响,分支结果可对比;
4. **行为审计与回归**:历史任务的黑板快照存档,知识源或调度策略升级后重放对比,是蜂群模式最重要的回归测试资产。

## 五、重放的语义边界

必须诚实面对:重放可以复现控制流,不能复现模型输出的随机性。重放的价值在结构性验证——重放后黑板的层次依赖是否仍合法、关键结论的证据链是否仍闭合、调度序列是否落预期区间;不要追求字节级复现,那是做不到也不必要的执念。重放工具要显式标注"结构性重放"语义,防止使用者误读。

## 六、存储治理

按代全量冻结的成本随代数线性增长,治理三招:热区只保留最近 N 代全量,更早的转增量;归档代压缩冷存,证据链引用按需解压;分支黑板用写时复制共享主干,只存分叉后的增量。存储预算应进黑板的整体预算表,快照粒度(每代 vs 每 K 代)作为可调参数,按审计需求与存储成本动态平衡。

## 七、验收

版本机制的验收用例:并发写入时被拒方拿到的是清晰的前提失效信息(含失效条目的版本与取代链);任意历史代的快照可重建且证据链完整;分支实验的主线零污染;重放的结构性断言全部通过。四项达标,黑板才具备被严肃运维的资格——可以回看、可以对比、可以道歉(回滚)的系统,才配得上承载重要任务。

## 七、快照的存储实践

快照存储的实践要点:热区保留最近 N 代(按任务时长定,通常覆盖单任务全程)的完整快照,读取零重建;温区存增量加代指针,重建走增量回放;冷区压缩归档,只保留证据链可展开的最小集。三区的容量配比按访问分布调,常态下热区命中应覆盖九成以上读取。

快照的一致性标记:持久化落盘时附带校验和与代编号,恢复时校验不通过的代自动回退到上一个完整代,并告警要求人工检查存储层。静默使用损坏快照是灾难的起点——恢复路径的健壮性要与写入路径同等投入。

分支实验的写时复制要控制分叉深度:分支再分支的嵌套超过两层后,指针链的维护成本超过直接复制,此时物化(把分支状态实体化存储)更划算。物化时机由存储层自动判断,对使用者透明。

备份策略与普通数据库不同:黑板的价值在过程而非终态,备份必须覆盖中间代——只备份最终结论的黑板,丢失的是全部调试与回放能力。备份保留周期与任务的生命周期对齐:活跃任务的快照全保留,完结任务的快照按"证据链完整"标准裁剪后归档,归档件的可展开性每季度抽检。快照体系是黑板的记忆,记忆的完整性决定这个系统是否可被信赖地复盘。

## 八、快照体系的成本核算

快照体系的存储成本要常态核算:按任务类型统计快照的存储占比、访问频率、保留周期,产出"快照账本"。账本暴露的典型失衡:某些历史任务的快照从未被访问却全量保留(归档策略缺失)、某些高频访问的快照被错误归档(冷热分级失准)、分支实验的残留快照遗忘清理(实验纪律缺失)。

存储优化按账本对症:访问频率趋零的快照按"证据链可展开"标准裁剪后转冷;冷热分级的阈值按访问分布季节性调整;分支快照绑定实验任务的生命周期,任务关闭时快照进入待清理队列,清理前确认无引用。

快照压缩的投入产出:压缩节省存储但增加重建耗时,按访问频率决定压缩档位(高频访问的代不压缩或轻压缩,冷档用重压缩)。压缩率的调整也要看账本,不看不调的压缩参数,要么浪费算力要么浪费存储,总有一头在漏。

快照体系的年度健康检查:随机抽取十个历史任务的快照做完整回放(重建黑板、展开证据链、执行结构断言),全部通过说明快照资产仍然鲜活;任一失败即定位存储层的静默损坏,全量校验随之启动。快照的价值在"需要时可用",年度检查是对这个承诺的兑现验证。
