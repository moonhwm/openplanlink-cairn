# 四种模式的组合参考实现

## 一、组合才有生产力

四大原语单独存在多是教学形态,生产系统总是组合体。本章给出一个"检索综合任务"的参考组合:黑板承载证据与中间结论,扇出聚合执行多路检索与初稿生成,评审环打磨草稿,裁判席裁决争议与放行。组合的关键不是把四个骨架拼起来,而是定义好接口处的数据契约。

## 二、总体结构

```text
阶段一(黑板冷启动): 输入解析KS写入 L0/L1
阶段二(证据扇出):   检索KS多路触发, 事实层汇聚
                     —— 本质是黑板承载的扇出聚合
阶段三(草稿环):     起草KS写假设层 -> 校验KS挑矛盾 ->
                     修订KS差量改写 —— 评审环跑在黑板层上
阶段四(裁决收口):   不可消解矛盾打包成争议件 ->
                     裁判裁决写入结论层 -> 停机判定
```

## 三、关键接口契约

组合的胶水是三份数据结构,在系统内全局唯一:

```python
# 1. 证据卡: 扇出产物进黑板的桥
@dataclass
class EvidenceCard:
    claim: str; quote: str; source: str
    subquery: str; reliability: float

# 2. 缺陷单: 评审环在黑板上的流转单位
@dataclass
class Defect:
    target_entry: str      # 指向黑板条目
    rule_ref: str          # 违反的标尺条款
    severity: str          # blocking|major|minor
    suggested_fix: str

# 3. 争议件: 黑板冲突升级到裁判席的桥
@dataclass
class Dispute:
    conflict_entry: str    # 指向黑板 conflict 条目
    sides: list[str]       # 两侧条目链
    criteria: list[str]
```

三份契约的稳定性高于任何角色实现——角色可以换模型、换提示,契约不动,系统就还是那个系统。

## 四、控制权的接力

组合系统最微妙的是控制权接力:阶段二是黑板调度器主导(自发触发),阶段三切到环控制器(固定轮次推进),阶段四裁判主导(事件驱动裁决)。接力的实现:每个阶段是一个"模式驱动器",向前声明完成条件,完成条件满足时把主导权连同黑板快照交给下一驱动器。全局上保留一个薄薄的阶段机,只管接力不管内容——这符合编排器"只操作任务与状态"的纪律。

## 五、预算的贯通

预算必须在组合层统一,不能各模式自管:总预算在任务入口分配到四阶段(例:检索 40%、环 40%、裁决 10%、预留 10%);阶段内再按各模式规则细分;任一阶段透支,先尝试阶段间调剂,调剂失败触发整体降级。预算的事件流统一发射,单请求的成本账单可以完整还原。

## 六、失效的定位

组合系统的排障靠"分层定位":输出异常先看停机原因与保留意见(黑板收口层);质量不佳看环的缺陷存活分布(评审层);证据薄弱看扇出的覆盖与冲突统计(检索层);争议频发看裁判的翻转与升级记录(裁决层)。四层观测点已在可观测性一章定义,组合系统只是把它们串成一条因果链:检索质量决定证据,证据决定环的效率,环的残余矛盾决定裁判负载,裁判结论决定最终交付。

## 七、演化路线

组合系统从最小形态生长:先跑通"扇出 + 简单聚合"(无环无裁判),验证检索面;加环,验证迭代收益;最后加裁判,处理环消化不了的残余。逆向建设(先上裁判再补环)常见于组织压力,结果是为大量本可自动消解的争议支付人工级成本。顺序本身是经济学:越靠前的模式越便宜,先用便宜的消化问题,贵的只收尾。

## 七、组合系统的联调方法

组合系统的联调分层推进:先单模式自测(四个模式各自的测试套件独立通过),再接口联测(三份契约的数据在模式间往返,断言无损),最后场景联调(典型任务全链路跑通,断言各模式的观测点数据合理)。跳层联调是事故温床——接口没验证就跑全链路,出问题时四个模式都是嫌疑人,排查成本翻四倍。

联调环境的桩策略:不可控依赖(外部检索源、模型服务)用录制回放桩,请求响应对录制固化,联调可重复;可控部分用真实实现。录制库随版本更新,录制时的环境标注(模型版本、数据快照日期)随桩走,保证回放结果的语境可解释。

全链路的黄金路径集:十个左右的典型任务(覆盖各正常与降级路径)作为联调的固定集,任何变更跑全集,产物与观测点入库存档。黄金路径的存档产物构成"系统行为快照相册",新成员通过翻相册理解系统,事故时通过对比相册定位变化。

联调的最后一步永远是混沌注入:预算压缩、依赖劣化、节点故障各来一轮,断言降级阶梯按设计跌落。组合系统的优雅不只体现在全绿时刻,更体现在故障时刻的层次感——每个模式按自己的规则让位,组合起来仍是可用的系统。

## 八、组合系统的版本协同

组合系统的多个模式组件各自演化,版本协同是稳定性关键:兼容性矩阵——四大模式的接口版本两两之间的兼容关系,维护成矩阵,任一组件升级先查矩阵确认上下游;同发布窗口——强耦合的组件(如评审环与裁判席的裁决接口)同步发布,弱耦合的错峰;回滚半径——每个组件的回滚是否牵连他人,牵连的写成回滚组,组内同进退。

兼容性验证的自动化:接口契约的消费者驱动测试(上游变更前先跑全部下游的契约测试),矩阵中标注"需验证"的关系在 CI 强制覆盖。人工记忆的兼容关系在第十个组件加入时必然崩溃,矩阵加自动化是唯一的可扩展路径。

模式间接口的防腐层:每个模式对外暴露的接口单独定义,内部实现的重构不外溢;防腐层的测试独立于两侧组件,只测接口语义。防腐层的存在让"换掉环的实现"不影响"板与席"——组合系统的可维护性,就藏在这些看似多余的薄层里。

版本协同的日常仪式:每周组件负责人的十五分钟同步(本周谁要发版、矩阵影响),月度接口健康回顾(契约测试的覆盖率、防腐层的穿透事故)。仪式虽短,它们维持着组合系统的共同情境——没有共同情境的多团队,各自正确的决策合起来就是事故。
