# 35 提示参数补全的引用解析：prompt与resource template双目标

> 摘要：本文深入completion/complete的ref机制：提示引用与资源模板引用的解析差异、上下文参数的传递与利用、双目标补全的路由实现与一致性要求。

## 一、ref双目标的语义差异

补全请求的ref字段决定"补的是什么东西的参数"。指向提示时（ref/prompt形态，携带提示name），补全的对象是prompts/get的表单参数：服务器按提示名查到参数定义，针对指定argument返回候选值。指向资源模板时（ref/resource形态，携带uriTemplate），补全的对象是模板展开的URI变量：服务器按模板串定位家族，为指定变量返回候选实例。两者的差异体现在三处。定位键不同：提示以name定位，模板以uriTemplate字符串精确匹配，服务器必须对模板串做规范化比对，防止同义模板逃逸。候选性质不同：提示参数候选偏向"配置语义"（风格、语言、深度），模板变量候选偏向"存在性语义"（哪些城市、哪些表、哪些日期有数据可用）。生命周期不同：提示改参数名后补全引用随之失效，模板改结构后同理，两者的变更通知（list_changed）都应触发客户端清理缓存的补全配置。

## 二、上下文参数的传递与利用

补全请求可以携带arguments对象——除正在输入的参数外已填的其它参数值。这个上下文让补全从"静态字典"升级为"依赖感知建议"。典型利用场景：会议摘要提示中，用户已选定transcript_uri（某产品的会议记录），补全style参数时服务器可依据材料特征建议detailed（转写很长且多主题）；资源模板`db://{table}/{id}`中，用户已选table=orders，补全id时只返回订单表的ID前缀。实现纪律：arguments只作建议参考不作硬约束（用户改了已填参数后补全可能短暂失配，属正常）；上下文缺失（客户端未传或用户全未填）时补全必须退化为无依赖模式正常工作；上下文中的值同样不可信，参与查询前过与正式请求相同的校验。

## 三、双目标补全的路由实现

服务器侧的补全路由实现推荐"统一入口、双分支"结构。入口统一做三件事：解析ref类型、定位目标对象（提示注册表或模板注册表）、执行通用校验（目标存在、参数已声明、输入值合法类型）。之后进入双分支：提示分支把请求转译为对参数候选源（枚举配置、历史存储、依赖推导器）的查询；模板分支把请求转译为对变量域的查询（枚举器查询实际存在的实例前缀）。两分支的公共出口做排序、截断、权限过滤与超时控制，保证双目标的补全质量一致。路由层的测试要专门覆盖"ref错配"用例：用提示名去匹配模板、用模板串去匹配提示名，都必须返回明确错误而非空候选——空候选会让客户端误以为"没有可选项"，错配错误则能暴露集成配置问题。

```text
complete(ref, argument, arguments):
    target = ref.type == prompt ? prompts.lookup(ref.name)
                                : templates.lookup_canonical(ref.uriTemplate)
    if not target: error UNKNOWN_REF
    if argument.name not declared in target: error UNDECLARED
    cands = target.collect(argument, arguments)   # 分支实现
    cands = authorize(cands)                       # 权限过滤
    return top_n(cands, 10)
```

## 四、一致性与缓存要求

补全候选与最终校验的一致性是体验红线：出现在候选里的值，提交后必须被接受（除非时序内数据真实变化）。实现上要求候选查询与get校验读同一数据源、走同一权限模块，禁止补全走缓存副本而校验读实时库的分叉配置。缓存层面，客户端可对"ref+参数名+输入前缀"做短TTL缓存（数秒级）降低打字间请求量；服务器可对静态枚举类候选做长缓存并在变更时失效。缓存命中返回的候选同样要遵守排序稳定性，避免同一输入两次补全候选项跳变。

## 五、可观测性与滥用防护

补全端点的高频特性要求专门的可观测与防护：按ref维度统计请求量、延迟P99、空结果率（空结果率高说明候选源覆盖不足）；对单会话补全请求设频率上限，超限返回空结果而非错误，避免打字快时界面弹错；把补全查询的耗时纳入整体延迟预算，超过两百毫秒的候选源做降级或预计算。滥用信号（异常高频、穷举式前缀扫描）应触发限流并记录，防止补全接口被当作数据枚举的后门。

## 六、小结

双目标ref设计是补全机制的精妙之处：一套交互、一套客户端逻辑，同时服务提示表单与资源模板构造。服务器实现的关键是把"定位、分支、公共出口"三层切干净，并守住候选与校验一致、上下文仅作参考、错配显式报错三条纪律。补全做好后，参数化体系的最后一块体验拼图即告完成。
