# 18 资源URI注入与路径穿越防护

> 摘要：本文分析资源URI作为攻击面 的注入风险——路径穿越、scheme混淆、模板参数注入与重定向滥用，给出服务端的解析、校验与规范化防御体系。

## 一、风险面分析

URI是资源子系统的全部输入面，攻击者（或被诱导的模型）可以构造恶意URI试探服务器。典型攻击有五类。路径穿越：`file:///docs/../../etc/passwd`式的相对段逃逸虚拟根。编码混淆：双重百分号编码（%252e%252e）绕过朴素的字符串黑名单，解码后还原为../。scheme混淆：把预期file://的参数换成http://或file://加UNC路径，诱导服务器向内外部地址发起请求。模板参数注入：向模板变量塞入斜杠、问号、井号，改变展开后的URI结构，访问变量域之外的路径。存储型注入：资源内容本身包含伪URI，欺骗客户端下一步读取越权地址。这五类风险的共同根源是"信任了输入的结构"，防御必须建立在解析后校验而非字符串包含判断上。

## 二、解析与规范化防御

第一道防线是严格解析：URI先经标准解析器拆解为scheme、authority、path段数组，拒绝解析失败的输入。第二道是规范化：对每段做百分号解码（限一次），空段与单点段删除，双点段触发回退且禁止回退越过虚拟根，结果重新编码生成规范形，后续全部逻辑基于规范形。第三道是结构校验：scheme白名单、authority必须为空或精确匹配、路径必须以虚拟根前缀开始且逐段比对。第四道是段级字符策略：路径段允许字符集显式声明（如仅字母数字、连字符、下划线、有限CJK），其余一律拒绝。示意代码：

```text
def safe_resolve(virtual_root, uri):
    parts = parse(uri)                      # 严格解析
    assert parts.scheme in ALLOWED_SCHEMES  # scheme白名单
    segs = [decode_once(s) for s in parts.path_segments]
    out = []
    for s in segs:
        if s in (".", ""): continue
        if s == "..":
            if not out: return REJECT       # 越根即拒
            out.pop()
        else:
            if not SEGMENT_RE.match(s): return REJECT
            out.append(s)
    return join(virtual_root, out)          # canonical path
```

## 三、模板与内容侧防御

模板侧的防御在变量域收口：每个模板变量绑定校验器（正则或枚举），展开前先校验后编码，斜杠与保留字在简单展开下必然被百分号编码，使其无法改变结构；匹配方向同样基于规范形比对。内容侧防御针对存储型注入：服务器生成内容中的动态URI必须由自己构造而非拼接用户输入；对内容中引用外部scheme的，客户端应有确认关卡（读取非白名单scheme前询问用户）。服务器间代理场景（资源内容指向另一服务器）要防止SSRF：出站地址过内网黑名单，禁用重定向自动跟随，响应尺寸与超时受限。

## 四、测试与运营清单

- 攻击样本回归集：穿越变体、双重编码、空字节、超长段、大小写scheme、反斜杠混用；
- 模糊测试：对read与模板展开入口做结构化模糊，异常输入必须得到明确拒绝而非崩溃；
- 依赖库审计：URI解析库的已知绕过漏洞（历史上有多次双斜杠与反斜杠案例）纳入升级清单；
- 日志留痕：拒绝事件记录输入哈希与拒绝原因类别，供攻击面分析；
- 纵深备份：即使校验完备，服务器进程仍以最小文件系统权限运行，容器内只读挂载。

URI注入防护的成熟度直接决定资源服务器能否暴露在不可信输入之下。核心心法只有一条：输入永远是字节流，结构是服务器单方面赋予的解释权。
