# 37 多步骤工作流提示：分步消息与嵌套资源引用

> 摘要：本文探讨用提示承载多步骤工作流的设计方法：分步消息的编排语法、嵌套资源引用的导航结构、阶段推进的节流技巧，以及与工具调用的接力模式。

## 一、把工作流装进一个提示

复杂任务很少能一步完成：数据分析要先圈定范围、再取数、再清洗、再产出结论；代码迁移要先理解旧接口、再生成映射、再逐模块改写、最后回归验证。把这些工作流装进提示有两条路线。单提示长流程：一个提示的messages把全部阶段的目标、材料、中间要求一次性铺开，模型自主推进。分步提示接力：工作流拆为多个提示（analyze-scope、fetch-and-clean、produce-report），用户或模型按序逐个执行，每步的输出成为下一步的输入。选择依据是"步骤间的检查点价值"：需要人工确认再继续的流程必须拆步（每步结束是天然检查点），纯机械连续的流程可单提示长跑。两条路线都依赖同一套底层技术：分步消息的编排与资源引用的嵌套导航。

## 二、分步消息的编排语法

单提示长流程的编排语法核心是"阶段分隔加推进节流"。messages数组中，每个阶段占一到两条消息：阶段头消息声明本阶段目标与产出物（user角色），阶段材料消息携带资源或数据。阶段之间用显式分隔标记（如"——阶段二：数据清洗——"）划界，模型对边界的服从远好于对散落在长文本中的阶段描述。推进节流是防止模型抢跑的技巧：在早期阶段的任务消息中写明"完成本阶段后停止，等待下一步指令"，配合把后期阶段拆到对话的后续轮次（客户端在首轮只注入前两阶段，模型完成后再注入后续），形成受控的链式推进。注意节流语句属于模板可信文本，由作者书写，不与用户参数混排，避免被参数值注入篡改。

```json
{ "messages": [
  { "role": "user", "content": { "type": "text",
    "text": "——阶段一：范围确认——\n依据以下数据字典（嵌入资源），列出与本问题相关的表与字段，说明取舍理由。完成后停止，等待阶段二指令。" } },
  { "role": "user", "content": { "type": "resource",
    "resource": { "uri": "db://meta/schema-dictionary", "mimeType": "application/json", "text": "……" } } } ] }
```

## 三、嵌套资源引用的导航结构

工作流的材料往往呈现层级：项目目录资源指向文档子资源，文档内又引用数据集。嵌套引用的导航设计有三条原则。索引资源模式：顶层材料做成索引（目录、清单、Schema说明），模型先读索引再按需深挖，而不是把全树一次性塞入；索引中每个条目附一句话摘要与URI，充当"路标"。引用就近原则：后续阶段需要的资源在紧邻的任务消息中给出，不依赖模型记忆几十轮之前的引用；同一资源在多个阶段使用时，重复给出引用的代价远小于模型翻找错漏的代价。快照化关键材料：决定后续走向的材料（当时的范围确认结果、选定的字段清单）在阶段边界固化为资源快照（嵌入或引用），后续阶段基于快照而非基于对话记忆工作，长流程中对早期内容的遗忘与幻觉即可被快照锚定。

## 四、与工具调用的接力模式

提示负责开局与阶段框架，执行类动作交给工具，接力模式有三种种形态。提示引导型：模板文本中写"本阶段可使用query-db工具获取样本数据，调用前先说明意图"，模型在阶段内自主调用工具完成任务；提示只约定使用边界（只读、频率、需确认），不硬编码调用序列。检查点接力型：每个提示阶段结束时，模型被要求产出结构化的阶段产物（JSON形式的中间结论），下一阶段的提示把上一阶段产物作为参数或嵌入资源带入；结构化产物让接力不依赖自然语言的准确转述。人工确认型：涉及高风险动作（写入、外发）的阶段，提示约定模型必须先输出计划并等待用户确认，确认后由用户触发对应工具或下一提示。三形态常组合使用：同一工作流中，只读阶段引导型、中间产物检查点型、终局动作人工确认型。

## 五、失败恢复与断点续跑

长流程必然中断（用户离开、会话超限、上游故障），设计时就要为恢复留桩。状态外置：阶段产物全部落为资源或结构化消息，恢复时从最后的完整产物重入，不重放对话；断点标记：提示支持resume语义参数（如from_stage），跳过已完成阶段直接注入当前阶段的任务与既有产物快照；幂等材料：各阶段对材料的要求设计为幂等（重读同一资源结果一致），配合版本戳避免恢复时材料已漂移造成的错乱。测试上专门演练"每个阶段边界中断后恢复"的用例，断言恢复后的产物与不中断路径一致。

## 六、小结

多步骤工作流提示的设计精髓是"结构显式化"：阶段显式（分隔与节流）、材料显式（索引与快照）、接力显式（结构化产物与确认点）。提示提供框架与上下文，工具承接执行，用户掌握检查点，三者配合即可把原本需要专业操作者盯全程的流程，变成普通用户可以放心启动、随时恢复、按点确认的自动化工作流。这是提示原语在生产环境中最有分量的应用形态。
