# 08 资源子树与URI模板的目录语义

> 摘要：本文解释资源子树（resource subtree）概念在MCP中的表达方式、静态资源与资源模板如何共同构成目录结构，以及子树级订阅与批量操作的实现模式。

## 一、从扁平列表到层级目录

MCP的资源发现模型由两部分构成：静态资源直接出现在resources/list中；参数化的资源家族通过resources/templates/list以uriTemplate形式公布。二者叠加即可表达树形目录：父路径作为聚合节点，子路径由模板展开。例如模板`file:///docs/{path}`声明了docs子树的可达性，`db://{table}/{id}`声明了全库表的行级可达性。子树并非协议中的显式对象，而是一种约定语义：URI共享同一父前缀的资源构成子树，客户端据此渲染层级浏览、实施批量操作、划分子树级订阅。这种"模板即目录索引"的设计避免了服务器枚举全部实例，把展开成本推迟到用户真正进入某分支时。

## 二、子树目录的构建规则

用模板构建目录需遵守四条规则。第一，模板参数顺序应与层级语义一致：从粗到细（库→表→行），使未填参数的前缀即目录层级。第二，模板description必须说明参数域，例如"path为docs目录下的相对路径，不含上级引用"，否则客户端无法生成合法实例。第三，静态资源与模板应互补而非重叠：已在列表中的静态项不应再被模板覆盖，防止双身份。第四，为深度较大的子树提供中间聚合资源，例如每目录一个"README"资源作为该分支的语义入口，提升模型导航效率。

```json
{
  "resourceTemplates": [
    {
      "uriTemplate": "git://repo/{repo}/blob/{ref}/{path}",
      "name": "仓库文件内容",
      "description": "读取指定仓库、指定提交(ref)下的文件内容，path为仓库相对路径",
      "mimeType": "text/plain"
    }
  ]
}
```

## 三、子树级订阅与变更粒度

MCP的订阅以单个URI为目标，但通知可以携带子树语义：客户端订阅目录资源URI后，服务器在该子树任何内容变化时发出notifications/resources/updated，客户端据此重读目录或受影响子项。实现子树订阅的推荐模式：订阅目标用目录URI（或模板展开的集合URI）；服务器维护"目录到订阅者"的反向索引，写入路径触发对应子树的失效广播；updated通知不携带diff，客户端负责重读。粒度权衡很关键——过粗导致无效重读风暴，过细导致订阅管理复杂，实践中按"用户可见的浏览单元"（目录、表、订单）划分粒度最稳。

## 四、批量遍历与安全边界

子树语义还为批量操作提供了边界原语。客户端递归展开模板遍历子树时应设置深度与总量熔断；服务器侧对模板展开做白名单校验，拒绝越出预定根的路径（详见安全专题）。导出与备份场景可实现"子树快照"资源，把整棵子树打包为单一blob，配合版本戳实现一次性迁移。子树模型的核心价值在于把无限实例空间压缩为有限模式集合，让资源目录在数据规模增长时保持常数级的元数据开销，这是MCP资源设计中最具伸缩性的机制之一。
