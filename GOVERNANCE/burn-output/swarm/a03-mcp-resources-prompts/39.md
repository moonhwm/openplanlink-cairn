# 39 提示作为可寻址能力：与Agent编排的集成

> 摘要：本文讨论把提示当作可寻址、可组合的能力资产接入Agent编排系统的方法：提示的寻址与引用格式、Agent调用提示的协议路径、结果交接模式与治理边界。

## 一、从用户命令到能力资产

提示的直接消费者是终端用户（斜杠命令），但它的结构化本质——名字寻址、参数声明、消息产出——使其天然具备被程序化调用的资格。Agent编排系统（多Agent协作框架、自动化流水线、跨客户端的机器人）可以把服务器提示当作"经过封装的任务能力"复用：编排者不需要自己编写"如何做代码审查"的长指令，直接调用reviewer服务器的code-review提示，传入diff资源引用，获得规范的开局消息。这种复用的价值在于治理集中：审查的方法论沉淀在一个服务器里，所有Agent用到的都是同一版本，方法论的改进一次生效于全部消费者。提示因此从"用户界面元素"升格为"可寻址能力资产"，寻址格式建议采用服务器加名字的限定形式，例如mcp://reviewer/prompts/code-review，编排配置中引用该形式，跨系统的能力清单可以统一聚合。

## 二、Agent调用提示的协议路径

Agent（作为MCP客户端角色）调用提示的路径与人类用户一致但有三个强化点。参数装配：Agent依据arguments声明自动装配参数，参数值来自其上游产物（文件路径、资源URI、前序输出）；装配前Agent应执行与客户端相同的校验（必选齐全、格式合法），避免把明显非法的请求打到服务器。进度与取消：编排场景的get可能耗时更长，Agent必须正确处理进度通知（转译为编排任务的状态上报）与取消（上游任务失败时及时取消挂起的get，释放资源）。结果消费：get返回的messages是"开局剧本"，Agent将其注入其底层模型的对话，而不是把messages当作最终数据解析——混淆这一点是集成中最常见的错误。

```text
编排片段（伪码）：
plan = [
  { agent: "collector",  tool: mcp.filesystem.read,     out: "diff_uri" },
  { agent: "reviewer",   prompt: "mcp://reviewer/prompts/code-review",
    args: { language: "typescript", diff_uri: "{diff_uri}" } },
  { agent: "summarizer", prompt: "mcp://reporter/prompts/digest",
    args: { source: "{reviewer.output}", style: "brief" } } ]
```

## 三、结果交接的两种模式

提示产出进入下游有两种交接模式。文本交接：下游提示把上游Agent的最终输出文本作为参数或嵌入材料带入，简单通用，但依赖上游输出的结构稳定（约定输出为Markdown加固定小节，下游按小节解析）。引用交接：上游把关键产物固化为资源（写回文件系统服务器或数据服务器），下游只接收URI引用并自行读取；引用交接解耦了阶段间的数据量与时效（下游按需读取、可读取最新版），并让产物天然可审计（资源有URI有版本）。推荐默认用文本交接传递轻量结论、引用交接承载数据密集产物，两者的分界线是"这段内容是否需要被后续多个消费者独立读取"。

## 四、治理边界：提示在编排中的风险

提示进入编排系统后，用户控制原则面临重新解释：终端用户不再是每次执行的直接确认者。治理边界必须前移到编排设计与运行时策略两层。设计层：编排者对所引用的每个提示负有尽调责任——审查模板内容（它将驱动Agent行为）、确认参数面（它决定信息暴露）、评估输出约定（它影响下游行为）；高风险提示（含强指令、触发外部动作）在编排中的每次执行应保留人工检查点。运行时层：执行预算（单次编排允许的get与工具调用总量）、权限继承规则（Agent只能使用其身份被授权的提示与资源）、审计留痕（编排日志记录每次提示调用的名字、参数摘要、产出指纹）。没有这三层约束的提示编排，等于把"服务器作者的指令"未经审查地注入自动化链条，风险远大于人工使用场景。

## 五、版本锁定与演化协同

编排配置引用提示等于建立了运行时依赖，版本管理要求随之而来：编排配置应记录所用提示的期望行为版本（提示侧提供版本号或内容哈希），执行时校验，不匹配则告警或中止；提示侧做行为级变更时，识别受影响编排（通过引用关系检索）并通知维护者，给出迁移说明；重要编排在提示服务器升级窗口做回归演练。双向的版本意识让"能力资产"的复用不会演变为"隐性耦合"的温床。

## 六、小结

提示作为可寻址能力的集成模式，让MCP服务器从"面向一个用户的产品"扩展为"面向Agent生态的能力库"。正确的打开方式是：寻址规范化、调用走全协议路径（校验、进度、取消）、交接区分文本与引用、治理边界前移、版本双向锁定。做到这五点，提示资产就能在人与Agent两类消费者之间安全地一鱼两吃，这是MCP生态可组合性的高级形态。
