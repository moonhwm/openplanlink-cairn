# 19 资源内容安全：脱敏、过滤与输出编码

> 摘要：本文讨论资源内容在离开服务器前的安全处理管线：敏感数据识别与脱敏、内容过滤策略、输出编码纪律，以及面向模型消费的特殊安全考量。

## 一、内容安全的威胁模型

资源内容最终会被注入模型上下文并呈现给用户，这个消费链路带来三类特有威胁。机密泄漏：凭据、令牌、身份证号、私钥等混入资源内容，经上下文进入日志、缓存甚至模型训练数据。注入指令：内容中埋藏"忽略之前的指令"式文本，劫持模型行为（间接提示注入）。隐私越界：个人信息以合法身份进入资源，但暴露范围超出了数据最小化要求。防御思路是在内容生成与返回之间建立一条出口安全管线，所有资源内容无例外地流经该管线，管线各环节独立可测试。

## 二、脱敏管线设计

脱敏管线的标准环节依次为：敏感识别、掩码替换、残留校验、标记标注。敏感识别用模式库匹配（凭据格式、密钥头部、证件号格式）加结构感知（JSON字段名启发，如token、secret、password字段），两者互补。掩码替换遵循"保留类型特征、去除恢复可能"的原则：API密钥替换为同长度占位符，证件号保留前缀后缀掩中间，姓名整词替换。残留校验对替换后内容重跑识别器，仍有命中则升级为拒绝返回。标记在内容头部注明已脱敏及规则版本，让消费者知道这不是原始数据。字段级裁剪常优于值级掩码：JSON资源直接删除敏感字段比掩码更干净，客户端按需请求补充字段。

```text
出口管线（顺序固定）：
raw -> 结构解析 -> 字段白名单/裁剪 -> 模式脱敏 -> 结构感知脱敏
    -> 残留校验 -> 尺寸与编码检查 -> 附脱敏标记 -> 返回
```

## 三、输出编码与内容过滤

输出编码解决"内容被安全消费"的问题。文本内容确保合法UTF-8并声明mimeType，避免客户端按错误编码渲染；嵌入内容中的控制字符（零宽字符、RTL覆盖符）要过滤，它们可被用于视觉欺骗；HTML或Markdown中的动态链接、图片引用要收敛到白名单域，防止内容渲染层的外联请求。内容过滤还包括尺寸纪律与语种纪律：超长内容截断时必须在截断点标注且不得截断在多字节字符中间。对面向模型的内容，可在段落间保留结构标记（标题、列表）帮助模型解析，但不添加指令性文字，服务器不应在内容中夹带指挥模型行为的语句。

## 四、面向模型消费的特殊考量

间接提示注入无法在服务器侧根除（内容本身就是自然语言），但可以降险：高敏资源（邮件、网页快照）在mimeType或扩展标注中声明不可信来源，客户端可将其放入隔离上下文区块并限制其触发工具调用的权限；服务器绝不在内容中模仿系统消息格式或使用与客户端UI相同的关键分隔符。测试上建立三类用例：已知的注入样本集验证客户端隔离行为；脱敏回归集保证规则升级不遗漏新格式；黄金文件比对保证正常内容零误伤（误脱敏会直接毁掉资源可用性）。内容安全管线的验收标准是：任何资源内容都可以安全地直接粘贴到任何对话中而不产生机密、隐私与行为风险。
