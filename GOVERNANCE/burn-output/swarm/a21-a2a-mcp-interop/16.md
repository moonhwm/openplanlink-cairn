# 16 · 组合模式四：网关聚合——MCP总线与A2A目录的会师

> 所属主题：A2A×MCP双栈互操作——工具连接与智能体互操作的分工和组合模式（子题目 16/48）

## 一、模式描述

网关聚合模式把分散的治理职能收拢到两个平行的控制面：**MCP网关**聚合全部工具连接，提供统一工具端点与调用策略；**A2A注册表**（目录）收录全部智能体的AgentCard快照与路由元数据，提供发现、健康与准入。两者之下是自由的数据面：智能体之间直接A2A对话，智能体到工具统一经网关。控制面与数据面分离，是大型多智能体系统的成熟形态。

与前三种模式不同，此模式的收益主要在治理规模效应：当智能体超过一打、工具超过五十个，点对点连接的熵必须由目录与网关吸收。

## 二、组件职责矩阵

- **A2A注册表**：卡片收录与快照缓存、版本变更提醒、健康探测、准入审核（安全方案齐备才上架）、按标签/skill检索。
- **MCP网关**：工具聚合与命名空间、按主体的投影暴露、调用审计与限流、下游健康与熔断。
- **策略引擎**（共享）：把"主体×能力"的授权矩阵同时作用于两处——注册表决定谁能委托谁，网关决定谁能用哪些工具。
- **审计汇流**：两面的日志以task_id与trace_id关联，形成端到端任务画像。

## 三、注册表数据结构示例

```json
{
  "entries": [
    {
      "kind": "agent",
      "id": "research@corp",
      "cardUrl": "https://research.internal/.well-known/agent-card.json",
      "cardSnapshot": { "version": "1.4.2", "skills": ["lit.review", "citation.check"] },
      "health": { "probe": "/health", "intervalS": 60, "consecutiveFailures": 0 },
      "access": { "allowedPrincipals": ["role:analyst", "role:writer"] },
      "status": "active"
    },
    {
      "kind": "mcp-server",
      "id": "tools/db@corp",
      "endpoint": "https://gw.internal/mcp",
      "via": "gateway",
      "toolPrefix": "db",
      "status": "active"
    }
  ]
}
```

注意MCP服务器在目录里以"经网关"的形态出现，避免调用方直连造成旁路。

## 四、运行期流程

1. 智能体启动时向注册表订阅关注标签，获得候选协作方与工具前缀清单。
2. 委托前查询健康与准入结果，跳过不健康端点。
3. 工具调用一律发往网关统一端点，由网关按前缀路由下游。
4. 注册表检测到卡片version变化时推送提醒，消费方按需刷新能力认知。
5. 审计汇流按trace_id拼接"A2A委托段 + MCP调用段"，输出完整链路。

## 五、实施清单

- 注册表只存快照与元数据，不代理业务流量，保持轻量高可用。
- 准入策略代码化：卡片缺安全声明、缺描述、描述与行为不符的记录拒绝上架。
- 网关与注册表共享同一主体身份体系，避免出现两个"身份真相源"。
- 为目录设计淘汰机制：连续失败或长期无流量的条目自动降级归档。
- 所有旁路（直连工具、绕过目录的硬编码端点）列入架构违规扫描。

## 六、小结

网关聚合模式用两个控制面驯服了双栈的规模复杂度：目录回答"找谁"，网关回答"用什么"。它是团队从十几人走向平台化时的必经形态，也是后续混合编排器（模式五）的地基。
