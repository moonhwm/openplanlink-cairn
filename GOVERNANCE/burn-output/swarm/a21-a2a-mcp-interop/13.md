# 13 · 组合模式一：垂直分层——工具在下、智能体在上

> 所属主题：A2A×MCP双栈互操作——工具连接与智能体互操作的分工和组合模式（子题目 13/48）

## 一、模式描述

垂直分层是双栈组合的默认形态：所有工具接入统一收束在MCP层，所有跨智能体协作统一走A2A层，两层之间只有单向依赖——上层智能体调用下层工具，下层对上层一无所知。整个系统像一座楼：地下室放工具与数据，楼层住智能体，电梯（A2A消息）在楼层之间运送任务。

这一模式的成立前提是存在明确的"能力归工具、协作归智能体"共识。团队只要守住第03篇的判别规则，多数场景自然收敛到这里，因此它是其余所有模式的基线参照系。

## 二、数据流示例

以"客户投诉处理"为例的完整数据流：

```text
1. 客服智能体(A2A)收到委托：处理订单X的退款投诉
2. 客服智能体经MCP调用 crm.lookup_order -> 取得订单与历史
3. 客服智能体判断金额超权限，A2A委托 政策智能体 裁定
4. 政策智能体经MCP调用 policy.query -> 检索退款政策条款
5. 政策智能体返回Artifact：允许，附条款引用
6. 客服智能体经MCP调用 billing.refund(order=X, amount=...)
7. 任务completed，Artifact链完整可审计
```

七步里MCP调用三次、A2A委托一次，各司其职：凡是"查数据、执行动作"走工具，凡是"需要判断力的分权决策"走智能体。

## 三、优缺点评估

优点：

- 职责清晰，故障定位按层切分，排查成本低。
- 工具可被任意智能体复用，避免能力重复建设。
- 权限模型按层独立设计：工具作用域与委托关系互不纠缠。

代价：

- 每次跨层都有协议转换开销，简单查询也要经过智能体的推理循环，时延与token成本上升。
- 对工具的细粒度流式与进度体验会被智能体层吸收，最终用户感知变钝。
- 层数固定后，临时性的"直连捷径"（智能体绕过网关直连工具）会成为治理债。

## 四、适用场景清单

1. 组织内多智能体共享同一工具生态（数据、检索、执行类工具集中运维）。
2. 审计与合规要求高，需要工具调用与任务委托分层留痕。
3. 工具版本变更频繁，需要网关层统一灰度。
4. 智能体数量在个位数到两位数之间，拓扑尚不需要更复杂的对等网络。

## 五、实施要点

- 为每层定义明确的SLO：工具调用P99、任务端到端时延分别度量。
- 在智能体内部做工具调用批处理与结果缓存，缓解跨层开销。
- 禁止下层感知上层：工具服务器不得在返回值里夹带"给某个智能体的指令"。

## 六、小结

垂直分层是双栈的第一块基石：简单、可审计、易演进。它的价值在于把"组合"约束成有纪律的形状，为后续更激进的桥接模式提供对照基线。
