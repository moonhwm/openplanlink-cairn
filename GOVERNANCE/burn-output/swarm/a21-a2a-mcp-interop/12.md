# 12 · 双栈参考架构：一个智能体的两面暴露

> 所属主题：A2A×MCP双栈互操作——工具连接与智能体互操作的分工和组合模式（子题目 12/48）

## 一、双面暴露的含义

双栈互操作最实用的参考架构，是让同一个智能体进程同时开放两个正面：对智能体世界开放A2A端点，接受任务委托；对工具世界暴露MCP服务器接口，把自身的某些确定性能力（如"生成报告文档"）以工具形式供其他宿主直接调用。双面暴露消除了一类常见的重复建设——不必为了"既能被委托又能被当工具用"而部署两套服务。

但要明确主从：A2A面承载完整智能（多轮、澄清、长时任务），MCP面只投影其中参数可枚举、同步可完成的子集。MCP面是智能体的"快速通道橱窗"，不是替代品。

## 二、进程内部结构

```text
                 +--------------------------------+
  A2A面          |          智能体内核             |        MCP面
  /a2a endpoint  |  任务管理器 | 推理循环 | 记忆     |  /mcp endpoint
  ------------>  |     |          |        |       |  <------------
  AgentCard发布  |  A2A适配器   工具路由   MCP适配器  |  tools/list
                 +--------------------------------+
                          |            ^
                          v            |
                    [MCP Client] --> 外部工具网关
```

- **A2A适配器**：AgentCard托管、任务状态机、SSE流、push通知注册。
- **任务管理器**：任务的创建、挂起、恢复与终态落库。
- **工具路由**：把推理循环的调用意图分派给本地MCP适配器或外部工具网关。
- **MCP适配器**：把选定的内部能力包装成tools暴露，含schema定义与调用分派。

## 三、代码骨架

以Python为例的双面服务雏形（框架无关化简）：

```python
class DualStackAgent:
    def __init__(self, core):
        self.core = core            # 推理与任务管理
        self.a2a = A2AServer(self.core.handle_task)
        self.mcp = McpServer(name="report-tools")

        self.mcp.tool(
            name="render_report",
            description="把结构化章节渲染为定稿文档",
            input_schema=REPORT_SCHEMA,
            handler=self.core.render_report,   # 复用同一内核
        )

    def run(self):
        serve_concurrently(
            a2a=self.a2a.app(port=8081),
            mcp=self.mcp.app(port=8082, auth="oauth"),
        )
```

关键在 `handler=self.core.render_report`：MCP面直接复用内核方法，不另起一套逻辑，避免双面行为漂移。

## 四、双面一致性清单

1. 能力同源：MCP工具的行为与其对应A2A skill必须调同一内核实现，任何差异只能来自参数化程度。
2. 版本同步：AgentCard的version与MCP的serverInfo.version建议联动递增。
3. 认证分置：两面的信任锚不同（委托方凭证 vs 宿主凭证），权限模型分别声明。
4. 限流独立：MCP面按调用计流，A2A面按任务计流，互不挤占配额口径。
5. 观测统一：两面共享trace体系，task_id与mcp会话在日志中可互相检索。

## 五、小结

双面暴露是"分工"最优雅的落点：同一份智能资产，按访问者需要呈现主体视图或工具视图。守住"能力同源、认证分置、观测统一"三条纪律，双面就是优势；违反任何一条，双面就会变成双倍的故障面。
