# 03 · 问题域差异：智能体互操作与工具连接的分界

> 所属主题：A2A×MCP双栈互操作——工具连接与智能体互操作的分工和组合模式（子题目 03/48）

## 一、一句话分界

MCP回答"模型如何使用一个外部能力"，A2A回答"一个智能体如何委托另一个智能体"。前者连接的是动词（操作、数据读取），后者连接的是主体（有目标、有状态、可能有不同所有者的自治系统）。这条分界不是技术细节，而是架构设计里最常被混淆的判断题。

实践中常见的误判有两种：其一，把一个远程智能体包装成本地工具，导致对方的长时任务、澄清式交互、流式产出在工具接口里全部失真；其二，为调用一个无状态的REST端点专门部署一个智能体，凭空引入了提示注入面、认证复杂度与不可预测性。两种误判的根源都是没有先问"对端有没有自主性"。

## 二、语义差异对照

把两个协议放到同一张表上，差异立即显形：

- **对端模型**：MCP服务器是被动执行体；A2A远端是主动协作体。
- **契约粒度**：MCP到参数级JSON Schema；A2A到能力级自然语言描述。
- **交互回合**：MCP单次调用即终结；A2A任务可多轮、可挂起等待补充输入。
- **状态**：MCP会话基本无业务状态；A2A任务有显式状态机与历史。
- **发现物**：MCP发现的是工具清单；A2A发现的是AgentCard主体档案。
- **信任边界**：MCP工具输出直接进上下文；A2A对端输出是"另一个智能体的话"，需要按不可信输入对待。

## 三、判别决策清单

设计新能力时，可按下列顺序自问：

1. 对端是否存在自己的推理循环与规划逻辑？是则倾向A2A。
2. 调用是否需要对方主动反问澄清？是则倾向A2A（MCP的elicitation面向最终用户，不面向对等智能体）。
3. 操作是否幂等、可参数化、秒级返回？是则倾向MCP。
4. 产出是否需要以Artifact形态被第三方消费与审计？是则倾向A2A。
5. 能力是否要分发给任意宿主复用？是则倾向MCP生态。
6. 双方是否分属不同组织且互不共享提示词？是则倾向A2A。

```text
需求 -> 是否有自主对端?
         |-- 否 --> 参数化? --是--> MCP工具
         |              `--否(纯数据)--> MCP资源
         `-- 是 --> 需要多轮/长时? --是--> A2A任务
                        `--否--> 仍建议A2A(保留演进空间)
```

## 四、小结

问题域的差异决定了双栈不是竞争而是互补：MCP向下扎进能力层，A2A横向打通主体层。架构图上让工具归工具、智能体归智能体，接口的每一侧才都能保持最小惊讶。后续所有组合模式都建立在这条分界线之上。
