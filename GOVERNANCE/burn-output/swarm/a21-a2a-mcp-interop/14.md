# 14 · 组合模式二：A2A智能体包装为MCP工具

> 所属主题：A2A×MCP双栈互操作——工具连接与智能体互操作的分工和组合模式（子题目 14/48）

## 一、模式描述

这一模式把方向倒过来：宿主只懂MCP，但又想借用某个强大的远程智能体，于是在宿主侧加一个适配器，把"向该智能体委托任务"伪装成一次工具调用。适配器负责把工具参数转成A2A消息、等待任务终态、把Artifact折叠成工具结果。对宿主里的模型而言，远处那个智能体就像一个"特别聪明但有点慢"的工具。

适用动机通常有三：宿主平台暂不支持A2A客户端；希望统一在MCP网关里做配额与审计；或想给既有工具面板低成本追加一项智能能力。

## 二、适配器实现骨架

```python
class AgentToolAdapter:
    """把一个A2A skill包装成MCP工具"""

    def __init__(self, card_url: str, skill_id: str):
        self.card = discover(card_url)
        self.endpoint = self.card["url"]
        self.skill = find_skill(self.card, skill_id)

    def tool_def(self) -> dict:
        return {
            "name": f"agent_{self.skill['id'].replace('.', '_')}",
            "description": (
                f"[远程智能体] {self.skill['description']} "
                "注意：耗时可能超过普通工具，参数尽量一次给全。"
            ),
            "inputSchema": {
                "type": "object",
                "properties": {
                    "instruction": {
                        "type": "string",
                        "description": "给远程智能体的完整自然语言指令"
                    }
                },
                "required": ["instruction"],
            },
        }

    def invoke(self, args: dict) -> dict:
        task = a2a_send(self.endpoint, message=args["instruction"])
        final = await_task_terminal_state(task.id, poll="5s", timeout="600s")
        if final.state != "completed":
            return {"content": [{"type": "text",
                                 "text": f"远程任务{final.state}"}],
                    "isError": True}
        return artifact_to_tool_result(final.artifacts)
```

`inputSchema`故意只收一个自由文本instruction——这是对"参数空间本质是对话性"的诚实处理，比虚构一堆假字段更安全。

## 三、有损折叠清单

工具化必然丢信息，适配器要知道自己丢了什么：

- **进度与流式**：A2A的status-update与增量Artifact被折叠掉，宿主只见长时间静默后一次性返回。
- **澄清轮**：input-required状态无法回传给宿主模型（MCP的elicitation面向最终用户，不是模型间对话），只能配置成"失败并提示补充后重试"。
- **多Artifact语义**：工具结果只有单一content列表，多个Artifact要么拼接要么只取第一个并注明。
- **取消传播**：宿主取消工具调用应映射为tasks/cancel，适配器必须实现，否则产生孤儿任务。

## 四、风险与缓解

- **提示注入面扩大**：远程智能体的输出经工具结果直接进宿主上下文。缓解：在结果文本外层加来源标注，宿主侧对带标注内容限制其触发高危工具。
- **超时错配**：宿主给工具的默认超时常为秒级，而智能体任务是分钟级。缓解：适配器声明工具为慢速类，宿主配置差异化超时。
- **成本失控**：一次"工具调用"背后是一次完整智能体任务，token消耗高一个量级。缓解：适配器在描述中标注成本等级，网关按工具调用与任务双口径计费。

## 五、小结

智能体当工具用是可行的权宜，但必须认清它是"降维折叠"：快路径换掉了丰富交互。把它定位为过渡方案或长尾能力补丁，而不是长期架构主干，是这个模式正确的打开方式。
