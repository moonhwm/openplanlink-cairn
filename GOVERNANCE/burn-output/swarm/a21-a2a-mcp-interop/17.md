# 17 · 组合模式五：混合编排器——同时说两种协议的大脑

> 所属主题：A2A×MCP双栈互操作——工具连接与智能体互操作的分工和组合模式（子题目 17/48）

## 一、模式描述

混合编排器是一个特殊的智能体：它站在系统顶端，左手是MCP客户端（接工具网关），右手是A2A客户端（接注册表里的其他智能体），由自身的推理循环决定每一步"自己想、用工具、还是找同事"。它不是简单的路由器——路由决策本身是模型基于上下文做出的判断，而非规则表。

这是表达力最强的形态，也是复杂度最高的形态：编排器成为系统的单点认知中枢，其提示词质量、工具面板规模与委托策略直接决定全局上限。适合任务链路高度动态、无法预先固化为工作流的场景。

## 二、决策路由的分层设计

编排器的每步决策可拆为四问，层层收窄：

```text
第1问：当前子目标能否由确定性操作完成？
   是 -> 从工具面板选工具（MCP路径）
   否 -> 第2问
第2问：子目标是否超出自身能力或权限？
   是 -> 从目录选智能体（A2A路径）
   否 -> 自主完成（本地推理路径）
第3问（对工具路径）：参数是否齐备？
   缺 -> 读取resource或调用查询工具补齐
第4问（对A2A路径）：候选是否多个？
   多 -> 按卡片描述+健康度+历史成功率排序择优
```

## 三、实现骨架

```python
class HybridOrchestrator:
    def __init__(self, model, tool_bus, agent_dir):
        self.model = model
        self.tools = tool_bus      # MCP客户端聚合
        self.dir   = agent_dir     # A2A注册表客户端

    def step(self, state: TaskState) -> Action:
        panel = self.build_panel(state)      # 按任务裁剪工具+同事面板
        decision = self.model.decide(state, panel)
        if decision.kind == "tool":
            return self.tools.call(decision.name, decision.args)
        if decision.kind == "delegate":
            return self.dir.dispatch(decision.agent, decision.brief)
        return decision.local_answer

    def build_panel(self, state) -> Panel:
        # 控制上下文成本：工具按相关性取前N个，同事按skill匹配取前M个
        tools = self.tools.rank(state.goal)[: self.max_tools]
        peers = self.dir.search(state.goal)[: self.max_peers]
        return Panel(tools=tools, peers=peers)
```

`build_panel`是成本控制的核心：全量工具schema加全部AgentCard的描述会撑爆上下文，必须按任务相关性裁剪。

## 四、复杂度管理清单

1. **面板预算**：单步决策可见的工具数与同事数设硬上限，超限走两级检索（先粗筛类目再精筛条目）。
2. **委托深度上限**：A2A委托链设最大深度（通常2-3），超深改为失败上抛，防递归风暴。
3. **在途任务上限**：编排器同时挂起的A2A任务数限流，防并行失控。
4. **幂等保护**：对可能重复触发的工具（写入类）在委托前后做去重键设计。
5. **回退路径**：每个A2A委托都预置"同事失联时"的工具级降级方案或人工关卡。
6. **决策留痕**：每步的panel快照与决策理由落日志，供事后复盘与提示词迭代。

## 五、与其他模式的组合

混合编排器不排斥其他模式：它可以架在模式四的网关与目录之上；可以对简单子任务用模式二把同事包装成工具以简化面板；也可以在特定环节用模式三让工具内嵌智能。工程实践里，"模式四做地基、模式五做大脑、二三做局部优化"是常见的三层混搭。

## 六、小结

混合编排器把双栈的使用权交给模型本身，是灵活性的天花板。它的成败不在协议而在纪律：面板预算、深度上限、决策留痕三件套，决定了这个"会两种语言的大脑"是运筹帷幄还是语无伦次。
