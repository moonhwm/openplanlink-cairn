# 11 本地网关的进程隔离与权限降级

网关集中持有全部上游凭据与工具通道，一旦以高权限运行并被攻破，攻击者获得的将是"整个用户账户甚至整台机器"。权限降级因此不是可选项而是必修课：让网关以能够完成工作的最小权限运行，把爆炸半径压缩到单点。本篇讨论桌面环境下可用的隔离手段——专用低权限账户、工作目录与文件系统约束、子进程沙箱、以及凭据的运行时隔离——并给出Windows、macOS、Linux三平台的落地差异与操作清单。

## 一、最小权限原则在网关上的具体化

最小权限要回答"网关到底需要哪些权限"。逐一梳理其行为：监听本地套接字与回环端口；读写配置、日志与审计文件；以受控方式访问策略允许的用户文件（这是文件工具的用途）；拉起stdio上游子进程；发起对远端上游的出站连接。由此推导的权限清单是：无需管理员或root组的任何成员身份；无需操作系统的敏感注册表与系统目录写权限；文件系统访问仅限配置指定的根目录集合；出站网络仅限上游清单中的地址。任何超出这份清单的需求都应当触发架构审视而非权限放开。

权限降级的第一步是专用账户。Linux与macOS上为网关创建系统用户，属主仅该用户，配置目录700；Windows上使用标准的非提升用户账户运行服务，并利用受限制的令牌进一步剥离侧载权限。第二步是文件系统边界：网关的运行时文件（套接字、锁、缓冲）放在专用运行时目录，与用户日常数据隔离，避免被浏览器下载等低信任目录污染。

## 二、上游子进程的沙箱约束

stdio上游以网关子进程身份运行，继承网关的全部权限，这是最容易被忽视的提权通道：一个恶意或被投毒的"服务器"包，拿到的是网关账户的全部能力。缓解手段按平台选择。macOS可用沙箱描述文件限制子进程的文件与网络可达范围；Linux可用命名空间与seccomp过滤，把每个上游关进仅能访问自身所需资源的笼子；Windows可对子进程应用受限制令牌与作业对象，限制其再拉起进程与访问窗口站。即便不引入重型沙箱，至少要做到按上游配置资源边界：允许的文件根、禁止的网络出口、内存与CPU上限。

```yaml
# 每上游沙箱声明（示意）
upstreams:
  - name: fs
    sandbox:
      fs_read:  ["/data/projects"]     # 仅这些根可读
      fs_write: ["/data/projects/out"] # 仅此目录可写
      net: none                        # 禁止一切网络
      rlimits: { memory_mb: 512, cpu_percent: 50 }
  - name: kb
    sandbox:
      fs_read: []
      fs_write: []
      net: { egress: ["kb.internal.example:443"] }  # 仅此出口
```

## 三、凭据的运行时隔离

权限模型再好，凭据保管失当就会前功尽弃。原则有三。第一，物理隔离：凭据存放于操作系统提供的保管机制（Windows凭据管理器、macOS钥匙串、Linux的秘密服务或加密文件），网关启动时解密进内存，磁盘上的配置只留引用别名。第二，进程内隔离：凭据只存在于网关主进程的策略与连接模块，永不传入上游子进程的环境——上游需要认证时由网关在连接层注入到该上游自己的会话，子进程环境变量里看不到任何相邻上游的凭据。第三，日志盲区：脱敏中间件在日志与错误上报前统一遮蔽已知敏感字段，并采用无法从遮蔽值反推原文的标记方式。

## 四、桌面平台的具体落地差异

三个平台的降级手段各有细节。Windows上服务可配置为专用虚拟账户运行，文件访问通过ACL精确授予；要特别处理UI隔离——服务会话无法弹窗，工具确认类交互必须走"会话内伴随进程"或委托客户端展示，设计权限时就应把"网关永不需要桌面交互"当作目标。macOS的沙箱描述文件以声明式方式列举允许的文件读写路径与网络出口，launchd再配合用户与组设定完成账户层隔离；全盘访问、辅助功能等敏感授权绝不授予网关本体。Linux组合最丰富：systemd服务可设ProtectSystem、PrivateTmp、NoNewPrivileges等加固开关，一行单元文件配置就能实现文件系统只读化与特权提升封禁，成本低到没有理由不用。

落地的验证手段同样重要：权限配置完成后应做"反向验证"——以网关账户身份尝试访问一个未授权路径、尝试监听特权端口、尝试读取其他用户文件，全部应当失败且失败原因清晰。这类验证脚本应随安装器提供，让"降级是否真的生效"变成可重复执行的检查项，而不是依赖配置评审的肉眼比对。升级网关版本后也要重跑验证，因为安装器或打包脚本偶尔会以宽松默认值覆盖此前的严格设置。

## 五、降级的代价与平衡

权限降级不是免费的。过严的沙箱会让正常工具频繁失败，用户在挫败中倾向于全部放行，反而毁掉整个体系。平衡的做法是把降级分成档位并给出清晰映射：默认档面向低敏感的本地工具；加强档面向网络类上游；企业档面向受控环境，由管理员统一下发。每一档的能力边界写成用户可读的说明，让"为什么这个工具被限制"永远有答案。权限体系的生命力在于用户理解并信任它，而非在于技术上的严丝合缝。

- 先列行为再定权限，专用账户加文件系统边界是起点；
- stdio子进程是隐藏提权通道，按上游声明沙箱边界；
- 凭据三隔离：保管隔离、进程内隔离、日志盲区；
- 降级分档并解释边界，用户信任比锁死更重要。
