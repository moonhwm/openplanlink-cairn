# 12 网关日志与本地可观测性：结构化日志、指标与追踪

可观测性是网关"治理组件"定位的直接兑现：无法被观察的策略执行等于没有执行。本地网关的可观测性建设与企业服务相比预算受限——没有专职运维、没有全套观测平台——因此设计必须在"信息完整"与"资源克制"之间精确定位。本篇给出三层观测方案：结构化事件日志、轻量指标暴露、以及贯通单次调用的追踪标识，并讨论脱敏、采样与本地留存策略，全部内容不依赖任何外部付费服务。

## 一、结构化事件日志

网关日志的第一原则是结构化：每行日志是一个JSON对象而非自由文本，字段固定、类型稳定、可被任何工具解析。事件模型建议围绕"一次工具调用的一生"展开：会话建立、能力查询、策略判定、调用发起、上游执行、结果返回、审计落账。每类事件定义最小字段集——时间戳、追踪标识、事件类型、会话标识、客户端标识、上游名称、工具名、结果状态、耗时。字段命名从第一天就冻结，下游的检索与统计都建立在字段稳定性之上。

```json
{"ts":"2026-08-27T22:31:04.512+08:00",
 "trace_id":"gw-7f3a2c",
 "event":"tool_call_completed",
 "session":"s-114","client":"ide-alpha",
 "upstream":"fs","tool":"fs_read_file",
 "status":"ok","duration_ms":37,
 "policy":{"rule":"allow-fs","action":"allow"}}
```

脱敏必须在写入前完成而不是写入后过滤：日志管道的末端是脱敏中间件，参数与结果字段按敏感字段名单遮蔽，遮蔽采用保留长度特征的标记形式，便于排障时判断"参数是否传对"而不暴露内容。本地留存采用滚动加封顶：单文件达到上限即轮转，保留最近N份，磁盘总占用有硬性预算，防止审计日志悄悄吃满系统盘。

## 二、轻量指标与追踪标识

指标回答"聚合状态如何"：当前会话数、每上游在途调用数、按工具的调用速率与错误率、策略拒绝次数、上游健康状态。本地场景不需要重型时序数据库，网关内置一个固定窗口的环形缓冲保存最近若干分钟的指标，同时在回环端点以文本格式暴露即时快照，任何监控工具或简单的定时抓取脚本都能消费。指标的价值在趋势而非单点：调用错误率的缓慢爬升、某工具耗时的逐步膨胀，都是用户报告问题之前就能发现的信号。

追踪标识是贯通三层的线索。网关在会话建立时生成会话标识，在每次调用时派生调用级追踪标识，注入到日志行、上游请求上下文与审计事件。这样一次"AI删错文件"的排查可以从审计事件出发，串起策略判定、参数内容（脱敏后）、上游响应的全过程。反向场景同样重要：从上游日志里的错误出发，凭追踪标识找到对应的客户端会话与调用方。

## 三、观测的成本控制与采样策略

全量记录一切是资源不可承受的，必须有分级采样。审计类事件（策略判定、调用结果）全量记录，这是治理底线；调试类事件（逐条转发细节）默认关闭，排障时按会话或按时间窗临时开启；内容类事件（参数与结果快照）按工具敏感级决定是否记录摘要而非全文。开启临时观测要有自动过期：一次性开启三十分钟，到期自动回落，避免排障开关永远忘关。

- 三层方案：结构化事件、环形缓冲指标、贯通追踪标识；
- 脱敏在写入前，留存滚动加封顶，磁盘预算硬性；
- 审计全量、调试按需、内容按敏感级摘要；
- 临时观测自动过期，防止开关忘关。
