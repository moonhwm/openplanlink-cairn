# 07 本地网关进程模型：常驻守护进程与按需拉起的权衡

网关在操作系统里以什么形态活着，决定了它的资源占用、启动体验与故障恢复方式。本地MCP网关的进程模型有两大流派：常驻守护进程与按需拉起。前者把网关做成开机即启的系统服务，后者让网关在第一个客户端连接到来时才启动、空闲一段时间后自动退出。两种模型各有清晰的适用场景，也有混合形态的空间。本篇分析两种模型的机制细节、生命周期事件与工程陷阱，并给出选择依据。

## 一、常驻守护进程模型

守护进程模型下，网关由操作系统的服务机制管理：Windows上注册为服务或计划任务，macOS上使用launchd守护，Linux上交给systemd。开机即启动意味着MCP能力永远就绪，客户端接入零等待；同时守护进程有明确的监督者，崩溃后自动重启，健康检查与日志轮转也有成熟方案。代价是常驻内存占用与"是否被滥用"的担忧——一个空闲时也占几十上百兆内存的网关，在低配设备上会被用户视为负担。

常驻模型的另一个深层优势是状态连续性。网关可以维护长时间积累的运行时状态：上游健康探测的历史、限流窗口的计数、审计缓冲、能力清单的缓存。这些状态在按需模型里会随进程退出而丢失，重启后需要重新预热，表现为首批请求的延迟抖动。对审计要求严格的场景，常驻模型几乎是必选项，因为审计缓冲的可靠落盘需要一个稳定的宿主。

## 二、按需拉起模型

按需模型把网关当作"第一个客户端的子进程或由其触发启动的临时进程"。最简单的实现是：客户端的MCP配置指向一个启动脚本，脚本检查网关是否已在运行，未运行则拉起再完成连接，即经典的单例套接字模式。空闲超时后网关自行退出，释放全部资源。这个模型对轻度用户友好——不装"又一个后台程序"，资源占用为零直到真正使用。

但按需模型有三个工程陷阱。第一是竞态：两个客户端同时冷启动，都发现网关未运行，各自拉起一份，必须以文件锁或命名管道路径抢占来保证单例。第二是状态丢失：退出太积极会丢限流窗口与审计缓冲，退出太迟又失去资源优势，超时阈值难以两全。第三是监督缺位：没有系统级监督者，网关崩溃时若恰好没有客户端在线，无人负责重启，故障要等到下一次使用才暴露。Windows上还存在会话隔离问题：按需拉起的网关继承触发者的用户会话，切换用户后旧实例不可见也不可用。

```text
按需拉起的单例抢占流程：
客户端启动 → 探测命名管道/Unix套接字是否存在
  ├─ 存在 → 直接连接
  └─ 不存在 → 尝试获取文件锁
        ├─ 抢到 → 拉起网关、创建套接字、释放锁、连接
        └─ 未抢到 → 等待对端创建完成（带超时）→ 连接
```

## 三、混合形态与选择依据

实践中常见的混合形态是"常驻但轻、忙时扩容"：守护进程常驻但内存压到极低，上游stdio子进程按需拉起、空闲回收，重负载任务（如大文件解析）交给工作进程池。这样常驻的只是调度核心，资源大头仍然按需。选择模型的判断依据可以列为四问：使用频率是否每天都发生；是否存在无人值守时期的审计要求；设备资源是否紧张；是否有多个客户端共享。前两问为是则选常驻，第三问为是且第四问为否则按需亦可，否则优先混合形态。

## 四、跨平台的服务注册差异

守护进程模型在各平台的落地方式差异不小，直接决定安装器的复杂度。Windows上推荐使用服务控制管理器注册，但要处理好服务账户与桌面会话的交互限制：服务运行在会话零，无法弹UI，若网关需要向用户弹出工具确认窗口，就必须通过一个会话内的伴随进程中转，或者干脆把确认动作委托给客户端展示。macOS上launchd的plist声明支持KeepAlive与RunAtLoad，配合套接字激活特性还能实现"系统按需拉起"——launchd监听套接字，第一个连接到来时才真正启动网关进程，等于官方支持的按需模型，规避了自行实现单例竞态的麻烦。Linux上systemd的单元文件同样支持套接字激活与看门狗协议，看门狗还额外提供了"进程活着但死锁"的检测能力，比单纯的重启策略更可靠。

跨平台差异还体现在信号语义上。POSIX平台的SIGTERM是标准停机信号，而Windows服务收到的是服务控制码，网关的停机钩子要分别适配；统一的做法是在内部定义一个平台无关的"优雅停机"事件，各平台的入口层把它翻译成本地信号或控制码。此外，安装器应同时提供命令行的注册与注销命令，便于脚本化部署与卸载残留清理——忘记注销服务是用户报告"卸载后仍在运行"的头号原因。

## 五、生命周期事件清单

无论哪种模型，网关都要正确处理一组生命周期事件：启动时的配置加载与上游健康预检；运行中的配置热重载；收到操作系统停机信号时的优雅退出——停止接受新会话、等待在途调用完成或超时收割、向上游发送关闭通知、刷盘审计缓冲、释放文件锁。优雅退出的每一环都容易被忽略，尤其是stdio上游子进程的收割：Windows上父子进程不会自动级联退出，网关必须显式终止子进程树，否则会积累孤儿进程。

- 常驻优势：零等待、状态连续、有监督者；
- 按需陷阱：单例竞态、状态丢失、监督缺位、Windows会话隔离；
- 混合原则：常驻的只有调度核心，资源大头按需伸缩；
- 优雅退出四步：拒新、收尾、通知、刷盘，外加子进程树回收。
