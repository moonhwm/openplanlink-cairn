# 10 网关生命周期管理：启动序列、健康检查与优雅退出

网关从进程启动到最终退出之间的一条时间线，布满了容易被忽视的工程细节。启动太快会让客户端连上一个尚未就绪的网关，退出太粗暴会丢掉在途调用的结果与未落盘的审计事件。本篇把网关生命周期切成启动、就绪、运行、降级、退出五个阶段，逐阶段定义正确行为与检查清单，并给出可执行的伪代码框架。这些细节决定了网关在真实桌面上是"安稳的背景设施"还是"间歇性消失的玄学故障源"。

## 一、启动序列与就绪门槛

启动阶段最大的诱惑是"尽快监听端口"，但过早监听意味着客户端可能在配置未加载、上游未握手时连入。正确的启动序列分六步：加载并校验配置、初始化存储与审计通道、按需预热关键上游、注册对外通道、发送就绪信号、开始接受会话。就绪门槛要区分两种状态：存活（进程在运行）与就绪（可以服务请求）。监督系统按存活判断是否重启，客户端与负载层按就绪判断是否接入，两者必须分开暴露——把存活当就绪是故障扩大的经典原因。

预热策略值得斟酌。全量预热所有上游会拖长启动时间，尤其存在网络上游时；完全不预热则首个请求要承担握手成本。折中方案是分层预热：本地stdio上游同步拉起（毫秒级），HTTP上游异步探测，探测结果标记就绪状态但不阻塞启动。每个上游条目携带一个就绪标志，客户端查询能力清单时，未就绪上游的工具可以先行出现并附带状态注记，调用时若仍未就绪则返回明确的可重试错误，而不是让请求悬挂。

## 二、运行中的健康检查体系

运行阶段的健康检查分三层。进程层由监督者执行，按周期探活，配合看门狗协议检测死锁（进程响应心跳但业务线程卡死的情况，纯探活发现不了）。上游层由网关执行，对每个上游维护健康状态机：正常、疑似异常（探测超时一次）、异常（连续超时）、恢复中。状态迁移要带迟滞，即连续N次失败才判异常、连续M次成功才判恢复，避免抖动导致路由来回切换。会话层检查在途调用的年龄分布：某类工具的P99耗时突然翻倍往往是上游劣化的先兆，网关可以用滑动窗口统计触发主动告警。

```python
# 上游健康状态机骨架（示意）
class UpstreamHealth:
    FAIL_THRESHOLD, OK_THRESHOLD = 3, 2
    def __init__(self):
        self.state, self.fails, self.oks = "ok", 0, 0
    def probe_result(self, ok: bool):
        if ok:
            self.fails, self.oks = 0, self.oks + 1
            if self.state != "ok" and self.oks >= self.OK_THRESHOLD:
                self.state = "ok"          # 恢复，重新纳入路由
        else:
            self.oks, self.fails = 0, self.fails + 1
            if self.state == "ok" and self.fails >= self.FAIL_THRESHOLD:
                self.state = "down"        # 摘除，触发熔断与告警
```

## 三、降级运行与部分故障

健康检查的目的是支撑降级运行而非简单重启。单个上游异常时，网关应当把它从路由表摘除，但保留其工具清单的最近快照并标记不可用，客户端可以感知"哪些能力暂时缺席"；其他上游不受影响。全部上游异常这种极端情况下，网关仍应存活并明确报告全局只读状态，而不是自行退出——退出了，客户端连"哪里出了问题"都无从得知。降级期间的行为要在审计日志中留痕：摘除时间、恢复时间、期间被拒绝的调用次数，这些是事后复盘的第一手材料。

## 四、重启风暴与退避策略

监督者自动重启是双刃剑：上游持续故障或配置错误会让网关陷入"启动、失败、被重启"的循环，每次循环都消耗资源并刷屏日志，这就是重启风暴。对策是给重启加指数退避与熔断计数：连续失败次数越多，下一次重启的等待间隔按倍数拉长；达到上限后进入冷却状态，只保留最小探活，等待人工干预或外部条件变化（如配置文件被修正）再恢复。冷却期间监督者应通过系统通知或日志中的显式标记告知用户，避免"网关消失了却无人知晓"。

另一个相关陷阱是依赖循环：网关的上游如果依赖网关本身提供的服务（例如一个把日志工具暴露为MSP服务器的上游），重启顺序会形成环。部署时应把这类自指依赖显式禁止——上游清单校验阶段检测地址回环到网关自身监听端口的条目并拒绝加载，从配置层面斩断环的可能。健康检查的探测请求本身也要节制：对每个上游的探测频率过高会给上游造成负担，过低又延迟发现，经验起点是本地上游一秒级、远端上游五到十秒级，并支持按上游覆盖。

## 五、优雅退出的完整清单

退出阶段的目标是无损收尾。收到停机信号后依次执行：停止接受新会话与新请求；向存活会话广播即将停机的通知（客户端可选择快速切换）；在途调用给予宽限期等待完成，超时则向上游发送取消、向客户端返回明确的中断错误；逐个关闭上游连接并回收stdio子进程树（Windows需显式遍历进程树终止）；刷盘审计缓冲与指标快照；释放套接字文件与文件锁；最后退出。每一环都设独立超时，防止任何一环卡死拖住整个退出。宽限期的默认值建议三十秒并可配置——足够大多数工具调用完成，又不至于让系统关机等待过久。

- 启动区分存活与就绪，预热分层不阻塞；
- 健康三层：进程探活、上游状态机带迟滞、会话时延监控；
- 部分故障走摘除加标记，全局故障存活报告而非退出；
- 退出七步全带超时，审计缓冲必须最后刷盘。
