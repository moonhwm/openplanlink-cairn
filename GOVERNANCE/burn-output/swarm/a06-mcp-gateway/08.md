# 08 网关与客户端的本地通信：stdio桥接、命名管道与回环HTTP

客户端接入本地网关的通信方式看似细节，实则同时影响兼容性、安全与性能三个层面。可选通道有三条：stdio桥接（网关伪装成普通stdio服务器）、操作系统本地的命名管道或Unix域套接字、以及回环地址上的HTTP服务。三条通道在客户端兼容度、连接多路复用能力与访问控制粒度上差异显著。本篇逐一分析三条通道的机制、安全属性与适配代码形态，并给出组合建议。

## 一、stdio桥接：最大兼容度的代价

多数桌面AI客户端只支持把MCP服务器配置为一条stdio命令，因此网关最稳妥的对外形态就是"伪装服务器"：客户端执行网关提供的桥接命令，通过其标准输入输出对话。桥接进程本身很薄——把stdin的JSON行转发给真正的网关守护进程，把应答写回stdout。它的优点是零配置适配任何客户端；缺点是每个客户端多一个桥接进程，且stdio语义限制了主动推送——服务器发起的通知只能在客户端发出请求的应答流中捎带，纯下行通知在部分客户端实现里会被丢弃。

桥接进程与守护进程之间的第二条腿怎么设计有讲究。常见做法是桥接通过命名管道或Unix套接字连到守护进程，从而把stdio语义转换为全双工语义，通知可以独立送达。桥接进程应当做到"无脑"：不含任何策略逻辑与凭据，崩溃即重启，保证攻击面最小——因为桥接以用户身份运行且可能被其他程序拉起。

## 二、命名管道与Unix域套接字：本地全双工通道

操作系统的本地IPC通道提供内核级访问控制与全双工能力。Windows命名管道支持基于ACL的授权，可以限定只有特定用户或组能连接；Unix域套接字则依赖文件系统权限控制访问，配合chmod与属主设置即可限定。两者都支持多客户端并发连接，是共享网关形态下比stdio更优雅的通道。MCP协议在规范层面并未定义域套接字传输，实践做法是在Streamable HTTP语义外再包一层本地传输适配，或采用社区约定的socket传输扩展。

```typescript
// 网关侧：在Unix域套接字上接受多客户端连接（示意）
import { createServer } from "node:net";
const srv = createServer((socket) => {
  const session = gateway.newSession({ peer: socket.remoteAddress });
  socket.on("data", (buf) => session.feedLines(buf.toString("utf8")));
  session.on("response", (msg) => socket.write(JSON.stringify(msg) + "\n"));
  socket.on("close", () => session.shutdown("client_disconnected"));
});
srv.listen("/run/mcp-gateway.sock");
// 权限：属主为网关专用用户，chmod 660，客户端经白名单组访问
```

## 三、回环HTTP：面向浏览器扩展与现代客户端

第三条通道是在127.0.0.1上监听的HTTP服务，对外呈现标准的Streamable HTTP端点。它的存在主要是为了服务浏览器扩展、Web技术栈的桌面壳（Electron类应用）与远程调试工具——这些客户端无法拉起子进程，却天然会说HTTP。回环HTTP必须处理好三件安全事项：绑定地址严格限定回环接口而非全接口；实施来源校验（Origin头白名单加本地令牌）；对跨端场景预置CORS策略，防止任意网页向本地网关发起请求。本地令牌通常在网关首次启动时生成，写入仅当前用户可读的文件，客户端凭令牌连接，等价于一把本地访问门钥匙（示例中均为占位符，非真实凭据）。

## 四、通道层的安全加固细节

三条通道各自还有值得展开的加固细节。stdio桥接要防"身份冒充拉起"：任何本地进程都可以执行桥接命令从而连上网关，因此网关不能把"能连上桥接"当作身份证明，策略中的用户确认机制不能因为连接来自本地而豁免。域套接字在类Unix平台上还要注意路径目录的权限：套接字文件本身660，但若其所在目录任何用户可写，攻击者可以抢先创建同名文件或用假套接字替换，稳妥做法是把套接字放进仅网关用户可写的运行时目录，并在启动时校验已存在文件的真实性。回环HTTP的来源校验要理解浏览器的同源模型：网页里的脚本向127.0.0.1发起请求时Origin头是该网页的源，网关应只放行白名单扩展的来源标识，其余一律拒绝且不返回详细信息，避免成为本地服务探测的 信息泄露点。

另一个容易忽视的细节是通道的版本对齐。多通道并行意味着同一客户端能力可能从不同通道进入，网关在会话建立时记录通道类型，并在策略与日志中把通道作为属性之一——审计事件里"经浏览器扩展调用了文件工具"与"经IDE调用了文件工具"应当可区分，这在事后追责与异常检测时价值巨大。同时回环HTTP通道暴露的端点应与域套接字通道在能力上保持一致，避免出现"某工具只能从某通道访问"的隐性差异，那会制造排查噩梦。

## 五、通道组合与选择

三条通道并不互斥，成熟的本地网关同时开放三者：stdio桥接照顾传统客户端，域套接字服务本机高性能客户端，回环HTTP服务浏览器形态。选择优先级建议：客户端原生支持自定义传输时优先域套接字，需要被任意客户端即插即用时用stdio桥接，面向Web形态或需要远程调试时开回环HTTP。性能上三者差异对MCP流量而言都不构成瓶颈——单次工具调用的耗时大头在上游执行，本地通道的开销在微秒到毫秒级，选型应以兼容与安全为先。

- stdio桥接：最大兼容，桥接层保持无脑与无凭据；
- 域套接字/命名管道：全双工、内核级访问控制，首选通道；
- 回环HTTP：服务浏览器形态，必须配回环绑定、来源校验与本地令牌；
- 三通道并行是常态，按客户端形态分配而非二选一。
