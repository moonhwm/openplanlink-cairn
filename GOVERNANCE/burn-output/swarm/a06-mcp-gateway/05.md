# 05 网关架构设计目标：安全、隔离、可观测、可扩展的优先级排序

任何架构文档都会列出安全、性能、可扩展等目标，但不排优先级的目标清单等于没有目标。MCP网关的特殊性在于：它同时握有凭据、执行着策略、代理着智能体的动作，任何一项设计目标的实现方式都会挤压其他目标的实现空间。例如把工具描述实时透传给客户端利于兼容性，却可能泄露内部拓扑；把全部调用缓存起来利于性能，却可能把敏感数据留存在磁盘。本篇给出六项设计目标的定义、度量方式与相互冲突时的裁决规则，作为后续所有机制设计的价值坐标。

## 一、六项设计目标的定义与度量

第一是安全默认：开箱即用的配置必须是保守的——未知工具默认拒绝、上游凭据默认不出网关、危险工具默认要求人工确认。度量方式是新装网关在零配置下的攻击面测试通过率。第二是隔离：多客户端、多上游之间不能相互污染，一个客户端的会话上下文、一个上游的故障都不能越界传播。度量方式是故障注入测试：杀死任意一个上游，其余能力可用性必须保持。

第三是可观测：每一次工具调用都能还原出完整链路——谁发起、经哪条路由、命中什么策略、返回什么结果、耗时多少。度量标准是审计日志的字段完整率与追踪标识贯通率。第四是低延迟加成：网关引入的额外延迟应控制在毫秒级，本地回环路径的P99开销不应明显高于一次空转转发。第五是可扩展：新增上游服务器、新增策略类型、新增客户端形态都不应修改核心代码，通过配置或插件完成。第六是兼容演进：MCP规范仍在快速迭代，网关必须能同时服务旧版本客户端与新版上游，协议适配层可独立升级。

## 二、冲突时的裁决规则

目标之间必然冲突，裁决规则比目标本身更重要。本文主张的优先序是：安全默认 > 隔离 > 可观测 > 兼容演进 > 低延迟 > 功能丰富。举例说明这个序列如何落地。

- 当兼容旧客户端需要放开某项安全检查时：拒绝兼容，宁可让旧客户端走降级路径；
- 当性能优化要求绕过审计日志时：拒绝优化，审计是网关存在的理由之一；
- 当新功能要求改动核心转发路径时：拒绝直达，功能以插件形式挂在钩子上；
- 当观测的verbose日志可能记录敏感参数时：默认脱敏，提供显式的按需解锁开关。

这套裁决的本质是：网关是治理组件而非性能组件。企业完全可以为吞吐再挂一层专用转发层，但不能为吞吐牺牲治理属性。个人桌面场景下排序可以微调——单用户时隔离的重要性下降，低延迟与轻量化的权重上升，但安全默认仍然居首，因为个人机器上的凭据泄露代价同样高昂。

## 三、把目标转成架构约束

设计目标要变成可执行的架构约束才能指导编码。安全默认转化为三条硬约束：所有策略检查在转发前同步完成，不存在"先转发后补检查"的路径；凭据只存在于网关进程内存与受保护的存储区，任何日志与错误消息经过脱敏中间件；策略引擎的默认动作是拒绝，白名单而非黑名单。隔离转化为两条：上游连接按服务器维度池化且故障域封顶为单服务器；客户端会话标识贯穿全链路，任何共享缓存必须以会话为键分片。可观测转化为一条：追踪标识在网关入口生成，注入到每个上游请求的上下文与日志行。

```text
请求进入网关
  │
  ├─ ①追踪标识生成 → 贯穿后续所有日志
  ├─ ②策略同步检查（默认拒绝）→ 审计记录
  ├─ ③会话亲和路由 → 上游连接池（按服务器分片）
  ├─ ④响应脱敏中间件 → 审计记录
  └─ ⑤返回客户端（携带完整链路元数据）
```

## 四、反模式清单：目标失调的四种典型症状

把设计目标落地的过程中，有四种反复出现的反模式值得警惕。第一种是"功能倒挂"：为了让某个新工具尽快跑通，在策略引擎里开了绕过审计的旁路，此后每个新工具都要求同样的旁路，安全默认名存实亡；症状是审计日志的覆盖率先升后降。第二种是"隔离塌方"：为了实现跨客户端共享缓存提升性能，把会话维度的分片键改成了全局键，一个客户端的上下文开始渗入另一个客户端的工具结果。第三种是"观测税"：每个请求打二十条结构化日志且全部同步落盘，延迟目标被观测成本吃掉，正确做法是分级采样，审计事件全量、调试事件抽样。第四种是"兼容黑洞"：为了兼容一个不肯升级的旧客户端，网关核心里堆满特判分支，协议适配层失去独立性，后续每次规范升级都要在核心里动刀。

这四种症状的共同根源都是在压力下让局部目标篡改了全局优先序。定期用裁决序回检架构决策，例如每季度做一次"旁路审计""全局键""同步日志""核心特判"四项扫描，能把失调扼杀在早期。

## 五、小结与要点回顾

本篇的价值在于给出了排序而非罗列：安全默认与隔离压倒一切，可观测是存在理由，兼容与性能次之，功能以插件方式生长。所有后续篇章讨论的具体机制——权限模型、路由引擎、聚合策略、限流配额——都可以拿这把尺子回检：它是否破坏了默认安全？是否扩大了故障域？是否在审计链路上开了洞？

- 六目标：安全默认、隔离、可观测、低延迟、可扩展、兼容演进；
- 裁决序：安全默认 > 隔离 > 可观测 > 兼容 > 延迟 > 功能；
- 目标落地的形态是入口处的硬约束与贯穿全链路的追踪标识。
