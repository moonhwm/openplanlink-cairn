# 04 桌面AI接入MCP的典型拓扑：单客户端直连、共享网关与混合形态

架构讨论若不落到具体拓扑，就容易停留在概念层面。桌面AI接入MCP的部署形态在现实中演化出了四种典型拓扑：客户端各自直连、单客户端独占网关、多客户端共享本地网关、以及本地网关加远端服务器的混合形态。每种拓扑在配置管理、进程开销、权限边界与故障域上各有取舍，没有绝对最优，只有与用户画像的匹配。本篇逐一拆解四种拓扑的结构、适用场景与迁移路径，并给出选型判断清单。

## 一、拓扑一：客户端各自直连

这是MCP普及初期的默认形态。每个AI客户端（聊天应用、IDE、命令行助手）独立加载自己的服务器配置，stdio服务器被各客户端分别拉起，HTTP服务器各自建立连接。它的优点是零新增组件、上手即用；缺点在规模化后集中爆发：三个客户端各拉起十个stdio进程是三十个进程；同一工具在A客户端已授权、在B客户端还要再授权一遍；日志分散，无法回答"今天AI到底对我的文件做了什么"。

- 适用：单一客户端、少量服务器、个人尝鲜阶段；
- 痛点阈值：当服务器数量超过五个或客户端超过两个时，维护成本陡增；
- 安全隐患：凭据分散在各客户端配置中，无法集中轮换与吊销。

## 二、拓扑二：单客户端独占网关

第二种形态是引入网关但只服务一个客户端。这看起来多此一举，实则有明确价值：当单个客户端需要接入大量服务器、或需要企业级策略（审计、脱敏、工具白名单）而客户端本身不具备时，网关成为策略挂载点。独占形态还常见于开发调试——工程师用网关做协议录制与回放，观察客户端与服务器之间的真实交互。此拓扑的配置管理收敛到网关一处，客户端配置只剩指向网关的一个条目。

## 三、拓扑三：多客户端共享本地网关

这是桌面场景的目标形态。网关以守护进程常驻，所有AI客户端统一接入网关端点。共享带来三个直接收益：进程唯一（同一stdio服务器全系统只有一份实例）、策略唯一（授权与审计一次性生效）、观测唯一（全系统的AI工具调用汇聚成一条时间线）。代价则是网关成为单点：它崩溃则全部客户端的MCP能力同时中断，因此必须配套监督进程、健康检查与自动重启。多客户端并存还引入了隔离问题——A客户端的会话不应看到B客户端的会话状态，网关要按客户端维度划分会话上下文。

```text
┌──────────┐ ┌──────────┐ ┌──────────┐
│ 聊天助手  │ │ IDE      │ │ 浏览器扩展│
└────┬─────┘ └────┬─────┘ └────┬─────┘
     │ stdio      │ HTTP       │ loopback HTTP
     └────────────┼────────────┘
                  ▼
        本地网关守护进程（唯一策略点）
        会话隔离 │ 能力聚合 │ 审计
     ┌──────┬────┴─────┬───────┐
     ▼      ▼          ▼       ▼
   文件    数据库     浏览器   远端API服务器
```

## 四、拓扑四：混合形态与迁移路径

真实桌面环境往往是混合的：本地工具（文件、剪贴板、窗口管理）走本地stdio上游；需要团队共享或集中管控的服务器（企业知识库、内部数据库代理）以Streamable HTTP上游的形式挂在远端，由本地网关统一代理。这样端侧数据不出机器，团队能力又有集中治理点。从直连迁移到共享网关的推荐路径分三步：先以旁路模式部署网关并录制现有配置；再迁移低风险服务器验证路由与审计；最后收编全部配置并从客户端删除直连条目。

选型判断可以浓缩为四问：客户端数量是否大于一；服务器总数是否超过五；是否需要集中审计与凭据管理；是否存在必须本地处理的敏感数据。两问以上答案为是，就应当考虑共享网关形态。

## 五、拓扑演化的隐性成本与降级设计

拓扑切换不只是搬配置，还牵动两块隐性成本。其一是客户端兼容成本：并非所有桌面AI客户端都支持自定义网关端点，部分客户端只认自己的配置格式与stdio直连；对这类客户端，网关需要提供"伪装服务器"模式——在客户端配置里把自己注册成一个普通stdio服务器，从而在客户端无感知的情况下完成收编。其二是回退成本：一旦网关故障且无降级路径，所有AI能力同时失效。稳妥的做法是保留直连配置的备份副本，网关提供一键导出"直连等价配置"的能力，紧急时刻可以快速回退到拓扑一，代价只是重新分散管理。

降级设计还有一层含义：网关内部的上游也应分故障域。文件系统这类本地工具与远端知识库这类网络工具，应挂在不同的连接池与不同的重试策略上，远端不可达时本地能力必须完好无损。把这条规则倒过来表述更清晰：任何上游的故障都不允许表现为网关整体的故障，客户端最多看到个别工具标记为不可用。这个要求会直接约束后文讨论的连接池分片与熔断设计。

## 六、小结与要点回顾

四种拓扑构成一条演进光谱：直连是起点，独占网关是策略过渡，共享网关是桌面终态，混合形态解决跨边界需求。拓扑选择本质上是把"策略放哪里、状态放哪里、故障域多大"三个问题的答案组合起来。本系列后续默认以共享本地网关为基准形态展开。

- 直连适合尝鲜，独占网关补策略，共享网关是目标态；
- 混合形态按数据敏感级切分本地与远端上游；
- 迁移走旁路录制、低风险试点、全量收编三步。
