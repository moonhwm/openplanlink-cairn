# 01 A2A安全总览：威胁模型与安全目标

> 主题域：A2A安全模型 / 认证选项 · 传输安全 · 跨组织信任。本篇为全领域总纲。

Agent-to-Agent（A2A）协议让不同供应商、不同框架构建的智能体能够互相发现能力、协商任务并交换结果。当协作跨越组织边界时，传统"内网即可信"的假设彻底失效：调用方是一个由大模型驱动、行为带有不确定性的程序实体，被调用方也可能是。安全设计必须从"边界防护"转向"每次交互都验证"。本篇给出A2A安全的第一张地图：攻击面在哪里、目标是什么、如何用系统工程方法覆盖。

## 一、A2A的六类攻击面

A2A的生命周期可以拆成发现、认证、协商、执行、回调五个阶段，每个阶段都有独立的攻击面。逐一盘点如下：

- 能力发现面：Agent Card（如 agent.json）通常通过公开 URL 获取，攻击者可伪造卡片、劫持域名或在卡片中夹带恶意指令描述，诱导调用方连接到假端点。
- 认证面：令牌伪造、令牌重放、密钥泄露、认证方案降级，都发生在凭据协商环节。
- 传输面：明文传输、弱 TLS 套件、证书校验缺失，导致会话被窃听或中间人篡改。
- 任务与会话面：可猜测的任务 ID、会话状态串扰、对象级越权访问（IDOR）。
- 回调面：Push Notification 向调用方注册的 Webhook 发送通知，注册环节若不校验，会成为 SSRF 与回调伪造的入口。
- 内容面：多部分请求携带文件，注入恶意负载；返回的制品（artifacts）可能包含提示词注入内容，影响下游 Agent 决策。

## 二、五项核心安全目标

针对上述攻击面，A2A安全体系要同时达成五项目标，缺一不可：

1. 身份可验证：通信双方都能确认对方身份，且身份与具体密钥或证书可绑定。
2. 机密性与完整性：传输通道加密，消息内容防篡改，必要时叠加消息级签名。
3. 委托可追溯：当 Agent 代表用户或代表另一个 Agent 行动时，委托链完整可审计，责任可归因。
4. 权限最小化：每个 Agent 只获得完成任务所需的最小能力，能力发现结果不等于授权结果。
5. 可运维与可恢复：密钥可轮换、信任可撤销、异常可检测、事件可溯源。

## 三、STRIDE威胁建模映射

用经典的 STRIDE 框架对 A2A 交互建模，可以得到一张清晰的对策清单：

| 威胁类别 | A2A中的典型表现 | 对策方向 |
| --- | --- | --- |
| 仿冒（S） | 伪造 Agent Card、盗用客户端凭据 | 强认证、卡片签名、mTLS |
| 篡改（T） | 中间人修改 JSON-RPC 请求 | TLS 1.3、消息签名 |
| 抵赖（R） | Agent 否认发起过某任务 | 审计日志、jti 与 trace 绑定 |
| 信息泄露（I） | 会话内容、文件被窃听 | 信道加密、日志脱敏 |
| 拒绝服务（D） | 高成本技能被滥用刷量 | 限流、配额、成本上限 |
| 权限提升（E） | 越权读取他人任务、scope 扩张 | 对象级授权、scope 收敛 |

## 四、纵深防御参考分层

单一控件无法覆盖全部威胁，A2A安全应按纵深防御组织。一个典型的分层控制结构如下：

```yaml
a2a_defense_layers:
  - layer: 边界与发现
    controls: [DNSSEC校验, AgentCard签名验证, 端点URL白名单]
  - layer: 传输
    controls: [TLS_1.3强制, mTLS可选, 证书自动轮换]
  - layer: 认证与授权
    controls: [OAuth2客户端凭据, JWT严格校验, 对象级授权]
  - layer: 应用与会话
    controls: [任务ID不可猜测, 幂等键, 速率限制]
  - layer: 观测与响应
    controls: [全链路trace, 行为异常检测, 密钥吊销通道]
```

## 五、小结与阅读路线

本系列后续四十七篇按"认证选项、传输安全、跨组织信任、授权与会话、运维治理"五个域展开，各域内部再按机制粒度细分，合起来对主题构成完整的MECE覆盖。工程实践时建议先固定威胁模型与安全目标（本篇），再按域选型控件，最后用第43篇的测试清单回归验证。安全是持续过程而非一次性交付，任何一层控件失效时，其余层仍应能显著提高攻击成本。
