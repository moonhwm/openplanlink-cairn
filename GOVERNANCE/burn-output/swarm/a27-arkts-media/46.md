# 46 · 播放异常兜底：错误分类、重试与格式降级

> 一句话摘要：异常兜底把播放失败组织为"分类—策略—降级—用户沟通"四层流水线：网络类有限重试回断点、格式类走替代源降级链、资源类释放重建、未知类收集现场上报，任何终点都不允许静默失败。

## 一、错误分类学

播放链路上的失败按可恢复性与归属分为五族。网络族：超时、DNS、连接重置、HTTP 4xx/5xx——特征是"内容没问题，通路有问题"，策略是指数退避重试并回断点。格式族：容器/编解码不支持（如某些冷门编码的 MKV、DTS 音轨）——重试无意义，策略是走替代源降级链或明确告知。资源族：解码器资源耗尽、内存不足、实例数超限——策略是释放其他实例后重建，往往伴随降级（关掉预加载池再试）。状态族：非法状态调用（5400102 类）——几乎都是自家时序 bug，策略是记录调用栈修代码，运行期容错为"忽略该命令"。数据族：文件损坏、fd 失效、本地缓存被清理——策略是重新下载或回源拉流。分类器输入错误码与消息特征，输出族标签；分类不确定时归"未知族"，走保守路径（释放重建一次）并上报现场。

## 二、兜底流水线实现

```typescript
export class FailurePipeline {
  private retry = 0;
  private readonly MAX_RETRY = 2;

  async onFailure(err: { code: number; message: string },
                  svc: PlayerService): Promise<void> {
    const family = this.classify(err);
    hilog.error(0x0, 'FB', `family=${family} code=${err.code}`);

    switch (family) {
      case 'network':
        if (this.retry < this.MAX_RETRY) {
          this.retry++;
          const backoff = 1000 * 2 ** (this.retry - 1);        // 1s, 2s
          await sleep(backoff);
          await svc.reopenAt(this.lastKnownPosition());        // reset换源+断点seek
          return;
        }
        await svc.notifyUser('网络不稳，请稍后重试', { retryable: true });
        break;
      case 'format':
        const alt = await this.findAlternative(this.currentItem);
        if (alt) { await svc.open(alt); break; }               // 降级链：备用编码/音源
        await svc.notifyUser('该格式暂不支持播放', { retryable: false });
        break;
      case 'resource':
        await svc.shrinkAndRebuild();   // 释放预加载池/多余实例后重建（第13篇）
        break;
      case 'data':
        await this.redownloadOrRefetch(this.currentItem);      // 回源
        break;
      default:
        await svc.shrinkAndRebuild();
        this.report({ err, state: svc.snapshot(), ts: Date.now() });
    }
    this.retry = 0;   // 成功打开新项后由svc重置
  }

  private classify(err: { code: number; message: string }): string {
    const m = err.message.toLowerCase();
    if (m.includes('network') || m.includes('timeout') || m.includes('http')) return 'network';
    if (m.includes('format') || m.includes('unsupported') || m.includes('codec')) return 'format';
    if (m.includes('no memory') || m.includes('resource')) return 'resource';
    if (m.includes('fd') || m.includes('file') || m.includes('source')) return 'data';
    return err.code === 5400102 ? 'state' : 'unknown';
  }
}
```

## 三、降级链设计与用户沟通

降级链是"同一内容的多技术形态"的有序尝试：高码率源→标准源；多音轨 MKV→单音轨 MP4 备源；视频版→纯音频版（内容型应用常见的最终降级，AVPlayer 换 AudioRenderer 语义或直接播音频流地址）；在线→本地缓存版本。链的每一级都是"上一级失败的退出路径"，需在内容分发层预登记（每个 assetId 挂替代列表），播放层只消费。用户沟通三原则：可重试的错误给按钮不给死路（"重试"点击走同一流水线并重置重试计数）；不可重试的错误给原因与建议（"该格式暂不支持，已为你切换音频版"）；一切错误在 UI 上有终态，绝不出现无限转圈或无声播放中。状态族的错误用户完全无感（内部忽略），但必须打点上报——它是缺陷的信号，不是可容忍的常态。

## 四、兜底检查清单

- [ ] 五族分类器覆盖真实错误样本，未知族走保守重建并上报。
- [ ] 网络重试指数退避 ≤2 次，断点来自常驻进度缓存（第11篇）。
- [ ] 格式族接内容层替代链，最终降级路径（如音频版）产品确认过。
- [ ] 资源族先收缩（释放预加载/多余实例）再重建，验证有效。
- [ ] 所有错误 UI 有终态：可重试/不可重试/自动降级三种呈现。
- [ ] 错误上报带脱敏现场（错误、状态快照、源特征），供归因聚合。

兜底保障"坏情况有出路"，最后一篇解决"好情况不浪费"：性能与内存优化。
