# 26 · 后台播放总体架构：长时任务 + AVSession + 播放器分层

> 一句话摘要：后台播放是"播放器内核、后台长时任务、AVSession 系统播控"三层协同的系统能力拼图，任何一层缺席都会表现为退后台即停、锁屏无控件或任务被回收。

## 一、三层各自解决什么问题

第一层是**播放内核**：AVPlayer 或 AudioRenderer 本身并不关心前后台，退后台后应用进程被冻结（挂起）才是声音中断的真正原因——进程一冻结，所有线程停摆，播放自然停止。第二层是**后台长时任务**（continuousTask，音频播放型）：向系统声明"我正在做用户可感知的音频播放"，换取应用在后台不被冻结、继续运行的资格；它解决的是"进程活着"。第三层是 **AVSession**（媒体会话）：把播放状态与元数据登记到系统媒体框架，使通知栏、锁屏、控制中心可以展示封面标题并下发控制命令；它解决的是"用户在后台可控、可见"。三层关系可以一句话概括：长时任务保命，AVSession 保体验，播放器保声音。只申请长时任务不做 AVSession，声音在但用户失去控制入口；只做 AVSession 不申请任务，锁屏控件几秒后随进程冻结而失效。

## 二、标准分层与职责边界

```typescript
export class BackgroundMusicService {
  private player?: media.AVPlayer;       // 层1：内核
  private session?: avSession.AVSession; // 层2：系统播控
  private taskRunning = false;           // 层3：长时任务状态

  async onPlayPressed(item: MediaItem) {
    await this.ensurePlayer(item);        // 内核就绪
    await this.session?.activate();       // 会话激活（详见第30篇）
    await this.startTask();               // 申请AUDIO_PLAYBACK长时任务（第28篇）
  }

  async onPausePressed() {
    await this.player?.pause();
    await this.syncPlaybackState();       // 状态回写AVSession（第32篇）
    await this.stopTask();                // 暂停即撤销任务，省电且合规
  }

  async onSessionCommand(cmd: 'play' | 'pause' | 'next') {
    // 层2命令统一路由回内核，保证单一事实源（第33篇）
    if (cmd === 'play') return this.onPlayPressed(this.current!);
    if (cmd === 'pause') return this.onPausePressed();
  }
}
```

职责边界三条铁律：其一，单一事实源——播放状态的唯一权威在内核层，UI 与 AVSession 都是它的视图，命令无论来自界面还是锁屏，都汇入同一个服务方法；其二，任务与播放状态强一致——任务的生命周期绑定"是否真的在出声"，播放暂停就撤任务，宁可重新申请也不要"无声保活"；其三，会话与元数据同源——AVSession 展示的标题封面来自媒体库/元数据层（第 15 篇），不要在会话层再维护一份拷贝。

## 三、完整数据流走读

以"用户点播放后锁屏，在锁屏按下一首"为例：①UI 调用 `onPlayPressed`：AVPlayer 设源并 prepare/play，同时业务层 `createAVSession` + `setAVMetadata` + `setAVPlaybackState(PLAY)` + `activate`，再 `startBackgroundRunning(AUDIO_PLAYBACK)`；②用户按电源键锁屏——因为长时任务在，进程不冻结，`timeUpdate` 继续更新，服务层按节流频率同步 `setAVPlaybackState` 的 position；③用户在锁屏点"下一首"——系统媒体框架把命令路由到该 AVSession 的 `playNext` 回调，服务层切歌（预加载实例接管，第 13 篇），更新元数据与状态，长时任务保持；④用户在锁屏点"暂停"——`pause` 命令进来，内核 pause、状态同步 PAUSE、撤销长时任务；此时进程可被冻结，会话仍显示在控制中心（历史会话），再点播放时命令仍能唤起服务并重新申请任务。

## 四、架构检查清单

- [ ] 三层封装在同一个服务对象中，对外暴露 play/pause/next/prev/seek 命令集。
- [ ] 长时任务申请/撤销与真实出声状态严格一致，无"无声保活"窗口。
- [ ] AVSession 命令与 UI 命令走同一条处理链路，不出现状态分叉。
- [ ] 锁屏/通知栏/控制中心三端真机验证控件与状态一致。
- [ ] 异常路径（错误、打断 STOP）下三层同步收尾。
- [ ] 服务随 Ability 生命周期规划重建路径（冷启动恢复播放态，见第35篇）。
