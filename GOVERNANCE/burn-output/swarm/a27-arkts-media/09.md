# 09 · AVPlayer 轨道管理：音轨/字幕/视频轨查询与切换

> 一句话摘要：多轨媒体（多语言音轨、内封字幕、多机位视频轨）通过 `getTrackDescription()` 查询、`selectTrack()/deselectTrack()` 切换，切换结果以 `trackChange` 事件确认。

## 一、轨道描述模型

一个多轨媒体文件在容器层可以同时封装备用轨道：若干条音频轨（国语、英语、评述）、若干条字幕轨（简中、英文字幕）、甚至多条视频轨（多角度）。AVPlayer 在 prepared 态之后可通过 `avPlayer.getTrackDescription(): Promise<Array<media.TrackDescription>>` 拉取轨道清单，每个 `TrackDescription` 是一个键值记录，核心字段包括：`trackIndex`（轨道序号，后续 selectTrack 的入参）、`trackType`（轨道类型，取值为 `media.MediaType` 枚举：视频/音频/字幕，数值以枚举常量为准，不建议硬编码数字）、以及描述性字段如语言 `language`、采样率 `sampleRate`、声道数 `channelCount`、码率 `bitRate`、分辨率 `width/height` 等（不同类型轨道暴露的字段集合不同）。查询必须在 prepared 之后进行，此前解封装未完成，清单为空或直接报非法状态。

## 二、查询与切换的标准流程

```typescript
interface TrackUI { index: number; type: 'audio' | 'subtitle'; label: string }

async loadTracks(player: media.AVPlayer): Promise<TrackUI[]> {
  const descs = await player.getTrackDescription();
  const ui: TrackUI[] = [];
  for (const d of descs as Record<string, Object>[]) {
    const idx = d['trackIndex'] as number;
    const t = d['trackType'] as number;
    const lang = (d['language'] as string) ?? '未知';
    if (t === media.MediaType.MEDIA_TYPE_AUD) {
      ui.push({ index: idx, type: 'audio', label: `音轨 ${lang}` });
    } else if (t === media.MediaType.MEDIA_TYPE_TXT) { // 字幕轨
      ui.push({ index: idx, type: 'subtitle', label: `字幕 ${lang}` });
    }
  }
  return ui;
}

async switchTrack(player: media.AVPlayer, index: number, on: boolean) {
  on ? await player.selectTrack(index) : await player.deselectTrack(index);
}
// 结果确认：
player.on('trackChange', (from: number, to: number) => {
  console.info(`轨道 ${from} -> ${to} 切换完成`);
});
```

## 三、切换行为细节与产品化要点

轨道切换是无缝的：切音轨不中断播放，画面继续；切换字幕即时生效。需要注意四点。第一，`trackChange` 事件参数携带轨道索引变化，UI 的选中态应以事件回写为准。第二，字幕轨的 `deselectTrack` 表示关闭内封字幕，此时若应用还叠加了自绘字幕（网络字幕、双语字幕），要同步隐藏，避免双字幕叠加。第三，默认轨道选择遵循容器声明，产品上通常提供"跟随系统语言"的默认策略：查询时读取 `language` 字段与系统 `i18n` 语言匹配，未命中再回落容器默认轨。第四，HLS 的多码率流不是"多视频轨"业务——码率自适应由播放服务内部调度，`getTrackDescription()` 返回的视频轨列表中可能看到它们，但手动 select 码率轨道的行为依版本实现而定，业务层不要把它当作"清晰度切换"接口来依赖；服务端提供独立多码率地址、应用层换源切换更可控（换源走 reset，保留进度 seek 回去）。

## 四、轨道管理检查清单

- [ ] prepared 之后才调用 `getTrackDescription()`，空清单时隐藏轨选入口。
- [ ] 轨道类型判断使用 `media.MediaType` 枚举常量，不硬编码数字。
- [ ] 切换结果以 `trackChange` 回写 UI；失败（不支持轨）时回退原选中态并提示。
- [ ] 字幕关闭同步隐藏自绘字幕层；双语字幕叠加场景单独设计。
- [ ] 默认轨策略：系统语言匹配 > 容器默认轨 > 第一条可用轨。
- [ ] 清晰度切换不依赖轨道接口，走"换源 + 断点 seek"闭环。

轨道能力是多语言内容、双语网课、演唱会多机位等场景的基础设施，配合 AVSession 的控制命令（第 33 篇）可以把"切轨"扩展到系统播控层。

## 五、实战问答与易错点

**问一：getTrackDescription 返回的字段名拼不确定，怎么稳健取值？** TrackDescription 是键值记录，取值统一走字符串键 + 类型断言 + 默认值的封装函数（如 readNum(d, 'trackIndex', -1)），不存在的键返回默认值而不是崩溃。语言字段还要做归一化（zh-CN/chi/zho 等变体映射到统一语言码）再与系统语言匹配，否则"明明有国语轨却匹配不上"的抱怨会反复出现。

**问二：切换音轨后音量变小或声道反了？** 两个独立问题。音量变化多因不同轨的响度差异（内容制作问题），应用侧可记录每轨的补偿增益做归一化；声道反了常是内容本身的声道排布与预期不符（评论轨左声道是解说），提供手动左右声道选择（第 6 篇/第 21 篇）比强行交换更稳妥。切换后要复核一次 audioInterrupt 状态，部分实现切轨会重建音频流导致焦点状态短暂变化。

**问三：字幕轨切换了但画面没字幕？** 先确认字幕类型：内封字幕（容器里的轨）走 selectTrack 生效；外挂字幕（网络 srt/ass）要走应用自绘层渲染，selectTrack 对它无意义。其次是编码问题，某些字幕轨编码异常时选择成功但渲染为空，视觉上要给"字幕开启但无内容"的状态一个可辨识的 UI（半透明提示），并提供切换其他字幕轨的快捷入口。

**问四：默认轨策略怎么写最稳？** 三级回落：系统语言精确匹配（含地区变体）> 系统语言主语言匹配（zh 任意变体）> 容器默认轨/第一条可用轨。再叠加用户显式选择记忆：用户手动选过的内容（按系列/频道维度）优先沿用其选择，全局默认仅作为无记忆时的入口。策略要在拉到轨道清单后立即执行一次选择，避免"第一秒是英文、两秒后跳中文"的观感。

**问五：trackChange 事件没触发，切换到底成功没有？** 以事件为准但要有超时对账：selectTrack 的 Promise 成功只代表命令受理，真正的生效信号是 trackChange；若 1~2 秒内无事件，主动重查 getTrackDescription 对比选中态（或听感/视觉验证）并重试一次。把"命令受理-事件确认-对账兜底"三段式作为轨道切换（以及一切异步媒体命令）的通用可靠性模式，它在 seekDone、speedChange 上同样适用。
