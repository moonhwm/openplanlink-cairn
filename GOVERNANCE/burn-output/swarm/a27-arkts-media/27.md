# 27 · 后台播放权限与 module.json5 配置详解

> 一句话摘要：后台播放的前置配置是 ability 上声明 `backgroundModes: ["audioPlayback"]` 并申请 `ohos.permission.KEEP_BACKGROUND_RUNNING`，网络源另需 INTERNET 权限，配置错位是"长时任务申请被拒"的第一排查点。

## 一、两份配置各管一段

后台播放的配置分布在 `module.json5` 的两个位置。第一处是 **ability 级的 backgroundModes**：Stage 模型下每个 UIAbility 可声明自己支持的后台模式，音频播放对应 `"backgroundModes": ["audioPlayback"]`，它告诉系统"这个 ability 具备在后台执行音频播放的能力类别"。第二处是 **requestPermissions 中的长时任务权限**：`ohos.permission.KEEP_BACKGROUND_RUNNING` 是申请长时任务的系统授权，属于 normal 级安装即授予，但仍必须显式声明，否则运行时 `startBackgroundRunning` 直接报权限错误。两处缺一不可：只声明 backgroundModes 不申请权限，运行时被拒；只申请权限不在 ability 上声明模式，任务类型校验不过。此外，sourceType 为网络时还需 `ohos.permission.INTERNET`；若播放的同时要写缓存到公共媒体目录，则涉及用户媒体目录权限体系，按需另配。

## 二、标准配置文件

```json
// module.json5
{
  "module": {
    "requestPermissions": [
      {
        "name": "ohos.permission.KEEP_BACKGROUND_RUNNING",
        "reason": "$string:bg_task_reason",
        "usedScene": { "abilities": ["EntryAbility"], "when": "inuse" }
      },
      {
        "name": "ohos.permission.INTERNET",
        "reason": "$string:net_reason",
        "usedScene": { "abilities": ["EntryAbility"], "when": "always" }
      }
    ],
    "abilities": [
      {
        "name": "EntryAbility",
        "srcEntry": "./ets/entryability/EntryAbility.ets",
        "backgroundModes": ["audioPlayback"]
      }
    ]
  }
}
```

`string.json` 中补齐 reason 文案（如 `bg_task_reason: "用于在后台继续播放音频"`），这是应用市场审核可见的用户解释，措辞要具体到功能而非泛泛的"需要权限"。usedScene 的 when 值（inuse/always）描述使用时机，按实际播放场景填写。

## 三、常见配置病症与排查

病症一：`startBackgroundRunning` 报 201 权限错误——排查 requestPermissions 是否遗漏 KEEP_BACKGROUND_RUNNING，或拼写错误（该权限名必须逐字符精确）。病症二：任务申请成功但退后台仍被冻结——排查 backgroundModes 是否声明在正确的 ability 上（多 ability 工程容易配到非播放 ability），以及申请任务时传入的 context 是否属于该 ability。病症三：升级/多目标产物（多 HAP）下时灵时不灵——确认配置落在真正承载播放服务的模块的 module.json5 中，_feature_ 模块与 entry 模块的权限声明作用域不同。病症四：市场审核被拒——backgroundModes 声明了但应用内无可感知的音频功能，或 reason 文案空泛；模式声明必须与真实功能对应。病症五：HTTP 流播放失败——INTERNET 已配但明文 http 被安全策略拦截，需检查网络明文传输策略（第 3 篇）。

## 四、配置检查清单

- [ ] ability 上声明 `backgroundModes: ["audioPlayback"]`，位置在正确模块。
- [ ] requestPermissions 含 KEEP_BACKGROUND_RUNNING，reason 文案具体。
- [ ] 网络播放含 INTERNET；明文 http 评估明文传输策略。
- [ ] 多 ability/多 HAP 工程逐一核对声明归属。
- [ ] 配置改动后执行全量卸载重装验证（增量更新偶有权限缓存干扰）。
- [ ] 把配置项纳入代码评审检查表，防止新模块拆分时被遗漏。

配置是后台播放的"准入证"，下一篇进入运行时：用 backgroundTaskManager 真正把长时任务申请下来。
