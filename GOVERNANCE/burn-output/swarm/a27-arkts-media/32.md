# 32 · AVSession 播放状态同步：state/position/speed/bufferedTime

> 一句话摘要：`setAVPlaybackState` 承担"播放器状态向系统播控的持续镜像"，position 携带 elapsedTime 与 updateTime 双字段让系统外推进度，同步节律（事件驱动 + 秒级心跳）与暂停态的准确快照是两大纪律。

## 一、状态对象与外推机制

`AVPlaybackState` 的字段：`state`（`avSession.PlaybackState.PLAYBACK_STATE_PLAY / PAUSE / STOP / BUFFERING / COMPLETED` 等枚举）；`speed`（当前倍速，与第 5 篇联动）；`position`（`{ elapsedTime, updateTime }`，已播毫秒数与该快照的生成时刻）；`bufferedTime`（已缓冲可播毫秒数，来自第 3 篇的 CACHED_DURATION）；`loopMode`/`isFavorite`（循环与收藏偏好）。position 的双字段设计是理解同步机制的关键：系统不需要应用每 100ms 上报一次进度，只需要在"关键时点"（播放、暂停、seek 完成、切歌）给出 (位置, 时刻) 快照，播放中的进度由系统按 `(now - updateTime) × speed + elapsedTime` 自行外推。这既降低通信频率，又保证锁屏进度条平滑。反之，若 updateTime 语义用错（填 0 或填未来时刻），进度条会狂奔或冻结。

## 二、同步器实现

```typescript
import { avSession } from '@kit.AVSessionKit';

export class StateSync {
  constructor(private s: avSession.AVSession) {}

  private async push(state: avSession.PlaybackState, player: media.AVPlayer) {
    await this.s.setAVPlaybackState({
      state,
      speed: this.currentSpeed,                     // 倍速联动（第5篇）
      position: {
        elapsedTime: player.currentTime,            // 毫秒
        updateTime: new Date().getTime()            // 快照时刻，系统据此外推
      },
      bufferedTime: this.bufferedMs,                // 缓冲镜像（第3篇）
      loopMode: this.loopMode
    });
  }

  async onPlay(player: media.AVPlayer)   { await this.push(avSession.PlaybackState.PLAYBACK_STATE_PLAY, player); }
  async onPause(player: media.AVPlayer)  { await this.push(avSession.PlaybackState.PLAYBACK_STATE_PAUSE, player); }
  async onSeekDone(ms: number, player: media.AVPlayer) {
    await this.push(avSession.PlaybackState.PLAYBACK_STATE_PLAY, player);  // position用最新值
  }
  async onBuffering(on: boolean, player: media.AVPlayer) {
    await this.push(on ? avSession.PlaybackState.PLAYBACK_STATE_BUFFERING
                       : avSession.PlaybackState.PLAYBACK_STATE_PLAY, player);
  }
}
```

## 三、同步节律与边界处理

节律设计遵循"事件优先、心跳兜底"：stateChange（play/pause/completed）、seekDone、缓冲起止都即时推送；另加一个 3~5 秒的低频心跳重推快照，纠正长时间播放后的外推漂移（倍速、直播等场景漂移更明显，心跳可加密到 2 秒）。边界处理四条：其一，暂停态的快照必须准——暂停后再点锁屏播放，系统从最后 position 续推，若暂停快照错了 10 秒，恢复即跳变；其二，BUFFERING 状态要显式切换，否则弱网时锁屏进度条停在半路无解释；其三，completed 态推送后 position 归零语义按产品定（自动连播时直接切元数据 + PLAY）；其四，速度变化必须与 position 同帧推送，否则外推系数错、进度条与声音越漂越远。

## 四、状态同步检查清单

- [ ] 关键时点（play/pause/seekDone/buffering/切歌）即时推送快照。
- [ ] position 双字段语义正确：elapsedTime 毫秒 + updateTime 当前时刻。
- [ ] 3~5 秒心跳重推；直播/倍速场景加密心跳。
- [ ] 倍速变化与 position 同帧更新，防外推漂移。
- [ ] 暂停快照精度真机验证：暂停→恢复无进度跳变。
- [ ] 弱网注入测试：BUFFERING 显隐及时，恢复后进度正确。
