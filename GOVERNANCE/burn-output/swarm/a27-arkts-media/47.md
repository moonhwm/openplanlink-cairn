# 47 · 播放性能优化：内存、Surface 复用、预加载与省电

> 一句话摘要：播放性能优化沿四条线推进——内存（封面 LRU、实例上限、PixelMap 释放）、渲染（Surface 复用不重建、按需绑定）、调度（预加载与心跳节流）、电量（后台收缩非必要活动），每条线都要有可测指标。

## 一、内存治理

播放类应用的内存大头依次是：封面位图、播放器实例（解码器缓冲）、进度/歌词数据结构。治理手段：封面解码统一限制尺寸（desiredSize 到列表展示尺寸，第 31 篇）并用 LRU 缓存（上限按页面可见数 + 预取数设定，典型 12~24 张），列表大量滚动时命中率与峰值双达标；PixelMap 用完释放，传给 AVSession 后确认持有策略；播放器实例总数设硬上限（当前 1 + 预加载 1，视频场景警惕"列表页每项一实例"的反模式，改为单激活+按需建）；长音频的波形/歌词数据分页加载，不整文件进内存。度量方式：DevEco Profiler 的内存曲线跑"连续切歌 30 次""列表滚动 5 分钟"两个脚本，观察稳态与回撤。

## 二、渲染与调度优化

渲染线的核心原则是"Surface 生命周期 ≥ 页面切换节奏，但 ≤ 播放会话"：小窗/全屏/迷你页间切换复用同一 XComponent 树或至少同一 surfaceId（第 7 篇），全屏切换只动布局属性；页面不可见（onPageHide）时视频可降级为纯音频播（视频链路释放，按产品定）或保持；解码器在多实例视频场景按"仅激活项拥有"调度。调度线即预加载纪律（第 13 篇）：下一首预加载到 prepared、Wi-Fi 才预取大文件、切向改变立即释放旧预加载。此外把高频回调变低频：timeUpdate 驱动的 UI 刷新节流到 500ms~1s；AVSession 状态同步走"关键时点+3 秒心跳"（第 32 篇）而不是每秒推送；日志在 release 构建里关闭 debug 级音频回调打点。

## 三、优化决策表

| 优化项 | 手段 | 收益指标 | 风险与约束 |
|---|---|---|---|
| 封面内存 | 尺寸限制+LRU | 滚动峰值内存降幅 | 过小导致大屏模糊，按密度分级 |
| 实例上限 | 单激活+预加载1 | 连续切歌内存平稳 | 预加载失效要有降级切换 |
| Surface 复用 | 布局切换不重建 | 全屏切换无黑帧 | 注意组件树结构约束 |
| 预加载 | prepared 待命 | 切歌接管耗时 | 流量策略与弱网开关 |
| 心跳节流 | 3s+关键时点 | 后台 CPU 占用 | 进度外推漂移可控 |
| 后台收缩 | 停 UI 刷新/降日志 | 后台耗电曲线 | 前台恢复时全量恢复 |

## 四、性能验证检查清单

- [ ] 内存脚本：连续切歌 30 次、列表滚动 5 分钟，曲线平稳无锯齿上涨。
- [ ] 耗电脚本：前台播放、后台播放、后台暂停三态分测并达标。
- [ ] 切歌 P90 接管耗时指标建立（预加载命中/未命中两条基线）。
- [ ] 全屏/小窗切换录屏验证无黑帧、无进度跳变。
- [ ] 高频回调（timeUpdate/bufferingUpdate/volumeChange）节流审计。
- [ ] 低端机型（小内存）专项回归：实例收缩策略生效、无 OOM。

性能优化的原则是"先测量后优化、每项优化绑定一个指标"，避免为不可感知的收益增加复杂度；所有优化都不得改变第 45 篇架构的状态语义。
