# 20 · AudioRenderer 低时延播放模式与回调驱动调优

> 一句话摘要：低时延由"低时延渲染标志 + 约束参数（典型 48kHz/2ch/16bit）+ writeData 回调驱动 + 紧凑块尺寸"共同达成，目标是把"样本生成到出声"的端到端延迟压到几十毫秒级。

## 一、时延的构成与可压空间

端到端音频时延由四段叠加：应用生成样本的处理时延、写入/回调的供数时延、系统音频缓冲区深度（最的大头，通常数十至数百毫秒）、硬件输出通路时延。应用能直接施加影响的是中间两段：供数模式改用 writeData 回调可以消除应用自行定时的抖动；系统缓冲深度则依赖创建参数中的低时延渲染标志（`rendererInfo.rendererFlags` 置为低时延标志位，配合版本支持的 `audio.LowLatencyMode` 相关能力，具体枚举以所用 API 文档为准）压缩内部缓冲。开启低时延能力通常伴随格式约束：典型为 48000Hz、双声道或单声道、S16LE，且要求使用回调供数模式——低时延通道下缓冲余量极小，主动 write 的节奏抖动会直接转化为欠载爆音。

## 二、低时延链路的组装

```typescript
export async function createLowLatency(): Promise<audio.AudioRenderer> {
  const opts: audio.AudioRendererOptions = {
    streamInfo: {
      samplingRate: audio.AudioSamplingRate.SAMPLE_RATE_48000,   // 低时延推荐48k
      channels: audio.AudioChannel.CHANNEL_2,
      sampleFormat: audio.AudioSampleFormat.SAMPLE_FORMAT_S16LE,
      encodingType: audio.AudioEncodingType.ENCODING_TYPE_PCM
    },
    rendererInfo: {
      usage: audio.StreamUsage.STREAM_USAGE_GAME,                // 游戏返听类语义
      rendererFlags: 1                                           // 低时延标志（以文档为准）
    }
  };
  const r = await audio.createAudioRenderer(opts);

  // 预生成一小段就绪块，再启动，避免首拍欠载
  this.preRoll(4);                       // 预备4个块的静音/头部数据
  r.on('writeData', (buf: ArrayBuffer) => {
    const out = new Int16Array(buf);
    const block = this.readyQueue.shift();
    if (block) out.set(block.subarray(0, out.length));
    else out.fill(0);                    // 兜底静音
    if (this.readyQueue.length < 2) this.kickSynthThread();   // 欠产催促
  });
  await r.start();
  return r;
}
```

## 三、调优手段与度量

第一，块尺寸权衡：块小则时延低但回调频率高、抖动敏感；块大则相反。低时延链路通常接受系统给定的回调块尺寸，业务侧重在"永远有就绪块"。第二，预滚（pre-roll）：start 前在队列里垫 2~4 个块，吸收启动瞬间的合成抖动。第三，生产者优先级：合成/解码线程避免与渲染回调争抢锁，队列用无锁或轻锁实现，回调内禁止日志、内存分配（复用 ArrayBuffer 池）。第四，度量闭环：记录每次回调时队列深度与静音兜底次数，"静音兜底率"是低时延链路最核心的质量指标；在开发者选项/Profiler 中观察线程调度，确认回调没有长尾阻塞。第五，降级预案：设备不支持低时延或欠载率超标时，自动退回常规模式（重建实例，rendererFlags=0，块尺寸放大），宁可时延高一点也不要持续爆音。

## 四、低时延检查清单

- [ ] 确认设备/系统版本支持低时延能力，不支持时走常规模式并记录。
- [ ] 参数满足约束（典型 48k/S16LE），rendererFlags 按文档设置。
- [ ] 供数一律 writeData 回调；主动 write 不与低时延混用。
- [ ] start 前预滚 2~4 块；回调内零锁、零日志、零分配。
- [ ] 监控静音兜底率与队列水位，超标自动降级重建。
- [ ] 真机横评目标机型时延（拍手回路/示波器法），形成机型档案。

低时延是"参数+模式+纪律"的三合一工程，缺一环就会退化为普通时延或爆音链路，其回调供数基建与第 19 篇完全复用。
