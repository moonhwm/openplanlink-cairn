# 07 · AVPlayer 视频渲染：XComponent 与 surfaceId 关联

> 一句话摘要：视频画面渲染走独立 Surface 通路，ArkUI 侧通过 XComponent（Surface 类型）获取 `surfaceId` 并在 prepared 态之前绑定给 AVPlayer，绑定时机与生命周期管理决定视频能否正常出画。

## 一、视频渲染链路与 Surface 的角色

AVPlayer 的音频走音频服务输出，视频画面则走渲染合成通路：解码器输出的帧被推送到一块与显示系统直通的 Surface 上，ArkUI 通过 XComponent 组件在自己的布局区域内"开窗"显示这块 Surface 的内容。因此视频播放的三要素是：布局中放置一个 Surface 类型的 XComponent；从该组件拿到 `surfaceId`（一个数字句柄）；把它赋给 `avPlayer.surfaceId`。三者的时序约束是：surfaceId 必须在 AVPlayer 进入 prepared 态之前完成绑定，也就是在 `prepare()` 调用前或 initialized 态时设置；绑定太晚解码器找不到渲染目标，画面表现为黑屏但声音正常，这是视频类应用第一大高频缺陷。XComponent 自身的 surface 就绪也是异步的（组件挂载、布局完成后才创建底层 Surface），所以取 surfaceId 必须在其 surfaceReady 回调里进行，不能在 aboutToAppear 里同步取。

## 二、ArkUI 声明式绑定完整示例

```typescript
import { media } from '@kit.MediaKit';
import XComponentController from '...'; // 依工程导入路径

@Entry
@Component
struct VideoPage {
  private xctl = new XComponentController();
  private avPlayer?: media.AVPlayer;

  build() {
    Column() {
      XComponent({
        id: 'videoSurface',
        type: XComponentType.SURFACE,       // Surface 类型用于视频
        libraryname: ''
      })
        .controller(this.xctl)
        .onLoad(() => {
          // XComponent底层surface就绪：此刻才能安全取surfaceId
          const surfaceId = this.xctl.getXComponentSurfaceId();
          this.bindPlayer(surfaceId);
        })
        .width('100%').height(211)          // 16:9 示例
    }
  }

  async bindPlayer(surfaceId: string) {
    this.avPlayer = await media.createAVPlayer();
    this.avPlayer.url = this.itemUrl;
    this.avPlayer.on('stateChange', async (state: string) => {
      if (state === 'initialized') {
        this.avPlayer!.surfaceId = surfaceId;   // 关键：prepare之前绑定
        await this.avPlayer!.prepare();
      } else if (state === 'prepared') {
        await this.avPlayer!.play();
      }
    });
  }

  aboutToDisappear() {
    this.avPlayer?.release();               // 页面销毁回收，防止surface悬空
  }
}
```

## 三、生命周期错配的四种典型病症与处方

第一种：黑屏有声。surfaceId 绑定晚于 prepared，处方是把绑定动作放进 initialized 分支（如上）并在绑定后再 prepare。第二种：从播放页返回再进入黑屏。旧实例未 release，旧 Surface 已销毁，新实例拿到的 surfaceId 指向已失效窗口，处方是 aboutToDisappear 强制 release 并置空引用，页面每次进入都新建实例。第三种：小窗/全屏切换闪烁。切换本质是布局变化，Surface 本身可以跟随组件移动缩放，不需要重建播放器；若实现为"销毁重建"就会闪黑并丢进度，处方是只改 XComponent 的宽高与位置，保持 surfaceId 不变。第四种：列表内多个视频同时出画异常。一个 surfaceId 只能绑定一个解码输出，多路视频必须多个 XComponent、多个 AVPlayer 实例，并以"仅激活项播、其余 pause/stop"策略控制资源（第 47 篇展开）。

## 四、渲染绑定检查清单

- [ ] surfaceId 在 `getXComponentSurfaceId()`（onLoad/surfaceReady 后）获取，不在 aboutToAppear 同步取。
- [ ] 绑定顺序固定：设 url → initialized 态设 surfaceId → prepare。
- [ ] 页销毁/组件卸载路径 release 播放器，防句柄泄漏与悬空 Surface。
- [ ] 全屏/小窗切换只改布局不重建实例，surfaceId 保持复用。
- [ ] 多视频列表采用"单实例激活 + 预加载下一项"的资源策略。
- [ ] 视频区域外层容器避免嵌套 `borderRadius` 裁剪异常问题，必要时用 `clip(true)` 验证各版本表现。

Surface 通路打通后，画面尺寸适配（videoSizeChange）与轨道切换等渲染进阶能力才有落点，分别在下一篇与第 9 篇展开。

## 五、实战问答与易错点

**问一：onLoad 里取 surfaceId 与 getXComponentSurfaceId 时序哪个对？** 以 onLoad（surface 就绪回调）为准。XComponent 的底层 Surface 在组件完成挂载布局后才创建，aboutToAppear 阶段组件树尚未提交渲染，取值可能为空或无效。若日志显示 surfaceId 拿到了但画面仍黑屏，下一步核对的就是绑定时机（必须在 prepare 之前）与该 surfaceId 所属的组件实例是否就是当前页面这一块——路由复用场景下拿到旧页面的 surfaceId 也会黑屏。

**问二：从列表页进详情页，视频要在两个页面"无缝"继续，怎么做？** 首选方案是组件复用而不是播放器重建：把 XComponent 连同播放器一起放在持久的容器层（比如页面栈之上的覆盖层），详情页只是改变它的布局位置与尺寸，surfaceId 始终不变。次选方案是两个 XComponent 之间迁移：新页面组件就绪后，用 reset 回 idle 重新绑定新 surfaceId 再 prepare 恢复进度，能接受短暂黑帧。无论哪种，都不要走"销毁重建播放器"的路线，进度与缓冲全丢。

**问三：Surface 上叠加弹幕、水印层会不会影响性能？** 叠加层走 ArkUI 渲染树，与视频 Surface 是两个合成层，功能上互不影响；性能上的注意点是叠加层自身的刷新开销——弹幕高频重绘时要控制刷新区域（局部刷新）与频率（合并到动画帧），避免整层无效重绘把 GPU 拉高。水印类静态层设置一次即可，不要放进高刷容器。

**问四：视频播放后台返回后画面冻结几秒才恢复？** 通常是退后台期间解码管线暂停、回前台后需要追帧。系统通路本身会处理恢复，应用能做的是不要在前后台切换时做多余动作：不要 onBackground 就 release、onForeground 又重建（除非产品如此定义），保持实例存活让通路自行恢复；确实要省资源的场景，退后台转"纯音频继续播+视频暂停渲染"策略由产品权衡。

**问五：多窗口/分屏下视频比例异常？** 分屏改变可用区域，onAreaChange 会触发重排，此时要重新计算宽高比与裁剪策略（第 8 篇），并验证 Surface 内容是否随组件正确缩放。个别版本下分屏过渡动画期间的 Surface 尺寸会经历中间态，布局逻辑要做去抖，以稳定后的最终尺寸为准做一次适配即可。
