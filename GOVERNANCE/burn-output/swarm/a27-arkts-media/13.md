# 13 · AVPlayer 实例池与预加载设计

> 一句话摘要：切歌速度的瓶颈在 prepare 而非网络，通过"预加载下一首到 prepared 态"与"小容量实例池 LRU 复用"可把换源耗时从秒级压到百毫秒级，代价是可控的内存与解码器占用。

## 一、为什么需要预加载与实例池

用户对切歌的耐心阈值约在 1 秒上下，而一次完整的"reset → 设源 → prepare → play"串行链路在普通网络下耗时 1~3 秒，其中 prepare（建流、解封装、解码器初始化）占大头。压缩思路有两条：其一是**预加载**——在当前曲目还在播放时，提前为下一首创建实例并推进到 prepared 态，切歌时只需对旧实例 release、对新实例 play，耗时接近零；其二是**实例池**——播放器创建本身也有几十毫秒开销，保留 1~2 个热实例循环复用（reset 换源），避免反复 createAVPlayer。两者结合即"池中常备当前实例 + 预加载实例"，是音乐、播客、短视频应用的标准性能设计。

## 二、双实例预加载切换器实现

```typescript
export class PreloadSwitcher {
  private current?: media.AVPlayer;
  private preload?: media.AVPlayer;     // 已prepare好的下一首
  private pendingUrl?: string;

  async prime(nextUrl: string, surfaceId?: string) {
    if (this.pendingUrl === nextUrl) return;          // 已在预加载同一首
    await this.releasePreload();
    const p = await media.createAVPlayer();
    p.url = nextUrl;
    if (surfaceId) p.surfaceId = surfaceId;           // 视频：提前绑定surface
    p.on('stateChange', async (s) => {
      if (s === 'prepared') { /* 停在prepared待命，不play */ }
    });
    this.preload = p;
    this.pendingUrl = nextUrl;
  }

  async switchTo(): Promise<boolean> {
    if (!this.preload) return false;
    const old = this.current;
    this.current = this.preload;                       // 立即接管
    this.preload = undefined;
    this.pendingUrl = undefined;
    await this.current.play();                         // 百毫秒内出声
    old?.release();                                    // 旧实例异步回收
    return true;
  }

  private async releasePreload() {
    if (this.preload) { await this.preload.release(); this.preload = undefined; }
  }
}
```

## 三、容量、时机与失效策略

预加载容量建议恒为 1（当前 + 下一首），至多 2（下下首），再多只会徒增解码器与内存压力，系统在低内存时也可能回收后台解码资源导致预加载失效。触发时机优先级：当前曲目剩余时长低于阈值（如 30 秒）时启动、用户点击列表"下一首"前、列表滚动减速停留在某项超过 1 秒。失效与刷新：用户手动跳转到非预加载曲目时，立即 release 预加载实例再 prime 新目标；播放模式是随机时按"随机序列的下一位"预加载；网络从 Wi-Fi 切到蜂窝时，大文件预加载应评估流量策略（播客类应用通常询问用户）。视频场景的预加载必须同步传递当前可用的 surfaceId（第 7 篇），否则切过去黑屏。同时要防止"预加载实例错误未处理"：它同样要挂 error 监听，错误即从池中剔除并重建。

## 四、预加载与实例池检查清单

- [ ] 池容量上限 2~3，超限按 LRU release，杜绝"每首歌一个新实例"。
- [ ] 预加载停在 prepared 态，不提前 play，不提前申请焦点。
- [ ] 切换方向变化（用户改选）时先 release 旧预加载再 prime 新目标。
- [ ] 预加载实例同样注册 error/audioInterrupt 监听，带病实例不入池。
- [ ] 视频预加载传递有效 surfaceId；页面销毁时连预加载一起回收。
- [ ] 弱网/蜂窝下预加载遵循流量策略，失败静默降级为普通切换。
- [ ] 压测指标：连续切换 20 次的平均接管耗时与内存峰值平稳。

实例池是纯客户端优化，与服务端预取（提前下载到沙箱再本地播）叠加后，切歌体验可以做到"无感"，该模式将在第 47 篇性能专题中与内存治理合并收口。
