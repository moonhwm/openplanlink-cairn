# 41 · 音频输出设备管理：getDevices 与设备变更监听

> 一句话摘要：`AudioRoutingManager` 的 `getDevices`/`on('deviceChange')` 提供输出设备清单与变化流，应用据此展示"当前声音从哪出"、预判路由切换并做设备能力适配，是音频设置页与播放兜底的基础设施。

## 一、设备模型与查询入口

系统音频路由层维护一张设备表：每台设备由 `DeviceDescriptor` 描述，核心字段 `deviceType`（扬声器 SPEAKER、有线耳机 WIRED_HEADPHONES/HEADSET、蓝牙 A2DP、USB 等）、`id`、`displayName`（可展示名）。查询入口在 `audio.getAudioManager().getRoutingManager()`：`getDevices(audio.DeviceFlag.OUTPUT_DEVICES_FLAG)` 返回当前可用输出设备集合（同步方法 getDevicesSync 依版本提供）；`on('deviceChange', flag, cb)` 订阅变化，回调携带本次新增/移除的设备描述集合；配套 `isDeviceActive` 类查询（按版本）判断某设备当前是否激活。注意查询语义是"设备在不在/活不活"，而"我的声音实际走哪台"由路由策略与流用途共同决定——媒体流跟随系统默认路由，通话流走独立通信设备通道（第 42 篇），两者不要混为一谈。

## 二、设备面板与监听实现

```typescript
import { audio } from '@kit.AudioKit';

export class DevicePanel {
  private routing = audio.getAudioManager().getRoutingManager();

  listOutputs(): audio.AudioDeviceDescriptor[] {
    return this.routing.getDevices(audio.DeviceFlag.OUTPUT_DEVICES_FLAG);
  }

  describe(d: audio.AudioDeviceDescriptor): string {
    switch (d.deviceType) {
      case audio.DeviceType.SPEAKER:         return `扬声器（${d.displayName ?? '本机'}）`;
      case audio.DeviceType.WIRED_HEADPHONES:
      case audio.DeviceType.WIRED_HEADSET:   return `有线耳机`;
      case audio.DeviceType.BLUTOOTH_A2DP:   return `蓝牙音频（${d.name ?? d.displayName ?? ''}）`;
      default:                               return `其他输出（${d.deviceType}）`;
    }
  }

  watch(cb: (summary: string, hasHeadset: boolean) => void): void {
    this.routing.on('deviceChange', audio.DeviceFlag.OUTPUT_DEVICES_FLAG,
      (descs: audio.DeviceChange) => {
        const all = this.listOutputs();
        const hasHeadset = all.some(d =>
          d.deviceType === audio.DeviceType.WIRED_HEADPHONES ||
          d.deviceType === audio.DeviceType.BLUTOOTH_A2DP);
        cb(all.map(d => this.describe(d)).join(' / '), hasHeadset);
      });
  }
}
```

## 三、工程应用与坑位

应用一：播放页的输出指示。展示"正在通过蓝牙播放"并允许用户跳系统设置切换，比应用内自造切换逻辑更稳（媒体路由尊重系统策略，第 42 篇详述边界）。应用二：能力适配。检测到蓝牙/耳机时启用高音质档位（高采样率内容），仅扬声器时提示或调整，避免在受限通道上浪费解码资源。应用三：事件兜底联动。deviceChange 与第 36 篇的打断双通道配合，做拔出暂停、接入提示。坑一：回调只携带本次变化的设备，做全量展示要重新 `getDevices` 拉清单。坑二：蓝牙设备的上线/下线往往先出现在系统蓝牙层、后反映到音频路由，短暂延迟属正常，UI 做去抖（500ms）再刷新。坑三：模拟器设备模型有限（常只有扬声器），设备矩阵验证必须真机覆盖有线、蓝牙、USB 声卡。坑四：监听要成对 off（页面销毁时），否则回调持有页面闭包造成泄漏。

## 四、设备管理检查清单

- [ ] 展示层用"全量 getDevices + 变化触发重拉"模式，不依赖回调增量拼状态。
- [ ] 设备类型映射到用户可读名称，未知类型兜底展示。
- [ ] UI 刷新去抖 500ms；监听随页面销毁 off。
- [ ] 能力适配策略（音质档位）与设备类型挂钩且有默认回退。
- [ ] 与打断/焦点通道的事件去重（第 36 篇时间窗）。
- [ ] 真机设备矩阵：扬声器、有线、蓝牙 A2DP、车载至少各一。
