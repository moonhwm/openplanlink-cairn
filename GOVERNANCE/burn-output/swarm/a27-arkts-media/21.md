# 21 · AudioRenderer 音量、速率与音频属性控制

> 一句话摘要：AudioRenderer 提供 `setVolume` 实例音量、`setRenderRate` 变速渲染、声道模式与静音混音开关等实例级属性，全部只在合法状态下生效且与系统流音量叠加作用。

## 一、实例音量 setVolume

`renderer.setVolume(volume: number)` 与 AVPlayer 的同名 API 语义一致：仅作用于本实例，范围 0.0~1.0（越界报参数错误），与系统流音量是相乘叠加关系。典型用途有三：游戏里"音效音量/音乐音量"分离的设置项（音效走 AudioRenderer、音乐走 AVPlayer，各自实例音量独立持久化）；界面切换时对 UI 音做淡出；混音总线下按类别加权。注意点：音量设置在 pause/stop 后保持，但实例 release 重建后回到默认 1.0，业务要在重建后重新应用用户设置；连续快速调节（滑条拖动）建议本地节流到 50~100ms 一次，避免命令风暴。

## 二、变速渲染 setRenderRate

`renderer.setRenderRate(rate: audio.AudioRendererRate.RENDER_RATE_NORMAL / RENDER_RATE_DOUBLE 等)` 改变 PCM 的消费速率：不做音高补偿的"快放/慢放"——速率翻倍时同一段数据在一半时间内播完、音调升高，这与 AVPlayer 的不变调变速本质不同。适用场景：语音备忘 1.x 倍速速听（人声稍变调可接受）、快进扫描式回放、彩蛋变速效果。需要不变调的听书倍速应回到 AVPlayer（第 5 篇）。配套接口 `getRenderRate()` 查询当前速率；变速后播放进度估算必须按速率折算：`已播时长 = 已写字节 / 每秒字节 / rate`，否则进度条与真实听感脱节。

## 三、声道模式与静音混音

声道控制解决"立体声内容只想要单边/混单"的需求：通过 `setAudioChannelMode(audio.AudioChannelMode.CHANNEL_MODE_LEFT / RIGHT / BOTH...)`（以版本 API 为准）可以将双声道输出切换为仅左、仅右或混合模式，适合单边耳机听双语广播（左国语右粤语，用户选边）、单声道外设适配等场景。另一组实用能力是静音开关联动：`setSilentModeAndMixWithOthers(on: boolean)`（如版本提供）允许实例在系统静音模式下仍与其他应用混音播放，导航、跑步提示类"必须出声"的短音频常用它避免被静音开关完全消音。两者都属于实例级属性，同样受状态约束，且在打断恢复（第 22 篇）后需要复核是否保持。

```typescript
export async function applyVoicePrefs(r: audio.AudioRenderer) {
  await r.setVolume(0.8);                    // 用户音效音量设置
  await r.setRenderRate(audio.AudioRendererRate.RENDER_RATE_DOUBLE);
  hilog.info(0x0, 'AR', `rate=${await r.getRenderRate()}`);
}
```

## 四、实例属性检查清单

- [ ] 音量参数 clamp 到 [0,1]；用户设置持久化，实例重建后重放。
- [ ] 倍速用 setRenderRate 前确认"可变音调"产品上可接受，否则用 AVPlayer。
- [ ] 变速后进度估算公式带 rate 折算项，UI 与听感一致。
- [ ] 声道模式切换与耳机物理布局核对，双语单边场景做真机验证。
- [ ] 静音混音开关仅用于必须出声的短提示，尊重系统静音的默认语义。
- [ ] 打断恢复回调里复核音量/速率/声道三属性，防静默丢失。

实例属性是产品体验的"细粒度旋钮"，它们全部叠加在系统策略之上——真正的系统级交互（焦点、路由、系统音量）在后台播放与焦点管理两大板块展开。
