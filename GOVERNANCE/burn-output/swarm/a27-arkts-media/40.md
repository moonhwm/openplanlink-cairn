# 40 · Ducking（压低音量让路）与恢复处理

> 一句话摘要：Ducking 是焦点仲裁的柔性形态——收到 DUCK 提示把实例音量平滑压到让路值、收到 UNDUCK 按记账原值恢复，期间播放不中断，淡变曲线与记账纪律决定体验的精致程度。

## 一、Ducking 的场景与价值

导航播报、语音助手应答、新消息语音朗读等场景里，完全暂停音乐再恢复的体验是割裂的：音乐停顿、恢复突兀、进度感知断裂。柔性方案是压低（duck）：提示音出现期间把音乐压到很低（典型 0.15~0.25）保持"呼吸感"，提示结束后恢复原值，全程不暂停。系统焦点仲裁对这类场景本就倾向下发 DUCK/UNDUCK 而非 PAUSE/RESUME（具体取决于对端 usage 与系统策略），应用侧的职责是把这些提示执行得又快又优雅。Duck 的应用侧处理要点全在"三个平滑"：压低要平滑（防跳变咔哒）、恢复要平滑、状态呈现要平滑（用户几乎不该察觉，最多看到音量条的细微变化）。

## 二、带记账与淡变的处理器

```typescript
export class DuckHandler {
  private preDuckVolume = 1.0;
  private ducking = false;

  constructor(private player: media.AVPlayer,
              private readonly DUCK_LEVEL = 0.2) {}

  async onInterrupt(info: audio.AudioInterrupt) {
    switch (info.hintType) {
      case audio.InterruptHint.INTERRUPT_HINT_DUCK:
        if (!this.ducking) {
          this.preDuckVolume = await this.readBusinessVolume(); // 记账：原值可能不是1.0
          this.ducking = true;
        }
        await this.rampVolume(this.preDuckVolume, this.DUCK_LEVEL, 120); // 120ms淡降
        break;
      case audio.InterruptHint.INTERRUPT_HINT_UNDUCK:
        if (this.ducking) {
          await this.rampVolume(this.DUCK_LEVEL, this.preDuckVolume, 200); // 淡升略慢
          this.ducking = false;
        }
        break;
      default:
        break;   // PAUSE/RESUME/STOP走第10/38篇的标准分支
    }
  }

  private async rampVolume(from: number, to: number, ms: number,
                           steps = 8): Promise<void> {
    for (let i = 1; i <= steps; i++) {                 // 线性/正弦缓动均可
      await this.player.setVolume(from + (to - from) * (i / steps));
      await new Promise(r => setTimeout(r, ms / steps));
    }
  }

  private async readBusinessVolume(): Promise<number> {
    return this.businessVolume;                        // 用户设置的实例音量（第6篇）
  }
}
```

## 三、细节纪律

第一，记账原值。用户可能把实例音量设在 0.6，UNDUCK 恢复到 1.0 就是一次"音量劫持"；记账必须存"进入 duck 前的业务音量"。第二，重复 DUCK。导航连续播报会产生密集 DUCK/UNDUCK 交替，`ducking` 标志防重入；两次 DUCK 之间间隔极短时可延长恢复（合并成一次长压低），避免音量条呼吸机式抖动。第三，与 FORCE 型的组合。系统可能已强制压低（FORCE+DUCK），此时应用侧仍要做记账与标志维护，但不必再调 setVolume（避免二次压低叠加）；以第 38 篇矩阵为准。第四，恢复的时机容错。UNDUCK 到达时对端播报可能还有尾音，恢复淡变取 200~300ms 且从低斜率起步，听感更自然。第五，duck 期间不做任何播放状态变化——不暂停、不同步 PAUSE 到 AVSession、不动长时任务；锁屏进度条应继续走，这是 duck 与 pause 在系统呈现上的根本区别。

## 四、Ducking 检查清单

- [ ] DUCK/UNDUCK 分支独立于 PAUSE/RESUME，互不误触发。
- [ ] 压低/恢复带 100~300ms 淡变，无跳变咔哒。
- [ ] 记账业务原音量；重入防抖；密集交替做合并延长。
- [ ] FORCE+DUCK 只记账不重复压低。
- [ ] duck 期间播放状态与三层镜像保持"播放中"不变。
- [ ] 真机用导航播报连测 10 分钟，音量曲线录屏回归。
