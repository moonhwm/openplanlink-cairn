# 36 · 耳机拔出与蓝牙设备切换的后台播放处理

> 一句话摘要：耳机拔出/蓝牙断连可能以打断事件或路由变更事件两种形态到达，策略上需要"媒体类暂停防外放、通话类迁移保连续"，并通过设备变更监听做双通道去重与 UI 反馈。

## 一、事件的两种到达形态

音频输出设备变化在系统里有两个观察窗口。窗口一是**打断事件**：在独立焦点模式下，耳机拔出等场景系统会下发打断（hint 通常为暂停类），AVPlayer/AudioRenderer 的 audioInterrupt 回调可以收到——这是"防外放"的主信号：用户拔耳机多半不想让声音从扬声器公放。窗口二是**路由变更事件**：`audio.getAudioManager().getRoutingManager().on('deviceChange', deviceFlag, callback)` 订阅输出设备集合变化，回调携带新增/移除的设备描述，它回答"现在声音会从哪出"。两个窗口的覆盖面随版本与设备策略演进（例如部分蓝牙断连只走路由事件），稳妥的工程做法是**双通道都订阅**，以"音频流是否实际仍有效"做最终裁决，并对同一物理事件的两路通知做时间窗去重（300ms 内视为一次）。

## 二、处理策略与实现

```typescript
import { audio } from '@kit.AudioKit';

export class DeviceGuard {
  private lastDeviceEvent = 0;

  bind(p: media.AVPlayer, ui: { toast: (m: string) => void }) {
    // 通道一：打断事件（耳机拔出的主信号）——复用第10篇处理器
    p.on('audioInterrupt', (info: audio.AudioInterrupt) => {
      if (info.hintType === audio.InterruptHint.INTERRUPT_HINT_PAUSE ||
          info.hintType === audio.InterruptHint.INTERRUPT_HINT_STOP) {
        // 媒体类内容：暂停防外放；resume策略见下文“仅手动恢复”
        this.userPausedByDevice = true;
      }
    });

    // 通道二：路由变更（蓝牙断连/接入、USB声卡等）
    const routing = audio.getAudioManager().getRoutingManager();
    routing.on('deviceChange', audio.DeviceFlag.OUTPUT_DEVICES_FLAG, (descs) => {
      const now = Date.now();
      if (now - this.lastDeviceEvent < 300) return;      // 双通道去重
      this.lastDeviceEvent = now;
      const hasBt = descs.deviceDescriptors.some(d =>
        d.deviceType === audio.DeviceType.BLUTOOTH_A2DP);
      if (!hasBt && this.wasBluetooth) {
        ui.toast('蓝牙已断开，已暂停播放');
        this.userPausedByDevice = true;
      }
      this.wasBluetooth = hasBt;
    });
  }
}
```

## 三、按内容类型分化的策略

媒体类（音乐/视频/播客）：拔出耳机→暂停，且**不随重新插入自动恢复**（自动恢复的经典事故是地铁上插拔瞬间外放或半夜自动响起），恢复交给用户按播放；重插耳机后由用户点播放，声音走新路由。通话类（VoIP）：目标是连续性——蓝牙断连时降级到听筒/扬声器继续会话而非中断，此时不应 pause 而应等待路由稳定后继续供数；对 AudioRenderer 实时链路，路由切换瞬间的缓冲欠载要以静音兜底吸收（第 19 篇）。提示音类（导航、跑步提醒）：目标是不间断播报，配合静音混音开关（第 21 篇）与新路由继续出声。另一个高频产品点：蓝牙音频的"重连即恢复"是可选项，若提供应做成用户开关且默认关闭，并在恢复前确认焦点仍归本应用（对方应用可能已占焦点）。

## 四、设备事件检查清单

- [ ] 打断与路由双通道都订阅，时间窗去重，以流有效性做最终裁决。
- [ ] 媒体类拔耳机即暂停、不自动恢复；自动恢复做成默认关闭的开关。
- [ ] 通话类断连走降级迁移（听筒/扬声器），会话不中断。
- [ ] 路由切换瞬间的欠载用静音兜底，恢复后无重复/丢帧可闻。
- [ ] UI 对断连/接入给出轻量反馈（toast/状态条），不打断操作流。
- [ ] 真机覆盖：有线拔插、蓝牙开关、蓝牙超范围断连、车载前后装切换。
