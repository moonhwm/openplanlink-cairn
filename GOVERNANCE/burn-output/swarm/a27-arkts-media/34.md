# 34 · AVSession 与系统播控（通知栏/锁屏/控制中心）联动

> 一句话摘要：锁屏、通知栏、控制中心是 AVSession 的三个系统呈现端，它们的展示内容由元数据与播放状态决定、操作经命令监听回流，上线前必须三端真机走查并覆盖冷热启动与多应用会话切换场景。

## 一、三个呈现端的共性与差异

系统媒体框架为每个活跃 AVSession 提供三处呈现。锁屏/通知媒体卡片：信息密度最高，展示封面、标题、艺术家、进度条与传输按钮，是最常用的"后台控制面"；控制中心（下拉快捷面板的媒体区）：聚合多个应用的会话，支持应用间快速切换，展示密度低于锁屏；通知栏常驻任务标识：与长时任务联动，保证用户知道"这个应用在后台播"。三端的共性：数据全部来自 setAVMetadata 与 setAVPlaybackState，命令全部走 on('play') 等监听——应用不需要（也不能）分别定制三端 UI。差异在于刷新时机与布局策略：锁屏进度条依赖 position 外推（第 32 篇），控制中心的会话切换顺序由系统按活跃度管理，通知标识由长时任务生命周期决定。因此"三端不一致"的缺陷几乎都能回溯到应用侧的状态同步问题，而不是三端各自需要适配。

## 三、联动异常的归因路径

症状一：三端卡片空白或旧数据。归因顺序：activate 前是否 set 过首版元数据（第 30/31 篇）→ 切歌时序是否"先音源后元数据"（第 31 篇）→ assetId 是否真的变了（没变则系统可能不刷新封面）。症状二：进度条不动或狂奔。归因：updateTime 快照错误（狂奔=时刻在未来或速度系数错；不动=外推中断，检查 state 是否停在 BUFFERING）。症状三：锁屏按钮点了没反应。归因：对应命令未注册监听（第 33 篇）→ 命令回调阻塞（慢操作未异步化）→ 会话未 activate。症状四：控制中心显示"上一首不可点"。归因：未注册 playPrevious（部分呈现端将未注册命令置灰），产品语义上"回退30秒"类应用应自行注册 previous 并在处理函数里翻译语义。症状五：与其他应用互抢。焦点模式与打断策略问题，转到第 37 篇主线。
