# 30 · AVSession 创建、激活与销毁生命周期

> 一句话摘要：AVSession 的正确生命周期是"播放会话开始时创建并 activate、控制期间保持、会话结束时 destroy"，一个应用同一时刻只应有一个活跃会话，销毁遗漏会让系统播控残留幽灵控件。

## 一、会话对象的生命周期语义

`avSession.createAVSession(context, 'tag', 'audio')` 创建媒体会话并得到会话句柄，第二参 tag 用于标识业务线（如 'music'、'audiobook'），第三参 type 决定系统播控的展示类别（audio/video 的控件形态与交互略有差异）。刚创建的会话是"未激活"状态：`activate()` 之后系统播控中心才会把它纳入当前可控会话（通知栏/锁屏/控制中心出现该应用的媒体卡片）；`deactivate()` 把会话切出可控集合但保留对象，可在再次播放时重新 activate；`destroy()` 彻底销毁会话并从系统侧注销。三者的关系类似"登记—上台—退场—注销"：activate 与 deactivate 可以反复，destroy 只有一次。核心纪律：应用进程内同一时刻只维护一个媒体会话——用户视角下"这个应用正在播的东西"只有一个；听书应用切到音乐模块时应复用/重置同一会话而不是叠加第二个。

## 二、生命周期管理模板

```typescript
import { avSession } from '@kit.AVSessionKit';
import { common } from '@kit.AbilityKit';

export class SessionHolder {
  private session?: avSession.AVSession;
  private active = false;

  async ensure(ctx: common.UIAbilityContext): Promise<avSession.AVSession> {
    if (this.session) return this.session;           // 单例：全应用唯一会话
    this.session = await avSession.createAVSession(ctx, 'main_media', 'audio');
    this.registerCommands(this.session);             // 见第33篇
    return this.session;
  }

  async activate(): Promise<void> {
    if (!this.session || this.active) return;
    await this.session.activate();
    this.active = true;
  }

  async deactivateIfIdle(): Promise<void> {
    // 暂停且短时间内无恢复：退出可控集合，但保留对象待复用
    if (this.session && this.active) { await this.session.deactivate(); this.active = false; }
  }

  async destroy(): Promise<void> {
    if (!this.session) return;
    this.unregisterCommands(this.session);
    try { await this.session.destroy(); } catch { /* 幂等 */ }
    this.session = undefined; this.active = false;
  }
}
```

## 三、时机选择与三类高频错误

激活时机：首次确认开始播放（play 成功）时 activate，并保证 activate 前已完成第一版元数据与播放状态设置（先 setAVMetadata/setAVPlaybackState 再 activate，避免卡片短暂显示空白）。去激活时机：用户暂停且超过滞回窗口（与第 28 篇任务窗口一致）可 deactivate——此时控制中心不再把它列为"正在播放"，但历史会话仍在；再次播放重新 activate。销毁时机：退出播放模式、应用退出、用户清除播放入口时 destroy。错误一：只 create 不 destroy，应用退出后系统播控残留一张点击无响应的幽灵卡片，用户只能滑掉——必须在 Ability 的 onForeground/onBackground 之外寻找确定的"会话终结点"（如退出播放页 + 停止服务）执行 destroy。错误二：重复创建会话（多个页面各自 create），系统按"最后创建者"展示，控制行为与真实播放状态错位；用单例收敛。错误三：activate 后从不更新状态，锁屏一直显示初始 position，属于第 32 篇要解决的同步纪律问题。

## 四、会话生命周期检查清单

- [ ] 全应用单会话单例，模块切换复用会话而非新建。
- [ ] activate 前完成首版 metadata 与 playbackState 设置。
- [ ] 暂停滞回超时 deactivate，退出播放模式 destroy，两处路径都接通。
- [ ] destroy 前统一 off 掉命令监听，防悬空回调。
- [ ] 真机验证：退出应用后控制中心无幽灵卡片；重进应用会话可重建。
- [ ] 冷启动恢复场景：从控制中心点播放能重建会话并续播（配合第35篇）。
