# 24 · AudioRenderer 播放本地 PCM/WAV 文件完整实现

> 一句话摘要：WAV 文件是"文件头 + 裸 PCM"的结构，解析 RIFF 头拿到采样率/声道/位深后，用文件流分块读取并按第 19 篇的主动 write 模式推入 AudioRenderer，即构成一个不依赖解码器的极简播放器。

## 一、WAV 文件头解析

标准 WAV（RIFF/PCM）的 44 字节文件头布局：偏移 0~3 为 "RIFF"，4~7 为文件大小减 8，8~11 为 "WAVE"，12~15 为 "fmt "，16~19 为 fmt 段长度（16 表示 PCM），20~21 音频格式码（1=PCM），22~23 声道数，24~27 采样率，28~31 字节率（=采样率×声道×位深/8），32~33 块对齐（=声道×位深/8），34~35 位深（16/24/32），36~39 为 "data"，40~43 为 PCM 数据长度；其后即为交错 PCM 样本。解析时要做三重防御：魔数校验（不合法直接报"非 WAV"）、位深映射（16→S16LE、32→S32LE，24 位需手工展宽为 16/32 位，系统枚举不含 S24）、以及 44 字节只是"典型值"——fmt 段可能有扩展（长度非 16），必须按段长度跳到 data 段而非死写 44。

## 二、完整播放器实现

```typescript
import { audio } from '@kit.AudioKit';
import { fileIo as fs } from '@kit.CoreFileKit';

export class WavPlayer {
  async play(path: string) {
    const file = fs.openSync(path, fs.OpenMode.READ_ONLY);
    const stat = fs.statSync(path);
    const head = new ArrayBuffer(512);
    fs.readSync(file.fd, head);                       // 读头部
    const dv = new DataView(head);
    const str = (o: number, n: number) =>
      String.fromCharCode(...new Uint8Array(head, o, n));

    if (str(0, 4) !== 'RIFF' || str(8, 4) !== 'WAVE') throw new Error('非WAV文件');
    const channels = dv.getUint16(22, true);
    const sampleRate = dv.getUint32(24, true);
    const bits = dv.getUint16(34, true);
    // 定位data段：从偏移12起遍历chunk（fmt长度可能非16）
    let off = 12, dataLen = 0;
    while (off + 8 <= 512) {
      const id = str(off, 4), len = dv.getUint32(off + 4, true);
      if (id === 'data') { dataLen = len; off += 8; break; }
      off += 8 + len + (len % 2);                     // chunk按2字节对齐
    }

    const fmt = bits === 16 ? audio.AudioSampleFormat.SAMPLE_FORMAT_S16LE
              : bits === 32 ? audio.AudioSampleFormat.SAMPLE_FORMAT_F32LE : undefined;
    if (!fmt) throw new Error(`不支持位深 ${bits}`);

    const r = await audio.createAudioRenderer({
      streamInfo: {
        samplingRate: sampleRate as number, channels,
        sampleFormat: fmt, encodingType: audio.AudioEncodingType.ENCODING_TYPE_PCM
      },
      rendererInfo: { usage: audio.StreamUsage.STREAM_USAGE_MUSIC, rendererFlags: 0 }
    });

    const CHUNK = 8 * 1024;                           // 8KB块
    let pos = off, written = 0;
    await r.start();
    while (written < dataLen) {
      const buf = new ArrayBuffer(CHUNK);
      const n = fs.readSync(file.fd, buf, { offset: pos });   // 读一块
      if (n <= 0) break;
      let view = new Uint8Array(buf, 0, n);
      while (view.length > 0) {                       // 流控：按实际写入推进
        const w = await r.write(view.slice().buffer);
        view = view.subarray(w);
      }
      written += n; pos += n;
    }
    // 收尾：等播完（缓冲排空）再release
    await new Promise(res => setTimeout(res, (written / dv.getUint32(28, true)) * 1000));
    await r.release(); fs.closeSync(file);
  }
}
```

## 三、工程化补全点

第一，播放结束检测：write 全部入缓冲不等于播完，剩余播放时长 ≈ 已写入字节/字节率，可按此延时后再 release，或对比 `getAudioTime()`/已写字节换算（更精确的做法见版本提供的播放时钟接口）。第二，暂停/恢复/进度：记录已写入位置，pause 时停读，恢复续读；进度 = 已写字节换算时长与缓冲内积压的差值。第三，性能：8KB~64KB 块是吞吐与时延的平衡点；顺序读大文件可预读下一块与写当前块并行。第四，边界文件：0 长度 data、非 PCM 格式码（如 float 格式码 3）、多 data 段拼接等异常文件要以解析失败显式报错，不要带病播放。第五，该播放器天然支持"边下边播"：把 fs.readSync 换成网络分片到达的缓冲读取，写入逻辑不变。

## 四、WAV/PCM 播放检查清单

- [ ] 头解析做魔数/位深/格式码校验，fmt 段长度自适应，不硬编码 44。
- [ ] 24 位样本先展宽再播，或解码阶段统一转 16/32 位。
- [ ] write 按实际写入量切片续写；块大小 8~64KB。
- [ ] 结束判定考虑缓冲积压，release 前等播完。
- [ ] 暂停/进度基于读写双指针实现，恢复无损续播。
- [ ] 解析失败显式报错并上抛可提示原因。
