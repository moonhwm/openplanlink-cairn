# 09 多步骤工具的中途失败与Saga补偿

> 摘要：本文分析由多个内部步骤组成的MCP工具在第k步失败时的状态残留问题，给出前向恢复与反向补偿两种Saga落地方式及补偿失败的人工兜底设计。

## 一、多步骤工具的失败窗口

一个工具对外是一个原子调用，对内常常是一条步骤链：读取参数、校验权限、创建草稿记录、调用外部接口、写回结果、发送通知。任何一步都可能失败，而协议层回给客户端的只有一条错误。若不做处理，第k步失败后前k减一步的副作用原样残留：草稿记录悬挂、外部调用已发生但结果未落库、后续通知缺失。客户端看到的错误无法反映已发生部分，重试会在残留状态上叠加新执行，典型的如重复创建草稿、对外部系统重复下单。失败窗口的本质是工具把内部的非原子性泄漏给了外部，而调用方按原子语义在使用它。

## 二、前向恢复与反向补偿

处理中途失败有两大学派。前向恢复承认部分成功，把执行状态持久化到检查点，重试时从最后成功的步骤继续而非从头再来，适合步骤昂贵且幂等重做代价高的场景，例如已经上传了大文件的处理流水线。反向补偿则在每个正向步骤登记对应的撤销动作，失败时逆序执行补偿，把系统拉回调用前状态，适合对外可见副作用必须消除的场景，例如已在外部系统创建的资源必须删除。补偿与回滚不同：数据库事务内的回滚是原子的，跨外部系统的补偿只能是最终一致的，且补偿本身也可能失败，必须设计重试与人工兜底。选择依据是业务语义：部分结果有价值就用前向恢复，部分结果有害就必须补偿。

## 三、补偿式执行器参考

```python
class SagaStep:
    def __init__(self, name, action, compensate):
        self.name, self.action, self.compensate = name, action, compensate

async def run_saga(steps, ctx):
    done = []
    try:
        for step in steps:
            await step.action(ctx)
            done.append(step)
        return Ok(ctx.result)
    except Exception as e:
        for step in reversed(done):
            try:
                await with_retry(step.compensate, ctx,
                                 attempts=5, backoff="exp")
            except CompensationFailed:
                await alert_human(step, ctx)   # 补偿失败进入人工队列
        return Error(isError=True,
                     data=f"failed, compensated={len(done)}",
                     meta={"compensated_steps": [s.name for s in done]})
```

实现要点：补偿逆序执行且每步带重试；补偿失败的记录带着完整上下文进入人工队列而不是被吞掉；返回给客户端的错误中包含已补偿步骤清单，让调用方知道系统回到什么状态。补偿动作必须满足两个性质——自身尽量幂等（可重试），且不依赖正向步骤留下的中间态（清理要彻底）。上下文对象应持久化到任务存储，进程崩溃后恢复时还能继续补偿，否则服务器重启就把未完成的补偿丢了。

## 四、Saga落地检查清单

- 枚举工具的全部内部步骤，为每个有副作用的步骤显式定义补偿或声明前向可续。
- 补偿动作幂等性评审：同一补偿重复执行不得产生二次副作用。
- 上下文与进度检查点持久化，覆盖进程崩溃场景。
- 补偿失败的人工兜底队列与告警通道，附带完整上下文快照。
- 错误返回中携带补偿状态元数据，客户端可据此决策重试策略。
- 混沌测试注入每一步的失败，验证补偿路径真实可走而不仅在代码里存在。

## 五、边界情形

补偿顺序存在陷阱：步骤间有依赖时简单逆序可能失败，例如先删子资源再删父资源的顺序不能反；登记时就要记录依赖关系。空补偿与悬挂补偿是另一对边界：补偿执行时正向动作实际未生效（空补偿，应容忍），正向生效但补偿永远没跑（悬挂，靠扫描任务表兜底）。不可补偿的步骤（外部系统无删除接口）要用隔离舱模式——先把副作用写到暂存区，最终确认时才对外提交。中途失败处理的成熟度直接决定多步骤工具能否在生产环境承载关键业务，是服务器侧边界工程的重心之一。
