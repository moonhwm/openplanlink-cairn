# 19 客户端重连后的会话重入：会话ID复用与状态恢复

> 摘要：本文讨论MCP客户端断线重连后如何正确"回到"原会话：会话标识的复用规则、服务器侧状态恢复的三种策略、恢复失败时的降级与重建路径。

## 一、重连不等于恢复

客户端重连成功只代表传输通道重建，会话是否恢复取决于标识与状态两层。Streamable HTTP传输中，服务器在initialize响应中分配mcp-session-id，客户端后续请求携带该标识；重连后沿用旧标识，服务器若仍有对应会话状态，链路无缝续用。但重连后标识可能失效：服务器重启丢失会话表、会话空闲超时被回收、负载均衡把新连接路由到没有该会话的节点。此时客户端拿着旧标识请求，得到"会话不存在"类错误，必须走重建路径。把重连与会话恢复混为一谈的实现，会在标识失效后反复用旧标识撞墙，既无法恢复也无法重建，卡死在中间。

## 二、服务器侧状态恢复的三种策略

策略一是会话状态外置：会话上下文（能力协商结果、订阅登记、任务进度）存于外部存储（Redis、数据库），服务器节点无状态，任何节点凭会话标识都能装载上下文继续服务。恢复最彻底，支持跨节点漂移，是集群部署的首选；代价是每次访问的状态装载成本与外部存储的可用性依赖。策略二是粘性路由：负载均衡按会话标识哈希路由到固定节点，状态留在节点内存。成本低，但节点故障即状态丢失，扩缩容时大量会话失效。策略三是可重建状态：会话只保存可从客户端信息重建的内容（重新握手、重新拉清单、重新订阅），重连后客户端走完整重建流程。实现最简单，语义最保守，适合状态轻的会话。三种策略的选择取决于会话状态的重量与业务对连续性的要求。

## 三、客户端恢复流程参考

```python
async def resume_or_rebuild(transport):
    if self.session_id:
        transport.set_header("mcp-session-id", self.session_id)
        try:
            await transport.ping_or_probe()        # 带旧标识的轻量探测
            return SessionResumed(self.session_id)
        except SessionNotFound:
            log.warn("session expired, rebuilding")
        except TransportError:
            pass                                    # 传输问题，先重建连接
    # 重建路径：完整握手 + 状态补偿
    init = await handshake(transport, self.client_caps)
    self.session_id = init.session_id
    await self.tools.cache.refresh_all()            # 清单全量拉取
    for sub in self.subscriptions.pending():
        await sub.re_subscribe()                    # 订阅重建
    await self.reconcile_inflight()                 # 在途请求对账
    return SessionRebuilt(self.session_id)
```

流程的关键决策：恢复探测必须是轻量且无副作用的；会话失效与传输故障分诊，前者直接重建会话，后者先修连接再探测；重建后的补偿动作有清单且按序执行——清单刷新先于订阅重建（订阅可能引用新清单中的条目），在途请求对账最后进行。重建期间上层调用应被排队或快速失败，禁止静默丢失。

## 四、会话恢复工程清单

- initialize响应中的会话标识持久化到磁盘，进程级重连也能尝试恢复。
- 探测会话有效性的轻量方法（如对无效方法的受控探测或专用ping）标准化。
- 会话失效错误码与普通错误可区分，客户端可程序化触发重建。
- 集群部署优先会话状态外置，外置存储的读写失败有降级路径。
- 重建补偿清单版本化：握手、清单、订阅、通知游标、在途对账五项齐全。
- 会话恢复成功率与平均恢复耗时作为韧性的一级指标。

## 五、边界情形

边界之一是恢复的时序窗口：服务器侧会话尚未过期与客户端重建完成的瞬间，同一会话可能存在新旧两套订阅登记，服务器需以标识内单调递增的世代号裁决，迟到消息按世代丢弃。边界之二是部分恢复：订阅重建失败但清单刷新成功，恢复流程应继续完成其余项并对失败项给出明确状态，而不是整体回滚重来。边界之三是安全：会话标识是能力凭证，重连恢复的探测与请求都要走原有鉴权链路，会话标识本身不得被视为认证凭据。会话重入的本质问题是"同一身份的第二 incarnation 如何被正确接纳"，恢复策略、世代裁决、补偿清单三者齐备，重连才真正等于恢复。
