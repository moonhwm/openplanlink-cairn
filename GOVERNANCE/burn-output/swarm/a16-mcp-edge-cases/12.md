# 12 能力协商不一致导致的功能部分不可用

> 摘要：本文分析MCP initialize握手中能力声明与运行期行为不一致的各类形态，包括声明了却不支持、支持了却未声明、版本错配三种，给出防御性探测与服务降级策略。

## 一、握手承诺与运行期现实的落差

MCP的initialize握手用capabilities对象交换双方的能力清单：客户端声明sampling、roots、elicitation等，服务器声明tools、resources、prompts、logging、completions等。协议假定握手声明与运行期行为一致，但现实中的落差无处不在。落差形态一：声明了却不支持——服务器在capabilities里声明了tools.listChanged，客户端据此订阅变更通知，结果服务器从不发送，客户端的缓存无限期陈旧。形态二：支持了却未声明——服务器实现了资源订阅但不声明resources.subscribe，客户端只能退化为轮询，性能白白损失。形态三：版本错配——双方协议版本不同，某版本引入的字段在一侧存在另一侧缺失，解析出空值或默认值，行为悄无声息地偏离预期。这些落差造成的不是崩溃而是部分功能静默失效，比崩溃更难发现。

## 二、落差的具体危害面

能力落差的危害集中在依赖链上。客户端依据声明决定调用路径：声明了分页游标就走增量拉取，声明了变更通知就放弃轮询。声明为真则万事大吉；声明为假，客户端的行为在不知情的前提下系统性地偏离最优解。更危险的是负向依赖：客户端可能依据"未声明某能力"而启用补偿机制，例如未声明进度通知就缩短超时阈值，而服务器实际会发进度，两条逻辑在边界上打架。声明与实现漂移的常见根因包括：服务器升级了实现但握手代码没同步；不同传输层能力不同但握手统一声明；配置开关热改了能力但握手结果被缓存；客户端对可选字段的解析在不同版本间语义变化。

## 三、防御性协商参考

```python
class CapabilityView:
    def __init__(self, declared, negotiated_version):
        self.declared = declared
        self.version = negotiated_version
        self.verified = {}

    def declare(self, key, default=False):
        return bool(self.declared.get(key, default))

    def verify(self, key, probe):
        # 对关键能力做一次轻量探测，落实验握手承诺
        if self.declare(key) and not self.verified.get(key):
            self.verified[key] = probe()      # 如list一次、订阅一个资源
        return self.verified.get(key, False)

    def on_capability_violation(self, key):
        # 运行期发现行为与声明不符：降级并记录
        self.verified[key] = False
        metrics.incr(f"cap_violation.{key}")
```

该模式的核心思想是信任但验证：对影响架构选型的能力（分页、订阅、变更通知），握手后做一次廉价探测落实；运行期检测到违背声明（例如订阅后超时窗口内无确认），把该能力标记为不可用并切换补偿路径，同时保留指标供事后追责。服务器侧的对称义务是实现单一事实源：能力声明由实现自动推导，禁止手工维护两份清单。

## 四、能力一致性治理清单

- 握手响应中的每个能力字段与实现代码用常量绑定，杜绝手工漂移。
- 客户端对关键能力做探测验证，探测失败自动降级并打点。
- 协商出的版本号写入日志，跨版本行为差异建立对照表。
- 变更通知类能力设置陈旧度上限：超时未收到通知则强制全量刷新一次。
- 能力违背事件进入专门的观测通道，与普通错误分开统计。
- 升级发布前跑能力声明与实现的契约测试。

## 五、边界情形

版本协商本身有边界：客户端建议版本、服务器可改选，最终版本以服务器响应为准；两侧对同一可选字段的默认值理解不同时，未声明字段必须按规范默认值处理，不得自行脑补。另一个边界是能力随会话变化：会话中途能力变化没有协议内通知机制，客户端只能通过listChanged类通知间接触发重新拉取清单，把能力视图与清单刷新联动。能力协商的价值在于让双方用最便宜的握手换取架构决策依据，而防御性验证是这份依据的保险丝——声明可以错，架构不能因声明错误而坍塌。
