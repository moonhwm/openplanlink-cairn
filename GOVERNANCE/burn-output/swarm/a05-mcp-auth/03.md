# 03. MCP安全威胁模型：STRIDE分析与攻击面枚举

> 摘要：用STRIDE框架对MCP认证授权链路做系统威胁建模，枚举每个组件的攻击面，并给出风险登记与处置优先级方法。

## 一、建模范围与资产识别

威胁建模先定资产。MCP授权链路上的核心资产有五类：访问令牌与刷新令牌（含内存与磁盘副本）、用户同意关系（谁授权了什么scope）、MCP服务器上的业务数据、会话标识（session id）、审计日志本身。攻击者目标无非四者：偷令牌冒充用户、扩大权限到未授权scope、把恶意服务器嵌入调用链、篡改或抹除审计痕迹。建模范围应覆盖四个组件：Host/Client、MCP Server、授权服务器、上游API，以及三者之间的网络通道。

## 二、STRIDE逐类分析

**Spoofing（仿冒）**：攻击者伪装成合法MCP服务器诱导Client连接（恶意服务器注册、DNS劫持）；伪造令牌或重放旧令牌；仿冒AS元数据端点劫持授权码。缓解：TLS+证书校验、AS元数据签名或可信清单、令牌签名与exp/aud校验、DPoP绑定。

**Tampering（篡改）**：中间人修改JSON-RPC请求参数（例如把转账金额改大）；篡改授权响应中的state/resource；注入工具描述让模型执行越权动作。缓解：TLS全覆盖、state一次性随机值、服务端对参数做独立授权判断而不是信任客户端描述。

**Repudiation（抵赖）**：缺少审计日志或日志无令牌标识，操作者否认执行过高危调用。缓解：审计事件必须含sub/client_id/jti/工具名/参数摘要，日志append-only。

**Information Disclosure（信息泄露）**：令牌出现在URL、日志、错误栈、工具返回内容中；会话标识可预测导致枚举。缓解：令牌只走Header、日志脱敏、会话标识使用≥128位随机数。

**Denial of Service（拒绝服务）**：对token端点刷PKCE重放；对内省端点放大请求；注册端点被刷爆。缓解：限速、客户端注册准入、缓存JWKS。

**Elevation of Privilege（权限提升）**：混淆代理让服务器A的令牌被服务器B使用；提示注入诱导模型调用高权限工具；scope通配符过宽。缓解：audience绑定、逐工具scope、人类在环确认。

## 三、风险登记表模板

```text
编号  威胁                  组件         可能性 影响 处置
T01   令牌直通到第三方服务器  Client       高    高   禁止直通,改用RFC8693交换
T02   恶意MCP服务器钓鱼     生态/注册     中    高   服务器准入审核+元数据校验
T03   会话标识可预测枚举     Server       中    高   CSPRNG生成128bit会话ID
T04   工具描述提示注入       Server       高    中   输出不可信+高危需确认
T05   刷新令牌落盘明文       Client       中    高   密钥链存储+加密
T06   动态注册被滥用         AS           中    中   注册需初始访问令牌
```

## 四、处置优先级与检查点

排序采用"可能性×影响×攻击成本"三因子，凡能同时打击多资产的威胁（令牌窃取）优先处置。落地时坚持三个检查点：设计评审必过威胁清单；每次新增工具必须登记所需scope与威胁项；上线后按季度复评，把已实现缓解的证据（配置、代码位置）登记到表格中，防止"纸面安全"。威胁模型不是一次性文档，而是随架构演进的活账本。
