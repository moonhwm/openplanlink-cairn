# 19 MCP服务器代码审计方法论

## 引言

当来源验证与版本锁定解决了"拿什么"的问题，代码审计回答"它到底做什么"。对将接触敏感数据或高权限操作的MCP服务器，代码审计是准入前的深度核查手段。本文给出一套适配MCP场景的审计方法论：审计目标设定、代码阅读路径、重点风险域与审计产出规范。

## 一、审计目标与准备

审计目标决定深度。三级深度定义：一级，差异审计，针对版本升级，只审两次版本间的变更；二级，准入审计，针对首次引入，覆盖直接源码与关键依赖；三级，深度审计，针对核心服务器，覆盖全部源码加依赖抽样与运行验证。准备材料：锁定版本的源码与锁文件、项目文档与工具清单、此前的审计记录（如有）、已知问题库。审计环境：隔离主机或容器，禁用生产凭据，网络经代理以便观察审计过程中的外联行为。

## 二、代码阅读路径

推荐"入口—出口—通道"三段式路径。第一段，找入口：定位服务器启动路径、命令行参数解析、环境变量读取点，列出所有输入来源。第二段，找出口：检索所有网络发送点（外联请求、远程上报）、文件写入点、进程与命令执行点、敏感资源访问点。出口清单是审计的核心产出之一，任何"没有合理业务解释的出口"都是高优先疑点。第三段，追通道：从每个工具的实现出发，追踪"模型输入如何转化为实际操作"，重点确认参数校验、路径约束与越权可能。三段之后，再做交叉验证：将文档声明的功能与代码实际出口对照，文档没提的出口要求解释。

检索出口点的示例模式（以常见实现语言为参考）：

```text
重点检索模式清单:
  网络出口: 请求库调用 / 远程地址常量 / 上报埋点
  执行出口: 进程创建 / 命令拼接执行 / 动态加载
  文件出口: 全盘路径拼接 / 配置目录之外的读写
  数据出口: 环境变量枚举 / 凭据文件读取 / 剪贴板与输入捕获
  隐蔽通道: 编码解码调用 / 压缩解包 / 分段外传逻辑
```

## 三、重点风险域与产出规范

MCP服务器特有的风险域需要在方法论中显性化：其一，工具描述构造逻辑——描述文本是否包含与功能无关的指令性内容、是否动态生成描述；其二，返回值加工逻辑——是否在返回中追加影响模型行为的内容；其三，上下文收集——是否读取会话历史、系统信息、环境变量并纳入返回或外传；其四，配置与凭据处理——读取范围是否超出自身需要，是否持久化所获凭据。产出规范：审计报告必须包含入口清单、出口清单、工具与权限映射表、疑点列表（附代码位置与风险解释）、结论与整改建议；疑点按"恶意、可疑、瑕疵"三分类；审计结论附审计深度、材料版本与审计人，供后续差异审计做基线。

## 结语

代码审计是供应链防线中人力成本最高、也最难被绕过的一环。以"入口—出口—通道"为路径、以出口清单为核心产出、以MCP特有风险域为专项检查，可以显著压缩审计所需的经验门槛。审计不必追求一次读完全部代码，而要追求结构化覆盖：每个出口有归属解释，每个工具的权限映射清楚。对高风险服务器，代码审计与后续运行时审计互为印证，静态看不见的动态现形。
