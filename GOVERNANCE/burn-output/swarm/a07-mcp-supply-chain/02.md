# 02 MCP协议架构与攻击面分析

## 引言

要做好MCP服务器的供应链安全，必须先理解MCP协议自身的架构与数据流。攻击面分析是安全工程的基本功：只有清楚"哪些组件、哪些通道、哪些数据"参与了协议交互，才能判断供应链投毒可能在哪些位置生效。本文从MCP的分层架构出发，系统枚举攻击面，并给出攻击面收敛的设计原则。

## 一、MCP核心架构与数据流

MCP采用客户端—服务器架构。宿主应用（如集成开发环境、智能体框架）内嵌MCP客户端，客户端与MCP服务器建立会话，服务器再向下对接本地文件、数据库、远程接口等真实资源。协议交互围绕三类原语展开：工具是模型可主动调用的操作；资源是服务器暴露给模型读取的数据；提示是服务器预置的模板。此外，服务器通过能力协商声明自身支持的功能集合，客户端据此决定暴露哪些内容给模型。

从数据流看，一条典型调用链为：模型生成工具调用请求，客户端序列化后发给服务器，服务器执行实际操作，将结果返回，再进入模型上下文。供应链风险就藏在这条链路的每一跳：服务器代码本身可能被篡改；服务器返回的文本可能携带注入指令；服务器与下游资源之间的凭据可能被窃取；客户端与服务器的传输通道可能被中间人利用。理解这条链路，是后续所有审计与防护专题的基础。

## 二、攻击面系统枚举

第一，安装与更新面。客户端配置通常以命令行方式拉起服务器，涉及包管理器、注册表、镜像仓库与安装脚本。浮动版本、缺失哈希校验、可被劫持的脚本执行，都属此面。第二，代码与依赖面。服务器实现语言各异，依赖树深且传递依赖不受直接审视，是投毒代码的主要藏身处。第三，配置与凭据面。配置文件中声明启动命令、参数与环境变量，其中常含各类密钥；配置文件若纳入版本库或共享目录，凭据即可能扩散。第四，协议交互面。能力协商、工具列表、工具描述与返回结果都进入模型上下文，攻击者可在描述或返回值中夹带指令，实施越权诱导。第五，运行环境面。服务器的文件系统、网络、进程权限决定了被攻破后的横向移动能力。第六，日志与遥测面。日志若记录完整提示词与返回内容，本身成为敏感数据汇聚点，也可能被恶意服务器当作外传通道。

## 三、攻击面收敛原则与核查清单

架构层面的防御思路是"每一条链路都假设可能被污染，用最小授权与显式验证压缩可利用空间"。落地核查清单如下：

- 服务器进程只读其声明的资源目录，禁止全盘文件系统访问；
- 工具描述在准入时人工审阅，运行时对比变更；
- 服务器出站网络仅放行功能必需的域名，默认拒绝其余；
- 凭据通过独立注入机制提供，不写入共享配置文件；
- 传输通道使用本地受保护套接字或加密远程连接；
- 日志脱敏，禁止记录完整密钥与用户原始输入；
- 每个服务器独立进程与独立凭据，禁止多服务器共享令牌。

一个体现最小授权思想的客户端配置示例（仅含占位符，不含真实凭据）：

```json
{
  "mcpServers": {
    "docs-search": {
      "command": "./releases/docs-search-server-1.4.2",
      "args": ["--read-only", "--data-dir", "./data/docs"],
      "env": {
        "API_ENDPOINT": "内部网关地址占位",
        "CREDENTIAL_REF": "密钥管理系统引用占位"
      }
    }
  }
}
```

该示例中可执行文件使用本地固定路径的锁定版本，参数显式声明只读与数据目录，凭据以引用方式注入而非明文存放。

## 结语

攻击面分析的价值在于把模糊的"供应链风险"翻译成可核查的具体位置。安装更新、代码依赖、配置凭据、协议交互、运行环境、日志遥测六个面，构成了MCP服务器供应链审计的检查骨架。后续专题将分别针对这些面展开具体方法：来源验证针对安装面，版本锁定针对更新面，代码与运行时审计针对依赖与交互面，隔离加固针对环境面。掌握骨架，各专题方法才能真正落地。
