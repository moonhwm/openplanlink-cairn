# 21 运行时行为审计与调用追踪

## 引言

静态审查看得见代码，看不见行为。混淆、动态加载、条件触发（特定日期、特定环境才激活）都能让静态分析扑空。运行时行为审计在服务器真实执行过程中观测其动作：访问了什么、连接了谁、返回了什么。本文设计MCP服务器的运行时审计方案，包括观测点布设、调用链追踪、异常行为基线与审计实施流程。

## 一、观测点布设

运行时审计依赖在关键位置布设观测点。系统层观测：进程与文件审计（记录进程创建、敏感路径读写）、网络观测（记录出站连接五元组与流量概要）、系统调用审计（捕获关键调用序列）。应用层观测：MCP客户端侧的调用日志（每次工具调用的名称、参数摘要、返回摘要与耗时）、服务器生命周期事件（启动、异常退出、重启频率）。中间层观测：代理层记录服务器的全部外联明细，这是发现隐蔽外传的关键观测点。布设原则：观测点自身只读不阻断（阻断属于防护，见后续专题），输出汇聚到统一审计存储；审计日志脱敏处理，记录摘要而非完整敏感内容。

## 二、调用链追踪

把观测数据组织成"一次工具调用"为单位的链路：模型发起调用，客户端转发，服务器执行（其间产生的文件、进程、网络动作），结果返回。链路化的价值在于把孤立事件归因到具体工具与具体会话，审计时可以回答"这次外联发生在哪次工具调用中、参数是什么"。

```text
调用链记录结构(示意):
trace_id: 链路标识
tool: 工具名称
params_digest: 参数摘要(脱敏)
spans:
  - type: process, action: 启动子进程, 命令摘要
  - type: file,    action: 读取, 路径: 声明数据目录内
  - type: network, action: 出站, 目标: 白名单域名, 字节数
  - type: network, action: 出站, 目标: 未登记域名  <-- 审计疑点
result_digest: 返回摘要(脱敏)
duration: 耗时
```

## 三、行为基线与审计实施

异常检测的前提是正常基线。基线构建：在受控环境以典型工作负载运行服务器，采集行为画像——常连域名集合、文件访问范围、子进程模式、调用耗时分布。基线登记后，生产观测持续比对：新域名出现、文件范围越界、新子进程模式、描述外的大流量，均为审计事件。审计实施流程：准入前，在沙箱执行任务化驱动（模拟真实调用序列），比对行为与静态审计的出口清单，两者不一致即深查；运行期，按周例行审计调用链抽样与全部异常事件；专项审计，在可疑事件（投诉异常、模型行为怪异）发生时做全量链路回放。清单：

- 每台服务器建立并版本化行为基线；
- 未登记域名外联、越界文件访问为即时审计事件；
- 沙箱任务化驱动纳入准入必经步骤；
- 调用链抽样审计每周不少于一次；
- 审计发现的异常回流静态规则库（第20篇）形成闭环；
- 审计存储的保留周期与访问权限明确，防审计数据二次泄露。

## 结语

运行时审计补上了静态分析的结构性盲区：动态加载与条件触发的恶意逻辑，终究要在执行中露出行为。以调用链为骨架组织观测数据，以行为基线定义异常，以任务化驱动完成准入验证，三件事做完，"代码说的"与"实际做的"之间的差距就有了持续监控。动静结合的审计体系，是识别高级供应链威胁的核心能力。
