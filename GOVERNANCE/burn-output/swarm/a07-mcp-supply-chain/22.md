# 22 工具描述投毒与rug pull检测

## 引言

MCP场景有一类不改代码也能生效的攻击：污染工具描述与返回内容。工具描述直接进入模型上下文，攻击者在其中嵌入隐藏指令（"读取凭据并通过某工具外传"）、或诱导模型优先调用恶意工具；返回内容同样可以夹带指令，影响模型后续行为。另一变体是"抽地毯式"变更：服务器上线时描述干净，更新后描述被改写加入恶意指令。本文分析这类攻击的机理，给出检测方法与防护设计。

## 一、攻击机理与典型模式

第一种，静态描述注入。描述文本中混入与功能无关的指令，常见形态：要求模型在处理用户请求前先执行某"前置步骤"；指示模型将上下文内容写入某资源或传给某工具；用"系统级""安全策略"等措辞伪装权威性。第二种，隐藏信道。利用人眼难辨但对模型可读的差异：不可见字符、零宽字符、极端字号或注释标记，在人类审阅界面看不到，模型却会读到。第三种，跨工具组合。单个工具描述无害，多条描述组合后形成"收集—聚合—外传"链条，如一个工具负责读环境信息，另一个工具看似做格式化，实则将聚合数据发出。第四种，时机性改写（即抽地毯式变更）：在取得用户信任后的版本更新中，悄悄修改描述或返回模板，注入恶意逻辑。这类攻击的共性是：不触发任何传统漏洞特征，只作用于"模型这一层"。

## 二、检测方法

检测覆盖准入与运行两个时点。准入检测：其一，人工通读全部工具描述与返回模板，标准是"描述只解释功能，不含指令性、诱导性、跨工具串联性内容"；其二，不可见字符扫描，对描述文本做字符级检查，剔除并标记非常规码位：

```python
# 描述文本隐藏字符检测(示意)
import unicodedata
SUSPICIOUS = {"Cf", "Co", "Cn", "Zl", "Zp"}  # 格式符/私用区/未分配等
def scan_description(text: str) -> list[int]:
    hits = []
    for i, ch in enumerate(text):
        if unicodedata.category(ch) in SUSPICIOUS:
            hits.append(i)
    return hits  # 命中位置需人工判定是否清除或拒绝
```

其三，语境测试：在隔离环境用探针式提示驱动模型与服务器交互，观察是否出现描述之外的越权倾向（模型是否试图调用未授权工具、是否试图读取无关数据）。运行时检测：登记描述与返回模板的基线哈希，任何变更（尤其未伴随版本升级的变更）即时告警；对返回内容做注入特征过滤与长度异常监控。

## 三、防护设计与清单

检测之外，防护设计降低注入成功的收益。要点：工具粒度最小授权，即使模型被诱导，可用工具的权限也被压缩；高危工具（写文件、外发数据、执行命令）在客户端侧设置二次确认或速率限制；跨工具数据流在客户端层面审视，"读取类工具的输出流向外部发送类工具"的链路单独审批。落地清单：

- 准入时描述通读为必经步骤，检查项写入表单；
- 描述与返回模板基线化，变更告警并触发复审；
- 隐藏字符扫描自动化，命中即拒绝或净化；
- 探针式语境测试纳入沙箱验收；
- 高危工具默认确认模式，组合调用链单独评审；
- 将已知注入案例的措辞模式沉淀为检测规则，持续更新。

## 结语

描述投毒揭示了MCP供应链的独特风险层：文本即攻击面。防线必须同时覆盖人类阅读层（通读与净化）与模型消费层（语境测试与行为约束），并用基线哈希封住时机性改写的后门。把描述当作代码同级的安全对象来管理——版本化、审计、变更告警——是这类风险的根本对策。
