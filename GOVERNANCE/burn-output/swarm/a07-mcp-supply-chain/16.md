# 16 私有注册表与内部镜像源建设

## 引言

让所有MCP服务器及其依赖经由组织自有的分发基础设施获取，是供应链管控的枢纽工程：它是强制校验的执行点、缓存与镜像的受控层、审计日志的汇聚点。本文给出私有注册表与内部镜像源的建设方案，包括架构分层、同步与校验策略、缓存防污染规则与运营要点。

## 一、架构分层

参考架构分四层。接入层：所有终端与构建环境出站仅指向内部源，公网直连在网络层阻断。代理与缓存层：内部源作为上游公网源的受控代理，按白名单转发请求并缓存制品。校验层：同步与首次缓存时执行签名验证或哈希校验，未通过校验的制品不落库。登记层：每个缓存的制品记录坐标（命名空间、名称、版本）、摘要、上游来源、首次获取时间与获取方，形成资产账本的自动输入。对语言包生态，内部源对每种包管理器形态提供对应端点；对容器镜像，提供内部镜像仓库与路由策略；对源码形态分发，提供内部代码镜像与归档。

## 二、同步与校验策略

同步策略分拉式与推式。拉式：终端请求触发向上游拉取并校验后缓存，冷启动自然，但首次请求方承担等待。推式：运维预先将审核通过的制品推入内部源，终端只能取到已审制品，管控最强，适合生产环境的"选择性供给"模式。两者通常并存：试验环境用拉式加自动校验，生产环境用推式加显式审批。校验策略要点：

```text
同步校验(制品P):
  上游白名单检查: 命中 -> 继续, 未命中 -> 拒绝并记录
  完整性校验: 优先验签名, 无签名则官方基准哈希比对
  登记入库: 坐标+摘要+来源+时间+请求方
  不可变规则: 同坐标制品仅可首次写入, 重复同步须摘要一致
  黑名单检查: 命中已知恶意版本 -> 拒绝并告警
```

## 三、缓存防污染与运营要点

缓存一旦被污染，内部源就从防线变成扩散器，因此防污染规则必须严格。规则一：不可变性。同一坐标的制品元数据与内容缓存后禁止覆盖，重新同步摘要不一致时保留旧件并告警，由人工裁决。规则二：命名空间治理。内部源区分"上游镜像区"与"自研发布区"，自研区仅流水线可写，防止源内伪造。规则三：删除治理。上游撤包不自动同步删除，撤下的制品保留归档并标记，避免历史环境无法重建。运营清单：

- 上游白名单变更走审批，新增上游附理由与风险评估；
- 每日巡检：异常坐标请求、校验失败记录、高频获取的新制品；
- 磁盘上的制品库启用防篡改（只读挂载或对象存储版本化）；
- 内部源自身按高价值资产防护：最小权限运维、操作审计、可用性冗余；
- 定期演练：从零重建内部源与生产配置的完整过程；
- 指标化运营：命中率、拦截数、校验失败趋势、未登记部署数。

## 结语

私有注册表与内部镜像源把获取环节从"各自为战"收敛为"单一关口"。它同时服务于强制校验、版本锁定、审计取证与应急封堵（发现恶意版本可秒级全网拉黑）。建设投入与组织规模相关，但分层架构与防污染规则是共性要求。当生产环境的每一份制品都能回答"何时、从何上游、经何校验进入"，供应链的可观测性与可控性就同时成立，这也是后续漂移检测与应急响应的基础设施前提。
