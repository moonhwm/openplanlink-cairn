# 23 能力面审计：枚举与评估MCP工具暴露面

## 引言

一台MCP服务器暴露多少能力，决定了它失陷时能造成多大伤害。能力面审计的任务是完整枚举服务器声明的工具、资源、提示与所需权限，评估其与业务需要的匹配度，压缩多余暴露。本文给出能力面的枚举方法、暴露度评估模型与裁剪策略。

## 一、能力枚举

枚举要覆盖四类能力。工具能力：全部工具的名称、描述、输入输出结构，标注每个工具的副作用类型（只读、写入、执行、外发）。资源能力：服务器暴露的资源范围（路径、数据集、服务端点），标注数据敏感级别。提示能力：预置提示模板的内容与用途。环境能力：启动所需的文件系统范围、网络访问、凭据类型、子进程权限。枚举产出统一的能力清单，每项附"业务理由"字段——说不清用途的能力就是裁剪候选。能力清单应与代码审计的出口清单（第19篇）交叉验证：声明的能力与代码实际出口不一致，本身就是审计发现。

## 二、暴露度评估

用四个维度给每台服务器算暴露度。维度一，数据接触：能否读取敏感数据（凭据、客户数据、内部文档），级别从无到高。维度二，副作用深度：纯只读为最低，写入与执行依次升高，可外发数据为最高。维度三，权限宽度：文件范围（单目录到全盘）、网络范围（无出站到任意出站）、凭据数量。维度四，组合风险：与其他在用服务器组合后形成的链路（读取类加外发类的组合显著提升风险）。评估输出三档：低暴露（只读、数据范围窄）、中暴露（有写入或局域数据访问）、高暴露（高敏数据、可外发或可执行任意命令）。评估结论直接决定运行隔离强度与审计频率（高暴露服务器对应更严格的沙箱与更频繁的行为审计）。

## 三、裁剪策略与持续管理

能力面治理遵循"默认最小、按需申请、动态回收"：

```text
能力裁剪流程(服务器S):
  1. 依据业务场景列出必需能力最小集
  2. 能力清单逐项比对: 必需 -> 保留; 非必需 -> 关闭或剥离
  3. 无法关闭的多余能力: 以隔离补偿(降级数据/收窄网络/加确认)
  4. 高危工具默认确认模式, 生产稳定后再评估是否放开
  5. 变更触发重评: 版本升级/业务变化/安全事件
```

持续管理清单：

- 能力清单随版本更新，升级审查必含能力差异比对（新增工具与权限即新增审查项）；
- 暴露度评分纳入资产库，与隔离策略联动；
- 季度复核：不再使用的能力与工具即时回收；
- 同类功能服务器去重，减少总暴露面（三台功能重叠的服务器意味着三份风险）；
- 高暴露服务器的引入设定更高级别审批权；
- 能力面指标（在用工具数、高危工具占比、平均暴露度）纳入月度供应链报告。

## 结语

能力面审计把"这台服务器有多危险"变成可计算的问题：枚举求全，评估分维，裁剪求小。它与权限隔离互为表里——审计决定"该给多少"，隔离保证"只给到的能被执行"。在MCP生态服务器能力日益丰富的背景下，主动压缩暴露面是最直接的减害手段：失陷假设下，能力面每缩小一分，事故的上限就降低一分。
