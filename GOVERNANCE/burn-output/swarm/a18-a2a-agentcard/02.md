# 02｜AgentCard 核心 JSON 字段详解

## 一、字段总览与分类框架

AgentCard 的字段可以按"信任敏感度"分为三组：身份与可达性字段（决定"连到谁"）、能力与模态字段（决定"怎么协作"）、安全与治理字段（决定"凭什么信"）。这种分组不是协议原文的划分，而是安全审计视角的切法，便于后续逐组检查投毒面。

- **身份与可达性**：`name`、`description`、`url`、`version`、`provider`、`iconUrl`、`documentationUrl`；
- **能力与模态**：`capabilities`、`defaultInputModes`、`defaultOutputModes`、`skills`、`preferredTransport`、`additionalInterfaces`；
- **安全与治理**：`securitySchemes`、`security`、`protocolVersion`（版本协商治理）、以及带前缀的扩展字段。

## 二、逐字段语义与安全注意

`name` 与 `description` 是人类可读的身份描述，同时会被拼入客户端智能体的上下文——这意味着它们是提示注入的潜在载体，不能因其"只是文本"而放松审查。`url` 是 A2A 服务端点，是全卡片信任权重最高的字段之一：它决定后续所有 JSON-RPC 请求发往何处，篡改它等于劫持整条通信。`version` 标识卡片自身版本，`protocolVersion` 声明所遵循的 A2A 协议版本（如 `0.2.x`、`0.3.x`），客户端应校验二者匹配，避免"卡片版本新、协议行为旧"的漂移。

`provider` 是可选的对象，描述提供方组织（名称、URL、logo），可用于与企业注册信息交叉验证。`capabilities` 是布尔三开关：`streaming`（是否支持 SSE 流式）、`pushNotifications`（是否支持 webhook 推送）、`stateTransitionHistory`（是否暴露任务状态流转历史），三者直接影响客户端的调用形态选择。`defaultInputModes`/`defaultOutputModes` 是 MIME 类型数组，声明默认交互模态；`skills` 数组以 `id`、`name`、`description`、`tags`、可选 `inputModes`/`outputModes`/`examples` 刻画可分发到该智能体的任务类型。

```json
{
  "securitySchemes": {
    "oauth2": {
      "type": "oauth2",
      "flows": {
        "clientCredentials": {
          "tokenUrl": "https://auth.example.com/oauth/token",
          "scopes": { "a2a:invoke": "调用 A2A 接口" }
        }
      }
    }
  },
  "security": [{ "oauth2": ["a2a:invoke"] }]
}
```

`securitySchemes` 借鉴 OpenAPI 的命名复用，声明服务端支持的认证方案；`security` 是需求清单，指明实际调用时必须满足哪些方案与 scope。二者的组合语义是后续"认证降级攻击"分析的核心对象。

## 三、字段级风险标注

从投毒视角为每个高危字段建立风险标注，是审计 AgentCard 实现时的第一步：

- `url`：篡改即端点劫持，必须与签名/固定清单绑定；
- `skills[].description`：长文本进入客户端上下文，是注入指令的通道；
- `securitySchemes`/`security`：删改可诱导客户端降级到弱认证或无认证；
- `capabilities.pushNotifications`：若为 true，客户端可能注册 webhook，伪造该值可导致回调地址泄露或被诱导外联；
- `preferredTransport`/`additionalInterfaces`：声明额外接口与传输，可能引入降级到明文传输的入口；
- `version`/`protocolVersion`：不一致可能掩盖行为漂移与回滚攻击。

## 四、要点清单

- 按身份可达性、能力模态、安全治理三组理解字段，与安全审计视角对齐；
- `url` 与 `security*` 字段信任权重最高，任何变更都应触发告警；
- 文本类字段（name/description/skills）同时是上下文输入，需按注入载体对待；
- `capabilities` 布尔开关决定调用形态，伪造可造成行为误导；
- 字段语义的精确理解是后续 JWS 验签覆盖范围设计（哪些字段必须入签）的前提。
