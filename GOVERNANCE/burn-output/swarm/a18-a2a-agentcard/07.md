# 07｜能力发现的信任模型与信任起点

## 一、为什么"发现"本身是安全决策

能力发现常被当作纯功能性步骤（拿到卡片即开始调用），但从威胁建模看，它是整条信任链的起点：客户端把卡片内容注入自身的决策上下文与网络行为（拼提示词、发请求、注册回调）。起点的污染会以"合规执行"的形式向下传导，比运行时漏洞更隐蔽。因此发现阶段必须回答三个信任问题：这份卡片是谁发布的（主体身份）、内容是否被篡改（完整性）、此刻是否仍然有效（新鲜度与吊销状态）。三个问题分别对应身份绑定、签名验证、生命周期管理三组机制。

## 二、四种信任起点及其强度

按信任锚的位置，实践中存在四种起点模式：

- **域名锚定**：信任 = 对服务端域名的 DNS/证书信任。强度依赖 WebPKI，无法防御域内篡改与卡片层面的伪造（域名合法不代表卡片内容经域名所有者认可，除非引入签名）。
- **目录背书**：信任 = 目录运营方的筛选。强度等于目录方的审核质量，且目录本身可能成为单点投毒目标。
- **带外指纹**：合作前线下交换卡片指纹（如 SHA-256 摘要），发现后比对。强度高（锚定具体内容），但扩展性差，指纹轮换需要流程支撑。
- **签名链锚定**：卡片经提供方私钥 JWS 签名，公钥经 JWKS 发布并由可信根（企业根、目录公示、DNS 记录）背书。强度与可扩展性最好，是本系列的主推方案。

四种模式并非互斥：高安全场景应叠加域名锚定 + 签名锚定 + 指纹抽查。

## 三、TOFU 与首遇问题

"首次使用即信任"（TOFU，Trust On First Use）是签名方案落地时的现实补丁：客户端在首次发现某主体时记录其公钥/指纹，此后要求一致性。TOFU 把信任问题压缩为首遇时刻，但首遇若恰逢投毒（攻击者抢在真卡发布前布假卡），错误信任将固化。缓解手段包括：首遇强制人工确认（对高权限协作）、从多个独立信道交叉获取指纹比对（well-known 与 DNS TXT 记录、目录公示三方一致才采信）、以及首遇后短期内的高敏操作二次确认。TOFU 适用于中低风险场景的冷启动，高风险场景应以带外指纹或预置根为准。

## 四、要点清单

- 发现是信任链起点，需同时回答身份、完整性、有效性三个问题；
- 四种信任锚（域名、目录、带外指纹、签名链）强度与扩展性各异，可叠加；
- TOFU 解决冷启动但存在首遇投毒窗口，高权限场景需人工或多信道交叉；
- 信任起点的选择应写入客户端的安全策略配置，而非散落在代码分支里；
- 后续 JWS/JCS 系列文档即围绕"签名链锚定"这一主推方案展开。
