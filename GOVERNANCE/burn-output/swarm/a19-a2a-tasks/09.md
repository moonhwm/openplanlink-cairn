# 09. 状态迁移的合法路径与非法迁移防护

## 概述：状态机需要交通规则

状态枚举是词汇，迁移路径才是语法。任务生命周期里并非任何状态之间都能自由跳转：从completed回到working、从canceled跳到completed，都是语义灾难。协议虽然没有在规范正文里绘制完整的状态迁移图，但由状态语义可以推导出一组公认合法的路径。把这组路径固化成显式的迁移表，并在服务端入口处强制校验，是把状态机从"约定"升级为"设施"的关键一步。

## 合法迁移路径推导

合法迁移服从三条推导规则。规则一：非终态之间按语义流动。submitted可去queued或working或直接去任意终态（受理即拒绝产生rejected）；queued去working或终态；working可去input-required、auth-required，也可回落working（自我更新），还可去任意终态。规则二：交互性等待恢复后回到working。input-required与auth-required在客户端响应后进入working继续执行，也可能直接转终态（例如补充的信息仍不满足则failed，或客户端放弃则canceled）。规则三：终态是吸收态。终态没有任何出边，任何"从终态迁出"的请求都是非法。此外auth-required可通向canceled（放弃授权）。把上述规则整理成显式表，就是服务端实现的迁移白名单。

## 非法迁移的来源与危害

非法迁移不会凭空出现，它们来自四类现实来源：并发竞态（两个执行分支同时推进同一任务，各自带着过期的当前状态做判断）；重试重放（客户端重发旧消息，触发对已终态任务的续写）；内部bug（执行器异常路径直接改写状态字段）；以及恶意或劣质的对端实现。危害是连锁的：一次"completed后改failed"就可能让客户端已经消费的结果失去效力，下游流水线基于旧终态做出的决策全部需要回滚，审计链出现自相矛盾的记录。因此非法迁移必须当一等错误对待：拒绝、告警、留痕，而不是静默容忍。

## 迁移校验的实现模式

```python
LEGAL_TRANSITIONS = {
    ("submitted", "queued"), ("submitted", "working"),
    ("submitted", "completed"), ("submitted", "failed"),
    ("submitted", "canceled"), ("submitted", "rejected"),
    ("queued", "working"), ("queued", "completed"),
    ("queued", "failed"), ("queued", "canceled"),
    ("working", "working"), ("working", "input-required"),
    ("working", "auth-required"),
    ("working", "completed"), ("working", "failed"),
    ("working", "canceled"),
    ("input-required", "working"), ("input-required", "canceled"),
    ("input-required", "completed"), ("input-required", "failed"),
    ("auth-required", "working"), ("auth-required", "canceled"),
    ("auth-required", "failed"),
}

def transition(task, new_state):
    edge = (task.state, new_state)
    if edge not in LEGAL_TRANSITIONS:
        raise IllegalTransition(edge)   # 拒绝并告警，绝不静默放行
    persist_atomically(task, new_state) # 原子落库，防并发双写
```

## 迁移防护要点清单

- [ ] 把合法迁移固化为显式白名单表，与业务代码解耦；
- [ ] 终态无出边，任何从终态迁出的请求一律拒绝；
- [ ] 状态落库必须原子（条件更新/乐观锁），防并发双写；
- [ ] 迁移失败要告警留痕，作为对端质量与自身bug的信号；
- [ ] 客户端重发旧消息命中去重逻辑，而不是触发新迁移；
- [ ] 状态迁移与副作用（通知、事件发布）要么原子要么有补偿；
- [ ] 迁移表要有单元测试全覆盖，包括全部非法边。

## 小结

迁移白名单是状态机的交通法规：合法路径由状态语义推导，非法迁移由显式表拦截。工程重心有二：一是校验前置，让非法请求进不了落库层；二是落库原子，让并发竞态无法产生双写。迁移表配上全覆盖测试，任务状态机才配得上"机器"二字。
