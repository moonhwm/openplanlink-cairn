# Origin验证与DNS重绑定防护：本地HTTP服务器的安全基线

**一句话摘要**：本文解释MCP规范对本地Streamable HTTP服务器强制的安全基线——校验Host与Origin头防DNS重绑定、绑定回环地址、拒绝跨源请求——并给出可复用的中间件实现与测试方法。

## 一、威胁模型：为什么本地HTTP端口需要防"网页"

一个只监听127.0.0.1的MCP服务器看似与公网绝缘，但它面对一个经典Web威胁：DNS重绑定（DNS Rebinding）。攻击链是这样的：用户浏览器访问恶意网站evil.example，该站点的DNS记录被攻击者控制，可以先把域名解析到攻击者服务器加载恶意脚本，随后把同一域名重新解析到127.0.0.1；此时页面里的JavaScript向http://evil.example:port/mcp发请求，浏览器实际连的是用户本机的MCP端口。由于请求源是"网页"而非MCP客户端，若服务器不校验来源，恶意网页就能以本地用户身份调用MCP服务器上的工具——读取文件、执行命令、访问内网资源，危害不亚于任意命令执行。同理，公网上任意网站的页面也可以直接尝试http://localhost:port/mcp（浏览器虽用同源策略保护响应读取，但简单请求仍会发出，跨源读取在某些CORS误配下也会被放开），因此仅"绑定回环"不足以自保，必须辅以请求层校验。MCP规范据此规定：本地HTTP绑定必须校验Host头（只允许localhost、127.0.0.1、[::1]等本地名与配置端口），必须校验Origin头（存在且不在白名单即拒绝），远程HTTP绑定也建议做Origin或等价的来源校验。

## 二、校验规则细节

Host校验的语义：Host头必须精确匹配本地回环主机名（localhost、127.0.0.1、[::1]，或显式配置的额外本地主机名）加上服务器监听端口。收到其他Host（例如攻击者域名的重绑定请求会带着evil.example:port的Host）一律403拒绝。Origin校验的语义分三种情形：请求无Origin头（curl、SDK的非浏览器客户端通常如此）——放行，因为非浏览器客户端不受重绑定威胁且会按规范自带认证；Origin为http://localhost:*、http://127.0.0.1:*等本地源——放行（本地开发页面场景）；Origin为任何其他值——403拒绝，并禁止通过宽松的Access-Control-Allow-Origin: *把接口暴露给任意网页。此外，凡是放行跨源浏览器访问的实现，都应避免给"简单请求"回配通配CORS，必要时仅允许具体本地源且不启用凭据透传。这些规则合起来切断重绑定的两个必要条件：错误的Host与网页来源的请求。

## 三、防护中间件的参考实现

下面是一段可直接接入Express/Fastify风格管线的校验中间件（TypeScript），逻辑与官方SDK内置防护一致：

```typescript
import type { Request, Response, NextFunction } from "express";

const LOOPBACK_HOSTS = new Set(["localhost", "127.0.0.1", "[::1]"]);

function hostAllowed(hostHeader: string | undefined, port: number): boolean {
  if (!hostHeader) return false;
  // 剥离端口：注意IPv6形式 host:port 的括号
  let host = hostHeader.trim().toLowerCase();
  if (host.endsWith(`:${port}`)) host = host.slice(0, -(`:${port}`).length);
  else { // 无端口或非默认写法也容忍，仅取主机部分
    const i = host.lastIndexOf(":");
    if (i > host.lastIndexOf("]")) host = host.slice(0, i);
  }
  return LOOPBACK_HOSTS.has(host.replace(/^\[|\]$/g, ""));
}

function originAllowed(origin: string | undefined): boolean {
  if (origin === undefined) return true;           // 非浏览器客户端
  try {
    const u = new URL(origin);
    const h = u.hostname.replace(/^\[|\]$/g, "");
    const isLocal = LOOPBACK_HOSTS.has(h) || h.endsWith(".localhost");
    return isLocal && (u.protocol === "http:" || u.protocol === "https:");
  } catch { return false; }
}

export function dnsRebindingGuard(port: number) {
  return (req: Request, res: Response, next: NextFunction) => {
    const okHost = hostAllowed(req.header("host"), port);
    const okOrigin = originAllowed(req.header("origin"));
    if (!okHost || !okOrigin) {
      // 双重失败原因都记录，方便排障；拒绝信息对外保持简短
      req.app.locals?.log?.warn?.({ host: req.header("host"),
        origin: req.header("origin") }, "blocked possible DNS rebinding");
      res.status(403).json({ error: "forbidden origin/host" });
      return;
    }
    next();
  };
}

// app.use(dnsRebindingGuard(3000)); 且监听地址用 127.0.0.1 而非 0.0.0.0
```

## 四、配套基线与验证清单

除Host/Origin校验外，本地HTTP MCP服务器的完整安全基线还包括：监听地址显式绑127.0.0.1（需要局域网访问时再显式放开并加认证，绝不默认0.0.0.0）；不依赖CORS做安全机制（CORS是浏览器的读取保护，不是服务器的访问控制）；若配TLS则证书校验不可关闭；日志中不回显完整请求头以防泄露cookie类信息。验证方法清单：用curl带伪造Host（-H "Host: evil.example:3000"）应得403；用curl不带Origin应通；模拟浏览器带Origin: http://evil.example应403，带Origin: http://localhost:5173应通；用nmap从外部扫描确认端口未暴露到非回环接口；回归用例把这些断言固化，防止后续重构悄悄削掉防护。这条防线成本极低、收益极大，是所有本地HTTP MCP实现的上线前置项。
