# Kotlin SDK的HTTP传输与Android场景适配

**一句话摘要**：本文讲解Kotlin官方MCP SDK（modelcontextprotocol-kotlin-sdk）的传输体系——Ktor驱动的HTTP/SSE传输、JVM与Android多目标构建、协程结构化并发下的会话管理——并给出Android端集成MCP客户端与服务器的实战要点。

## 一、Kotlin SDK的传输家族与Ktor底座

Kotlin官方SDK以Ktor为网络底座、以Kotlin协程为并发模型，传输家族覆盖：StdioClientTransport/StdioServerTransport（进程管道，语义同19篇）、HttpClientSse（旧版双端点）、HttpClientStreamableHttp（新版单端点）、以及服务端基于Ktor embeddedServer或route挂载的SSE/Streamable HTTP处理器。SDK采用Multiplatform工程结构，核心协议层面向common目标，IO层按平台分置，JVM目标最成熟，Android目标经Ktor的okhttp引擎可用——这使"手机作为MCP客户端连接远程服务器"与"手机本地运行轻量MCP服务器供其它设备访问"都成为一等公民场景。传输接口形状与其它语言一致：connect()建立、sendMessage()发送并返回挂起函数、close()关闭、入站经SharedFlow回调，全部以suspend/Flow表达，天然贴合结构化并发。

协程模型带来的差异点值得点名：其一，消息收发跑在CoroutineScope上，绑定的生命周期必须显式管理——Android上严禁用GlobalScope，应该用viewModelScope或自定义的SupervisorScope，界面销毁即取消传输；其二，SSE流的背压由Flow的buffer/onBufferOverflow策略决定，慢消费时默认挂起而非丢弃，要根据场景选SUSPEND/DROP_OLDEST；其三，取消即关闭——协程取消会级联到Ktor请求，传输的onclose依赖这个级联语义，手动管理线程池反而容易漏。

## 二、Android客户端集成实战

Android端最常见的需求是作为客户端连远程MCP服务器获取工具能力。要点依次是：网络权限与明文策略（targetSdk 28+默认禁明文HTTP，远程MCP应走https或在debug清单里显式允许localhost）；Ktor引擎选okhttp并配置连接/呼叫超时；SSE流要考虑应用切后台被系统冻结——长连接适合前台服务（Foreground Service）保活，普通Activity生命周期内使用则要接受断流重连；token等认证材料存Keystore而非常量。骨架代码：

```kotlin
// 依赖：io.modelcontextprotocol.sdk:kotlin-sdk + ktor-client-okhttp
class McpClientEngine(private val scope: CoroutineScope) {
  private var client: Client? = null
  private var transport: HttpClientStreamableHttp? = null

  suspend fun connect(endpoint: String, token: String) {
    val t = HttpClientStreamableHttp(
      endpoint = endpoint,
      httpClient = httpClientOf(token),           // 见下
    )
    val c = Client(transport = t, scope = scope)  // 结构化并发：scope取消即断
    c.initializeBlockingCompat()                  // 完成initialize握手
    client = c; transport = t
  }

  private fun httpClientOf(token: String) = HttpClient(OkHttp) {
    install(HttpRequestRetry) { retryOnServerErrors(3); exponentialDelay() }
    install(HttpTimeout) {
      requestTimeoutMillis = 30_000
      // SSE长流不适合套request超时：对流式请求单独放宽
    }
    defaultHeaders {
      append(HttpHeaders.Authorization, "Bearer $token") // 真实项目从Keystore取
    }
  }

  suspend fun callTool(name: String, args: JsonObject): JsonObject? =
    client?.let { c ->
      c.callTool(name, args).let { res -> res.content as? JsonObject }
    }

  fun shutdown() { scope.launch { transport?.close() } }
}

// Activity/ViewModel中：
// val scope = CoroutineScope(SupervisorJob() + Dispatchers.IO)
// engine = McpClientEngine(scope); engine.connect(url, token)
// onDestroy: scope.cancel() —— 级联关闭传输，无泄漏
```

## 三、Android本地服务器与边界条件

Android作为MCP服务器（供PC端IDE连手机调试、或局域网设备共享手机能力）时的要点：Ktor embeddedServer绑定到0.0.0.0才能被局域网访问，必须同时启用Origin/Host校验（10篇）与简单配对码认证，因为移动网络环境不可信；前台服务声明前台服务类型并通知用户；电池策略下长连接会被Doze打断，服务器形态建议按需启停而非常驻；本机回环形态（App内部组件间用MCP通信）可用内存传输替代网络栈，省电且无权限问题。边界条件清单：网络切换（WiFi↔蜂窝）后SSE流必须重建，重连逻辑放前台服务里；应用进程被杀后的冷启动要能自动恢复会话（重新initialize+重放订阅）；TLS证书固定（certificate pinning）按企业策略配置；ProGuard/R8规则保留SDK的序列化模型类。

## 四、验收清单

JVM/Android双端验收清单：stdoio与HTTP两类传输在JVM冒烟通过；Android真机上前后台切换、飞行模式开合、进程被杀三类扰动后的恢复行为符合预期；无GlobalScope、无未捕获异常（接入CoroutineExceptionHandler）；token不入日志不入常量；本地服务器形态的Origin校验用例齐备；弱网模拟（限速加丢包）下超时与重试表现合理；内存剖析确认每会话对象随关闭释放。达成后，Kotlin/Android侧的MCP传输即达到可用于生产的工程水位。
