# Java SDK传输实现体系与Servlet集成

**一句话摘要**：本文梳理Java官方MCP SDK（io.modelcontextprotocol.sdk:mcp）的传输体系——McpTransport接口、StdioServerTransport与HttpClientSse/WebFlux双栈的HTTP传输、基于McpServlet注解的Servlet容器集成——并给出Spring Boot场景的落地要点与清单。

## 一、Java SDK的传输家族地图

Java SDK按运行时栈分成两大分支，传输类随分支成对出现。反应式分支基于Project Reactor：核心接口McpTransport约定connect(McpTransportConsumer)、sendMessage(McpSchema.JSONRPCMessage)返回Mono<Void>、closeGracefully()、unmarshalFrom(String)等；对应实现有StdioClientTransport（拉起子进程的reactor版）、HttpClientSseClientTransport（旧版SSE客户端）、HttpClientStreamableHttpTransport（新版单端点客户端）以及服务端的Servlet系传输。同步/Servlet分支面向传统容器：McpAsyncService与McpSyncService包裹同一Server逻辑，服务端HTTP通过McpServlet暴露——一个继承HttpServlet的抽象类，子类只需提供ServerSessionProvider，doGet/doPost/delete由父类实现好SSE流、JSON应答、会话头处理。这种"一份协议内核、两种并发模型"的结构让Java生态既能贴WebFlux的响应式管道，也能贴war/传统Spring MVC部署。

值得注意的版本演进：早期0.x版本HTTP传输默认旧版HTTP+SSE语义（GET /sse+POST /message），后续版本加入Streamable HTTP实现与配套开关；迁移期SDK常提供双模开关，升级时要核对默认值变化。此外Java SDK对stdio子进程的构造通过ServerTransportProvider注入命令参数，处理了Windows的cmd包装与进程树终止，这与19篇的Node实现语义一致。

## 二、Servlet集成的机制与代码

McpServlet把规范第06、07、09篇的语义固化进doGet/doPost/doDelete：POST解析单条JSON、按会话头路由到ServerSession、决定回JSON还是SSE流（通过startFromConcreteAsync提交消息并把响应写回流）；GET开推送SSE并注册会话的downstream；DELETE终结会话。集成到Spring Boot的样板如下：

```java
// 依赖：io.modelcontextprotocol.sdk:mcp + spring-boot-starter-web（Servlet栈）
@Configuration
public class McpServletConfig {

  @Bean
  public McpAsyncServer mcpServer(ObjectMapper mapper) {
    McpServerFeatures.SyncToolSpecification echo =
        McpServerFeatures.SyncToolSpecification.builder()
            .tool(McpSchema.Tool.builder()
                .name("echo")
                .description("回显文本")
                .inputSchema(Map.of("type", "object",
                    "properties", Map.of("text", Map.of("type", "string")),
                    "required", List.of("text")))
                .build())
            .callHandler((exchange, req) -> {
              McpSchema.CallToolResult out = new McpSchema.CallToolResult(
                  List.of(new McpSchema.TextContent(
                      String.valueOf(req.arguments().get("text")))), false);
              return out;
            })
            .build();

    return McpServer.async(mapper)
        .capabilities(McpSchema.ServerCapabilities.builder()
            .tools(true).logging().build())
        .serverInfo("java-demo", "1.0.0")
        .addTool(echo)
        .build();
  }

  @Bean
  public HttpServlet mcpServlet(McpAsyncServer server) throws Exception {
    // McpServlet：父类实现POST/GET/DELETE的传输语义，这里只接线会话提供者
    return new McpServlet() {
      private final ServerSessionProvider provider =
          new StandardServletServerSessionProvider(); // 按会话头建/查会话
      @Override protected ServerSessionProvider provider() { return provider; }
      @Override protected McpAsyncServer server() { return server; }
    };
  }
}
// 再用ServletRegistrationBean把该Servlet映射到 /mcp，即完成HTTP端点暴露
```

反应式分支则用HttpServlet之外的一套：Spring WebFlux应用把McpWebFluxServerAutoConfiguration提供的路由挂上RouterFunction，行为等价、载体换成Reactor Netty。两分支都内置了Origin校验钩子（10篇基线），公网部署前必须显式配置允许的来源。

## 三、运维与并发要点

Java侧特有要点：线程模型——同步服务的callHandler跑在Servlet容器线程池上，工具内部若做长阻塞IO要给出独立线程池并设超时，防止拖垮容器；HttpClientSse的断流重连由SDK的restart策略控制，网关空闲超时要与其对齐；JVM进程托管多个会话时注意每会话的对象图（订阅、挂起请求）设上限并接入会话清扫；日志走SLF4J，确保无任何输出流向stdout之外的协议通道以外路径造成污染（Servlet场景stdout不是协议通道，风险低于stdio，但stdio模式下要复查System.out调用）；GraalVM原生镜像场景要核对传输对进程spawn与反射的配置。

## 四、验收清单

交付Java HTTP端点时的核对清单：initialize签发会话、后续无会话头404、DELETE终结（对应09篇矩阵）；POST双形态（JSON与SSE）按工具特性正确选择；GET流心跳与网关超时对齐；Origin/Host校验中间件启用且测试用例覆盖伪造Origin被403；旧版双端点与新版单端点若并存，指标可区分；客户端SDK（Java版）与服务端（其它语言）互操作冒烟通过；压测下容器线程池与每会话内存曲线平稳。这份清单加两分支选型判断（团队技术栈是WebFlux还是MVC），即构成Java侧传输决策与交付的完整闭环。
