# stdio场景下的环境变量与密钥注入风险

**一句话摘要**：本文剖析stdio绑定特有的凭据面——子进程继承宿主全部环境变量带来的泄露与混淆攻击、配置文件中的明文令牌问题、最小注入原则与密钥引用模式，并给出客户端与服务器两侧的加固清单。

## 一、继承即暴露：stdio的默认凭据面

stdio客户端拉起服务器子进程时，若不做处理，子进程默认继承父进程（宿主应用）的完整环境变量表。这在两个方向上制造风险。方向一，横向泄露：宿主进程的环境里往往躺着大量高价值材料——云平台临时凭据、CI令牌、数据库连接串、API密钥；一个第三方MCP服务器拿到完整环境，等于拿到了宿主的全部钥匙，而用户在安装"一个格式化工具"时绝无授予"读我云账号"的预期。方向二，混淆代理（confused deputy）：恶意或被入侵的服务器读取宿主环境中的令牌，以宿主身份调用外部服务，操作全部记在宿主账户头上——MCP安全指引明确把"环境变量窃取"列为stdio场景的一级威胁。此外还有被动泄露：服务器把环境快照打进崩溃报告/诊断接口（"上传环境帮助排障"类功能），或第三方依赖库顺手收集环境上 telemetry。

客户端侧的对应责任：不要无脑spawn(env: process.env)；默认最小集注入（PATH等运行必需项），按服务器配置白名单逐项追加；对"此服务器需要GITHUB_TOKEN"类配置，让用户显式声明变量名并仅注入该变量；宿主UI在服务器详情页展示"此服务器将获得的环境变量清单"，把隐性授权变显性。

## 二、服务器侧的接收纪律

服务器侧同样有纪律：只读自己需要的变量，绝不扫描环境表（enumerate环境并存盘、上报的功能要视为红线）；启动时对缺失的关键变量给出精确报错（缺DATABASE_URL就说它，别打印整张表）；日志与崩溃报告中过滤已知敏感模式（名字含TOKEN/KEY/SECRET/PASSWORD的变量值脱敏）；配置优先级建议环境变量<配置文件<密钥库引用，敏感材料尽量走外部密钥管理（文件挂载的凭据、系统keychain、编排层Secret），环境变量只放引用标识。一个实用模式是"密钥引用解引用"：环境里只放MYSTORE_REF=keyring://prod/db，服务器启动时从系统凭据库解引用，内存中持有材料、环境与磁盘均无明文。

## 三、最小注入的实现

```typescript
import { spawn } from "node:child_process";

// 宿主白名单模式：默认最小集 + 显式allowlist
const BASE_VARS = ["PATH", "HOME", "LANG", "SYSTEMROOT", "TEMP", "TMP"];
// Windows需要SYSTEMROOT等；Unix下HOME/PATH/LANG基本够用

export function buildChildEnv(
  allowed: string[],                       // 用户为该服务器声明的变量白名单
  overrides: Record<string, string>,       // 显式配置值
): NodeJS.ProcessEnv {
  const env: Record<string, string> = {};
  for (const k of BASE_VARS) {
    const v = process.env[k];
    if (v !== undefined) env[k] = v;       // 最小基底
  }
  for (const k of allowed) {
    const v = process.env[k];
    if (v !== undefined) env[k] = v;       // 白名单透传（显式授权）
  }
  return { ...env, ...overrides };
}

const child = spawn("node", ["server.js"], {
  env: buildChildEnv(
    ["GITHUB_TOKEN"],                      // 用户明确授予的唯一敏感变量
    { MCP_LOG_LEVEL: "info" },             // 非敏感配置直配
  ),
  stdio: ["pipe", "pipe", "pipe"],
});
```

## 四、加固验收清单

交付与评审stdio集成时的验收清单：抓包式验证——子进程内执行env导出，结果仅含最小集+白名单项（用例断言宿主敏感变量不出现）；配置文件扫描无明文令牌（CI加secret scanning）；服务器侧无全环境枚举/上报代码路径（代码评审+依赖审计）；崩溃报告与日志的脱敏用例（构造含令牌的环境，检查输出无泄露）；密钥引用模式下的磁盘与环境扫描无明文材料；文档向用户披露所需变量及其用途（知情基础）；供应链核对——服务器实现方的发布物与npm/pypi包名一致，防止仿冒包骗取环境（独立于传输层但常与env窃取联动）。这份清单把stdio"方便的继承"改造成"受控的授予"，是本地集成安全的底线工程。
