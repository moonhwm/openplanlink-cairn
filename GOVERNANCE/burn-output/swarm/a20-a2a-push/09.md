# 09 · TaskStatusUpdateEvent与TaskArtifactUpdateEvent的推送差异

## 一、问题背景

A2A事件体系里两大高频事件是任务状态更新（TaskStatusUpdateEvent）与制品更新（TaskArtifactUpdateEvent）。前者描述任务机身的跃迁，后者描述任务产物的增量产出。二者在推送频率、载荷形态、终态语义上差异显著，混用一套投递策略会导致制品风暴压垮通道，或状态事件被制品洪流淹没延误终态感知。

## 二、维度差异对比

频率维度：状态事件稀疏且关键，一个任务生命周期内通常个位数；制品事件密集且可容忍延迟，流式回答场景下可能每秒多条。载荷维度：状态事件小而结构固定（from、to、message可选）；制品事件可能携带分块内容，必须支持分片字段（artifactId、chunkIndex、lastChunk）与"引用优先"策略——大内容放对象存储链接，事件体只带指针。终态语义：状态事件有明确的final标记，final之后通道应停发；制品事件没有天然终点，通常由状态事件的completed来封口，因此消费端要能处理"制品块到达晚于completed"的竞态。可靠性要求：状态事件（尤其final）丢失代价极高，必须高优先级重试；制品块丢失可通过任务制品接口补拉，优先级可以更低。

## 三、差异化投递的配置骨架

```python
PUSH_PROFILES = {
    "status": dict(priority=0, max_attempts=10,
                   backoff_base=2.0, timeout=(3, 10)),
    "artifact": dict(priority=3, max_attempts=4,
                     backoff_base=5.0, timeout=(3, 30),
                     coalesce_window_ms=200),
}

def route(evt):
    kind = "status" if evt.type.endswith("status-update") else "artifact"
    p = PUSH_PROFILES[kind]
    if kind == "artifact":
        evt = coalesce_partial_chunks(evt, p["coalesce_window_ms"])
    return queue.enqueue(priority=p["priority"], profile=p, event=evt)
```

优先队列保证状态事件插队，制品事件允许小窗口合并相邻分块以削减请求次数。

## 四、落地检查清单

- 状态与制品是否使用独立投递配置与优先级
- final状态事件是否进入最高优先级通道
- 制品事件是否引用优先、指针化大内容
- 分块字段是否完整（artifactId、chunkIndex、lastChunk）
- completed与晚到制品块的竞态是否有处理规则
- 制品通道是否有合并窗口与速率上限
- 两类事件是否共享eventID去重而配置互不影响
- 消费文档是否分别给出两类事件的处理示例

按事件类别分化投递策略，是通知语义精细化落地的关键一步。
