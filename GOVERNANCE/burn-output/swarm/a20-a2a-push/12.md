# 12 · 通知语义中的可见性与隐私：最小化披露原则

## 一、问题背景

推送通道天然外发数据：事件要经过发送方出口、网络、可能的代理、以及消费方入口。如果事件体里混入了内部主机名、用户身份细节、完整 prompt 或中间推理内容，推送系统就变成了数据泄露管道。通知语义设计必须内建"最小化披露"原则：事件只携带完成路由与处理所必需的字段，其余一律以引用或脱敏形式表达。

## 二、三层披露控制

第一层是字段最小化：逐字段质询"消费方没有这个字段能否完成任务"。路由必需的taskId、eventType、seq必须保留；用户级身份信息用不可逆替身（pseudonymous ID）表达；中间推理、原始输入除非下游显式订阅且授权，否则不出事件体。第二层是载荷指针化：大内容与敏感内容放对象存储，事件体只带短时效签名URL，链接本身设过期与单次有效限制，越权窗口被压缩到分钟级。第三层是通道内加密与签名：传输层强制TLS1.2以上；消息层加HMAC签名防篡改、防伪造（签名密钥通过独立通道分发，绝不写入事件体）；必要时对data字段做信封加密，仅授权消费者可解。可见性还包括元数据层面：生产者标识、时间戳等路由元数据也可能泄露拓扑，跨信任域转发时应允许剥离。

## 三、脱敏与签名的实现示意

```python
ALLOWED_FIELDS = {"eventID", "eventType", "occurredAt",
                  "sequenceNumber", "taskId"}

def minimize(evt):
    safe = {k: evt[k] for k in evt if k in ALLOWED_FIELDS}
    if "data" in evt:
        safe["data"] = redact(evt["data"], policy=CURRENT_POLICY)
        if size(safe["data"]) > LIMIT:
            safe["dataRef"] = signed_url(evt, ttl=300)
            del safe["data"]
    return safe

def sign(payload: bytes, key: bytes) -> str:
    ts = now_unix()
    mac = hmac.new(key, f"{ts}.".encode() + payload, "sha256")
    return f"t={ts},v1={mac.hexdigest()}"
```

消费端验签时校验时间戳偏差（建议五分钟内）以阻断重放窗口。

## 四、落地检查清单

- 是否建立事件字段白名单并默认拒绝白名单外字段
- 身份信息是否替身化、敏感内容是否脱敏或指针化
- 签名URL是否短时效且限单次使用
- 是否强制TLS并禁用降级
- HMAC签名是否带时间戳并校验偏差
- 跨信任域转发是否剥离内部元数据
- 是否有事件体敏感词扫描的上线前检查
- 隐私策略变更是否有事件schema的评审流程

最小化披露让推送通道在承担通知职责的同时不成为泄露面，这是语义设计的收口篇。
