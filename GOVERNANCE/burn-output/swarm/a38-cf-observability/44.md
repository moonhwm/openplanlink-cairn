# 单位经济学：每次请求成本与成本效率指标体系

> 一句话摘要：本文定义云函数的单位经济学指标集——每千次调用成本、单位业务量成本、观测成本占比、成本收入比，讲解其计算管道、基准管理与驱动决策的用法。

## 一、从总成本到单位成本：视角的升级

总成本回答"花了多少"，单位成本回答"效率如何"，而只有后者支持跨时间、跨规模、跨业务的公平比较。场景对比：A月成本十万、月订单一百万单，每单成本零点一元；B月成本二十万、订单三百万单，每单成本零点零七元——B更贵但更高效，规模化健康。单位成本的三层价值：其一趋势预警，总成本随业务涨是正常的，单位成本涨才是效率恶化的信号（第42篇模式二检测的基础）；其二横向对标，不同服务、不同租户、新旧版本的单位成本可比；其三决策输入，单位成本×业务量预测即预算模型，比拍脑袋的预算精确一个量级。

## 二、核心指标集的定义与计算

四个核心单位经济学指标。指标一每千次调用成本（CPC，Cost Per Kilo-Call）：函数计算与请求费用除以调用量×1000——技术口径的最小单位成本，衡量函数本身的运行经济性；要剔除外部流量费单独看（流量费由响应大小决定，与函数效率无关）。指标二单位业务量成本：服务成本除以业务计量（每订单、每笔支付、每GB处理、每活跃用户）——业务口径的成本，管理层与财务的语言；数据来自成本管道（第40篇）与业务计量打点（第25篇业务计数器）的关联，两者都必须有服务与时间维度才能 join。指标三观测成本占比：日志加追踪加指标费用除以被观测系统的计算费用——衡量观测体系自身的经济性，健康区间百分之十到三十，超过三十说明采样与保留策略要收紧（第09、14、19篇），低于百分之五可能观测不足（该采的没采）。指标四成本收入比（面向商业系统）：服务成本除以该业务收入——终极口径，识别"越卖越亏"的业务单元；需要收入数据接入，通常做到业务线粒度即可。

指标计算管道示例：

```sql
-- 每日按服务计算单位经济学指标(数据仓库SQL示意)
SELECT
  date, service,
  cost_total_cny,
  invocations,
  biz_orders,                       -- 业务计数器(第25篇)
  cost_total_cny / invocations * 1000      AS cpc_cny,
  cost_total_cny / NULLIF(biz_orders,0)    AS cost_per_order,
  obs_cost_cny / NULLIF(compute_cost_cny,0) AS obs_ratio
FROM dws_cost_daily  c
JOIN dws_biz_daily   b USING (date, service)
-- 产出进指标库与看板(第41篇视图三)，配环比告警(第42篇)
```

## 三、基准管理与归因分解

单位成本要有基准（baseline）才能判断好坏。基准的三种建立法：历史基线（过去九十天的中位数）、同型基线（同类函数的分位数，如"IO型函数的CPC分布"）、外部参照（业界公开的量级参考，仅作方向校验）。偏离基准的处置：CPC偏离同型基线两倍以上进优化清单（第43篇解剖：是内存档位、执行时长还是架构问题）；每单成本环比恶化超百分之二十触发归因分析。归因分解的标准动作：把单位成本变化拆成因子——调用量因子（摊薄固定成本）、时长因子（执行变快慢）、单价因子（调价或档位变化）、结构因子（新函数占比）——用两期对比的乘法分解（类似第41篇瀑布），找到主导因子再下钻。一个常见陷阱：分母失真。业务量指标口径变化（统计规则调整、漏埋点）会让单位成本"假涨"，归因时先验分母的稳定性（业务计数与日志对账，第25篇）。

## 四、用单位经济学驱动决策的三个场景

场景一容量与预算决策：业务方给出明年订单量预测（×3），用当前每单成本直接推算增量预算=预测增量×每单成本×(1+效率改进系数)——比"去年预算×3"更能说服财务，也暴露规模不经济的风险点。场景二架构选型：同一需求两种实现的单位成本对比——同步函数链（每次一毛）vs事件驱动异步链（每次七分），叠加时延与错误率一起决策；重大迁移的论证必须有单位经济学测算（"迁移后每单成本从X到Y，年省Z"）。场景三租户与产品线经营：按租户的每租户服务成本对比其收入贡献，亏损租户进入商务谈判或架构优化流程；内部结算（chargeback）用单位成本定价，让资源消耗对业务方可见，倒逼各团队自发优化——这是单位经济学的组织学价值：把成本责任翻译成业务方能理解的每单几分钱。

单位经济学落地清单：

```text
[ ] 四指标管道: CPC/每业务量成本/观测占比/成本收入比
[ ] 成本数据与业务计数器按服务+时间维度可join
[ ] 三种基准(历史/同型/外部)建立；偏离2倍进优化清单
[ ] 归因分解四因子(量/时长/单价/结构)；先验分母稳定性
[ ] 预算推算、架构选型、租户经营三场景实际使用
[ ] 月度例会展示单位成本趋势而非仅总额
```

## 五、口径协商：与财务对齐语言

单位经济学要发挥对上沟通价值，必须与财务口径对齐：明确含税与否、云折扣（ RI/节省计划/商务折扣）是否折入单位成本、内部分摊费用（平台组、安全组的公共成本）如何摊入；建议双口径并行——工程口径（未摊牌前单价，用于技术优化对比）与财务口径（全摊后，用于预算与核算），看板注明口径切换。每季度与财务做一次口径对账会，差异写进备忘录。语言不通时再准的数字也只会制造分歧。

## 结语

单位经济学是成本观测的"汇率体系"：它把不同规模、不同业务、不同时期的成本折算到同一标尺，让每一次比较都公平、每一个决策都有数。当团队习惯用"每单成本"而非"总花销"谈论钱，成本意识就从月底的焦虑变成了日常的工程素养。
