# 值班响应与Runbook：从告警到处置的标准化

> 一句话摘要：本文讲解Runbook（值班手册）的结构设计、质量标准与维护机制，告警响应的标准动作（确认、止血、恢复、记录），以及新人可独立值班的训练路径。

## 一、Runbook：告警的"随叫随到的资深工程师"

一条告警的价值上限是它的Runbook质量：值班者（可能是新人、可能是凌晨三点被叫醒的人）收到告警后，第一件事就是打开链接。Runbook的结构标准七段。第一段症状概述：这个告警意味着什么、影响谁、多紧急——两句话说清。第二段第一响应清单：接警后五分钟内要做的三到五步（看哪个图、跑哪条命令、找谁确认），按"止血优先"排序。第三段诊断决策树：if-else分支（若劣化集中新版本→走回滚流程；若限流计数非零→扩容流程），每个分支给判据与跳转。第四段处置方案：止血（回滚、扩容、降级开关、切流）与根治（修复路径）分开写，凌晨只做止血。第五段升级条件：何时拉谁（第二线、主管、厂商支持），带联系方式占位。第六段历史案例：本告警的历史处置记录链接（每次事件后自动追加）。第七段验证恢复：怎么确认真的恢复了（看哪个指标回落到什么水平、持续多久）。质量红线：可执行性——每个步骤写具体命令与链接而非"检查网络"；时效性——六个月内被使用或校验过；任何人按册操作能在时限内完成第一步。

## 二、标准响应动作：确认、止血、恢复、记录

值班响应的四个标准动作。确认（Ack）：两分钟内在值班系统确认接手，升级计时停止；确认消息简述初步判断（"疑似发布回归，排查中"）。止血（Mitigate）：优先恢复用户服务而非找根因——可用手段按速度排序：回滚版本（分钟级，发布回归首选）、扩容/提高并发限额（容量类）、降级开关（关非核心功能保主干）、切流（摘除故障单元）；止血决策的依据是诊断树的最初两步，不必等完整定位。恢复验证：止血后盯关键指标（SLO燃烧率、错误率）回落并持续（十分钟以上），才算恢复。记录（Document）：处置过程中用时间线记录（14:02告警、14:05确认、14:07执行回滚、14:12燃烧回落），这条时间线直接成为复盘素材与Runbook案例积累。两个纪律：不做未记录的变更（凌晨的临时改动必须留痕，否则次日无人知道系统被动过）；超出Runbook的处置现场补录（"手册没写但有效"的招要回流进Runbook）。

Runbook模板骨架示例：

```markdown
# RB-1024: order-api P95燃烧快速告警(P1)
## 症状: 下单延迟SLO快速燃烧，用户下单变慢/超时
## 第一响应(5分钟内):
1. 打开总揽看板 http://grafana/d/order —— 看错误还是慢
2. 查最近2小时发布: http://ci/releases?svc=order-api
3. 版本切片对比P95(新旧版本) —— 新版本独有劣化? → 执行§回滚
## 决策树:
- 新版本劣化 → §回滚流程(RB-ROLLBACK)
- 限流计数>0 → §扩容流程(RB-SCALE): 并发300→600
- 下游db慢 → 联系dba值班(转P1)，同时评估§只读降级
- 无明显归因 → 采trace样本3个入工单，升级二线
## 验证恢复: 燃烧率<1且持续10min; 错误码分布恢复正常
## 升级: 20min未止血→order-lead; 涉及资金→风控组通报
## 历史案例: #E-881(8/12 回滚解), #E-905(8/30 扩容解)
```

## 三、Runbook的生命周期管理

Runbook是活文档，需要机制保鲜。归属：每本Runbook有owner，与服务归属一致（第34篇服务目录联动）。校验：每次真实使用后，使用者修正与实际情况不符的步骤（"这次实际用了扩容到800而非600"）；每季度owner通读校验一次链接、命令、联系方式有效性（失效链接是Runbook腐烂的第一征兆）。演练：季度混沌演练（第47篇）随机挑选高频Runbook执行，验证步骤真实可走通；演练发现的断点当周修复。覆盖率指标：P1/P2告警的Runbook覆盖率应为百分之百（没有Runbook的P1告警不允许存在，先降级或补册），P3覆盖率目标八成。度量Runbook有效性：平均首次正确处置率（按册走通的比例）、处置时长趋势、凌晨事件（人力最低谷）的MTTR对比。

## 四、值班能力建设：从新人到独立值班

值班能力是训练出来的。三步路径。第一步影子值班：新人跟随资深值班者两到四周，旁观全部动作，事后复述判断逻辑。第二步模拟演练：在演练环境注入故障，新人对着Runbook独立处置，考核"时限内完成第一响应"与"决策树走对分支"。第三段正式值班初期双人制：首月与资深者互为备岗，任何P1双人响应。持续能力建设：月度"故障案例会"复盘真实事件（比任何培训教材都好）；Runbook更新计入贡献（谁把手册改准了谁署名）。对管理者的要求：值班负荷与成长挂钩（过载的值班表留不住人），值班豁免制度透明（发布周减负）。

值班与Runbook检查清单：

```text
[ ] P1/P2告警Runbook覆盖率100%；七段结构齐备
[ ] 每步可执行(命令+链接)；止血与根治分开；凌晨只止血
[ ] 响应四动作标准: 确认→止血→验证→记录时间线
[ ] 未记录的变更是违规；超册处置回流手册
[ ] 季度校验+混沌演练走通；失效链接即断点修复
[ ] 新人三步训练；月度案例会；值班负荷透明
```

## 结语

Runbook把组织的排障经验固化成凌晨三点也可靠执行的步骤，值班制度把它与人的训练、考核、轮换编织在一起。当任何一次告警都能被"任何人、按册、在时限内"处置，可观测体系的最后一公里才算打通——观测的终点从来不是看见，而是行动。
