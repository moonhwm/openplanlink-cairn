# 指标聚合与粒度：从函数实例到全局视图

> 一句话摘要：本文讲解指标的多层聚合模型（实例—函数—服务—业务）、预聚合与降采样的取舍、聚合的数学陷阱（比率与分位数不可再平均），以及全局视图看板的组织方法。

## 一、四级聚合模型：谁在哪个层级看什么

指标的消费者在不同抽象层需要不同粒度，聚合模型应显式分层。层一实例级：单实例的运行时指标（GC次数、内存占用、连接池状态），主要服务于"这个实例异常吗"的微观诊断，保留期短（数小时到一天）且可不上全局看板。层二函数级：实例指标被聚合（sum/max/avg按语义定），加上函数的RED三件套——这是排障主力层。层三服务级：一个业务服务由多函数组成，服务级指标由函数级再聚合或直接从入口函数度量（推荐后者：服务可用性只在边界测量，内部函数异常应体现为入口的错误与耗时）。层四业务级：订单量、支付成功率、GMV口径的派生指标，由业务计数器与外部数据组合而成，供管理层与运营看。分层的纪律是"每层有自己的权威指标"，避免把函数级指标简单堆到业务层看板凑数。

聚合操作的选择要贴语义：调用量sum、错误数sum、错误率=sum错误/sum调用（比率永远后算）、并发max、内存max或avg、耗时用直方图桶sum后算分位数（第27篇）、水位gauge取max（看峰值）或last（看当前）按场景定。

## 二、聚合的数学陷阱：三类不可再平均

陷阱一比率的平均：各函数错误率百分之零、百分之十的平均是百分之五，但全局真实错误率取决于各自调用量权重——正确做法是分子分母分别聚合再相除。陷阱二分位数的平均：第27篇已述，各实例P95的平均不等于全局P95，必须聚合桶计数。陷阱三计数器的瞬时采样：把计数器当gauge采样再差值，会因采样丢失重启期间的增量；正确做法是rate()语义（时间窗增量/窗长），且接受实例重启导致的低估（可用increase近似修正）。这三类陷阱是看板配置错误的重灾区，验收时专查"比率、分位数"两类面板的查询语句。

## 三、预聚合与降采样：长期视图的成本工程

实时查询在原始数据上算分位数既慢又贵，长期看板依赖两层加工。预聚合（rollup）：定时任务把细粒度数据聚合成粗粒度——如每五分钟把一分钟的直方图桶求和、计数器求增量，落成"五分钟序列"；再进一步每小时聚合成"小时序列"。降采样（downsampling）：旧数据只保留粗粒度（如三十天后只留小时级），配合第30篇的存储策略。两条纪律：预聚合必须用可聚合的形态（桶计数求和、分子分母分开存，绝不存已算好的比率），否则粗粒度层无法再聚合；分位数在每层重算而非传递，因为不同层样本集不同。预聚合任务的正确性要有验收：抽样比对粗粒度与细粒度重算结果，偏差超百分之一告警。

预聚合配置示例：

```yaml
rollups:
  - source: invoke_duration_ms_bucket      # 1分钟原始
    target_5m:  { op: sum, by: [function, le] }        # 桶求和
    target_1h:  { op: sum, by: [function, le] }
  - source: invoke_errors_total
    target_5m:  { op: delta }               # 存增量而非累计
  - source: invoke_count_total
    target_5m:  { op: delta }
  derived:                                   # 比率看板层现算
    error_ratio_5m: errors_delta_5m / count_delta_5m
  retention:
    raw: 15d; 5m: 90d; 1h: 400d
```

## 四、全局视图的组织：从告警到总揽

全局视图（排障起点页）的组织原则：第一屏四象限——流量（全局调用量与Top函数）、错误（全局错误率与劣化Top）、时延（核心服务P95）、饱和（并发水位、限流计数、队列积压），即四大黄金信号的宏观版。每个数字可点击下钻到对应函数层。看板信息层级：全局层只放十几个关键数字，细节留给函数层；用变量模板（按function/env过滤）一套看板复用所有函数，避免几十个复制粘贴的面板漂移失修。全局层的"Top N劣化榜"（错误率环比、P95环比的Top函数列表）是极高效的巡检入口，把"哪里不对劲"从人工滚动变成自动排序。

## 五、聚合数据的对账与信任建设

聚合层一旦出错，所有看板集体说谎，因此对账要制度化。三个对账动作：其一，抽样重算——每周随机抽取若干函数与时段，用原始数据现场重算错误率与P95，与预聚合值比对，偏差超百分之一即触发管线排查；其二，总量守恒——任何聚合层的调用量总和、错误量总和必须与入口层原始计数守恒（分维度拆分会因标签缺失造成归组不完全，允许显式的unknown桶但总量必须对上）；其三，跨系统对账——指标口径的调用量与日志请求ID计数、平台账单调用量三方定期互核（第24、40篇），三角互证把口径漂移扼杀在早期。对账结果以"数据质量周报"形式公开，信任来自可验证。

## 六、全局视图的访问与可达性

全局总揽页要让正确的人在任何时刻都能打开：值班手机端可访问（响应式布局或专用移动视图，数字字号适配小屏）、免登录或快捷登录（SSO打通，故障时刻不该浪费两分钟在验证码上）、降级方案（监控系统本身故障时的静态快照或备用只读副本）。这些细节平时无人注意，大故障时监控系统正好也过载或挂掉的双杀局面并不罕见——观测系统自身的可用性也应有预案（第30篇"观测系统自身的容量"的延伸），包括后端的多副本、查询限流保护、以及"观测挂了时的人工检查清单"。

## 结语

聚合是把海量实例噪声蒸馏成全局直觉的工艺：层次分明、操作贴语义、数学陷阱避开、长期视图靠预聚合降本。做完这些，一张全局总揽页就能让值班者在十秒内判断"系统是否健康、问题大概在哪"，这就是指标体系的终极产出形态。
