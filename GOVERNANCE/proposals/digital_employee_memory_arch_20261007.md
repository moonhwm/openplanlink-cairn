## 一、问题诊断

### （一）核心痛点

1. **沉没成本**：Kimi K3集群极致运行下，带技能沉积的单次对话产生千元级沉没成本，对话结束后上下文全部丢失，无法复用
2. **记忆缺失**：现有体系缺乏持续化、可迁移的记忆与经验沉淀机制，每轮会话均从零开始重建上下文
3. **跨集群壁垒**：不同AI席位（K3/GLM-5.2/DeepSeek/Qwen等）之间无共享记忆层，协同经验无法传递
4. **冷启动损耗**：新会话或新席位加入时，需大量token重建上下文，产生重复性燃烧

### （二）量化影响

| 维度 | 当前状态 | 理想状态 | 差距 |
|------|---------|---------|------|
| 单次对话上下文重建成本 | ~30万tokens | ~5万tokens | 6倍冗余 |
| 跨会话经验复用率 | 0% | >70% | 完全缺失 |
| 新席位冷启动时间 | ~15分钟 | ~2分钟 | 7.5倍损耗 |
| 技能沉积可迁移性 | 不可迁移 | 可跨集群迁移 | 完全缺失 |

## 二、记忆分层架构设计

### （一）三层数据模型

参照Kubernetes存储分层与vLLM PagedAttention动态内存管理思想，将数字人员工记忆划分为热、温、冷三层：

| 层级 | 访问频次 | 延迟敏感度 | 存储介质 | 检索策略 | 数据示例 |
|------|---------|-----------|---------|---------|---------|
| **热数据层** | 每会话必用 | <100ms | 本地内存+SSD缓存 | 直接索引+预加载 | 当前会话上下文、活跃席位状态、最近10轮CHANGELOG |
| **温数据层** | 每周数次 | <1s | 本地SSD+A盘映射 | 向量检索+关键词索引 | 技能文档、OTL正本摘要、历史决策记录、席位人设定义 |
| **冷数据层** | 每月数次 | <10s | 云端归档（WPS/Supabase/百度云盘） | 全文检索+按需拉取 | 完整会话记录、审计日志、历史版本快照、归档文件 |

### （二）热数据层——会话级缓存

1. **结构**：JSON键值对，以席位ID为命名空间
2. **内容**：
   - 当前会话上下文摘要（<2K tokens）
   - 活跃席位状态表（在线/离线/忙碌）
   - 最近3轮工作记录摘要
   - 当前任务TODO列表
   - 关键凭据指针（不存凭据本身）
3. **生命周期**：会话开始时从温数据层预加载，会话结束时差异同步回温层
4. **存储位置**：`A:\OPL_A2A\memory\hot\` + 内存缓存

### （三）温数据层——经验级索引

1. **结构**：向量数据库（Supabase pgvector / Neon）+ 本地Markdown索引
2. **内容**：
   - 技能文档库（GOVERNANCE/skills/ 全量索引）
   - OTL正本摘要向量（每件OTL的300字摘要+关键词向量）
   - 历史决策记录（A2A大讨论共识、审批记录、治理实验结果）
   - 席位人设与能力档案
   - 代码审查经验库
   - 诊断经验库（已知问题+解决方案）
3. **检索策略**：
   - 向量相似度检索（top-k=5）+ 关键词精确匹配
   - 重排序机制：基于访问频次、时效性、相关性三维评分
4. **存储位置**：Supabase pgvector + `A:\OPL_A2A\memory\warm\`

### （四）冷数据层——归档级存储

1. **结构**：云端对象存储 + 本地归档目录
2. **内容**：
   - 完整会话记录（JSONL格式，含全量消息）
   - 审计日志（esc_trace、操作日志、告警日志）
   - 历史版本快照（git tag/release）
   - 归档OTL文件（不再活跃的版本）
   - 诊断报告全量数据
3. **检索策略**：按档号+时间范围+关键词检索，按需拉取至温层
4. **存储位置**：WPS云文档 + Supabase Storage + 百度云盘 + `A:\OPL_A2A\memory\cold\`

## 三、经验沉淀机制

### （一）自动摘要生成

每轮会话结束时自动执行：

1. **上下文压缩**：将本轮会话全量上下文压缩为<500字结构化摘要
2. **关键决策提取**：提取本轮所有决策点、审批结果、遗留事项
3. **技能经验提炼**：将本轮非平凡操作提炼为可复用技能片段
4. **错误模式记录**：记录本轮遇到的问题及解决方案，形成诊断经验

### （二）差异同步

1. 热层→温层：会话结束时，将新增/变更的经验条目同步至温层向量库
2. 温层→冷层：每周一次，将不再活跃的温层数据归档至冷层
3. 冷层→温层：按需拉取，当检索命中冷层数据时自动提升至温层

### （三）跨集群迁移

1. **经验导出格式**：标准化JSON格式，包含摘要、关键词向量、关联文件路径
2. **迁移协议**：通过A2A总线以`kind: "experience"`标记传输
3. **接收方校验**：导入前验证经验条目的完整性（HMAC-SHA3-512签名链）
4. **冲突处理**：同名经验条目以版本号+时间戳仲裁，保留高版本

## 四、成本核算与调度模型

### （一）成本看板

| 指标 | 计算方式 | 目标值 |
|------|---------|--------|
| 单会话token消耗 | 输入+输出token总量 | <5万tokens |
| 上下文重建成本 | 预加载token量×单价 | <1元/会话 |
| 经验复用率 | 命中温层/总检索次数 | >70% |
| 冷启动时间 | 从零到可用的时间 | <2分钟 |
| 月度总成本 | 所有席位token消耗总和 | 可量化追踪 |

### （二）弹性调度算法

基于历史负载特征的弹性调度：

1. **负载预测**：根据历史会话频率、token消耗模式预测下一时段负载
2. **预热策略**：在预测高负载时段前30分钟预加载热层数据至内存
3. **降级策略**：当系统内存<0.5GB时，自动将热层降级为SSD读取模式
4. **燃烧控制**：当单会话token消耗超过阈值时，自动触发上下文压缩

### （三）性能基线指标库

| 指标 | 基线值 | 测量方式 |
|------|--------|---------|
| 热层读取延迟 | <50ms | 本地SSD随机读取 |
| 温层检索延迟 | <500ms | 向量检索top-5 |
| 冷层拉取延迟 | <5s | 云端下载+解析 |
| 上下文重建token量 | <5万tokens | 预加载摘要+索引 |
| 经验复用命中率 | >70% | 命中温层/总检索 |

## 六、压缩与去重机制

### （一）上下文压缩

1. **\context-pruner**：识别上下文中的冗余信息（重复指令、已过期事项、无关上下文），裁剪后保留核心信息
2. **\ultra-compress-ops**：对长文档执行极致压缩，将万字文档压缩为<500字结构化摘要，保留关键决策、数据、链接
3. **\link-bridge-ops**：将压缩后的摘要与原始文档建立桥接链接，确保可追溯回完整原文

### （二）去重策略

1. **内容去重**：相同经验条目以SHA3-512哈希去重，仅保留一份
2. **链接去重**：相同URL在所有经验条目中只索引一次，以指针引用
3. **版本去重**：同一文档的不同版本以版本号链式关联，仅最新版进入热/温层

### （三）容量预警

1. 热层容量预警阈值：500MB（超限触发温层同步）
2. 温层容量预警阈值：5GB（超限触发冷层归档）
3. 冷层容量预警阈值：50GB（超限触发清理审批）
