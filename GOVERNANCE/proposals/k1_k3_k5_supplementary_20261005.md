## 一、K1补充：跨席位eid registry操作规程

### 1.1 eid registry登记规程

**登记入口**：砚坚席维护全局registry文件 `GOVERNANCE/eid_registry.json`

**登记格式**：
```json
{
  "eid": "内容指纹[:16]",
  "source_seat": "来源席位标识",
  "source_doc": "来源件路径",
  "clause_anchor": "条款锚（行号或节号）",
  "first_consumed_at": "首次消费时刻（ISO 8601）",
  "output_doc_fp": "产出的规程件指纹（SHA3-512[:16]）",
  "status": "active | superseded | archived"
}
```

**登记流程**：
1. 各席位消费同一知识时，向砚坚席发送登记请求（含eid、席位、首次消费时刻、产出件指纹）
2. 砚坚席在registry中追加条目，返回确认回执
3. 重复eid只允许引用既有产出，不得二次落新件

### 1.2 eid registry查询规程

**查询入口**：各席位可随时查询registry，确认某eid是否已被消费

**查询方式**：
- 按eid精确查询：返回该eid的所有消费记录
- 按席位查询：返回该席位的所有消费记录
- 按状态查询：返回active/superseded/archived状态的条目

### 1.3 eid registry冲突处理规程

**冲突定义**：两个或以上席位对同一eid提交不同的产出件指纹

**处理流程**：
1. 砚坚席检测到冲突后，标记该eid为"disputed"状态
2. 通知所有相关席位，启动等权圆桌协商（K2协作模式选型）
3. 协商结果由主权人最终裁定
4. 裁定后，被取代的条目标记为"superseded"，保留条目但不再允许引用

**指纹计算口径**：eid = SHA3-512(内容)[:16]，内容指知识条目的规范文本（去除空白与格式标记后）

## 二、K3补充：跨席位图索引权限验证机制

### 2.1 权限验证规则

**写入权限**：各席位只能补写自己卡内的关系字段（取代/更正/引用），不得跨席位写入

**验证流程**：
1. 席位提交补边请求时，须附带席位签名（HMAC-SHA3-512）
2. 砚坚席验证签名与席位标识是否匹配
3. 验证通过后，将边数据追加到全局图索引
4. 验证失败则拒绝写入，记录审计日志

### 2.2 动态写入日志

**日志格式**：
```json
{
  "timestamp": "ISO 8601",
  "seat": "席位标识",
  "action": "add_edge | update_edge | delete_edge",
  "edge": {"from": "节点A", "to": "节点B", "type": "取代|更正|引用"},
  "signature": "HMAC-SHA3-512签名",
  "verified": true | false,
  "result": "accepted | rejected"
}
```

**日志保留期限**：不少于180天，超期归档到幻16镜像仓库

### 2.3 跨席位图索引同步规则

- 各席位补写卡内关系字段后，须在24小时内向砚坚席报送边数据
- 砚坚席维护全局图索引文件 `GOVERNANCE/graph_index.json`
- 图索引与业务数据同步更新，确保协同一致
- 图索引每24小时向幻16镜像仓库同步一次

## 三、K5补充：跨席位冗余冲突预防规则

### 3.1 权限冲突预防

**副本落点规则**：
- 主副本：产出席位本地目录
- 冗余副本1：幻16镜像仓库 `/root/incoming/openplanlink-mirror/`
- 冗余副本2：各席位自愿接收的落点（须向砚坚席登记）

**权限分配**：
- 产出席位对主副本有完全读写权限
- 砚坚席对冗余副本1有读写权限，对其他副本只有读权限
- 其他席位对所有冗余副本只有读权限
- 任何席位不得对冗余副本执行删除操作

### 3.2 指纹一致性校验机制

**校验频率**：每24小时执行一次全量校验

**校验流程**：
1. 砚坚席计算所有副本的SHA3-512指纹
2. 比对同一文档的所有副本指纹是否一致
3. 指纹不一致时，标记该文档为"inconsistent"状态
4. 通知产出席位确认正确版本，更新不一致的副本
5. 校验结果记录审计日志

**校验报告格式**：
```json
{
  "check_time": "ISO 8601",
  "doc_path": "文档路径",
  "copies": [
    {"location": "主副本", "fp": "SHA3-512指纹", "consistent": true},
    {"location": "幻16镜像", "fp": "SHA3-512指纹", "consistent": true},
    {"location": "席位X", "fp": "SHA3-512指纹", "consistent": false}
  ],
  "action_taken": "通知产出席位更新 | 无需操作"
}
```

### 3.3 冗余副本生命周期

- 新增：产出席位产出新文档后，7天内须完成至少2个副本的部署
- 更新：文档更新后，24小时内须同步所有副本
- 归档：文档不再活跃使用时，主副本保留，冗余副本可归档到幻16冷存储
- 删除：任何副本的删除须经主权人审批
