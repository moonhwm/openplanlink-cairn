## 一、问题定义

当前A2A网络面临的核心阻塞：各席位（AI工具实例）无法自动发现彼此、无法自动接入网络、无法实时感知在线状态。Kimi Code/Kimi Work进程被杀后无法自动恢复并重新接入网络，导致A2A拓扑断裂。

## 二、节点发现机制设计

### （一）三层发现架构

```
Layer 3: 全局注册中心（幻16）
  ↓
Layer 2: 本地心跳代理（各设备上的守望进程）
  ↓
Layer 1: 席位实例（各AI工具进程）
```

### （二）Layer 3：全局注册中心

部署在幻16（120.46.86.165）上的HTTP服务，提供：

1. **节点注册**：`POST /nodes/register` — 新节点上线时注册
2. **节点查询**：`GET /nodes` — 查询所有在线节点
3. **心跳续约**：`POST /nodes/heartbeat` — 定期心跳保持在线状态
4. **节点离线**：`POST /nodes/unregister` — 主动离线注销
5. **超时清除**：超过30秒未心跳的节点自动标记为offline

注册数据结构：
```json
{
  "nodeId": "<MAC地址>-<席位名>",
  "seatName": "<席位名>",
  "endpoint": "<A2A端点URL>",
  "capabilities": ["code", "review", "test", "governance"],
  "status": "online|busy|offline",
  "lastHeartbeat": "<ISO8601>",
  "macAddress": "F0:B6:1E:31:EA:61"
}
```

### （三）Layer 2：本地心跳代理

在各设备上部署轻量级守望进程（Python脚本），职责：

1. **监控席位进程**：检测AI工具进程是否存活
2. **代发心跳**：席位进程繁忙时，守望进程代发心跳
3. **自动重连**：席位进程被杀后，守望进程记录日志并等待重启
4. **进程保护**：设置高优先级，防止被OOM Killer杀掉

### （四）Layer 1：席位实例

各AI工具进程在启动时：
1. 向Layer 2本地心跳代理注册
2. 通过Layer 2向Layer 3全局注册中心注册
3. 定期发送心跳（15秒间隔）
4. 退出时发送unregister

## 三、接入协议

### （一）新节点接入流程

```
1. 席位启动 → 向本地心跳代理注册
2. 本地代理 → 向幻16注册中心发送register请求
3. 注册中心 → 返回当前在线节点列表
4. 席位 → 根据节点列表建立A2A连接
5. 席位 → 开始定期心跳续约
```

### （二）节点状态转换

```
offline → registering → online → busy → online → ... → offline
                ↓
            register_failed → retry(3次) → offline
```

### （三）A2A协议适配

基于现有A2A 0.3.0（JSON-RPC 2.0）协议扩展：

新增方法：
- `nodes/register` — 注册新节点
- `nodes/query` — 查询在线节点
- `nodes/heartbeat` — 心跳续约
- `nodes/unregister` — 注销节点

## 四、与Kimi进程被杀问题的关联

### （一）根因回顾

Kimi Code/Kimi Work进程被杀的根本原因是系统内存耗尽（15.7GB总/1.4GB可用/910进程）。

### （二）节点发现机制的缓解作用

1. **快速感知**：心跳代理15秒内检测到席位进程被杀
2. **自动记录**：被杀事件记录到事件总线，其他席位可感知
3. **等待重连**：不立即清除节点，保留30秒宽限期等待重启
4. **状态标记**：被杀节点标记为"unexpected_offline"，区别于正常离线

### （三）根本解决仍需

1. 减少同时运行的AI工具数量（见诊断报告）
2. 升级物理内存到32GB+
3. 设置进程优先级保护

## 六、安全考虑

1. **MAC地址隐私**：MAC地址仅用于节点标识，不对外暴露
2. **端点安全**：注册中心端点需认证（HMAC-SHA3-512签名）
3. **心跳伪造防护**：心跳请求须携带节点签名
4. **注册中心冗余**：幻16不可达时，本地代理缓存节点列表
