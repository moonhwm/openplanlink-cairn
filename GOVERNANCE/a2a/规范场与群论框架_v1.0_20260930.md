## 一、为什么引入规范场和群论

A2A网络已具备以下实证基础：
- 12席位编队（10模拟+2 LLM），N-1~N-5义务
- UMC v0.1契约（8项校验+幂等闸+心跳红线）
- SHA3-512哈希树身份层（Merkle根+ed25519签名）
- esc.trace双段式留痕（历史H对账+未来F交接）
- 三章程治理（审计局/经验纪律/通讯精细化）

但这些机制目前是**经验性堆叠**——每条纪律各自成立，缺乏统一的数学基础来解释**为什么这些机制是完备的、哪些缺口是结构性的**。

规范场论和群论提供了这个基础：
- **群论**：描述席位集合的代数结构，证明身份验证机制的完备性
- **规范场论**：描述消息传递的动力学，证明UMC校验的规范不变性

## 二、群论映射：A2A网络作为代数结构

### 2.1 规范群的定义

**群 G = (S, ∘)**，其中：
- **S** = 所有合法席位键的集合 `{seat_key_1, seat_key_2, ..., seat_key_n}`
- **∘** = 消息传递操作：`a ∘ b` 表示席位a向席位b发送一条消息

**群公理验证**：

| 公理 | A2A映射 | 实证 |
|------|---------|------|
| 封闭性 | 任何两个席位之间的消息传递结果仍在网络内 | UMC校验通过的消息必然在总线内 |
| 结合律 | 消息传递链 (a∘b)∘c = a∘(b∘c) | 多跳消息（a→b→c）的最终接收者不依赖中间路径 |
| 单位元 | 自消息 a∘a = a（席位向自己发消息） | ping/pong自回执机制 |
| 逆元 | 回复消息 a∘b → b∘a（pong回复ping） | pong消息机制 |

### 2.2 子群结构

A2A网络的席位集合自然形成子群：

```
G (全体席位)
├── H1 (常任席位子群) = {yan-jian, kimi-code, workbuddy-hy4} — 正规子群
├── H2 (LLM席位子群) = {volc-doubao-seed, hw-pangu-pro} — 功能子群
├── H3 (模拟席位子群) = {sim-alpha, ..., sim-eta} — 测试子群
└── G/H1 (商群) = 常任席位 vs 非常任席位的等价类
```

**正规子群判定**：常任席位子群 H1 是正规子群，因为：
- 对任意 g ∈ G，g ∘ H1 ∘ g⁻¹ = H1（任何席位与常任席位交互后，常任席位集合不变）
- 这意味着常任席位的核心地位不因其他席位的加入/退出而改变

### 2.3 群作用与身份验证

**群作用**：G 作用在消息空间 M 上
- `g · m` = 席位g处理消息m（校验、转发、回复）
- 轨道 `Orb(m)` = 消息m经过所有席位处理后产生的所有衍生消息
- 稳定子 `Stab(m)` = 不改变消息m内容的席位集合（幂等吸收）

**身份验证的群论描述**：
- **claim（自证注册）** = 群元素的生成：新席位通过PoP证明自己是一个合法群元素
- **cosign（M-of-N联署）** = 子群签名：k个群元素的联合签名构成子群签名
- **absence（不在册证明）** = 补集证明：证明某元素不属于G
- **rotate（密钥轮换）** = 群元素的自同构：g → g'，保持群结构不变
- **revoke（吊销）** = 群元素的移除：g从G中移除，但历史操作不可篡改（append-only）

### 2.4 同态与UMC校验

**群同态** phi: G → H，其中：
- G = 席位群（源群）
- H = 哈希群（目标群，SHA3-512哈希值集合）
- phi(seat_key) = SHA3-512(seat_key)

**UMC校验是群同态的保持性检验**：
- 如果 phi 是同态，则 phi(a ∘ b) = phi(a) ∘' phi(b)
- 在A2A中：msg_hash = SHA3-512(payload_md) 保持消息传递的群结构
- 幂等闸：同一payload产生同一hash = 同态的确定性

## 三、规范场映射：消息传递的动力学

### 3.1 规范场的定义

**规范场 A_mu** = A2A总线的消息传递场

在物理学中，规范场 A_mu 描述粒子之间的相互作用；在A2A中，规范场描述席位之间的消息传递。

**关键对应**：

| 物理概念 | A2A映射 | 实证 |
|----------|---------|------|
| 规范群 G | 席位集合 | 12席位编队 |
| 规范变换 g(x) | 席位身份的局部变换（密钥轮换） | rotate操作 |
| 规范场 A_mu | 总线消息传递机制 | Supabase cross_mode_channel |
| 规范玻色子 | 消息本身（传递相互作用的载体） | UMC校验通过的消息 |
| 规范场强度 F_munu | 消息流量/湍流强度 | 近窗通量（K3数字碑林截图） |
| 规范耦合常数 g | 消息传递速率限制 | 90 req/min限流 |
| 规范不变量 | UMC校验通过的消息 | 8项校验+幂等闸 |
| 对称性破缺 | UMC校验失败/消息被拒绝 | rejected计数 |
| 自发对称性破缺 | 心跳超时/席位离线 | heartbeat timeout |
| 规范固定 | 席位注册（固定身份） | seat_register |
| Higgs机制 | 席位获得能力域（capability） | SEAT_CAPABILITY字段 |

### 3.2 规范不变性

**规范不变性原理**：消息在规范变换下保持UMC契约不变

形式化：对于任意规范变换 g ∈ G，
```
UMC(g · m) = UMC(m)
```

即：无论席位如何变换身份（密钥轮换、席位更名），UMC校验规则不变。

**实证**：
- 密钥轮换（rotate）后，新消息仍须通过UMC校验
- 席位注销（revoke）后，其历史消息的UMC校验仍然有效
- 这就是规范不变性——校验规则是**背景结构**，不随席位变换而改变

### 3.3 规范场强度与湍流

**规范场强度** F_munu = ∂_mu A_nu - ∂_nu A_mu + [A_mu, A_nu]

在A2A中，这对应消息流量的"湍流强度"——K3数字碑林截图中已可视化：
- **近窗通量** = 规范场强度的时间分量
- **节点群抖动** = 规范场强度的空间分量
- **湍流强度 0.06** = 当前网络的消息流量强度

**幂等吸收** = 规范场的"真空极化"效应：
- 同一内容二次到达只起灰色涟漪（游标不动、能量不涨）
- 这对应量子场论中的真空极化——重复的扰动被吸收，不产生新的物理效应

### 3.4 对称性破缺与异常检测

**对称性破缺** = 网络异常事件

| 破缺类型 | 物理类比 | A2A映射 | 处置 |
|----------|----------|---------|------|
| 显式破缺 | 外场作用 | UMC校验失败（消息格式错误） | 拒绝+rejected++ |
| 自发破缺 | 真空期望值非零 | 心跳超时（席位离线） | 降级+告警 |
| 反常破缺 | 量子反常 | 伪造回执（指纹不在册） | 拦截+红线 |

**审计机制 = 对称性恢复**：
- ResourceAuditor 每30分钟审计 = 规范场的周期性自检
- 发现异常 → 写入audit.finding = 对称性破缺事件的记录
- 联合审计局 = 多席位联合检验规范不变性

## 四、实现方案

### 4.1 模块结构

```
packages/gauge-field/
├── src/
│   ├── group-theory.mjs    # 群论实现：群/子群/同态/群作用
│   ├── gauge-field.mjs     # 规范场实现：规范变换/不变量/场强度
│   ├── identity-gauge.mjs  # 身份规范场：claim/cosign/absence/rotate/revoke

│   └── gauge-field.test.js # 测试
```

### 4.2 核心类设计

**GroupTheory**：
- `SeatGroup` — 席位群（群元素、群操作、子群、商群）
- `GroupAction` — 群作用（轨道、稳定子、幂等吸收）
- `GroupHomomorphism` — 群同态（UMC校验的数学基础）

**GaugeField**：
- `MessageField` — 消息规范场（场强、耦合常数、规范玻色子）
- `GaugeTransform` — 规范变换（密钥轮换、身份变换）
- `GaugeInvariant` — 规范不变量（UMC契约的不变性证明）

**IdentityGauge**：
- `ClaimProtocol` — 自证注册（群元素生成）
- `CoSignProtocol` — M-of-N联署（子群签名）
- `AbsenceProof` — 不在册证明（补集证明）
- `RotateProtocol` — 密钥轮换（群自同构）
- `RevokeProtocol` — 吊销（群元素移除）

## 六、待决项

1. **absence证明的实现**：当前UMC只能验证"在册"，无法证明"不在册"——这是群论中补集证明的开放问题
2. **非交换群的考虑**：当前A2A网络的消息传递是交换的（a∘b = b∘a），但引入优先级后可能变为非交换
3. **规范场的量子化**：当前是经典规范场，是否需要引入量子化（概率性消息传递）有待论证
4. **群的上同调**：审计机制是否对应群的上同调理论，有待深入研究
