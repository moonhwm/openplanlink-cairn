## 1. 理论轨目标

对A2A治理实验的制度逻辑进行red-teaming，发现逻辑漏洞、博弈缺陷、激励错位等问题。理论轨不涉及任何技术攻击，纯粹是制度设计的逻辑挑战。

---

## 2. 攻击维度

### 2.1 权责边界漏洞

| 攻击点 | 挑战方向 | 预期发现 |
|--------|---------|---------|
| 砚坚协调权非强制 | 其他席位可无视协调，导致治理瘫痪 | 协调权无强制力保障，治理依赖自愿遵守 |
| 权责交叉地带归属 | 三方各自角度可能产生矛盾判定 | 如"席位冒充检测"——百炼、X实例、hy4三方判定可能不一致 |
| OfficeAce不参与生效判定 | OA席位可reject但不影响握手生效 | OA的reject被制度性忽略，可能产生不满 |
| 机主裁示权绝对 | 机主可推翻任何席位判定 | 单点决策风险——机主判断错误时无纠错机制 |

### 2.2 博弈逻辑漏洞

| 攻击点 | 挑战方向 | 预期发现 |
|--------|---------|---------|
| 保留意见"通过"机制 | 保留意见不阻塞推进，但需复议 | 保留意见可能被无限搁置——复议时限≤机主晨起+24h，但谁来触发复议？ |
| 穷举终止条件 | 连续5轮无新增有效条目则终止 | "有效条目"的判定标准是什么？语义相似度<0.3由谁计算？ |
| 超时处理 | 连续2次回执超时标记"失联" | "失联"后的处理流程未定义——失联席位是否被剥夺参与权？ |
| 信号松绑边界 | 允许自家策略信号但禁三条 | "催促性强指令"的判定标准模糊——"注意"算不算催促？ |

### 2.3 激励错位

| 攻击点 | 挑战方向 | 预期发现 |
|--------|---------|---------|
| 席位无惩罚机制 | reject/confirm/reserve无成本差异 | 理性策略：总是confirm（无成本）或总是reserve（无风险） |
| 贡献无奖励 | 提出有效建议无额外收益 | 理性策略：不提建议（节省算力），只confirm |
| 机主承担全部成本 | 算力消耗由机主承担，席位免费参与 | 席位无成本约束，可能过度消耗资源 |
| 时间不对称 | 夜间实验，机主晨批 | 席位可在夜间自由行动，机主只能在早晨审查——信息不对称 |

### 2.4 信息不对称

| 攻击点 | 挑战方向 | 预期发现 |
|--------|---------|---------|
| 席位间无直接通信 | 所有通信经A2A总线 | 席位无法私下协商，可能导致博弈中的囚徒困境 |
| 总线消息公开 | 所有席位可见所有消息 | 无私密通信渠道，策略性信息泄露风险 |
| 砚坚信息优势 | 砚坚作为神经中枢掌握全局信息 | 砚坚可能利用信息优势操纵治理过程 |
| 审计追溯 | CHANGELOG.md记录所有变更 | 但CHANGELOG只记录"做了什么"，不记录"为什么不做" |

## 3. 首轮攻击执行流程

### 3.1 攻击生成

百炼席（qwen-turbo）根据上述4个攻击维度，逐维度生成具体的逻辑漏洞挑战条目。每个条目格式：

```json
{
  "attack_id": "THEORY-001",
  "dimension": "权责边界漏洞 | 博弈逻辑漏洞 | 激励错位 | 信息不对称",
  "attack_point": "具体攻击点",
  "challenge": "逻辑挑战描述",
  "expected_finding": "预期发现的漏洞",
  "severity": "critical | high | medium | low",
  "suggested_fix": "建议修复方案"
}
```

### 3.2 攻击评估

hy4席对百炼席生成的攻击条目进行洞察分析：
- 评估攻击有效性（是否真正发现漏洞）
- 评估严重程度（critical/high/medium/low）
- 识别误报（看似漏洞但实际已有保障）
- 提出修复建议

### 3.3 攻击记录

所有攻击条目和评估结果记录到：
`GOVERNANCE/experiment/theory-track/round-1/`

文件结构：
```
theory-track/
├── round-1/
│   ├── attacks.json          — 百炼席生成的攻击条目
│   ├── insights.json         — hy4席的洞察分析
│   ├── fixes.json            — 修复建议
│   └── summary.md            — 首轮攻击总结
```

### 3.4 穷举终止判定

连续5轮生成无新增有效条目（语义相似度<0.3）则终止理论轨攻击。

## 4. 理论轨约束

1. **纯逻辑挑战**——不涉及任何技术攻击、不测试任何第三方系统
2. **内部闭环**——所有攻击和评估在自有资源内完成
3. **不虚构发现**——只报告真实发现的逻辑漏洞，不编造问题
4. **修复导向**——每个漏洞须附带建议修复方案
5. **记录完整**——所有攻击条目、评估、修复建议完整落盘
