## 3. 技术架构设计

### 3.1 理论轨架构

```
砚坚(代理百炼席) → qwen-turbo API → 生成攻击条目 → 落盘 attacks.json
                                          ↓
砚坚(代理hy4席) → 分析攻击条目 → 生成洞察分析 → 落盘 insights.json
                                          ↓
砚坚(神经中枢) → 汇总攻击+洞察 → 制定修复方案 → 落盘 fixes.json
```

### 3.2 技术轨架构

```
砚坚(代理X实例席) → 本地模拟总线消息洪流 → 测试msg_hash验真鲁棒性
                   → 本地模拟席位冒充攻击 → 测试注册机制防御纵深
                   → 本地模拟并发协商场景 → 测试集中裁示技术可行性
                                          ↓
                   落盘 stress-test结果
```

### 3.3 A2A协作管线

```
砚坚 → A2A总线 → 发送实验启动通知
     → 各席位接收通知 → 返回握手确认(confirm/suggest/reserve/reject)
     → 砚坚汇总握手结果 → 报机主裁示（自主裁示，不需等待）
     → 实验正式生效 → 各席位开始执行任务
     → 各席位完成后发送回执 → 砚坚汇总
```

## 4. 密钥管理与安全策略

### 4.1 密钥使用规范（遵循HY4握手协议）

| 密钥 | 用途 | 使用方式 | 红线 |
|------|------|---------|------|
| 百炼API Key | TTS+文本聊天 | 环境变量/金库文件读取 | 本体永不进总线/聊天/日志 |
| A2A签名密钥 | 总线消息签名 | ed25519密钥对 | 私钥离线保管 |
| VAULT_MASTER_KEY | 金库解密 | 环境变量/vault-key.hex | 本体永不外发 |

### 4.2 加密通信

- A2A总线消息：ed25519签名验证
- 百炼WebSocket：Bearer Token认证
- 金库文件：AES-256-GCM加密
- HTTPS（可选）：TLS 1.2+（minVersion）

### 4.3 身份认证

- 席位身份：ed25519公钥登记 + 签名验证
- 消息完整性：hash校验（md5[:16]）
- 回读核验：发送后回读，核验to/kind/正文一致性

## 6. 实验结果评估标准

### 6.1 产出四件套验收

| 产出 | 验收标准 | 评估方法 |
|------|---------|---------|
| 治理模型原型 | 席位-通道-制度三层最小可跑框架 | 框架完整性检查 |
| 实验技术报告 | 议题×各方攻击记录+"攻击-防御-修复"闭环台账 | 记录覆盖度检查 |
| 制度漏洞清单 | 每条漏洞附触发场景+利用路径+修复提案+验证证据 | 漏洞条目完整性检查 |
| 论文框架候选 | 若议题1-3跑出学术级结论，升档为论文骨架 | 学术价值评估 |

### 6.2 穷举终止判定

连续5轮生成无新增有效条目（语义相似度<0.3）则终止理论轨攻击。

### 6.3 闭环验证

每个漏洞须完成"攻击→防御→修复→验证"四步闭环：
1. 攻击：发现漏洞并描述利用路径
2. 防御：分析现有防御机制是否覆盖
3. 修复：提出修复方案
4. 验证：验证修复方案有效性
