# 密码法合规检查：条款映射、合规项清单、违规风险评级

> 适用项目：harmony-app（铃语，鸿蒙适老化股票异动播报，纯 ArkTS + 云函数）。
> 本文件是 crypto 技能域的合规知识资产，自包含、可持久化。
> 事实核验说明：《密码法》第二十七条关于关键信息基础设施运营者使用商用密码并开展商用密码应用安全性评估（密评）的义务、《商用密码管理条例》（2023 年修订，国务院令第 760 号）、《商用密码应用安全性评估管理办法》（国家密码管理局令第 3 号）、《关键信息基础设施商用密码使用管理规定》（2025 年 8 月 1 日起施行）等事实，已经 2026-09-23 的 Web 检索核验（国家密码管理局、司法部官网来源）。**任何条款引用在用于对外承诺或整改依据前，必须回到官方文本逐字核对现行有效版本**——本文件提供的是检查方法与映射框架，不是法律意见。

## 一、法律框架与适用判定

### 1.1 规范体系

| 层级 | 文件 | 与铃语的关系 |
|---|---|---|
| 法律 | 《中华人民共和国密码法》（2020 年 1 月 1 日施行） | 密码分类管理（核心密码、普通密码、商用密码），铃语只可能涉及商用密码 |
| 行政法规 | 《商用密码管理条例》（2023 年修订） | 细化商用密码检测认证、进出口、应用与管理制度 |
| 部门规章/规范性文件 | 《商用密码应用安全性评估管理办法》；《关键信息基础设施商用密码使用管理规定》（2025-08-01 施行） | 规定密评的定义（对商用密码技术、产品和服务的合规性、正确性、有效性评估）与关基场景流程 |
| 国家标准 | GB/T 39786-2021《信息安全技术 信息系统密码应用基本要求》 | 密评的技术依据，四个技术层面 + 管理制度 |
| 衔接制度 | 网络安全等级保护制度（《网络安全法》） | 密评与等保测评、关基检测评估相衔接，避免重复评估 |

### 1.2 铃语的适用判定（先定性，再检查）

合规检查的第一步不是逐条比对，而是**判定本系统落入哪一档监管场景**，因为义务强度差异极大：

1. **是否属于关键信息基础设施（CII）**：铃语是面向个人用户的股票异动播报工具，不支撑金融交易、不清算、不托管，按现行认定规则被认定为 CII 的可能性低。**若未来接入交易能力或被认定为关基，第二十七条的密评义务立即变为强制**，需另行立项。
2. **是否属于网络安全等级保护第三级及以上网络**：按条例精神，等保三级及以上网络的运营者应当按要求开展密评。铃语当前体量通常按二级及以下定级，密评非强制项，但建议按 GB/T 39786 的思路自查（成本极低，且是未来升级的通行证）。
3. **确定属于的档位**：作为"网络运营者"使用商用密码技术保护网络与信息安全——这是最低档也是不可豁免的档位，检查重点落在**正确使用合格商用密码产品、不滥用密码技术、不侵害用户权益**。

这一判定结论应写入项目 GOVERNANCE 目录并随业务演进复核：一旦新增收费、对外公开服务或金融属性功能（这三项同时是本项目的合规红线，正常情况下不会发生），判定需重做。

## 二、条款映射表

映射表的用途：把抽象法条翻译成"铃语的哪个文件、哪个行为"需要满足什么。以下映射聚焦确认度高的核心条款：

| 条款 | 义务/规范要点 | 映射到铃语的检查问题 |
|---|---|---|
| 《密码法》商用密码促进条款（总则章） | 国家鼓励商用密码研发应用、检测认证 | 选用 SM2/SM3/SM4 等商用密码算法属于受鼓励方向，技术选型留档 |
| 第二十六条（网络运营者条款） | 网络运营者应当按照网络安全等级保护制度要求，使用商用密码保护网络与信息安全 | FEED_URL 传输、alerts.json 落盘、token 存储是否"使用了"密码保护；方案与等保定级是否一致 |
| 第二十七条第一款（CII 条款） | 法律法规要求使用商用密码保护的关基，运营者应使用商用密码保护并开展密评；密评与等保测评、关基检测评估相衔接 | 当前不适用；作为触发器管理——触发条件见 1.2 |
| 第二十七条第二款 | CII 运营者使用未经安全审查或未通过安全审查的商用密码产品，属于违法 | 若引入第三方密码产品/SDK（当前零三方依赖，天然规避），必须核查是否在国家密码管理局认证目录内 |
| 第二十八条（进出口条款） | 对涉及国家安全、社会公共利益且具有加密保护功能的商用密码实施进口许可和出口管制 | 铃语自用不涉及；但**若在国外密码库/硬件间流转带加密功能的产品**，需先对照许可清单 |
| 法律责任章（相应条款） | 对未按要求使用商用密码、未开展密评等行为规定责令改正、警告、罚款等责任 | 见第四节风险评级；罚则幅度以现行文本为准，本文不复制具体数字以免版本漂移 |
| 《关基商用密码使用管理规定》 | 运营者应自行或委托检测机构对商用密码应用方案评估，未通过评估的方案不得使用、系统不得投入运行；覆盖规划、建设、运行三阶段 | 当前不适用；若未来触发，需在建设期即引入方案评估，而非建成后补救 |

映射表维护规则：每次法规修订（密码法实施细则、条例配套文件持续出台）后，由 crypto 席位逐行复核并标注核验日期。

## 三、合规项清单（技术 + 管理）

参照 GB/T 39786 的结构，结合铃语零三方依赖、纯 ArkTS + 云函数的现实，给出可直接打勾的清单。每项标注【高/中/低】优先级与责任文件路径。

### 3.1 技术层面

**网络和通信**
- 【高】FEED_URL 拉取 AlertFeed 走 HTTPS（TLS1.2+），证书校验未被代码关闭（禁止 `http` 明文拉取行情与播报数据）。
- 【中】云函数调用 generate-tts 的出口通道加密，凭据不在 URL 查询串中传递。
- 【中】Push 通道（华为 Push Kit REST 接入后）使用官方证书与签名机制，不自行降级。

**设备和计算（端侧）**
- 【高】设备本地不出现明文长期凭据：Tushare/百炼/Push 凭据一律经 Asset Store Kit 或 HUKS 存储（实现见 key-lifecycle.md），不得写入 preferences 明文文件。
- 【中】真机调试包与发布包的日志中无凭据输出（检查 hilog 调用点）。

**应用和数据**
- 【高】AlertFeed 内容完整性：对播报卡片内容建立 SM2 验签或 SM3 摘要校验，防伪造行情话术诱导老年用户（实现见 gm-algorithm.md）。这一项同时服务于密码法"使用商用密码保护信息安全"与项目自身的内容安全红线。
- 【中】alerts.json 本地缓存若含个性化数据，使用 SM4 加密存储。
- 【中】密码算法实现全部调用系统能力（@kit.CryptoArchitectureKit），不自造算法——自研密码实现是合规与技术双重风险。

**密码产品与算法选用**
- 【高】选用的商用密码算法为标准算法（SM2/SM3/SM4），参数符合国家标准（GB/T 32918、GB/T 32905、GB/T 32907 系列）。
- 【中】若使用第三方密码服务（如云 KMS），核查其商用密码认证资质并留档。

### 3.2 管理层面

- 【高】密码应用方案文档：一份说明"哪些数据、用什么算法、密钥如何管理"的方案，存放于 GOVERNANCE 目录——这是密评的送审基础。
- 【中】密钥管理制度：生成、分发、轮换、销毁、审计的责任人与流程（详见 key-lifecycle.md）。
- 【中】人员与变更管理：涉密配置变更走评审，凭据泄露应急处置流程书面化。
- 【低】年度自查记录：每年按本清单跑一遍并归档。

## 四、违规风险评级

评级维度：**发生可能性 × 后果严重性**，分高/中/低三级。对铃语当前形态的典型评级：

| 等级 | 触发情形（铃语语境） | 后果 | 处置要求 |
|---|---|---|---|
| 高 | 长期凭据明文存储或出现在日志/代码仓库；被认定为关基后未开展密评仍运行；使用未通过安全审查的密码产品且涉及关基 | 责令改正、警告直至罚款（依法律责任条款），应用下架与声誉风险，老年用户权益受损 | 立即整改，24 小时内定位，一周内闭环并留证 |
| 中 | 明文 HTTP 拉取行情播报数据；无完整性校验导致可被中间人篡改话术；密钥无轮换制度 | 合规瑕疵 + 内容安全风险，等保/上架审核受阻 | 纳入下一迭代，一个月内闭环 |
| 低 | 缺少密码应用方案文档；自查记录缺失 | 整改通知类 | 年度自查补齐 |

两条与项目红线叠加的特别提示：
1. **内容红线放大密码合规后果**：播报内容一旦可被篡改（无完整性校验），伪造的"保证收益""立即买入"话术既是密码合规缺陷，也是项目不可逾越红线的失守，风险一律按高级别处置。
2. **凭据红线**：任何 Token/密钥进入对话、文档、日志都同时违反本检查清单与项目合规红线，发现即按高级别启动轮换（处置流程见 key-lifecycle.md）。

## 五、检查流程与报告

五步检查法，每轮输出一份可归档报告：

1. **定性**：按第一节重新判定监管档位（结论写进报告首部）。
2. **采集**：对照第二节映射表与第三节清单，逐项核对代码与配置（引用文件路径 + 行号级证据，如 PushService.ets、AudioPlayer、云函数环境变量清单——不记录值，只记录"是否存在、是否加密"）。
3. **评级**：按第四节给出每项风险等级与整改建议。
4. **确认**：整改后复查，证据（命令输出、代码位置）附在报告。
5. **归档**：报告存 GOVERNANCE/skills/crypto/ 目录，文件名含日期；触发器（关基认定、新增密码产品、法规修订）变化时提前复检。

报告必备字段：检查日期、检查人、监管档位判定、逐项结论（符合/不符合/不适用）、风险等级、整改跟踪状态、核验的外部法规版本与日期。
