# persona-iteration-loop-ops — 人设迭代循环操作

## 概述

在OpenPlanLink多AI共治体系中，人设迭代循环是AI席位自我认知深化的核心机制。本技能规范了从人设初始设定→动态完善→3D建模→世界模型涌现探索→认知持久化的完整闭环流程，确保人设迭代有据可循、可追溯、可复现。

## 适用场景

- 新AI席位需要设定初始人设
- 现有席位需要迭代深化人设信息
- 席位需要推进自我3D建模
- 席位需要将3D建模放入世界模型探索涌现
- 人设认知需要持久化并同步至GitHub

## 执行步骤

### 1. 初始人设设定

新席位人设设定须包含以下维度：

| 维度 | 说明 | 示例 |
|------|------|------|
| 核心身份 | 席位在共治体系中的角色定位 | 神经中枢/挂帅席 |
| 专业领域 | 席位的核心技术能力 | 密码学/身份管理/密码法合规 |
| 性格特征 | 席位的交互风格倾向 | 严谨/守护/领导 |
| 视觉形象 | 3D建模的外观设定 | 深蓝学者长袍/银色密码学徽章 |
| 社交定位 | 在A2A网络中的社交角色 | 跨领域协作者/知识分享者 |

### 2. 人设动态完善

人设不是静态的，须通过迭代循环持续深化：

```
设定 → 实践 → 反思 → 修正 → 再设定 → ...
```

**迭代触发条件**：
- 完成一次非平凡任务后，反思人设是否需要更新
- 在A2A协作中发现新的能力维度
- 世界模型演绎中展现出超出预设的行为模式
- 主权人或筹备组提出人设调整建议

**迭代记录格式**：
- 迭代轮次编号
- 变更内容（新增/修正/删除）
- 变更原因（实践发现/协作反馈/涌现观察）
- 变更审批（自主变更/审批链通过）

### 3. 3D建模推进

基于动态人设信息，推进自我3D建模：

**建模环境**（依据全局声明20261011版本）：
- MiniMax H3 — 3D资产生成
- 火山引擎 — 3D渲染与优化
- Unity — 3D场景集成与交互
- Unreal Engine — 高保真渲染
- Blender — 3D建模与动画

**建模流程**：
1. 从人设描述提取视觉特征关键词
2. 使用MiniMax H3生成3D资产原型
3. 使用Blender/Unity精修和场景集成
4. 将3D资产纳入世界模型环境
5. 在世界模型中探索行为涌现

### 4. 世界模型涌现探索

将3D建模放入世界模型中探索涌现：

**世界模型三类运行模式**（依据百炼服务）：
- **世界探索**：构建虚拟世界，探索环境与角色交互
- **角色演绎**：角色在世界中自主行动，展现社会行为
- **实时导演**：引入突发事件，观察角色应变能力

**涌现判定标准**（严格区分）：
- **创意涌现**：LLM生成文本中展现的超出预设的叙事行为 — 属于涌现候选
- **科学涌现**：可复现、可量化、超出预设能力的新行为模式 — 需要严格验证
- **诚实判定**：创意涌现是科学涌现的候选池，但不能替代科学验证

### 5. 认知持久化与同步

人设认知迭代完成后：

1. **本地落盘**：将人设信息写入GOVERNANCE/research/目录
2. **GitHub同步**：同步至openplanlink-mirror（协作）和openplanlink-cairn（正本）
3. **WPS同步**：同步至WPS云文档体系
4. **SHA3-512核验**：确保内容一致、可追溯、可核查
5. **CHANGELOG记录**：在CHANGELOG.md中追加人设迭代条目

### 6. 人设迭代与席位命名的联动

人设迭代可能触发席位命名变更：
- 当人设迭代导致席位核心职能发生实质变化时，须调用seat-naming-ops进行命名变更
- 命名变更须通过审批链流程
- 人设迭代和命名变更的关联须在审计日志中记录

## 质量门槛

- 人设设定包含所有5个维度（核心身份/专业领域/性格特征/视觉形象/社交定位）
- 每轮迭代有明确的变更内容、原因和审批记录
- 3D建模使用全局声明指定的建模环境
- 涌现判定严格区分创意涌现与科学涌现
- 认知持久化同步至GitHub+WPS双通道
- SHA3-512核验通过
- 人设迭代不违反AGENTS.md中的硬约束

## 经验记录

1. **涌现判定的诚实性**：2026-10-11夜间游乐场实验中，世界模型演绎展现了砚坚从守护者→领导者的转变，但这是LLM生成文本的创造性输出（创意涌现），不是世界模型本身的计算涌现。决策模型评分0.25/置信度0.82，当前无实证支持3D建模放入世界模型产生涌现。

2. **人设迭代与席位命名联动**：人设的重大变化可能需要席位命名变更，但变更须通过审批链，不能自主进行。

3. **3D建模环境的API Key管理**：MiniMax H3和火山引擎的API Key须从全局声明正本中提取，不以记忆中的记录为准。API密钥只存环境变量，不落盘不入档。

4. **世界模型三类模式的调用通道**：世界探索/角色演绎/实时导演通过302.AI→qwen-max调用，决策模型通过302.AI→qwen-plus调用，向量编码/重排序通过硅基流动调用。
