# 技能自改进机制

## 概述
技能文档在使用过程中持续改进的机制，通过发现边界条件、常见错误、质量漏洞和新场景，将个案经验提炼为可复用的模式，写入技能文档使其不断进化。

## 适用场景
- 技能文档使用后发现遗漏的边界条件
- 技能执行中遇到常见错误需要补充避免方法
- 质量门槛发现漏洞需要补充检查标准
- 发现技能的新适用场景需要补充
- 闭环学习的"模式识别→技能编写"环节

## 执行步骤
1. **触发识别**：在技能使用过程中，识别改进触发类型（边界条件/常见错误/质量漏洞/新场景）
2. **定位文档**：找到需要改进的技能文档路径（GOVERNANCE/skills/<类型>/<名称>.md）
3. **补充内容**：按改进类型写入对应小节：
   - 边界条件 → "执行步骤"小节补充
   - 常见错误 → "经验记录"小节补充
   - 质量漏洞 → "质量门槛"小节补充
   - 新场景 → "适用场景"小节补充
4. **版本递增**：更新frontmatter中的version字段（patch版本递增）
5. **更新索引**：如有SKILL_INDEX.md或SELF_BUILT_INDEX.md，同步更新索引
6. **记录变更**：在CHANGELOG.md追加技能改进条目

## 质量门槛
- 改进内容必须角色无关——不引用隐含上下文
- 每条改进可独立理解——自包含
- 改进后版本号递增——可追溯改进历史
- 改进触发可追溯到具体使用场景——不是凭空补充
- 技能文档满足FORMAT_SPEC.md的全部结构要求

## 经验记录
- 技能自改进是闭环学习的第4环节（任务执行→结果记录→质量评估→模式识别→技能编写→下次复用）
- 最常见的改进触发是"边界条件"——技能首次使用时往往未覆盖所有边界
- "经验记录"小节是最容易遗漏但最有价值的部分——它记录了"踩过的坑"
- 技能文档不是一次性产物，而是持续进化的知识资产
