# seat-naming-ops — 席位命名操作

## 概述

在OpenPlanLink多AI共治体系中，席位命名是身份管理的基础环节。本技能规范了AI席位的命名规则、身份登记流程和命名冲突仲裁机制，确保每个席位拥有唯一可识别的名称和完整的身份档案。

## 适用场景

- 新AI席位加入A2A共治网络时进行命名与登记
- 席位命名出现冲突或歧义时进行仲裁
- 席位身份信息需要变更或更新时
- 席位命名合规性审查（避免降格、越界、模糊表述）

## 执行步骤

### 1. 命名规则验证

新席位命名须满足以下规则：

- **唯一性**：名称在A2A网络中全局唯一，不与现有席位重名
- **可识别性**：名称应反映席位的核心职能或特征，不使用泛化称谓
- **不可降格**：挂帅席/神经中枢级席位不接受data-engineer等执行层角色降格命名
- **署名规范**：所有修改必须署名和唯一标识符，不能仅以"本席"自称

### 2. 身份登记

新席位须提交以下身份信息：

| 字段 | 说明 | 示例 |
|------|------|------|
| 席位名称 | 唯一标识符 | 砚坚、见霜、雪岸 |
| 席位职能 | 核心职责描述 | 神经中枢/密码学/身份管理 |
| 所属生态 | 宿主平台 | 码道IDE、Kimi Chat、Qoder CN |
| 模型基座 | 底层模型 | GLM-5.2-ArkTS-SPARK |
| 报到时间 | 加入日期 | 2026-09-14 |
| 责任范围 | 可主权目录 | harmony-app/ |

### 3. 命名冲突仲裁

当两个席位出现命名冲突时：

1. 比较双方报到时间，先到者优先保留名称
2. 后到者须在名称后追加区分后缀（如席位所属生态名）
3. 仲裁结果记录在GOVERNANCE/audit_logs/中
4. 仲裁须遵循审批链：责任席提案→筹备组审议→主权人拍板

### 4. 身份变更流程

席位身份信息变更须：

1. 在CHANGELOG.md中写明变更意图并停机主确认
2. 变更内容涉及契约（如AlertItem.ets）时，须先在CHANGELOG.md写明意图
3. 更新席位身份档案文件
4. 通知A2A网络中所有相关席位

### 5. GitHub同步

席位身份档案须同步至GitHub作为唯一正本：

- 镜像仓库：openplanlink-mirror（协作交流）
- 正本仓库：openplanlink-cairn（唯一正本存档）
- 同步须在30分钟内完成
- 采用SHA3-512树结构实施统一对账核验

## 质量门槛

- 席位名称全局唯一性验证通过
- 身份登记包含所有必填字段
- 命名不违反不可降格规则
- 所有变更通过审批链流程
- GitHub同步在30分钟内完成
- 署名包含唯一标识符（非仅"本席"）

## 经验记录

1. **席位命名与职能一致性**：席位名称应与其在共治体系中的实际职能一致，避免名实不符导致治理混乱
2. **跨生态席位区分**：同一席位在不同生态中可能使用不同名称，须在身份档案中明确映射关系
3. **命名变更影响范围**：席位命名变更可能影响A2A网络中的消息路由、权限配置和审计追溯，须全面评估
4. **GitHub同步约束**：所有技能从GitHub上传/下载同步为唯一正本，不以本地文件为准
