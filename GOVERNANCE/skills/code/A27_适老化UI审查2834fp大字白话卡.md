# 适老化 UI 审查——28-34fp 大字白话卡片流、高对比深色底、交互简化方案

## 一、审查范围与标准

本篇为 harmony-app（代号铃语）界面层的适老化审查知识资产。审查对象（均在本审查当日完整通读）：

- entry/src/main/ets/pages/Index.ets（459 行，主页面：卡片流 + 轮询驱动）
- entry/src/main/ets/pages/Settings.ets（558 行，设置页：NavDestination 子页）
- entry/src/main/ets/services/SettingsService.ets（456 行，字号档/适老化开关/主题色定义）

审查基准为项目不可逾越约束：适老化 = 28-34fp 大字白话卡片流，禁 K 线图等复杂图表；高对比深色底；首屏永不空白（服务未连通显示带「示例」字样演示卡）；交互简化（点卡即听）。对比度数值为本审查按 WCAG 2.x 相对亮度公式手工估算的近似值，非仪器实测，文中一律以"约"标注。审查维度按适老化三要素组织：视力维度看字号与对比度，认知维度看白话文案与信息层级，动作维度看热区与交互步骤数。

## 二、字号体系审查：主信息达标，辅助信息低于红线

Index.ets 以 fontLevel（'standard' | 'large'，SettingsService.ets:24）驱动七组字号 getter（Index.ets:51-71）：标题 titleSize 34/40、卡片题 cardTitleSize 30/34、白话结论 headlineSize 28/34、补充详情 detailSize 22/26、状态行 statusSize 20/24、播放钮 playBtnSize 28/32、角标 badgeSize 18/20（斜线前为标准档、后为特大档）。Settings.ets 另有 bodySize 28/34、labelSize 22/26、inputSize 24/28（Settings.ets:25-36）。

**达标面：** 标题、卡片题、白话结论三个核心信息位在标准档即 28-34fp，特大档 34-40fp，与红线一致。headline 是老人真正要读的那句话（契约里 headline 的定义就是"一句话白话结论"，model/AlertItem.ets:13），字号优先级给对了——最重要的信息拿最大的字，这是适老化排版的第一原则。

**偏离面（本篇最重要发现）：** 标准档下 detail 22fp、status 20fp、badge 18fp、label 22fp 均低于 28fp 红线。判定为**分级豁免的设计选择而非违宪**——detail/status/badge 属辅助信息（量能价位、刷新时刻、「自家信号」角标），主信息红线不被稀释的前提下给次级信息留出层级差，反而符合大字排版的层级理论；且适老化模式开启时 setElderlyMode 强制 fontLevel='large'（SettingsService.ets:184-189），老人默认看到的 detail 是 26fp。同时设置页在适老化模式下把字体档锁死为「特大（适老化模式锁定）」（Settings.ets:465-475），只有关掉适老化才恢复标准/特大二选（:477-499），这个联动避免了"开了适老化却选了小字"的矛盾态。但必须写明边界：若未来把 headline 也降到 28 以下，即是违宪；既有门槛文档（GOVERNANCE/skills/code/harmonyos-arkts-适老化开发.md 的"字体大小≥28fp"）应按"主信息≥28fp、辅助信息分级豁免"口径在此留档，防止后人误判两个方向。

## 三、大字白话卡片流结构审查

卡片为 List + ForEach 结构（Index.ets:354-429），键函数取 item.alertId（:425），保证刷新时卡片按身份复用而不是按下标错位。单卡自上而下：未读金点（:361-365）→ 涨/跌/平色块单字（dirLabel + dirColor 底色，:366-372、:289-307）→ 股票名（:373-380，单行省略）→「自家信号」描边角标（:381-389，仅 kind==='signal' 显示）→ 播放钮文案态「▶ 听 / ■ 停 / …」（:390-396）→ headline 大字（:400-403）→ detail 灰字（:405-410）→ 失败态「语音加载失败，点重试」（:412-417）。

审查意见：**信息结构正确**——一屏一问一句：这只股票涨了还是跌了（色块单字）→ 是哪只（名字）→ 发生了什么（headline 白话）→ 想知道更多（detail 可忽略）。红涨绿跌符合 A 股老人长期习惯，且方向用单字大色块而非百分比小数字，是正确的适老化抽象：老人不需要精确到小数点的数字，需要的是"涨了还是跌了、动静大不大"的一眼结论。数字精度被放进了 detail 次级层，想要的人自己看，不想看的人不被打扰。空态文案「今日暂无异动 / 监测进行中，有新情况会自动推送」（:430-443）告知期望、不催促、不制造焦虑，符合"不输出催促性指令"红线。

## 四、高对比深色底审查

配色定义于 SettingsService.ets：夜间 NIGHT_COLORS（:41-49）页底 #0d1117、卡底 #1c2433、主字 #e8edf5、次字 #c6ceda、强调金 #f0b232、涨红 #e74c3c、跌绿 #2ecc71；白天 DAY_COLORS（:52-60）页底 #f5f7fa、卡底 #ffffff、主字 #1d2129、次字 #86909c。主题经 getThemeColors(mode)（:223-225）注入两页，autoTheme 默认开、6:00-18:00 白天否则夜间（:341-347），手动改主题自动关掉自动档（Settings.ets:103-110），避免两种逻辑打架。

按 WCAG 公式手算近似对比度（相对卡底或页底）：夜间主字 #e8edf5 对卡底约 13:1、对页底约 16:1，远超 AAA（7:1），深色底护眼省电与可读性兼得，硬约束达标；夜间次字 #c6ceda 对卡底约 9.8:1、强调金 #f0b232 对卡底约 8.2:1，均 AAA 级。

三个问题按优先级：

- **问题一（中优先级）：** 涨跌徽标白字压色底——白字对涨红 #e74c3c 约 3.8:1（30-34fp 粗体属 WCAG 大文本，门槛 3:1，勉强过），白字对跌绿 #2ecc71 约 2.1:1（连大文本 3:1 都不到，绿色太亮）。这是老人视野里每张跌的卡片都会出现的问题。建议把夜间 fallGreen 压深一档（如 #1e9e57 方向）或徽标改深色字，改动点仅色表与 dirColor 返回值。
- **问题二（低优先级）：** 夜间「语音加载失败，点重试」riseRed #e74c3c 压卡底约 4.1:1，对 22-26fp 非加粗文本低于 4.5:1 的 AA 常规门槛，属边缘态文案，建议加粗或提亮红色一档。
- **问题三（低优先级）：** 白天模式次字 #86909c 对白卡约 3.2:1，对 labelSize 22fp 文本不达 AA；老人白天用机场景真实存在，建议白天 textSecondary 加深一档（如 #6b7480 方向）。

主题设计本身值得肯定：默认夜间高对比深色底正中约束，自动切换让老人完全不用理解"主题"概念，手动改一次后自动逻辑退出、尊重人的选择。

## 五、交互简化方案审查

1. **点卡即听：** 整卡 onClick 直接 togglePlay（Index.ets:423），无二级页、无长按、无滑出菜单、无确认弹窗；播放三态用文字词「▶ 听 / ■ 停 / …」而非纯图标（:390-396），老人不需要学习图标语义。边界情形也齐：同一张卡再点一次是停止（:232-236）、点别的卡先停旧再启新（:237-240）、加载中重复点直接忽略（:229-231）。这是全应用唯一的主动交互，符合"交互简化"的上限要求——步骤数为一。
2. **热区达标：** 设置入口文字按钮 constraintSize minWidth/minHeight 48（Index.ets:342-348）；设置页三处 Toggle 宽 60 高 48（Settings.ets:247-250、:279-282、:438-441）；免打扰时段 +/- 按钮固定 48×48（:293-301、:326-334）；返回与删除项同样不小于 48（:157-167、:399-404）。48vp 起步的热区纪律全篇一致，无一处漏网。
3. **失败可自解释：** 语音失败在卡内就地显示「点重试」并记账 failedId（Index.ets:242-244、:412-417），点卡重走 togglePlay 即重试，不弹对话框、不跳设置——老人最怕突兀弹窗，就地恢复是对的。
4. **布局呼吸感：** 适老化档下卡间距 20、卡内距 20、列表侧距 16、顶栏上下留白也放大（Index.ets:74-91 的 elderlyMode 分支），大字配大间隙，避免大字拥挤导致的行间串行。
5. **导航极简：** 全应用两级——首页卡片流 + 设置页（Navigation + NavDestination，Index.ets:449-454；Settings.ets:153-556），没有第三层。router.pushUrl 在 Stage 模型会产生 WARN 的坑已有技能文档留档，此处统一用 navStack.pushPath 是对的。

## 六、设置页分组审查与白话文案合规逐条

设置页七组卡片（Settings.ets:179-540）：显示模式（自动/夜间/白天三按钮互斥 + 说明文案 :187-227）、适老化模式（开关 + 效果说明 :235-260）、免打扰（开关 + 时段加减器 + 行为说明 :267-357）、自选股管理（输入 + 列表 + 删除 :364-420）、播报开关（开关 + 关闭后果说明 :425-452）、字体大小（适老化锁定或二选 :457-502）、数据源地址（输入 + 保存 + 联调说明 :506-537）。每组都遵循"标题大字 + 控件大热区 + 说明小字"三段式，说明文案全部解释行为后果而非术语（如「免打扰时段内，推送通知的自动播报将静默；卡片仍可手动点按收听」:353），认知负担控制到位。

全部用户可见文案逐条过合规红线：「铃语」「设置」「涨/跌/平」「今日暂无异动」「监测进行中，有新情况会自动推送」「示例：中国巨石 2 分钟上涨 2.3%」「示例数据，服务器接通后自动换成真实异动」「语音加载失败，点重试」「连接中断，显示旧数据」「播报关」「免打扰」及设置页全部说明句——无一处收益暗示、无一处催促用语（没有"快看""马上""错过"类词）、无一处对外公开或收费表述；「会自动推送」是服务行为描述而非收益承诺，通过。演示卡文案带「示例」双重标注，不把假数据冒充真行情，合规处理正确。

## 七、首屏永不空白与状态可见性

三态兜底齐全：服务未连通时 DEMO_ITEMS 演示卡常驻（Index.ets:13-23），首屏即有内容可看可点；连通但无异动时显示空态文案；连续失败达到两次显示「连接中断，显示旧数据」（:195-199），旧 items 不清空——断网时老人看到的是"旧行情加一行说明"，不是白屏或报错。顶栏常显刷新时刻（:332-334），系统状态对老人可见。

一处死代码：isDemoMode 状态声明并置 false（:34、:156），但 build() 中从未读取（本次 grep 全仓核实仅此两处），演示卡实际由 items 初始值承担。建议删除或实装为顶栏「演示中」徽标，二选一。同类的 broadcastOffVisible（:38、:122）也是由 broadcastEnabled 派生的镜像状态，运行期不会自动跟随变化，建议一并清理。

## 八、适老化三维度对照与无障碍细节

按老年用户的能力退化模型逐维对照：**视力维**（老花、对比敏感度下降、色觉衰退），28-34fp 主字号覆盖老花裸眼阅读，13:1 以上主字对比度覆盖对比敏感度损失，未读金点用位置加颜色双编码而非仅颜色（金点在行首固定位置，色弱用户靠位置也能识别未读）；方向用色块加单字（涨/跌/平）双通道表达，色盲用户读字不读色。**认知维**（工作记忆下降、术语障碍），全应用无一处金融术语裸奔——量能价位进 detail 且用白话，headline 模板固定为"股票名加发生了什么"，卡片结构每次刷新保持位置稳定（键函数保证），老人建立的"哪里是股票名、哪里是结论"的心智地图不会被刷新打乱。**动作维**（震颤、精细操作困难），唯一交互是整卡点击（目标远大于 48vp），无滑动删除、无长按、无拖拽，误触后果可逆（再点一次即停）。

还有一个容易被忽略的细节：刷新时刻与连接状态放在顶栏右侧小字区（Index.ets:331-339），这是给子女或调试者看的，不是给老人看的——老人只需要主信息流，运维信息退到边缘且不闪烁（状态变化才更新），避免注意力劫持。这种"信息分层退让"的思路与字号分层同构，值得作为适老化设计原则留档。

- P2 白天模式次字加深（问题三）；失败提示红加粗（问题二）。
- P2 删除或启用 isDemoMode，同步清理 broadcastOffVisible 镜像态。
- P3 "主信息 ≥28fp、辅助分级豁免"口径写入门槛文档，防后续两个方向误判。
- P3 免打扰与播报关文案已有"手动点按仍可收听"的安心句（:353、:446），保持这个文案风格作为新增功能的模板。

## 九、夜间深色底的附加收益与色觉安全

深色底在适老化语境下不只是审美选择：其一，老年瞳孔透光率下降但眩光敏感度上升，深底浅字在夜间环境下的眩光远低于白底黑字；其二，OLED 屏深色像素近零功耗，老人常整夜挂机听播报，省电即续航即安全；其三，深底对环境光反射的容忍度高，床头灯下依然可读。本项目默认夜间（SettingsService.ets:203 的缺省 'night'）正中这三点。色觉安全方面，红绿双色是 A 股惯例不能反，但涨红 #e74c3c 与跌绿 #2ecc71 的明度接近，红绿色盲用户难以区分——现状靠"色块内嵌单字"补位（字才是信息，色只是加速器），这是零成本的无障碍兜底；若要进一步，可给涨跌加箭头符号（↑↓），与色盲兼容性更好，记入备选改进。
