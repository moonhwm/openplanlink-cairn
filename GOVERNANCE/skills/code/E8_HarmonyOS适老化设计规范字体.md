# E8 HarmonyOS适老化设计规范：字体大小、对比度、触摸区域、交互简化、语音辅助

> 适用项目：harmony-app（代号"铃语"，鸿蒙适老化股票异动播报应用），纯ArkTS+Stage模型（compatibleSdkVersion 20 / targetSdk 26）。本文自包含成文，是适老化UI的唯一裁决依据，审查类文档（如A27）以本文为基准。红线贯穿全文：不承诺收益/保本、不输出催促性指令、不涉对外公开/收费；禁K线图等复杂图表；首屏永不空白。

## 1 设计原则与用户画像

用户画像：60岁以上股民。生理特征——老花（近点距离后退，需要大字号大对比）、手部震颤（点按精度差、易连击）、色觉退化（红绿辨析弱、屏幕老化发黄）；认知特征——对K线、均线、MACD无感，对"涨了/跌了/为什么"敏感；心理特征——怕被骗、怕点错、怕错过但不接受被催促。

三句话设计总纲：字要大（28-34fp白话卡片流）、话要白（一条异动一句话讲清）、一步到位（看→听两步内完成）。任何设计争议按这三句裁决；与流量、留存、美观冲突时，一律让位于可读可点可懂。

## 2 字体大小规范

### 2.1 单位与档位

- 字号一律用fp（font pixel），随系统字号设置缩放；禁用px和固定vp写字号。vp只用于布局尺寸，不用于文字。
- 铃语档位（收敛在Token文件，全工程禁散落魔数）：

```ts
// common/FontTokens.ets
export class FontTokens {
  static readonly BODY: number = 28;   // 卡片正文，最小档，全应用不得低于此值
  static readonly EMPH: number = 32;   // 涨跌幅、价格等强调数字
  static readonly TITLE: number = 34;  // 卡片标题、页标题
}
```

- 28fp是全应用下限：辅助说明、按钮、标签一律≥28fp，不出现"小字备注"。这比通用无障碍规范更严，是适老化的核心成本，也是核心价值。
- 数字强调（如"+2.30%"）用EMPH档加粗，并遵守下节颜色冗余规则。

### 2.2 系统字号联动

老人最常做的系统设置就是把字体调到最大。必须监听fontScale变化并重排：

```ts
onConfigurationUpdate(newConfig: Configuration) {
  AppStorage.setOrCreate('fontScale', newConfig.fontSizeScale ?? 1.0);
}
```

- 页面侧用@StorageProp('fontScale')联动；文本容器高度禁写死，用List卡片自适应高度、Flex百分比宽度吸收放大后的溢出。
- 超长文本处理：maxLines + TextOverflow.Ellipsis截断，配"展开"大按钮看全文；严禁用缩小字号来塞内容——缩字号解决排版，却破坏可读，适老化场景一律不允许。
- 深浅色两套主题下都要复测字号渲染，粗体在深色底可能有视觉变细，关键数字统一FontWeight.Bold。

## 3 对比度规范

- 正文文字与背景对比度≥4.5:1（WCAG AA）。大字号（≥28fp，属"大文本"）按WCAG可放宽到3:1，但铃语从严仍按4.5:1执行——目标用户的屏幕普遍老化、常在户外强光下使用。
- 计算公式：(L1+0.05)/(L2+0.05)，L为相对亮度。常用组合参考：白底#FFFFFF配近黑正文#1A1A1A约17:1（富余）；深红#C5221F白底约5.8:1（达标）；亮红#D93025白底约4.4:1（临界，正文用建议加深）。新增配色先算再上。
- 红涨绿跌必须冗余编码，不能只靠颜色：色块+箭头符号（↑↓）+文字（涨/跌）三重编码。约8%男性有红绿色觉障碍，而股民以中老年男性为主，这是本项目的高发人群，不是小概率。
- 深色模式：避免纯黑底纯白字的大面积长时间组合（老花眼易眩光疲劳），用柔和深底（如#1C1C1E）配米白文字；涨跌色在深色底单独调亮并复测对比度。
- 禁低对比灰字："灰色小字免责声明"这类设计直接违反本文，说明文字也是28fp、4.5:1。

## 4 触摸区域规范

- 最小可点击热区：鸿蒙UX规范建议60×60vp，铃语加严到64×64vp。视觉尺寸可以小于热区，热区用padding或constraintSize扩出来：

```ts
Button('再听一遍')
  .fontSize(FontTokens.EMPH)
  .constraintSize({ minWidth: 192, minHeight: 64 })
  .padding({ left: 24, right: 24, top: 16, bottom: 16 })
```

- 相邻可点元素间距≥16vp，防手抖连点串台；纵向列表中两个按钮不得上下紧贴。
- 关键操作防抖：同一按钮二次点击间隔≥1秒（如"再听一遍"防止音频重叠起播）。
- List卡片整卡可点（点卡片=展开详情或播报），不提供散落的小链接、小图标按钮；必须用的图标按钮（如播放）一律按64vp热区执行并配accessibilityText。
- 单手可达：高频操作（播报、展开）落在屏幕右下半区；返回与关闭不与高频操作贴邻，避免误退。
- 不要求精确手势：不依赖双击、长按、多指操作；不用左右滑动删除等隐式手势，破坏性动作一律显式大按钮+二次确认（白话确认文案）。

## 5 交互简化规范

- 信息结构单层化：全局就是一页List卡片流。一张卡片=一只股票的一次异动：名称、白话事件一句话、涨跌幅、播报按钮；点卡片展开详情（还是文字与数字，不是图表）。无Tab嵌套、无抽屉、无二级导航。
- 禁图表：K线图、分时图、技术指标一律不出现（项目铁律）。数据表达只用大字数字+白话陈述，例如"较昨收上涨2.30%"。
- 操作步数：任何核心动作≤2步。看→听；定位某条→点播报。每新增一步都要在评审里说明老人为什么愿意多走这一步。
- 状态可感知：轮询中、播报中、失败重试都用大字+图标明示（如卡片高亮+播报中图标），禁静默状态；失败给白话原因与重试按钮。
- 首屏永不空白：服务未连通时展示带"示例"字样的演示卡，明示示例身份，防止老人把演示数据误读为真实行情——这既是体验要求也是合规要求。
- 文案红线（逐字执行）：不出现"稳赚""保本""翻倍""最后机会""立即买入""马上抢""点击赚钱"及一切催促性、承诺性、诱导性措辞；只用中性陈述，如"今日午后，XX银行较昨收上涨2.3%，成交量放大"。不出现任何收费、加群、外链导流入口。
- 弹窗克制：不用弹窗做运营触达；系统级必要提示（权限）一次说清白话用途。

## 6 语音辅助规范

- 播报链路：卡片白话文案 → 云函数generate-tts合成（audioUrl缺省时端侧按需触发，见E7）→ AVPlayer播放音频流（AudioPlayer模块，见A25）。语音辅助是本项目与"看"并列的第一通道，不是附加功能。
- 播报文案规范：先公司名后事件；数字交给TTS引擎读，文案保留"2.3%"原样即可；文案即卡片文案，同一句话看听一致，不做两套话术。文案过审时同时过红线检查（无承诺、无催促）。
- 播放交互：播报中卡片高亮并显示"播报中"状态；播完自动停，不自动连播轰炸；提供"再听一遍"；语速默认中速，可在设置里调慢（设置入口也要一步可达）。
- 读屏兼容：所有可点组件设置accessibilityText/accessibilityDescription/accessibilityLevel，读屏顺序与视觉顺序一致；图标必有替代文本；文案必须是真文本，严禁把文字渲染成图片（图片字无法缩放、无法读屏）。
- 音频焦点：来电或其他应用抢占音频时让路，回来后不自动续播，等用户手动"再听一遍"——避免老人被突兀的声音惊扰。

## 7 发版前自查清单

1. 真机两档目测：系统默认字号与系统最大字号，卡片无溢出、无截断异常、按钮无换行错位。
2. 抽查五张典型卡片的文字/背景对比度均≥4.5:1；涨跌信息三重编码齐全。
3. 两指并按快速乱点30秒，无误触发、无页面跳失。
4. 断网冷启动：3秒内出现示例卡；恢复后演示数据被真实数据替换且"示例"字样消失。
5. 播报文案全量过红线词表：无承诺收益/保本词、无催促词、无收费与外链。
6. 打开系统读屏，按视觉顺序能走完"看卡片→听播报"全程。

## 7 色彩与Token集中管理

全工程颜色只允许出现在Token文件，页面禁写裸色值；新增色先算对比度再入表：

```ts
// common/ColorTokens.ets
export class ColorTokens {
  static readonly BG: string = '#FFFFFF';      // 页面底
  static readonly TEXT_MAIN: string = '#1A1A1A'; // 正文
  static readonly UP: string = '#C5221F';      // 涨（配↑与"涨"字冗余）
  static readonly DOWN: string = '#1E7E34';    // 跌（配↓与"跌"字冗余）
  static readonly DEMO_TAG: string = '#8A6D00'; // 示例角标，深色底禁用浅灰
}
```

- 深色模式用资源限定词目录（resources的dark限定词）自动切换，两套主题各自复测对比度，不共享一套色值。
- 涨色用偏深的正红、跌色用偏深的正绿：饱和度过高的荧光红绿在低档屏幕上会溢色，反而降低辨识。

## 8 图标与动效规范

- 图标仅作辅助语义（喇叭=播报、铃铛=提醒），必配文字标签，永不单独表意；尺寸≥32vp，线性图标线宽≥2vp，全套同风格。
- 动效只保留两类：按压反馈（按钮按下沉降2vp）、内容切换淡入淡出（≤300毫秒）。禁弹跳、飞入、视差、旋转——老年用户视觉追踪能力下降，炫技动效是负担不是加分项，还拖慢低端机渲染。
- 轮播、自动滚动、悬浮随动入口一律不用：目标用户来不及反应，误触率高。

## 9 示例卡文案模板

固定模板（示例数据中性、无夸张数字，防误导也防红线联想）：

"【示例】XX银行午后上涨2.3%，成交量有所放大。这是演示内容，联网后自动显示真实行情。"

- 【示例】前缀必须用EMPH档加粗，与真实卡片视觉强区分；角标"示例"二字号同样≥28fp。
- 演示涨跌幅取2%上下的温和值，禁用涨停、暴涨等词，也不出现跌停惨状——两端都不制造情绪。
- 服务恢复后演示卡整体消失，不留"混合真假"的中间态。

## 10 设置项规范

- 设置入口固定页面右上角，64vp热区，图标加"设置"二字。
- 设置项上限三个：语速（慢/中）、字号档（大/特大）、自动播报开关（默认关）。
- 全部用大开关与大单选块呈现，禁下拉框、禁滑杆——精细拖动与展开小列表对老人都不友好。
- 每项改动即时生效并持久化（prefernces），重启不丢；设置页一键返回且保持卡片流滚动位置。

## 11 长时间使用与信息密度

- 每张卡片信息点上限四个：名称、白话一句话、涨跌幅、播报按钮；多余信息一律进"展开详情"。
- 卡片间距≥16vp，页面留白宁多勿少；信息密度让位于扫读效率。
- 盘中挂机场景倾向纯语音：自动播报开关开启时，新到异动先播报不打断滚动；文字流仍是唯一真相源。
- 夜间使用：深色模式外，播报音量跟随系统媒体音量，不自行放大惊扰。

### 自我评估
- 正确性：4分——fp与fontScale联动、WCAG对比度公式与示例值、热区与无障碍属性均为标准规范；对比度示例数值为按公式计算所得，标注"约"。个别ArkUI属性默认值细节以API 20实际行为为准。
- 完整性：5分——五个指定维度（字体、对比度、触摸、交互简化、语音辅助）全部展开，另补色彩Token、图标动效、示例卡模板、设置项、信息密度与自查清单；与E6（fontScale回调）、E7（generate-tts链路）分工引用明确。
- 可复用性：4分——档位Token、红线词检查、自查清单可直接用于其他适老鸿蒙应用；涨跌冗余编码与演示卡规则为铃语特有，已单独标注。
- 字数：约2685字（正文汉字，实测统计）
- 使用模型：GLM-5.3-Flash
