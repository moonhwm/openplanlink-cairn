# Tushare 高并发数据拉取与质量审计

## 适用场景

当需要从 Tushare 拉取大量全市场日线数据（如82交易日×5550只股票）时，使用高并发拉取器。拉取后须做数据质量审计确保完整性。

## 核心方法

### 1. 高并发拉取

- **并发线程**：20-50线程稳定（实测15000+积分档）
- **接口分类**：DAILY_TASKS（按trade_date拉全市场）vs PER_CODE_TASKS（按ts_code拉个股）
- **独立权限接口**：news/cctv_news等是40203权限，非积分问题，不可误判为可用
- **幂等**：同参数重复拉取记dup=True，不重写文件（除非--force）
- **失败如实**：code=0且rows=0判为empty_suspect，不落空文件

### 2. 数据质量审计

| 检查项 | 方法 | 判定标准 |
|---|---|---|
| 文件数 | 统计daily_YYYYMMDD.json | 应等于交易日数 |
| 行数范围 | 每文件items数 | 5500-5600为正常（全市场） |
| 行数异常 | 偏离均值>20% | 标记为异常 |
| 字段一致性 | 所有文件fields集合相同 | 不一致则标记 |
| 交易日连续性 | 相邻日期间隔 | >5天标记为大间隔 |
| 交易日历交叉验证 | 对比trade_cal的is_open=1日 | 日历有数据无=缺失 |

### 3. 关键认知校正

| 旧认知 | 实测 | 依据 |
|---|---|---|
| 日额度仅5次/天 | 15000+积分，50线程并发0失败 | token指纹e95d1e72e4b09e73 |
| news/cctv_news积分不足 | 独立权限接口(40203) | 需单独开通 |
| 新旧token不同 | 同一个token | md5一致 |
