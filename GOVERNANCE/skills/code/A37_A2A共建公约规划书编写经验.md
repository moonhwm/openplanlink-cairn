# A2A共建公约治理自治规划书编写经验

## 触发场景

当需要为一个多智能体A2A网络编写治理公约/规划书时，可复用本技能文档的方法论和经验。

## 方法论

### 1. 代码排查先行

在编写任何规划之前，必须先对当前代码库进行三路排查：
- **A2A通信链路**: grep搜索 `a2a|A2A|broadcast|cross_mode|heartbeat|registry`
- **定时心跳/轮询**: grep搜索 `cron|setInterval|setTimeout|scheduler|定时|轮询|poll`
- **kimi/外部调用点**: grep搜索 `kimi|KIMI|kimi-code|kimi_code`

排查结果作为规划书的"事实基底"，确保规划基于现实而非想象。

### 2. 理论框架选择

选择与项目气质契合的理论框架：
- **哈贝马斯交往行为理论**: 适合需要共识决策的多智能体网络
  - 四有效性主张（真实性/正当性/真诚性/可理解性）可映射为网络治理规则
  - 公共空间概念适合A2A总线设计
- **尼采《悲剧诞生》游玩态度**: 适合将事故/失败转化为制度化契机
  - "目的在其自身"——自治运转的价值在运转本身

### 3. 六节四段式清单

每项改造方案必须采用「文件/模块 → 改动 → 参数值 → 验证步骤」四段式清单：
- **文件/模块**: 给出具体文件路径
- **改动**: 描述具体改动内容
- **参数值**: 给出参数名、默认值、环境变量名
- **验证步骤**: 给出可执行的验证命令和预期结果

### 4. 扩展章节覆盖

核心六节之外，需覆盖：
- 自进化机制（Hermess/EvoMap对标）
- 每日自动化追新
- Harness/Loop/提示词工程
- A2A外交公约（理论映射+签署流程）
- 数字主权与密码学
- 经济学量化研究范式
- 前沿LLM论文复现

### 5. EvoMap进化路径追踪

规划书编写本身也是一个进化事件，须在EvoMap中记录：
- `evomap/charter/` — 公约修订事件
- `evomap/skills/` — 技能创建事件
- `evomap/incidents/` — 事故解决事件

## 经验教训

1. **代码排查不可跳过**——规划书必须基于代码事实，不能凭想象编写
2. **理论框架不是装饰**——哈贝马斯四有效性主张直接映射为落地机制，不是空谈
3. **四段式清单防止空泛**——每项都给出文件路径和验证命令，杜绝"构想描述"
4. **禁止新旧双通道并存**——停用kimi就是彻底停用，不允许过渡期双通道
5. **40w字是渐进目标**——先完成框架(768行)，再持续填充各章节
